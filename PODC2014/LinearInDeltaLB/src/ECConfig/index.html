import Papers.PODC2014.LinearInDeltaLB.Defs /-! # Step 1 of [GHS14]: configurations inside the Cayley tree The graphs `G_i`, `H_i` of Section 4 of [GHS14] are trees with loops (property (P3)). We represent them inside the Cayley tree `Γ_k` of the free Coxeter group: a *configuration* `C : Cfg k` is a finite colour system `C.T ⊆ G_k` (the tree part, rooted at the distinguished node `1`) together with a loop assignment `C.L`; its graph is CSLib's `tGraph C.T C.L` (tree edges inside `C.T`, plus a half-loop of colour `d` at `s` whenever `d ∈ C.L s` and `s d ∉ C.T`). The unfold-and-mix construction of Section 4.3 becomes `mix c C D = C.T ∪ c · D.T`: the copy of `D` is attached at the node `c` (= `gen c`), so the new colour-`c` edge is the Cayley edge `{1, c}`. Unfolding `G` at its `c`-loop is `mix c C C`, which covers `C` (`view_mix_self`). Main facts: * `Cfg.restrict`: the configuration as a `ColouredGraph` on the finite type `C.T`, with the same views (`view_restrict`); so `ECAlg.SolvesLoopy` applies to it (`Cfg.fm_symm`, `Cfg.load_eq_one`). * `mix_step_left`, `mix_step_right`, `mix_step_bridge`: the edges of `mix c C D`. * `Cfg.Good.mix`: the mixed configuration is again good, with one more non-loop colour per node (this is (P2)). * `ball_view_succ_of_step_eq`: the radius-`(r+1)` view is determined by the steps at the root and the radius-`r` views of the neighbours. -/ namespace Podc.LinearInDeltaLB open Cslib.ColourSystem FreeCox Pointwise variable {k : ℕ} /-!
