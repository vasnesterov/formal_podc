import Papers.PODC2014.SignatureFreeBA.Model /-! # One round of the attack, as a finite (decidable) computation Mostéfaoui, Moumen, Raynal, PODC 2014: the counterexample to Lemma 5 for `n = 4`, `t = 1`. Processes `0, 1, 2` are correct, `3` is Byzantine. This file describes the messages of *one* round `r` of the algorithm (Figures 1–2) and the adversary's schedule for that round as a finite state machine whose guards are decidable, so that the whole schedule is checked by `decide`. `Counterexample.lean` embeds it into the asynchronous model `Cslib.Byzantine.AsyncBroadcast` and glues the rounds together. At the start of a round, processes `0, 1` have estimate `a` and process `2` has `¬a`. The schedule (the coin of the round is `s`, revealed when process `0` calls `random()`): 1. `3` sends `B_VAL(¬a)` to everybody; `0`, `1`, `2` all echo the value they lack, so both values reach every `bin_values`, but in a chosen order; 2. `0` gets `bin_values = {a}` first and broadcasts `AUX(a)`; `1` gets `{¬a}` first and broadcasts `AUX(¬a)`; 3. `0` receives `AUX(a)` (own), `AUX(¬a)` (from `1`), `AUX(a)` (from `3`): `values = {0, 1}`; it calls `random()` and adopts `s`; 4. `1` gets `bin_values = {0, 1}`, receives the same three `AUX` values, calls `random()` and adopts `s`. **Only now does the adversary use `s`** (with a threshold coin that needs `n − t = 3` shares, the shares of `0`, `1` and `3` reveal it); 5. `2` gets `bin_values = {¬s}` first, broadcasts `AUX(¬s)`, and receives `AUX(¬s)` from itself, from `3` and from the one of `0`, `1` that sent `¬s`: `values = {¬s}`, but the coin is `s`, so it does not decide and adopts `¬s`; 6. all remaining messages of the round are delivered.
