Consensus with an Abstract MAC Layer — PODC 2014

Calvin Newport. Consensus with an abstract MAC layer. PODC 2014. DOI 10.1145/2611462.2611479. Formalized version: arXiv 1405.1382 v1; numbering follows it.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. All lower bounds hold: Theorems 3.2 (with n ≥ 2), 3.3, 3.9 and 3.10 are proved, and Theorem 4.1 holds for the two-phase algorithm described in the prose, with the 2 F_ack time bound, although line 23 of Algorithm 1 has a one-symbol slip. Claim 3.4 fails for D = 4, a non-degenerate case that Theorem 3.3 covers, so the networks of Figure 1 do not prove Theorem 3.3 there; we prove the theorem for every even D ≥ 4 with a different gadget, found by computer search. The multihop algorithm wPAXOS was not checked.

Mistakes in the paper

🛠️ Claim 3.4 for D = 4 (the networks of Figure 1)

For D = 4 (d = (D−2)/2 = 1) the paper's Network A has diameter 6, not 4, because node a₂⁺ of the gadget is at distance 2 from c (claim_3_4_false_D4).

Impact. D = 4 is the smallest case of Theorem 3.3, not a degenerate one, so Figure 1 does not prove Theorem 3.3 there. The theorem is still true: we prove it for all even D ≥ 4 with another gadget (theorem_3_3, exists_nets).

Details

In Lean the counterexample is the 15-node network for k = 0, i.e. 4 ≤ n ≤ 15. The padding nodes a*_j are attached to a_{d−1} = a₀, which does not exist.

Repair

Our gadget, found by computer search: a core c, t, s, r, u, p, padding twins of p, and a path of length d − 1 below t. B is a 3-fold voltage cover of it. (theorem_3_3, exists_nets)

🔧 Lemma 3.8 (lines of every length d)

Lemma 3.8 claims one t for lines of every length d, but its hypothesis only concerns networks of diameter D, so only d = D follows.

Impact. Only d = D is used, and we prove that case (lemma_3_8). Nothing is known for d ≠ D.

✏️ Slips

  • Algorithm 1, line 23: read literally, the algorithm violates agreement on two nodes, because the line looks for ⟨phase 2, *, decided(0)⟩ in R₂ only, while a phase-2 message received during the receiver's phase 1 goes into R₁ (twoPhaseLit_not_solvesConsensus; counterexample below, under Proof remarks). With the check over R₁ ∪ R₂, Theorem 4.1 holds, including the bound "decide by 2 F_ack" (theorem_4_1, theorem_4_1_time).

  • Theorem 3.2 needs n ≥ 2: with one node, deciding one's own input solves consensus with any number of crashes (theorem_3_2_card_one); theorem_3_2 assumes 2 ≤ n.

  • Lemma 3.8: "all nodes begin with initial value 0" should be b.

  • Lemma 3.6: the synchronous scheduler does not fix the order in which a node receives the messages of one round, and corresponding nodes must use the same order; we sort messages by a fixed order.

Proof gaps in true statements (1)Lemma 3.1

🔧 Lemma 3.1 (valency and crashes)

The proof's valency notion is ill-posed and Case 1 applies the valency of β₁ to an execution in which w crashes, which is not an extension by valid steps.

Impact. Statement true; repaired (lemma_3_1, exists_decision_off, stepV_comm).

Details

  • Valency is defined over extensions by valid steps. Then a fragment with no deciding extension is vacuously both 0- and 1-valent, and it is unclear whether extensions may contain crashes.

  • Case 1 applies the valency of β₁ to an execution in which w crashes. Such an execution is not an extension by valid steps of the paper's kind.

Repair

  • valency counts crash-free valid extensions; every reachable configuration has a possible decision;

  • the decision obtained by crashing w is transferred to the crash-free extension in which w is merely silent; both runs perform the same events and agree off w;

  • both cases of the proof become one: the two orders of the steps agree except at one node.

(lemma_3_1, exists_decision_off, stepV_comm)

The formalizationmodel, Lean names of the results, trust

Model (Podc/Computability/Distributed/AbstractMAC/, staged for CSLib as Cslib.AbstractMAC).

  • A graph G and deterministic algorithms: an initial state from an identity (Unit = anonymous, ℕ = unique ids) and a binary input, transitions on receive and on ack, an optional broadcast, an irrevocable decision.

  • Events recv u v, ack u, crash u; disabled events are no-ops. An ack is enabled only after every neighbour received the current message. Executions are sequences of blocks of events.

  • Crashes. A crashed node stops and its message is no longer delivered. Deliveries to a crashed node are bookkeeping events and acks wait for them: a sub-model of the paper's, so impossibility results transfer.

  • SolvesConsensus A G id f: agreement, validity and termination in every timely execution (bound F_ack on ack delay, for any F_ack) with diverging time and at most f crashes. Every fair execution is timely (Fair.exists_timely).

  • Synchronous rounds, possibly holding some nodes' broadcasts for some rounds (the paper's semi-synchronous scheduler), with a simulation lemma for covering/embedding maps (syncLoc_comp) and a locality lemma (syncLoc_congr_of_walk).

  • Theorem 3.2: clique, tolerance f = 1. All other results: no crashes (f = 0). Knowledge of n or D is modelled by quantifying only over networks with that size or diameter.

Proof remarks.

Algorithm 1, line 23. A phase-2 message received during the receiver's own phase 1 goes into R₁ (line 6), and the loop of line 20 then does not wait for it again. Counterexample with two nodes, crash-free and timely (bound F_ack = 8):

  • u (input 0) gets its phase-1 ack before hearing x (input 1), so u is decided(0);

  • x, still in phase 1, has heard u's input 0 (so it will be bivalent) and receives u's ⟨phase 2, u, decided(0)⟩ into R₁;

  • u decides 0. x finishes phase 2 with R₂ = {⟨phase 2, x, bivalent⟩}; both witnesses are covered by R₁ ∪ R₂, so it leaves the loop and decides 1.

The intended rule is evident: line 8 already looks for phase-2 messages in R₁, line 20 checks R₁ ∪ R₂, the prose says "if the set contains any message of the form decided v_w, then it decides v_w", and the proof assumes v "will see that u has a status of decided(0)".

"W.l.o.g. nodes always broadcast" (Sections 3.1, 3.3) is not justified in the paper. Our model allows idle nodes, so the bounds cover all algorithms without the w.l.o.g. step.

Not formalized. Corollary 3.7 (standard asynchronous broadcast model) and wPAXOS (Section 4.2, Lemmas 4.2–4.5, Theorem 4.6). Claim 3.4 for D ≥ 6 on the paper's own networks: they look fine, checked numerically for d ≤ 6, k ≤ 2.

Trust. No sorry. The listed theorems use only the axioms propext, Classical.choice, Quot.sound. Non-vacuity of SolvesConsensus: the repaired two-phase algorithm satisfies it on every clique (theorem_4_1), and the trivial algorithm on one node (theorem_3_2_card_one). The model is new (no CSLib abstract MAC model existed); it is staged in Podc/Computability/Distributed/AbstractMAC/{Basic,Sync}.lean as a CSLib candidate.
