import Mathlib import Cslib.Computability.Distributed.SharedMemory.Spec /-! # Theorem 4(b): a wait-free `(k, ℓ)`-SC object from a `(k, ℓ)`-universal construction Raynal, Stainer, Taubenfeld, *Distributed Universality* (PODC 2014), Section 4.3, Theorem 4(b): "a wait-free `(k, ℓ)`-SC object can be built in `ARW_{n,n-1}[(k, ℓ)-UC]`". ## The `(k, ℓ)`-UC as a black box The paper deliberately does not give the `(k, ℓ)`-UC an object interface (footnote 4). We use the weakest faithful black-box abstraction of *any* `(k, ℓ)`-universal construction instantiated with `k` objects (sequential specifications `spec m`, CSLib's `ObjSpec`): an infinite execution (`UCExec`) in which * process `p` issues a sequence of operations on each object `m` (the `j`-th one with argument `input m p j`), each possibly invoked (`inv`), linearized and responded (`resp`, with result `out`); * on every object the linearization points form a sequence over discrete time (`ev m t`: the operation linearized on `m` at time `t`, if any), each operation is linearized at most once, after its invocation, and before its response (if any); every responded operation is linearized; * the result of an operation is given by the sequential specification applied to the state produced by the operations linearized before it (`linState`): this is linearizability, "the processes see the same sequence of operations on each object"; * a process issues its operations on an object one at a time (`inv_seq`). `UCExec.IsWaitFree ℓ` is ℓ-wait-freedom of Appendix G.1: every correct process completes infinitely many operations on each of at least `ℓ` objects. ## Result and the gap in the paper's proof The paper instantiates the UC with `k` read/write registers: each process writes its value `v_{i,m}` into register `m` and then reads; "as soon as `p_i` sees that `ℓ` objects have progressed, it returns the `ℓ` values written in these objects". With a black-box UC a read returns the *last* written value, so two processes may return different values for the same entry (`register_counterexample`: two processes, one register, linearization `write(a) read→a write(b) read→b`, wait-free execution). The argument "the processes see the same sequence of operations on each object" does not help: the sequence is not observable through the registers' responses. Repair (`scFromUC`): instantiate the `k` objects as *sticky registers* (`sticky V`, "first-value" objects: `propose v` returns the first value ever proposed). Each process repeatedly invokes `propose (v p m)` on every object `m` and decides, at a time `T` when its first `propose` returned on at least `ℓ` objects, on `ℓ` of these objects with the returned values.
