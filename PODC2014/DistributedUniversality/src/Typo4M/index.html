import Papers.PODC2014.DistributedUniversality.Model /-! # Line 4M as written in Section 4.3 breaks safety Section 4.3 of [Raynal–Stainer–Taubenfeld, PODC 2014] describes the contention-aware wait-free `(k, ℓ)`-universal construction as Figure 2 with modified lines 2M–4M, and states line 4M as "`AC[2rᵢ][m].propose(operᵢ[m])` is invoked only for the remaining objects", whereas Figure 2's line 4M proposes `ac_opᵢ[m]` (the value obtained at line N1). The mode flag `typo4M := true` models the literal text. We exhibit an execution (`n = 2`, `k = 2`, `ℓ = 1`, no helping; the adopt-commit and SC responses satisfy the specifications, even the strong reading of the no-conflict property) in which two processes return, as the *first* operation on object `0`, two different operations: process 0 returns `(0,0)` computed from the local history `[(0,0)]`, process 1 returns `(1,0)` computed from `[(1,0)]`. The two local histories are not prefix-comparable, so the object is not linearizable. Schedule: process 0 commits `(0,0)` at line N1 on both objects (it skips the SC object); process 1 gets `adopt (0,0)` on object 0 at line N1 (it invoked `AC[1][0]` concurrently with process 0) and `commit (0,0)` on object 1, so it goes to `SC[1]`, which decides object 1. At line 4M it proposes its own `oper[0] = (1,0)` (instead of `ac_op[0] = (0,0)`) to the fresh `AC[2][0]`, alone, and commits it.
