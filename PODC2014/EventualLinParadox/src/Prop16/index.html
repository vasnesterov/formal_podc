Model: processes `Fin N`, registers `Proposal[0..N-1]` (`regT D`: values `Option D`, initially `⊥ = none`; `write v` with `v : D` returns `none`), semantics `elSys` of `ImplModel`: base accesses are split into invocation and response, the adversary chooses the responses, and an execution is admissible (`ELAdm`) iff every register's history is eventually linearizable (weakly consistent and `tₓ`-linearizable for some `tₓ`). The algorithm (`consImpl`): `Propose(v)` by `pᵢ`: read `Proposal[i]`; if `⊥`, write `v`; read `Proposal[0..N-1]` and return the leftmost non-`⊥` value. Proof structure: * `Prop16.el_step`: the possible steps of `elSys` (generic in the implementation). * `Prop16.PInv`/`Prop16.inv_all`: an invariant of admissible executions, by local state. It uses two consequences of the weak consistency of the registers (`adm_R1`: a read returning `w` is preceded by a write of `w`; `adm_R2`: a read by `pᵢ` of `Proposal[i]` after a completed write of `pᵢ` to it returns non-`⊥`). Consequences: writes to `Proposal[x]` are by `p_x`, during its first operation (`inv_write`), at most once (`write_unique`); a completed operation returns the leftmost non-`⊥` value of its scan (`inv_res`; the fallback is never used). * `cons_weaklyConsistent`: Definition 1 for the consensus history. * `cons_exists_tLin`: some `t`-linearization. We argue per register (no Lemma 7): each register is written at most once, so from some time on all its reads return a fixed value (`reg_stable`); operations invoked afterwards return the same value `w₀`, proposed by the operation `op₀` that wrote it; `op₀` followed by all other completed operations in the order of their responses, all returning `w₀`, is a `t`-linearization for large `t`. * `cons_waitFree`: a progress measure (`meas`). -/ namespace Podc.EventualLinParadox /-!
