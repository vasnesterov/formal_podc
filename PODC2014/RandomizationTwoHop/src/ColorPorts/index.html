import Papers.PODC2014.RandomizationTwoHop.Norris import Cslib.Computability.Distributed.PortNumbering.Basic -- CSLib candidate (paper-local for now; see README) /-! # Port numberings induced by a 2-hop colouring In a graph whose colouring `c` (values in a linear order) is injective on every neighbourhood, a node can number its ports by sorting its neighbours by colour: port `i` of `v` leads to the neighbour of `v` with the `i`-th smallest colour. This is how the paper's algorithms (which work with local views without port numbers) simulate a port-numbering algorithm `A_R`: the simulated graphs carry this numbering (`colorPN`). It is a simple port numbering of `G` (`colorPN_isSimple`, `colorPN_toSimpleGraph`). The port of `v` towards `u` is `rankC v (c u)`, the number of neighbours of `v` with smaller colour; it depends only on the colours around `v`, so a bijection between two neighbourhoods that preserves colours preserves degrees, ports and remote ports (`rankC_eq_of_equiv`, `pick_eq_of_equiv`). This is the basis of the locality lemma for runs (`Model.lean`). -/ namespace Podc.RandomizationTwoHop open SimpleGraph Cslib.PortNumbering variable {V C : Type} [LinearOrder C] (G : SimpleGraph V) (c : V → C) /-- The number of neighbours of `v` with colour `< a`. -/ noncomputable def rankC (v : V) (a : C) : ℕ := Set.ncard {w | G.Adj v w ∧ c w < a} /-- The degree of `v`. -/ noncomputable def cdeg (v : V) : ℕ := Set.ncard (G.neighborSet v) /-- Colours are injective on every neighbourhood. -/ def NbhdInj : Prop := ∀ v, Set.InjOn c (G.neighborSet v) /-- The neighbour of `v` behind port `i` (if any). -/ noncomputable def pick (v : V) (i : ℕ) : V := open Classical in if h : ∃ u, G.Adj v u ∧ rankC G c v (c u) = i then h.choose else v variable {G c} [Finite V] theorem rankC_lt_cdeg {v u : V} (hu : G.Adj v u) : rankC G c v (c u) < cdeg G v := by apply Set.ncard_lt_ncard _ (Set.toFinite _) refine ⟨fun w hw => hw.1, fun h => ?_⟩ have := (h hu).2;
