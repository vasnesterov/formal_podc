import Papers.PODC2014.RandomizationTwoHop.Lang /-! # Algorithm `A*` (§3.1, Figure 3) `A*` is a deterministic anonymous algorithm for `Πᶜ` that proceeds in phases `p = 1, 2, …`. Every node `v` keeps a bit string `b(v)` (initially empty); `I^p = (V, E, i, c, b^p)`. In phase `p`, node `v` * **Update-Graph**: computes its view `L = L(v, I^p)` and the set `F` of the view graphs of all *candidates* `Ĝ` (C1: at most `p` nodes; C2: some node of `Ĝ` has view `L`; C3: `Ĝ` without the bits is an instance of `Πᶜ`); if `F ≠ ∅` it selects the smallest one `Ĝ*` (fewest nodes, ties broken by a fixed order) and the node `v*` of `Ĝ*` corresponding to `v`; * **Update-Output**: simulates `A_R` on `Ĝ*` with the bits `b̂*` as random bits for `l = min |b̂*(u)|` rounds; if all nodes output (the simulation is *successful*), `v` outputs the output of `v*`; * **Update-Bits**: if some `p`-extension of `b̂*` (bit strings of length `p` extending `b̂*`) induces a successful `p`-round simulation, `v` sets `b(v)` to the value at `v*` of the smallest such extension. ## Formalization All objects are functions of views, represented by walk languages: * `bL p W`: the bit string `b^p(v)` of a node with depth-infinity view `W` (labels: input and colour). Phase `p` only looks at `Lv p W = trunc p (relabel (bL p) W)`, the view of tree depth `p` (i.e. `L_{p+1}(v, I^p)`) in the graph labelled with input, colour and bits. **Change w.r.t. the paper:** the paper uses `L_p(v, I^p)` (tree depth `p - 1`). With port numbers, `p - 1` simulated rounds depend on the view of tree depth `p` (see `decided_local`), so with depth `p - 1` Lemma 9's argument breaks; we use one more level. Computing it takes `p` rounds, exactly the paper's round count for this step. * The view graph `Ĝ*` is represented canonically by its node set `S` (a set of walk languages); the simulation runs on the infinite view graph `viewLGraph G` of a graph `G` realizing `S` chosen canonically from `S` (by choice), with colour-sorted ports. Ties in the selection and the "smallest" extension are resolved by choice functions of the (canonical) data; any fixed rule works (the analysis only uses that it is a function of the data). * `outPhase p W`: the output produced in phase `p` (if any). * `astar`: the message-passing algorithm (`Flood.lean`): every node floods its truncated walk language and, in round `r`, evaluates phase
