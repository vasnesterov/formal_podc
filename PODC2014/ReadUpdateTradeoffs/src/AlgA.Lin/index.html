Several `WriteMax` operations can be linearized at the same CAS (in any order; they are all `≤` the new root value, and one of them has exactly that value). The invariant `LInv` says: the linearization `L` built so far linearizes the execution, the root holds the abstract state `linState L`, and a pending `WriteMax(v)` is in `L` iff `v ≤` root. Three facts from the memory invariant `MInv` make this work: the root is non-decreasing (Lemma 8); a new root value is the operand of a pending `WriteMax` (`MInv.good`, replaces Lemma 10); and a `WriteMax(v)` returns only when the root holds `≥ v` (`PInv` of `wDone`, replaces Lemma 11). ## Differences from the paper's proof Definition 9 linearizes a `WriteMax` at the first event after which the root *counts* it (Definition 8: a chain of *visible*, i.e. value-changing, events from a leaf write of the operation to the root).
