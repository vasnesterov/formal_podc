import Papers.PODC2014.ReadUpdateTradeoffs.AlgA.Defs /-! # Definition 9 leaves completed `WriteMax` operations without a linearization point The paper linearizes a `WriteMax` operation `Φ` at the first event after which the root *counts* `Φ` (Definition 9), where (Definition 8) a node `N` counts `Φ` after `E` if some *visible* event `e` on `N.value` occurs in `E` and either `e` is issued in `Φ`, or `e` is issued by a process `p` that earlier read a child `N'` of `N` at a time when `N'` already counted `Φ`. An event is visible only if it changes the value of the object (Definition 1). Invariant 1 (used to prove Lemma 9) claims that after the last write/CAS of `Φ` on a node `N`, `N` counts `Φ`. This is false: below, with `N = 2` processes, process `0` performs `WriteMax(3)` to completion, then process `1` performs `WriteMax(2)` to completion. All CASes of process `1` succeed **trivially** (they install the value the node already holds), so no event after the invocation of `WriteMax(2)` changes the root, and the root never counts `WriteMax(2)`. Hence Definition 9 assigns no linearization point to this completed operation, Invariant 1 fails for `N = root`, and the proof of Lemma 9 (which assumes that both CASes of a refresh can be trivial only if *other* processes changed the node in between) breaks. The execution respects the paper's assumptions (both operands are `≥ N`, each process writes once). `Counts` below over-approximates Definition 8 (any value-changing event counts as visible, any access of a child as a read), so `not_counts` is a statement about the paper's notion as well.
