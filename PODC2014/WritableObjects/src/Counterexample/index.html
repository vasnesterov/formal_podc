It only uses condition (C), ownership, and sequential writability, which it applies to the *sub-history* `Λ_ℓ` of the operations with timestamp `ℓ` ("Subsequence `Λ_ℓ` is a history, and by (4.1), no `A[i_ℓ].SWrite()` overlaps any other operation call on `A[i_ℓ]`. Therefore, there is a linearization `S_ℓ` of `Λ_ℓ`", proof of Claim 4.7). Here is a transcript (`cex`) of a register `WT` over `ℕ` (initially `0`) with three processes that follows the template except for the "not in use" requirement, satisfies condition (C), in which the history of each base object is linearizable, but whose high-level history is not linearizable (`notInUse_necessary`): * `p₀` writes `1` (index `0`, `Ptr := 0`), then starts `Write(2)` reusing index `0` while it is in use: `A[0].SWrite(2)` completes; * `p₂` executes `Exec(read)`: `Ptr = 0`, reads `2` from `A[0]` and returns `2`; * `p₁` executes `Write(3)` (index `1`, `Ptr := 1`) and returns; * `p₀` writes `Ptr := 0` and returns from `Write(2)`; * `p₂` executes `Exec(read)`: `Ptr = 0`, reads `2` and returns `2`. The first read forces `Write(2)` before it, real time forces `Write(3)` after the first read and before the second read, which then must return `3`.
