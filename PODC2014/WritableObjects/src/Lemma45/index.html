import Papers.PODC2014.WritableObjects.HighLow import Papers.PODC2014.WritableObjects.ListAux import Cslib.Computability.Distributed.SharedMemory.Linearization /-! # Lemma 4.5: the template is linearizable under condition (C) Main result: `lemma_4_5`. Given a transcript that follows the template of Figure 4.4 and satisfies condition (C), and in which the history of every base object `A[i]` is admissible for a sequentially writable object, the high-level history is linearizable. ## The linearization As in the paper, every *matured* call `M` gets a timestamp `TS(M)` (here `keyPos`, the number of writes to `Ptr` before the chosen point of `M`). All calls with timestamp `ℓ` operate on the same base object `A[i_ℓ]` (the index written by the `ℓ`-th write to `Ptr`). Let `L_i` be a linearization of the history of `A[i]` (it exists, since no `SWrite` overlaps another operation on `A[i]`, `IsCtrl.writesIsolated`). The linearization of `WT` lists the blocks `ℓ = 0, 1, 2, …`, block `ℓ` being the operations of `L_{i_ℓ}` with timestamp `ℓ`, in the order of `L_{i_ℓ}`, replaced by their calls (`block`, `linWT`). The paper obtains the order inside a block from a linearization of the *sub-history* `Λ_ℓ` of the calls with timestamp `ℓ`, claiming that sequential writability applies to it. That inference is not valid as stated (a sub-history of a linearizable history need not be linearizable; see `Counterexample.lean`). We instead restrict the linearization `L_i` of the whole history of `A[i]` and prove that, on each `A[i]`, timestamps are sorted along `L_i` (`IsCtrl.ret_before_of_keyPos_lt`, which uses that `A[f]` is not in use when `A[f].SWrite` is invoked), so each block is a contiguous segment of `L_i` starting with its `SWrite`. -/ set_option linter.unusedSectionVars false namespace Podc.WritableObjects
