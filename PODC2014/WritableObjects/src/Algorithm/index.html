The array `A[0 … n(8n+9)-1]` is indexed by `Idx n = Fin n × Fin (8n+9)`; the owner of `(p, k)` is `p`. This is the paper's `I_p = {i | i mod n = p}` up to the relabelling `(p, k) ↦ k·n + p`. * Shared registers: `Ptr` (`ptr`), `Annc[q]` (`annc q`), `H_p[q]` (`hH p q`), `H'_p[q]` (`hH' p q`) and `S_q` (`S q`). `⊥` is `none`; the initial value `-1` of `S_q` is the integer `-1`. * Local variables: the four queues `usedQ, anncQ, hintQ, hint'Q` (`qs.q 0 … qs.q 3`), the counters `c_p` (`qs.cnt`), the set `free_p` (`qs.free`) and `ctr_p` (`ctr`). The paper's `ctr_p` is incremented modulo `n`; we keep the unbounded counter `ctr` and use it modulo `n` (`cq ctr`) wherever the paper uses `ctr_p`, which is equivalent. The unused local `lptr_p` of the figure is omitted. * One step = one atomic access of a shared register (or an invocation/response), together with the local computation that follows it up to the next shared access; local lines are attached to the adjacent shared step as on p. 58–59 of the thesis: lines 25–28 form one step (the first atomic step of `recycle()`, reading `Annc[ctr_p]`), lines 29–30 and 31–32 one step each, line 17 belongs to line 16, lines 41–42 to line 40 and line 38 to line 39. Line 24 (`ctr_p += 1`) belongs to line 21 resp. line 23. * `free_p.remove()` returns an arbitrary element of `free_p` (nondeterminism); if `free_p` were empty the step would be disabled (Claim 4.14 says this never happens; the safety properties proved here do not need it). * The `SW` objects are black boxes: invoking `A[i].SWrite(v)` / `A[i].Oper(o)` is one step that emits `swinv` / `opinv`, and its response is a separate step that emits `aret` with an *arbitrary* response chosen by the environment. Invocations of `Write(v)` / `Exec(o)` (with `o` not a write) are environment-chosen steps of idle processes. * Line 38 computes `owner(i)` of the value `i` read from `Ptr`; if `Ptr = ⊥` this is undefined and the step is disabled. After the initial `Write(v0)` (see `Initialized`) `Ptr ≠ ⊥`, so this never happens in the executions considered by the paper. ## Ghost state Some fields are *ghost* variables: they are written but never read by the algorithm (no guard or written value depends on them), so they do not restrict the behaviour.
