import Papers.PODC2014.WritableObjects.Defs import Cslib.Computability.Distributed.SharedMemory.LinPoints import Cslib.Computability.Distributed.SharedMemory.Model /-! # A sequentially writable `k`-word register (Figure 4.2, Section 4.1.1) Aghazadeh, Golab, Woelfel, *Making Objects Writable*, PODC 2014; numbering of Chapter 4 of Aghazadeh's PhD thesis. The `k`-word register (`kWordReg k W w₀`) stores a `k`-tuple of words, initially all `w₀`; `Read()` returns the tuple, `Write(x₀, …, x_{k-1})` replaces it. Implementation of Figure 4.2 (`kWordImpl`) from single-word registers `R[0..k-1]` (initially `w₀`): * `SWrite(x₀, …, x_{k-1})`: `for i = 0 to k-1 do R[i].Write(x_i)` * `Read()`: `for i = 0 to k-1 do x_i := R[i].Read()`; `return (x₀, …, x_{k-1})` The thesis states without proof ("It is obvious") that every history in which no `SWrite` overlaps another operation is linearizable, i.e. the object is sequentially writable (`SeqWritable`, `Defs.lean`). This is `kWord_seqWritable`. Each operation performs exactly `k` base-object accesses (`kwBound_invoke`, `kwBound_access`). Proof: operations are linearized at their response. While a write is pending every other process is idle, so a read only ever sees the memory of the last completed write. -/ namespace Podc.WritableObjects open Cslib.SharedMemory /-- Operations of a
