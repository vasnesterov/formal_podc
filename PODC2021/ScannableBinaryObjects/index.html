Verdict: 🔧 Easy fix. The lower bounds proved in the body (Lemmas 5–6, Theorem 8, Corollary 9) and the Section 4.1 upper bound hold, and the proofs of Lemmas 6 and 7 need only local changes. The bound "n + k − 2 for n ≤ 2^(k−1)+2" in the abstract, introduction and conclusion drops the body's conditions: it fails for k = 1, n = 3, and some cases of it are unproved. Observation 3 is false when the start configuration is not p₀-idle, which no use in the paper needs.

Mistakes in the paper

✏️ Slips

  • Abstract, introduction and conclusion (range of the n + k − 2 bound): the bound "n + k − 2 when n ≤ 2^(k−1) + 2" is stated without the body's k ≥ 3 and n > 2. The body's Theorem 8 and Corollary 9 hold.

    • k = 1: a single 1-bit object suffices for every n, because the atomic implementation works and the component is itself a 1-bit object. So the claimed bound of 2 for n = 3 is false, and Lemma 6's k ≥ 2 is needed (one_component_one_object, abstract_bound_fails_k1).

    • n = 1: no shared object is needed at all, yet the claim gives k − 1.

    • Similarly, the introduction states the n + k − r − 2 range without Theorem 8's condition k ≥ r + 3, so its instances with r ≥ k − 2 are claimed without proof (for k = 2, n = 4, see Not formalized.).

  • Observation 3 (start configuration not p₀-idle): a scanner's solo Scan may return the old value V of a pending Update of p₀ that has not taken a step, although the execution is V-absent (prose counterexample only, not in Lean). The scan may be linearized before the pending update. Yet the execution is V-absent, because the only p₀-idle configuration reached during αα' is the one after the update. The paper applies Observation 3 only from C₀α_j, which is p₀-idle, so the proofs are unaffected. We prove a correct version (scan_resp): a scan returns the value after some number of p₀'s operations that is at least the number of operations completed before the scan was invoked.

  • In the proof of Lemma 6, "V₁ contains a 1 in every component" should be "in its k-th component", which is all the argument uses.

  • In the proof of Lemma 1, "these final n collects" should be u + 1.

The formalizationmodel, Lean names of the results, trust

Model.

  • Asynchronous shared memory, CSLib Cslib.SharedMemory: deterministic processes P (n = |P|), invocation, steps and response as separate labels, no crashes. Base objects B : ι → ObjSpec (m = |ι|). Each one stores at most one bit (OneBit: states inject into Bool) and has arbitrary invocations and responses, arbitrary types and arbitrary initial values.

  • The implemented object scannable O has k components. Each is an arbitrary non-monotonic 1-bit object (BitObj), initially 0. The operations are update i o and scan. Readability of the components is not assumed, which strengthens the lower bounds.

  • Hypotheses on the implementation I: it allows at least the single-updater invocations (SingleUpdater p₀: p₀ updates, the others scan), so multi-updater implementations are covered too. It is Linearizable and ObstructionFree, both over all executions it allows.

  • Proof structure: instead of Lemma 7's simulated implementation I', we work with stages of I. A stage is a reachable configuration with active processes A, frozen objects F and k' live components. No execution of active processes that updates only live components may change F. The paper's executions of I' are exactly these restricted executions. Lemma 5 is proved for stages, and reduce_stage plays the role of Lemma 7.

Remarks on the paper (not mistakes). Corollary 9 (c) "also applies to larger values of n" is asserted without proof, but it is routine: an n-process implementation restricts to fewer processes. We prove it for all n ≥ 2^k − 2 and all k ≥ 2 (corollary9c).

Not formalized. The wait-free single-updater implementation from 2^k registers (§4.2) is cited from Vidyasankar and not formalized. Open remark: for k = 2, n = 4 the abstract claims 4 objects, but the paper proves only 3 (Lemma 6), and Theorem 8 needs k ≥ 3; we do not know whether the bound holds there. Lemma 1 is not a separate theorem; its counting argument is part of the linearizability invariant of Implementation 1. The n = 1 degenerate case is only discussed in prose.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. The model is CSLib's (Model, Linearization, Progress, Covering, Indist, Atomic). Shared library (Cslib/Computability/Distributed/SharedMemory, Cslib/Foundations/Data/Nat, Cslib/Foundations/Data/Finset): curOp and Impl.linearizable_of_run/Impl.run_induction for the linearizability invariant, Impl.exists_finish (completing pending operations by solo runs, paper's τ', τ''), Impl.LockFree.obstructionFree, InfExec.pre, Nat.eventually_const_of_succ_le and Fintype.sum_lt_sum_of_eq_off for the two potentials of the lock-freedom proof. Non-vacuity: every hypothesis of the lower bounds is met by Implementation 1 with k ≥ 2 and readable non-monotonic components, which uses k + 1 objects for two processes (two_process_tight). For k = 1, CSLib's atomic implementation meets them as well (Degenerate.lean). The upper bound assumes readable components (BitObj.Readable: a read invocation that does not change the value, with a response that determines it), as the paper does. Implementation 1 leaves the initial values of the handshake bits arbitrary.
