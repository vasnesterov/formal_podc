import Podc.Computability.Distributed.SharedMemory.WriteStrongLin import Cslib.Computability.Distributed.SharedMemory.Atomic import Mathlib.Tactic.FinCases /-! # Linearizable SWMR registers are write strongly-linearizable (Theorem 14) Hadzilacos, Hu and Toueg, *On Register Linearizability and Termination*, PODC 2021, Section 6 and Appendix E. **Theorem 14.** Any linearizable implementation of a SWMR register is write strongly-linearizable. We prove it for an arbitrary set `E` of histories in which only one process `w` invokes writes and each history has a linearization (`swmr_writeStrongLin`): this covers shared-memory, message-passing and hybrid implementations alike, as claimed by the paper. The corollary for CSLib's shared-memory implementations is `Impl.writeStronglyLinearizable_of_swmr`. ## The construction Our write strong-linearization function differs from the paper's (see below): for each history `α` it picks a linearization with the **least number of operations of the writer `w`**. In any linearization the operations of `w` are `w`'s first `m` operations in program order, where `m` is the number of completed operations of `w` or that number plus one (the pending operation). If `α` is a prefix of `β`, restricting a linearization of `β` to the operations invoked in `α` gives a linearization of `α` (`IsLinearization.restrict`) with at most as many `w`-operations; hence the minimal count does not decrease along prefixes, and the write sequences are prefixes of each other. ## The paper's construction fails (`lemma67_construction_fails`) The paper (Lemma 67) starts from an *arbitrary* linearization function `f` and removes the last operation of `f(H)` if it is an incomplete write. Claim 67.1 asserts that an incomplete write that is not the last operation of `f(H)` is read by some read of `H`; but the operation after it may be a *pending* read (Definition 2 allows pending operations with responses added). We exhibit a linearization function `f` of the atomic SWMR register for which the modified function `f*` violates property (P): in `G` the writer has completed `write 1` and invoked `write 2`, and a reader has invoked a read; `f(G) = write 1, write 2, read` (the read is pending, its response `2` is "added"). In the extension `H` the read returns `1`, and `f(H) = write 1, read`. Then `f*(G) = f(G)` and `f*(H) = f(H)`, and the write sequence `write 1, write 2` of `f*(G)` is not a prefix of the write sequence `write 1` of `f*(H)`. -/ namespace Podc.RegisterLinTermination open
