import Podc.Computability.Distributed.SharedMemory.WriteStrongLin /-! # Algorithm 1 (the game) over linearizable registers, against a strong adversary Hadzilacos, Hu and Toueg, *On Register Linearizability and Termination*, PODC 2021, Section 3. ## The model * `n` processes `Fin n`: the *hosts* `p₀`, `p₁` and the *players* `p₂, …, p_{n-1}`; three shared registers `R1`, `R2`, `C` (`Reg`) over the value type `Val` (`⊥`, pairs `[i, j]`, numbers, coin bits). Initial values (unspecified in the paper): `R1 = C = ⊥`, `R2 = 0`. * **Registers are abstract and only linearizable.** A register operation is an invocation event `inv p x o` followed later by a response event `ret p x v`; between them other processes take steps. The responses are chosen by the adversary, subject to the requirement that the history of every register is linearizable (`LinRegs`) — CSLib's `IsLinearization` on the projection `hist x α` of the execution to register `x` (Herlihy–Wing linearizability; pending operations may or may not be linearized). This is the most permissive behaviour of a linearizable register implementation. * **Processes** run the code of Algorithm 1 (`code`), one register operation or coin flip at a time; `procRun p α` replays the events of `p` in `α` (`none` if they do not follow the code). After returning (local state `done`), a process may keep taking `noop` steps (footnote 3). * **Strong adversary.** The adversary is a function `σ : List (Ev n) → Ev n` choosing the next event from the whole execution so far (in particular from all previous coin flips). When it schedules a coin flip of `p₀`, the outcome is the next coin of the random sequence `ω : ℕ → Bool` (`genRun σ ω`); the value proposed by `σ` is ignored. The theorems (Theorem 6: with merely linearizable registers some adversary keeps every process in the game forever, for every coin sequence; Theorem 7: if `R1` is write strongly-linearizable the game ends with probability 1) are stated and proved in `Theorem6.lean` / `Theorem7.lean`. -/ namespace Podc.RegisterLinTermination.Game open Cslib.SharedMemory /-- Register values: `⊥`, pairs `[i, j]` (`i = false` is `0`, `i = true` is `1`), numbers (`R2`) and coin bits (`C`). -/ inductive Val where | bot | pair (i : Bool) (j : ℕ) | num (k : ℕ) | bit (b : Bool) deriving DecidableEq /-- The three shared registers. -/ inductive Reg where | r1 | r2 | c deriving DecidableEq /-- Initial values of the registers. -/ def initVal : Reg → Val | .r1 => .bot | .r2 => .num 0 | .c => .bot /-- The register object `x` (CSLib sequential specification). -/ abbrev RegObj (x : Reg) : ObjSpec := register Val (initVal x) /-- Events of an execution. -/ inductive Ev (n : ℕ) where /-- `p` invokes operation `o` on register `x`. -/ | inv (p : Fin n) (x : Reg) (o : RWOp Val) /-- `p` receives the response `v` of its pending operation on register `x`. -/ | ret (p : Fin n) (x : Reg) (v : Val) /-- `p` flips a coin with outcome `b`. -/ | flip (p : Fin n) (b : Bool) /-- `p` takes a step after having returned. -/ | noop (p : Fin n) deriving DecidableEq /-- The process taking the event. -/ def Ev.proc {n : ℕ} : Ev n → Fin n | .inv p _ _ => p | .ret p _ _ => p | .flip p _ => p | .noop p => p /-- Local states (program counters with the round `j` and local variables) of Algorithm 1.
