import Podc.Computability.Distributed.SharedMemory.WriteStrongLin import Papers.PODC2021.RegisterLinTermination.Alg4 import Mathlib.Tactic.FinCases /-! # Algorithm 2: a write strongly-linearizable MWMR register from SWMR registers Hadzilacos, Hu and Toueg, *On Register Linearizability and Termination*, PODC 2021, Section 4. ``` Shared: Val[i], i = 1..n: SWMR register, initially (0, [0, …, 0]) Local: new_ts, initially [∞, …, ∞] write(v) by p_k: for i = 1..n: new_ts[i] ← Val[i].ts[i] (+ 1 if i = k) Val[k] ← (v, new_ts); new_ts ← [∞, …, ∞]; return done read(): for i = 1..n: (v_i, ts_i) ← Val[i] return v_j with ts_j the lexicographic maximum ``` ## Modelling * Processes and registers `Val[i]` are indexed by `Fin n`; a vector timestamp is a `List ℕ` (of length `n` once complete), compared lexicographically (`List.lt`). While a write is computing its timestamp, the local state holds the prefix `pre` computed so far: the paper's `new_ts` is `pre` padded with `∞`. * One base-object access per step. A `write v` returns `v` (CSLib's dummy write response). * The read keeps the best cell seen so far, starting from `(v₀, [0, …, 0])`, the least timestamp. ## Corollary 11 The paper derives Corollary 11 (Algorithm 2 is not strongly linearizable) from the impossibility result of Helmi, Higham and Woelfel (PODC 2012). We prove it directly (`alg2_not_stronglyLinearizable`, three processes, values in `ℕ`): in `G`, a read by `p₃` has read `Val[1]` (initial) when `p₁` runs `write 1` to completion. If the read then returns `0` (`H₁`), it must be linearized before `write 1`, hence already in `f(G)`; if instead `p₂` first runs `write 2` and the read returns `2` (`H₂`), it must be linearized after `write 2`, which follows `write 1`. -/ namespace Podc.RegisterLinTermination.Alg2 open Cslib.SharedMemory List /-- Contents of a register `Val[i]`: a value with its vector timestamp. -/ abbrev Cell (V : Type) := V × List ℕ /-- The base objects `Val[i]` (the `ObjSpec` initial value is ignored;
