import Papers.PODC2021.RegisterLinTermination.Game import Podc.Computability.Distributed.SharedMemory.LinPointCheck /-! # Theorem 6: with merely linearizable registers, a strong adversary prevents termination Hadzilacos, Hu and Toueg, *On Register Linearizability and Termination*, PODC 2021, Section 3.1. We follow the paper's schedule (Figures 1–2). For `n = m + 3` processes, round `j` with coin `b` is the event list `round m j b`: * **Phase 1, before the coin flip** (`roundPre`, independent of `b`): every player writes `⊥` to `R1` and `C`; `p₀` and `p₁` invoke their writes `[0, j]`, `[1, j]` to `R1` and every player invokes its first read of `R1`; `p₀`'s write returns. * `p₀` flips the coin `b`. * **after the flip** (`roundPost`): `p₀` writes `b` to `C`; `p₁`'s write returns; the first reads return `[b, j]`, the second reads (sequential) return `[1 - b, j]`; the reads of `C` return `b`. The linearization of `R1` puts the write of `p_b` first, then the first reads, then the write of `p_{1-b}` and the second reads (`ahistR1`): for `b = 1` this order is fixed only *after* `p₀`'s write has returned, which linearizability allows but write strong-linearizability does not. * **Phase 2**: all write `0` to `R2`; the players read and increment `R2` one after the other; `p₀`, `p₁` read `n - 2`. Linearizability of every prefix is shown with linearization points (`Cslib.SharedMemory.isLinearization_of_lpRun`). The adversary `adv` reads the coins off the history and schedules the next event of this run (`genRun_adv`). -/ namespace Podc.RegisterLinTermination.Game open Cslib.SharedMemory List namespace Thm6
