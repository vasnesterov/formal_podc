One protocol instance (`L = Unit`). The protocol `countP` ("count echoes"): * on any request, a server that has not echoed yet sends `ECHO` to every server; * on every delivered message it increments a counter; when the counter reaches `2f + 1 = 3` it indicates `deliver` (once). A message is just the pair `(sender, receiver)`. Over authenticated perfect links (no duplication + authenticity) three deliveries come from three different senders, at least two of them correct, and correct servers only echo after a request. So `countP` satisfies the property `Φ`: "if some correct server delivers, then at least two different correct servers were requested" (`holdsOverAPL_phi`). In the block DAG embedding, the Byzantine server `3` equivocates with two genesis blocks `Bb₁`, `Bb₂` (different only in their request). Both are valid, so the correct server `1` references `Bb₁` in its first block `D₁` and, after receiving `Bb₂`, references `Bb₂` in its second block `D₂`. Interpreting the DAG, server `1` receives the message `ECHO` from `3` twice: at `D₁` and at `D₂` (`lemma_4_3_2_false`). With the echo of the only requested correct server `0`, it counts to 3 and `shim(P)` at server `1` indicates `deliver` (`theorem_5_1_false`), although only one correct server was ever requested.
