import Papers.PODC2021.BFTInBlockDAG.Block /-! # Building the block DAG: Algorithm 1 (with the request buffer of Algorithm 3) The asynchronous system of Section 3. Servers `S`; the Byzantine servers form the set `Byz`, all other servers are correct. The network is a set `sent` of point-to-point messages `(from, to, payload)` that have been sent; a correct server may receive any message sent to it, any number of times and in any order (so the model covers arbitrary delays, reordering and duplication; Assumption 1, reliable delivery, is a fairness condition on runs, see `GossipLive.lean`). **Correct servers** run Algorithm 1; every handler is one atomic event: * `request s ℓ r`: the user calls `request(ℓ, r)` on `shim(P)` (Algorithm 3, lines 6–7); * `recv s src (blk B)`: lines 4–5 (put `B` into `blks` unless `B ∈ G`); * `recv s src (fwd B)`: lines 12–13 (answer a forwarding request if `B ∈ G`); * `validate s B`: lines 6–9 (for `B ∈ blks` that `s` considers valid: insert it into `G` and add a reference to the current block); * `askFwd s B' B`: lines 10–11 (ask `B'.n` for a missing predecessor `B` of `B' ∈ blks`); * `disseminate s`: lines 14–18 (seal the current block with all buffered requests, insert it, send it to every server, and start the next block). Algorithm 3 lines 10–11 call it repeatedly. The local block DAG `G` is kept as the list `log` of its blocks in insertion order. **`valid(s, B)`** (Definition 3.3) is read as: `B` is locally valid (genesis or exactly one parent) and `s` has already validated (inserted) all predecessors of `B`. This is the only reading under which line 7 always inserts into a block DAG, as Lemma A.5 claims: with a purely recursive reading ("all predecessors are valid", whether inserted or still in `blks`) line 6 may pick a block before its predecessor and `G` stops being closed under predecessors. **Byzantine servers** may send anything, except that they cannot forge signatures: a block they send must be *authentic* (`Authentic`), i.e. every block with a correct builder in its causal past was created by that builder. Ghost variables: `own` (the blocks `s` disseminated) and `reqs` (all requests from the user). Main results: the invariant `Inv` (`reachable_inv`), which contains Lemma A.4 (`lemma_A_4`), Lemma A.5 (`lemma_A_5`) and Lemma A.6 (`lemma_A_6`). -/ set_option linter.unusedSectionVars false namespace
