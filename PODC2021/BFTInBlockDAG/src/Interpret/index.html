import Papers.PODC2021.BFTInBlockDAG.Block /-! # Interpreting a deterministic protocol on a block DAG (Section 4, Algorithm 2) * `Protocol`: a deterministic protocol `P` as a black box. A process instance of `P` for label `ℓ` and server `s` starts in `P.init ℓ s` (the paper's `new process P(ℓ, s)`); on an input (a request `r` or a received message `m`) it moves to a new state and returns the messages and indications triggered by this input (`P.step`). Messages carry a `sender` and a `receiver`. * `interp P ℓ B : Res`: the canonical value of `B.PIs[ℓ]`, `B.Ms[out, ℓ]`, `B.Ms[in, ℓ]` and the indications at `B` after Algorithm 2 interpreted `B` (lines 4–12), defined by structural recursion over the DAG below `B`: - line 4: start from the parent's state, or from `P.init ℓ B.n` for a block without parent; - lines 5–6: feed the requests `(ℓ, r) ∈ B.rs`, in order; - lines 7–11: if a strict ancestor of `B` carries a request for `ℓ`, collect into `Ms[in, ℓ]` the set of messages `m ∈ Bᵢ.Ms[out, ℓ]` (`Bᵢ ∈ B.preds`) with `m.receiver = B.n`, and feed them in the order `<_M`. Line 6 of the paper *assigns* `B.Ms[out, ℓⱼ] ≔ …` inside a loop over the requests, so with two requests for the same label in `B.rs` the messages of the first one would be lost; we accumulate them (see `differencies.md`). * Algorithm 2 itself (picking eligible blocks in any order, `I[B]`, the per-block variables): `Trav G` with steps `TStep`. Lemma A.9 `TReach.val_eq_none`, Lemma A.10 `TReach.exists_step` / `TReach.exists_complete`, Lemma A.11 `TStep.val_eq`, and the key invariant `TReach.val_eq_interp`: every interpreted block holds exactly `interp P ℓ B`, whatever the order of picks and the block DAG `G ∋ B`. Lemma 4.2 is `lemma_4_2`. * Lemmas A.12–A.14 (`out_origin`, `owner_interp`, `sender_of_mem_out`), Lemma 4.1 (`lemma_4_1_1`, `lemma_4_1_2`), Lemma A.16 (`lemma_A_16`). -/ set_option
