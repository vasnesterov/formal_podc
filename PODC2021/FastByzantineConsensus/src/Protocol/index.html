import Mathlib import Cslib.Computability.Distributed.Byzantine.Certificate /-! # The fast Byzantine consensus protocol of Kuznetsov–Tonkikh–Zhang (generalized version) Kuznetsov, Tonkikh, Zhang, *Revisiting Optimal Resilience of Fast Byzantine Consensus*, PODC 2021 (arXiv:2102.12825v3), Section 3 and Appendix A. We model the *safety-relevant* part of the generalized protocol (parameters `f`, `t`, `1 ≤ t ≤ f`, `n ≥ 3f + 2t − 1`) as an asynchronous, interleaving transition system with an ideal signature scheme: * Every signed statement (and every message sent over an authenticated channel) is a *token* `Tok P V` with a signer. The global state records the set `E` of all tokens emitted so far. Since signatures are unforgeable and channels authenticated, a message carrying a token can only be received after the token was emitted, so all enabling conditions of correct processes are stated in terms of `E` (this over-approximates "received"; safety for this more permissive system implies safety for the real protocol). * Byzantine processes (`B`) may emit any token they sign, at any time. * A correct process may take any of its enabled steps at any time (the view synchronizer, timers and message delays are abstracted by nondeterminism; safety must hold for all of them). Votes carry, instead of the full certificates, the signed pair `(x, u)` of the latest acknowledged proposal and the pair of the latest collected commit certificate; the attached certificates (`σ`, `τ`, `cc`) are self-certifying, so a verifier checks their existence in `E` (`ValidBallot`, `ValidCC`). Views start at `0` (the paper's view `1`). Decisions are a predicate on `E` (`DecidedIn`): `n − t` `ack` tokens (fast path) or `⌈(n+f+1)/2⌉` `commit` tokens (slow path) for the same value and view. A correct process decides `x` exactly when it has received such a quorum, which is possible only if `DecidedIn E x v` holds for the current `E`. -/ namespace FastByzantineConsensus.Protocol open
