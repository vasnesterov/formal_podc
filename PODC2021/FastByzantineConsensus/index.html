Optimal Resilience of Fast Byzantine Consensus — PODC 2021

Petr Kuznetsov, Andrei Tonkikh, Yan X Zhang. Revisiting Optimal Resilience of Fast Byzantine Consensus. PODC 2021, pp. 343–353. DOI 10.1145/3465084.3467924. Formalized version: extended version arXiv:2102.12825v3 (numbering follows it). Copy of the paper: paper.pdf.

DOI · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The tight bound holds: for 1 ≤ t ≤ f, an f-resilient t-two-step consensus protocol exists iff n ≥ 3f + 2t − 1 (5f − 1 for t = f). We proved both directions in one formal model: the lower bound (Theorem 4.5), and the safety, liveness and two-step property of a concrete implementation of the protocol. The paper's safety proof has one gap, which we repaired with a harmless extra check.

Mistakes in the paper

✏️ Slips

  • Theorem 4.5 fails at f = 1, t = 0: then 3f + 2t − 2 = 1, and with one process "decide your own input" is an f-resilient t-two-step protocol (theorem_4_5_fails_f1_t0). §4.1 assumes n ≥ 3f + 1, and the lower bound holds for every 2 ≤ n ≤ 3f + 2t − 2 (no_fastConsensus_of_le).

Proof gaps in true statements (1)Protocol safety

🔧 Protocol safety (Sections 3.2–3.3, Appendix A: votes from "future" views)

The safety proof's induction on views breaks because nothing requires a valid vote sent to the leader of view v to carry a proposal (or commit certificate) from a view u < v, so the highest view w among the valid votes can be ≥ v.

Impact. A gap in the proof, not a known protocol bug; repaired with a harmless extra check (Protocol.ValidBallot, Protocol.ValidCC, Protocol.consistency).

Details

A vote (x, u, σ, τ) sent to the leader of view v is valid if its certificates check out. During asynchrony, other processes may already be in higher views, so a Byzantine voter can attach a correctly certified proposal from some view u ≥ v. The proof's induction on views ("every certified value of an earlier view is safe") cannot then be applied to w. The commit certificate carried in a vote has the same problem. Safety of the unmodified protocol is plausibly provable by a different induction, for example on certificate creation time.

Repair

We add the check that a vote for view v may only carry a proposal and a commit certificate from views < v. Correct processes only send such votes, so liveness is unaffected. (Protocol.ValidBallot, Protocol.ValidCC, Protocol.consistency)

The formalizationmodel, Lean names of the results, trust

Model. We use a shared partially synchronous model with Byzantine faults (Cslib.Byzantine.PartialSync).

  • n deterministic processes, at most f of them statically Byzantine. Point-to-point links with ideal unforgeable signatures; the unauthenticated case is a special case (theorem_4_5_noAuth).

  • Discrete time with an unknown GST and a known δ > 0. Correct processes step at every tick from time 0 (synchronized, drift-free clocks), as in the paper's §4.1.

  • Consensus means weak validity, agreement and termination in every valid run. t-two-step (TwoStep): in the T-faulty two-step execution tsRun with |T| = t, every correct process decides by time 2δ.

  • Differences from the paper.

    • Simultaneous deliveries are processed atomically, so the two-step execution is unique rather than "some ordering of simultaneous events". The lower bound therefore covers a slightly smaller class of protocols.

    • A reply leaves one tick after its trigger, so the two-step notion matches the paper's only for δ ≥ 2. The headline theorem assumes δ ≥ 2.

  • Positive side. It is proved twice.

    • First, for an asynchronous interleaving transition system over all emitted signed tokens, with arbitrary leaders and view changes. This over-approximates any implementation, so safety transfers.

    • Second, for a concrete algorithm in the model above: gossip of signed tokens, clock-driven views of length 6δ + 12, a rotating leader. Synchronized clocks make a view synchronizer unnecessary, which is friendlier than the paper's setting.

Proof remarks.

  • Commit certificates in case (3) of the Appendix A.3 safety induction (used for Theorem A.4): an imprecision. The proof argues that a slow-path decision for x in view w would leave a commit certificate for x in view w in votes′. This needs two things. First, a correct process commits only for its current view; this follows from the paper's rule behind Lemma 3.1. Second, "the latest commit certificate" must mean the one with the highest view rather than the most recent in time. The two coincide once the first point holds. We make both explicit.

  • Theorem 4.5 in the degenerate case f = 1, t = 0. Then 3f + 2t − 2 = 1, and with a single process "decide your own input at once" is an f-resilient t-two-step protocol (theorem_4_5_fails_f1_t0). This is outside the paper's intended scope, since §4.1 assumes n ≥ 3f + 1 and the protocol assumes t ≥ 1. We prove the lower bound for every 2 ≤ n ≤ 3f + 2t − 2, not just n = 3f + 2t − 2 (no_fastConsensus_of_le).

  • Unstated hypotheses (not errors). Lemma 4.4 uses n ≥ 2t + 2, which follows from n ≥ 3f + 1, and at least two input values.

Shared infrastructure. The two-step execution tsRun and the executions ρ₃, ρ₄ with their indistinguishability and admissibility lemmas are Cslib/Computability/Distributed/Byzantine/PartialSync/TwoStepLowerBound.lean (shared with GoodCaseLatencyBB); Run.DecidesBy is Cslib/Computability/Distributed/Byzantine/PartialSync/QuietRuns.lean; weak validity is CSLib's weakValidity P V. The progress and commit certificates Protocol.Certified, Protocol.HasCC are threshold certificates Cslib.Byzantine.Certified (Cslib/Computability/Distributed/Byzantine/Certificate.lean), the quorum arithmetic is Cslib/Foundations/Data/Finset/Quorum.lean, and the concrete protocol is an instance of Algorithm.Gossips (Impl.algo_gossips, Cslib/Computability/Distributed/Byzantine/PartialSync/Gossip.lean), which gives gossip, unforgeability and token origin.

Not formalized. Section 4.3 (suspect sets), Section 4.4 (disjoint proposers and acceptors, 3f + 2t + 1), extended validity, and bounded certificate size. The reduction of the vanilla protocol (Theorem 3.6) to the generalized one with t = f is argued on paper, not formalized. Liveness with a view synchronizer under loosely synchronized clocks is open: liveness is proved only with perfectly synchronized clocks.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. leaderEcho_fastConsensus (NonVacuity.lean) shows that FastConsensus is satisfiable, and Impl.algo_fastConsensus exhibits a nontrivial instance. The model comes from CSLib, Cslib/Computability/Distributed/Byzantine/PartialSync/.
