import Papers.PODC2021.GoodCaseLatencyBB.Basic import Cslib.Computability.Distributed.Byzantine.Certificate import Cslib.Computability.Distributed.Byzantine.PartialSync.Gossip /-! # The 2-round-BRB protocol (Figure 1, Theorem 5) Abraham, Nayak, Ren, Xiang, *Good-case Latency of Byzantine Broadcast: a Complete Categorization*, PODC 2021, Section 3. The protocol (`n ≥ 3f + 1`, asynchronous, authenticated): 1. *Propose.* The broadcaster `s` with input `v` sends `⟨propose, v⟩_s` to all parties. 2. *Vote.* On the first proposal of `s`, send `⟨vote, v⟩_i` to all parties. 3. *Commit.* On `n − f` signed votes for `v`, forward them, commit `v` (and terminate). ## Implementation in `Cslib.Byzantine.PartialSync` * Tokens `Tok P V`: proposals `prop p v` and votes `vote p v`, both signed by `p`. * Messages are finite sets of tokens (`auth.tokens m = ↑m`). Every process keeps the set `known` of all tokens it has received or created and **gossips** it to everybody at every time step (this subsumes "send the proposal / vote to all" and "forward the `n − f` votes"). * At each step, after adding the received tokens, a process that has not voted yet and knows a proposal of `s` votes for it ("first proposal": if several proposals of `s` arrive at the same step, a classical choice breaks the tie). The broadcaster starts knowing its own proposal. * A process has committed `v` as soon as its `known` contains `n − f` votes for `v` (`decide` is read off the state; termination of sending is irrelevant for the properties). ## Main results * `algo_gossips`: the protocol gossips its known tokens (`Algorithm.Gossips` of `Cslib.Computability.Distributed.Byzantine.PartialSync.Gossip`, which provides the generic token-origin and gossip lemmas); `algo_unforging`: correct processes only emit their own tokens and relay received ones. * `theorem_5_brb`: Byzantine reliable broadcast in all asynchronous runs (`asyncRuns f`). * `theorem_5_latency`: good-case latency `2Δ` in synchronous runs with delay bound `Δ`.
