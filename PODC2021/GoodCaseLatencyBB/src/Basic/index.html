import Cslib.Computability.Distributed.Byzantine.PartialSync.RoundOne import Cslib.Computability.Distributed.Byzantine.PartialSync.RunClasses /-! # Byzantine broadcast specifications and good-case latency Abraham, Nayak, Ren, Xiang, *Good-case Latency of Byzantine Broadcast: a Complete Categorization*, PODC 2021 (arXiv:2102.07240v3), Section 2. We work in the shared Byzantine message-passing model `Cslib.Byzantine.PartialSync` (discrete time, deterministic state machines, the adversary chooses the Byzantine processes, their messages and all delivery times; ideal signatures via `Auth`). ## Time conventions * **Synchrony (Section 5).** A batch sent at time `τ` and delivered at `dl` is processed in the step at `dl`, so it is visible in the state at time `dl + 1`. We call `dl + 1 - τ` its *effective delay*; the state at time `t` is the paper's local history at time `t` (it reflects all messages received at times `≤ t`, and a process reacts to a message at the same time it receives it). A *synchronous run with delay bound `d`* (`SyncValid f d`) has at most `f` Byzantine processes and effective delays in `[1, d]` between correct processes (the paper also allows delay `0`; forbidding it only weakens the adversary, which makes lower bounds stronger). "Commits before time `T`" is `CommitsBy A R p (T - 1)`. * **Partial synchrony (Section 4).** We use the CSLib model verbatim (`Run.Valid f D`: delays `dl - τ ∈ [0, max τ gst + D - τ]`). Rounds have length `D`; in the lock-step schedule round-`r` messages are delivered at time `r * D`, so "commits within `R` rounds" is `CommitsBy … (R * D + 1)` (as in the formalization of Kuznetsov–Tonkikh–Zhang, PODC 2021). -/ set_option linter.unusedSectionVars false namespace GoodCaseLatencyBB open Cslib.Byzantine.PartialSync Finset variable {P M S V K VI : Type*} [DecidableEq P] /-- `p` has committed some value by time `τ₀` (in its state at some time `≤ τ₀`). -/ def CommitsBy (A : Algorithm P M S VI V) (R : Run P M VI) (p : P) (τ₀ : ℕ) : Prop := ∃ v, R.DecidesBy A p v τ₀ theorem CommitsBy.decides {A : Algorithm P M S VI V} {R : Run P M VI} {p : P} {τ₀ : ℕ} (h : CommitsBy A R p τ₀) : ∃ v, R.Decides A p v := by obtain ⟨v, τ, -, hτ⟩ := h; exact ⟨v, τ, hτ⟩ /-- A **synchronous run with (effective) delay bound `d`**: at most `f` Byzantine processes, and every batch between correct processes sent at `τ` is processed by time `τ + d` (i.e. delivered at a time in `[τ, τ + d - 1]`).
