import Mathlib /-! # Claim of Section 4.2: unidirectional rounds implement SRB (Algorithm 3), safety core We formalize the certificate-level argument of Lemmas 3 (Case 1) and 4 for one instance of Algorithm 3: a fixed sender `p` and sequence number `k`. An instance (`Inst`) records * `signed`: the values `v` such that `p` signed `(k, v)` (one value if `p` is correct); * `fwd r`: the value a correct `r` forwarded (line 26) in its unidirectional round; * `heard r r'`: the value of `r'` that `r` received in that round before compiling its L1 proof (including `r`'s own copy, `heard r r`); * `l1 r`: the values for which `r` issued an L1 proof. `Valid` collects what the model guarantees: copies carry the sender's signature (`sValid`), copies from correct processes are genuine, Byzantine processes can only build L1 proofs of sender-signed values, and unidirectionality of the forwarding round (both forwarders take part in the same round instance). Two L1 rules for correct processes: * `RuleText`: the rule of the text of §4.2 — at least `t+1` copies of the own value "*and no other value*"; * `RulePseudo`: the rule of the pseudocode (lines 29–39, `validateValue`): at least `t+1` copies of the own value; other values are just ignored. An L2 proof of `v` is a set of `t+1` processes with L1 proofs of `v`; a correct process delivers `(k, v)` once it has a valid L2 proof (lines 12–14). * `agreement` (Lemma 3, Case 1): with `RuleText`, no two different values have L2 proofs. * `pseudo_disagreement`: with `RulePseudo` this fails already for `n = 3`, `t = 1` (a Byzantine sender), so Algorithm 3 as written violates property 2 of SRB. * `l2_signed` (Lemma 4): an L2-proved value was signed by the sender. * `validity_core` (combinatorial core of Lemma 2): with a correct sender and `n ≥ 2t + 1`, once a correct process has the copies of
