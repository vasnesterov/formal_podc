import Papers.PODC2021.AllYouNeedIsDAG.Safety /-! # Lemma 1 is false for indirectly committed leaders Lemma 1 of the paper: "If some process `p_i` commits the leader vertex `v` of a wave `w`, then for every leader vertex `u` of a wave `w' > w` and for every process `p_j`, if `u ∈ DAG_j[round(w', 1)]`, then `strong_path(u, v)` returns true in wave `w'`." Here *commits* means "pops from the stack" (Section 6.1), which includes leaders committed *indirectly* through the loop of lines 39–43. The proof only treats leaders committed by the commit rule of line 36. Counterexample (`n = 4`, `f = 1`, all vertices present, no weak edges, coin = process `0` in every wave). The observer is the correct process `3`; when wave `w` becomes ready its local DAG contains all vertices of rounds `1..4w` except its own `(4w, 3)` (not yet delivered back to it). This view is realizable: the round-`(4w+1)` vertex that process `3` then creates has strong edges exactly to the round-`4w` vertices of this DAG (`realizable`). * wave 1: only `(4,0)` of round 4 reaches the leader `v₁ = (1,0)` — no commit; * wave 2: the leader `v₂ = (5,0)` has strong edges to `(4,1), (4,2), (4,3)` only, so it has **no strong path to `v₁`**; only `(8,0)` reaches it — no commit; * wave 3: the three round-12 vertices of its DAG reach `v₃ = (9,0)` — direct commit; `v₃` reaches `v₁` (via `(5,1) → (4,0)`) but not `v₂`, so the process pushes `v₁`, i.e. **commits `v₁`** (indirectly) together with `v₃`. So `v₁` is committed, `v₂` is a leader of a later wave in the DAG of the same process, and `strong_path(v₂, v₁)` is false.
