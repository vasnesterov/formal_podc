A transaction graph has parties `P` and contracts (edges) `E`; each contract transfers `amt e` units of asset `asset e` from `src e` to `dst e`. Every party `p` initially owns `own p a` units of asset `a`. HTLCP edge-creation rules with brokering (§§2–3): a contract is created by its sender, one at a time. * A **leader** may create its outgoing contracts at any time; a **follower** only once *all* its incoming contracts have been created. * The sender must (tentatively) own the transferred amount: its initial endowment plus everything it received on created incoming contracts minus everything it already escrowed on created outgoing contracts (the "master contract" bookkeeping of §3). A leader set `L` is **adequate** if some order of creations following these rules creates every contract (`Adequate`). A **minimum leader set** is an adequate leader set of minimum cardinality. Besides the definitions this file contains the generic tools used for the reduction (`Reachable.closed`, `Reachable.balance`, `Adequate.first_hit`, `Reachable.batch`) and the §3 claims about graphs without brokering: there, the adequate leader sets are exactly the feedback vertex sets (`adequate_iff_isFVS`); with brokering, every adequate leader set is still a feedback vertex set (`Adequate.isFVS`). -/ namespace Podc.HTLCBrokeringHardness open Finset /-- A transaction graph: contracts `E` between parties `P`, each moving `amt e` units of asset `asset e` from `src e` to `dst e`.
