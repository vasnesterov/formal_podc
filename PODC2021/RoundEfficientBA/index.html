Round-Efficient BA via Proxcensus — PODC 2021

Matthias Fitzi, Chen-Da Liu-Zhang, Julian Loss. A New Way to Achieve Round-Efficient Byzantine Agreement. PODC 2021. DOI 10.1145/3465084.3467907. Formalized version: the 8-page proceedings version (no arXiv version; the IACR ePrint full version 2021/814 was not accessible to us); numbering follows the proceedings. Copy of the paper: paper.pdf.

DOI · PDF · All differences · Lean source · GitHub

Verdict: ⚠️ Weakened. Of the paper's two equal results, the (κ+1)-round BA for t < n/3 is wrong as printed for every n ≥ 3t + 2 with t ≥ 1, but is saved by one constant: with the threshold t + 1 instead of n - 2t (the same thing when n = 3t + 1) everything is proved, including error ≤ 2^{-κ}. The 3κ/2-round BA for t < n/2 runs the coin in parallel to the last Proxcensus round, and this fails against the paper's adaptive strongly rushing adversary: one iteration errs with probability at least 1/2, not 1/4. Tossing the coin after round 3 costs 2κ rounds, no gain over prior work, so the improvement claimed for t < n/2 is lost; the Proxcensus protocol itself (Lemmas 3.4–3.6) and Theorem 3.7 are correct.

Mistakes in the paper

❌ Cor. 3.8 for t < n/2 (coin tossed in parallel to round 3)

The claim "the slot pair is fixed after round 2" is false against the paper's adaptive strongly rushing adversary, which corrupts a party in round 3 depending on the coin, so one iteration errs with probability ≥ 1/2, not 1/4 (coin_parallel_adaptive_attack).

Impact. For κ = 2 this contradicts Cor. 3.8's 2^{-κ}, so the 3κ/2-round claim does not stand against the adversary the paper names. The Proxcensus protocol (Lemmas 3.4–3.6) and Theorem 3.7 are correct, and the claimed 1/4 holds against coin-independent corruptions, for one iteration (coin_parallel_static).

Details

To get 3 rounds per iteration, the coin is tossed in parallel to round 3 of Prox_5. The coin is revealed during that round (§2.2), so a strongly rushing adaptive adversary can corrupt a party in round 3 depending on the coin, and drop its round-3 forwarding. Example: n = 5, t = 2, inputs 1,1,0,0, party 4 Byzantine. Party 4 makes everybody hold Σ on 1, and lets only party 0 form Ω on 1.

  • Coin 4: nothing more happens. Party 0 outputs (1,2) and the others (1,1), split by coin 4.

  • Coin 3: the adversary corrupts party 0 in round 3 and forwards Ω only to party 1. Party 1 outputs (1,1) and parties 2, 3 output (⊥,0), split by coin 3.

Repair

We prove the claim for coin-independent corruption (e.g. a static adversary), even when the adversary picks its round-3 messages after seeing the coin (coin_parallel_static). Tossing the coin after round 3 also works, but costs 4 rounds per iteration, i.e. 2κ rounds and no gain over prior work.

🔧 Lemma 3.2, Cor. 3.3 and Cor. 3.8 for t < n/3 (Proxcensus expansion, n ≥ 3t + 2)

For every n ≥ 3t + 2 with t ≥ 1 the expansion's threshold n - 2t lets one Byzantine echo move a receiver by several grades; with n = 5, t = 1 the (κ+1)-round BA errs with probability 3/8 for κ = 3 (lemma32_counterexample, paper_cor33_counterexample, paper_cor38_counterexample).

Impact. The printed protocol is wrong outside n = 3t + 1, but with threshold t + 1 (the same as n - 2t when n = 3t + 1) Lemmas 3.1–3.2, Cor. 3.3 and Cor. 3.8 (t < n/3) hold for all n > 3t (expand_isProx, proxProtocol_spec, ba_third).

Details

A party outputs the slot "between" or "on" two adjacent old slots. The choice depends on which slot has ≥ n - 2t echoes. If n ≥ 3t + 2, the ≥ n - t honest echoes may split so that neither slot reaches n - 2t without Byzantine help. Then one Byzantine echo moves a receiver by several grades.

  • Example: n = 5, t = 1, honest Prox_5 outputs (0,1),(0,1),(0,2),(0,2). A receiver getting the extra echo (0,2) outputs grade 3. A receiver getting nothing from the Byzantine party outputs grade 0.

  • The protocol then breaks down from honest inputs 0,0,0,1. After 3 rounds the honest Prox_9 outputs are (0,2),(0,2),(0,3),(0,0), and the BA of Cor. 3.8 (κ = 3) fails for 3 of the 8 coin values (error 3/8, not 1/8).

  • Using the largest admissible t does not help: n = 5, t = 1 already is that case.

Repair

With threshold t + 1 we prove Lemmas 3.1–3.2, Cor. 3.3 and Cor. 3.8 (t < n/3) for all n > 3t, including error ≤ 2^{-κ}. For n = 3t + 1 that is the paper's protocol verbatim. (expand_isProx, proxProtocol_spec, ba_third)

Typos

  • The pseudocode of Prox_{2r-1} (§3.3.2) writes s for the number of rounds r.

  • In the proof of Theorem 3.7, 2G + 1 - j should be 2G + 1 - r, and this r = s mod 2 clashes with r = rounds.

  • In the first bullet of the proof of Lemma 3.2, "any honest P_j has g_j = g_i" needs maximality of g_i plus some slot having n - 2t honest echoes, which the proof does not say. Harmless for n = 3t + 1.

The formalizationmodel, Lean names of the results, trust

Model.

  • Proxcensus (Def. 2.2) is a property IsProx s x H out of the honest outputs: grades in [0, ⌊(s-1)/2⌋], validity, consistency for every ordered pair.

  • Theorem 3.7. The binary slots and the extraction function f are the paper's. The coin is ideal and uniform on [1, s-1] (PMF.uniformOfFintype). It is independent of the Proxcensus outputs, and the adversary may corrupt more parties after seeing it.

  • t < n/3. CSLib's synchronous lock-step model on the complete network: deterministic protocol, static Byzantine adversary sending arbitrary messages per round, sender and receiver (this covers rushing). Adaptive corruption reduces to static corruption of the finally corrupted parties, since the phase is deterministic. Values come from any finite linearly ordered domain.

  • t < n/2. Our own model with ideal unique (n-t)-out-of-n threshold signatures:

    • Certificates are represented by certified values. The adversary can send exactly the certificates it can form, from shares of parties honest in that round plus the keys of the corrupted parties.

    • Corruption is adaptive, at round granularity: a party corrupted in round k has its round-k messages replaced.

    • For the coin-in-parallel analysis, an adversary strategy is a family of adversaries indexed by the coin that agree before the last round.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. All counterexample runs are checked by decide on the actual protocol definitions, and their scenarios satisfy all hypotheses (corruption bound, validity of the adversary, PrefixAgree). The non-vacuity of coin_parallel_static is shown by an explicit strategy for which the bound 1/4 is attained (coin_parallel_static_tight). The t < n/3 model is CSLib's Cslib.Byzantine.LockStep. The Proxcensus specification is shared: IsProx, ProxCons, maxGrade are Cslib.Byzantine.Problem.Proxcensus, Proxcensus.Consistent, Proxcensus.maxGrade, and ProxSpec is its lock-step lift Cslib.Byzantine.Problem.ofOut (Cslib/Computability/Distributed/Byzantine/Specs.lean).
