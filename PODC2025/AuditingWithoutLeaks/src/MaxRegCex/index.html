import Papers.PODC2025.AuditingWithoutLeaks.MaxRegInv /-! # Lemma 38 (uncompromised writeMax) of Algorithm 2 is false Lemma 38 of the paper claims: for every finite execution `α`, every value `w` and every reader `p_j`, either `p_j` has a `w`-effective read in `α`, or there is an execution `α' ∼_{p_j} α` in which no `writeMax` has input `w`. Counterexample (one reader `p_0`, two writers `A = wr 0`, `B = wr 1`, no auditors, initial pair `v₀ = (0, 0)`): `A` runs `writeMax(0)` solo with nonce `N_A`, then `B` runs `writeMax(1)` solo with nonce `N_B`, then `p_0` runs one read, which fetches `R = (2, (1, N_B), _)` and returns `1`. Hence `p_0` has no `0`-effective read. But in every execution indistinguishable to `p_0`, its fetch&xor returns the same triple, so `R.seq = 2` and `R.val = (1, N_B)` at that point; since the pairs successively stored in `R` strictly increase with `R.seq` (`MaxRegInv.lean`), the pair with sequence number `1` lies strictly between `(0, 0)` and `(1, N_B)`. * With `N_A = 1`, `N_B = 0` (`θ₁`): that pair is `(0, N)`, `N ≥ 1`, so a `writeMax(0)` was invoked (`lemma38_false`, over all coins). * With `N_A = 2`, `N_B = 1` (`θ₂`) and *fresh* nonces (pairwise distinct and different from `N₀ = 0`): that pair is `(0, N)` with `N ≥ 1` (the only other candidate, `(1, 0)`, would reuse the nonce `N₀`), so again a `writeMax(0)` was invoked (`lemma38_false_fresh`). The paper's proof picks "the largest input `u` of a writeMax smaller than `w`", which does not exist when `w` is the initial value `w₀` (and in general the gap between `(u, N)` and `(w, N')` in `R`'s
