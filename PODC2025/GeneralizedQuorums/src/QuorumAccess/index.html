import Papers.PODC2025.GeneralizedQuorums.Defs import Cslib.Computability.Distributed.SharedMemory.History /-! # The quorum access functions of Figure 3 and their safety (Lemma 1, Theorem 3) The protocol of Figure 3, as an algorithm in the model `Cslib.ChannelFailures`, for arbitrary families of read quorums `RR` and write quorums `WW` (only Consistency is needed for safety). * The opaque top-level state is represented by the set of identifiers of the update functions applied to it: the update of the `quorum_set` invoked by `p` with sequence number `k` is `(p, k)` (`k ≥ 1`; the `k`-th operation of `p`, counted from `0` in the history, has sequence number `k + 1`). Applying an update inserts its identifier. Hence "`s` has incorporated `u`" is `u ∈ s`, and the Validity property says that `s` only contains identifiers of invoked `quorum_set`s. * `quorum_get` returns the list of states collected from a read quorum; `quorum_set` returns `[]`. * Waits are re-evaluated after every step (`advance`). A process keeps, for every sender, the `GET_RESP` with the highest clock received so far (`latest`): the wait at line 8 (resp. 20) is for a read quorum all of whose latest clocks are `≥ c_get` (resp. `≥ c_set`). The safety theorems (`realtime_ordering`, `validity`) are proved in `QuorumAccessProof.lean`. -/ namespace Podc.GeneralizedQuorums.QA open Cslib.ChannelFailures Cslib.SharedMemory variable {P : Type}
