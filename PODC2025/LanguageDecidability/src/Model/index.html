Each process repeats forever: * Lines 01–02: the adversary chooses the next invocation symbol `v ∈ Σᵢ<`; the process runs a block of code on its local state and the shared memory (`Alg.pre`, event `Ev.pre`); * Line 03: it sends `v` to the adversary `A` (event `Ev.send`); * Line 04: it receives a response symbol `w ∈ Σᵢ>` chosen by the adversary (event `Ev.recv`); * Lines 05–06: it runs a block of code and reports a value (`Alg.post`, event `Ev.post`). Modelling choices (they make the impossibility results stronger): * the shared memory is an arbitrary type `M` and each block is one atomic transition on it, so any base objects (of any consensus number, even an atomic snapshot-and-update of the whole memory) are allowed; a wait-free block run solo is a function of the local state and memory, and our executions are allowed to run blocks solo; * every block may also read a perfectly synchronized global clock (the global step number `t`); * report values are an arbitrary type `R`. An execution is a schedule `s : ℕ → Ev I O` (it does not depend on `V`): every event must be enabled by the program counter (`Phase`) of its process (`IsExec.valid`), and every process completes infinitely many iterations (`IsExec.fair`: fair, failure-free executions). The configurations `Alg.run` and the reports `Alg.outs` of `V` along `s` are then determined. The input `x(E)` is the subsequence of send/receive events (`HasInput`); it is unique (`HasInput.unique`). ## Decidability * `Decides V L P` — Definition 5.1 (`P`-decidability) for a predicate `P` of
