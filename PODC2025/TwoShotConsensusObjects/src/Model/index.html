import Papers.PODC2025.TwoShotConsensusObjects.Defs import Cslib.Computability.Distributed.SharedMemory.ObjClasses import Cslib.Computability.Distributed.SharedMemory.Recoverable /-! # Two-shot objects solving two-process consensus — the system model Model (Section 3 of the paper), on top of CSLib's asynchronous shared-memory model `Cslib.SharedMemory.Recoverable` used without crashes (`WFConsensus` = wait-free binary consensus in the crash-stop model): * two deterministic processes `0 = p₀` and `1 = p₁` (`Fin 2`), starting with binary inputs; a process outputs (decides) by entering an output state; * asynchronous scheduling; executions are lists of events (we only use crash-free ones); * shared objects (`withRW R O`): read/write objects `R j` (`j : ιR`, every operation read-only or a blind write, `ObjSpec.RWLike`; registers are an instance) and copies `k : ιS` (finitely many) of the deterministic type `O` under study; initial states are chosen freely by the algorithm (`Alg.mem₀`), as in Jayanti's model used by the paper; * **two-shot** (`TwoShot`): in every execution each process applies at most two operations to each copy of `O`; * **process-allowance map** (`Allowed m`): process `p` only applies operations of `m p` to the copies of `O`; * wait-free consensus: agreement, validity and wait-freedom (`WFConsensus`). `Solvable O m` — the paper's "objects of type `(O, m)` solve two-shot two-process consensus". The object families `withRW`, access counts `accCount` and the generic correctness tools (`prog_of_rank`, `wfConsensus_of_inv`, …) are in `Cslib.Computability.Distributed.SharedMemory.Recoverable`. -/
