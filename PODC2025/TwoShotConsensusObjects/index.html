Two-shot objects solving two-process consensus — PODC 2025

Minh Tung Nguyen, Pierre Sutra. An Exact Characterization of the Two-shot Deterministic Objects Solving Two-process Consensus. PODC 2025. DOI 10.1145/3732772.3733534. Formalized version: the PODC proceedings version (no arXiv version found); numbering follows it. Copy of the paper: paper.pdf.

DOI · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The main result is fully formalized: a deterministic two-shot type (T, m), together with registers, solves wait-free two-process consensus iff it lies in C₁ ∪ C₁.₅ ∪ C₂. Both directions and all three algorithms hold after local repairs: a typo in Algorithm 3, and missing cases and a changed graph definition in the proofs. The one claim lost is the illustrating example "the asymmetric queue AQ is in C₁.₅", which is false (AQ is in C₂) and which nothing depends on.

Mistakes in the paper

❌ §4.2.5 (the asymmetric queue AQ is in C₁.₅)

The asymmetric queue, where only p₀ may dequeue, is not in C₁.₅: the paper's witness violates property (1), and no witness exists (paper_AQ_witness_fails, aq_not_C15).

Impact. Illustration only: AQ is in C₂ (with the WQ witness), so it still solves consensus (aq_C2). The characterization itself is unaffected, but C₁.₅ is left without a concrete object: we proved no other example.

Details

The paper's witness is queue [0], f = dequeue, f' = read, g = enqueue(1), g' = read.

  • That witness already violates property (1): dequeue returns 0 whether or not enqueue(1) went first. Properties (3), (4) and (5) fail too; only (2) holds.

  • No witness exists, in any state and in either role orientation. Property (1) forces g = enqueue(y). Properties (1) and (3) then force g' = read, f = dequeue and an empty queue. But then p₁ reads [y] both in gg'ff' and in fgg'f', so property (4) fails.

🔧 §4.2.5, paragraph on WQ (conditions for distinguishing fg from gf)

"If fg and gf are distinguishable to p₀ then f = read(), g = enqueue(1) and the queue is initially empty" is false: for WQ, f = read, g = enqueue(y) distinguish from every state, so emptiness is not forced.

Impact. Dropping the overstated conditions is enough, and the conclusion that WQ is not in C₁.₅ is proved (part of wq_C2).

Details

For AQ, f = dequeue() on an empty queue also works.

✏️ Slips

  • Algorithm 3, line 30 tests v[1][1] where v[0][1] is meant; only p₀ executes the line, and its v[1][1] is ⊥, so taken literally agreement fails in the run where p₁ runs solo first. A brute-force search (Python, not in Lean) found a 4-state object in C₂ exhibiting the failure. With v[0][1] Algorithm 3 is correct (proved in Lean, solvable_of_C2Cond), and the characterization stands.

  • Corollary 1's "op ∈ [0, k]" should be [0, 3^k].

  • The proof of Lemma 2 is imprecise (its case a = 0 gives n = 3^{k-1}, which for n = 1 violates k > 0; it cites the "third" property of C₂ for the pairs of property (2)); the padding argument is formalized.

  • The proof of Proposition 2 writes "n ≥ 2 even" where n must be odd.

Proof gaps in true statements (3)Necessity proof, §6 · Proposition 2 · Lemma 4

🔧 Necessity proof, §6 (f and g assumed to be first accesses)

At the critical configuration the paper treats f and g as each process's first call to O, and Lemma 5 / Proposition 1 use "the second call f'", which need not exist.

Impact. Statement true; the missing cases are covered (KSetup.dist_of_last, KSetup.c15).

Details

  • If f is p₀'s second call, p₀ can never touch O again, so it must distinguish fg from gf.

  • The object is then in C₁, or in C₁.₅ with alternative (5a) and an arbitrary f'.

  • Likewise, p₀ may decide without calling O again after fgσg'; then (5a) holds.

🔧 Proposition 2 (the graph G must be bipartite)

With operations as nodes, an operation allowed to both processes merges a p₀-node with a p₁-node, so a path can switch sides there and "cᵢ ∈ m(p₀) for even i" fails.

Impact. Statement true; repaired with (process, operation) nodes (KSetup.Adj, KSetup.c2_or_smaller, reduction, necessity).

Repair

  • Using (process, operation) nodes repairs this; the reduction to fewer objects works unchanged.

  • The "minimal number of objects" argument becomes an induction on the number of copies, which needs finitely many copies. We prove the reduced algorithm correct and wait-free.

🔧 Lemma 4 (Algorithm 3, omitted histories)

Its case analysis ignores histories where the other process applies its operations on O after the decider's reads.

Impact. Statement true; the Lean proof enumerates all interleavings (decide0_ok, decide1_ok).

Details

k ≥ 1 is genuinely needed: with N = 1, line 23 would fire wrongly in the run g c_N f c_{N−1}.

The formalizationmodel, Lean names of the results, trust

Model.

  • Two deterministic processes with binary inputs; asynchronous; wait-freedom (every process taking infinitely many steps in an infinite schedule outputs).

  • Crashes are modelled by processes that stop taking steps: CSLib Cslib.SharedMemory.Recoverable without crash events, WFConsensus.

  • Shared objects:

    • Read/write-like objects (ObjSpec.RWLike, which includes registers of any value type).

    • Finitely many copies of the deterministic type O (the paper's "minimal number of objects" argument presupposes this; necessity is proved for such algorithms). Each process applies at most two operations to each copy in every execution (TwoShot), and only operations allowed by m (Allowed).

    • Initial states are chosen by the algorithm.

  • Solvable O m existentially quantifies over all such algorithms (Model.lean). Generalizing registers to read/write-like objects only strengthens necessity. The algorithms use one copy of O and plain registers.

  • Distinguishability (Dist, DistBoth) compares the lists of a process's responses along an interleaving (view). The classes are C1, C15 (incl. role swap) and C2, with the paper's exclusions (Defs.lean).
