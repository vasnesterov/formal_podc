import Podc.Computability.Distributed.Byzantine.AsyncBroadcast import Podc.Computability.Distributed.AsymmetricQuorum /-! # Algorithm 2 (asymmetric gather by quorum replacement) and its `r`-round generalization Amores-Sesar, Cachin, Villacis, Zanolini, *DAG-based Consensus with Asymmetric Trust*, PODC 2025 (arXiv:2505.17891). Algorithm 2 replaces "`n − f` messages" in the three-round gather of Abraham et al. by "messages from all members of one of my quorums". We model the natural `r`-round generalization (the paper speaks of running the same pattern for more rounds, Section 3.2 and Appendix A): * round `0`: arb-broadcast the input (`RMsg.val`); `acc ib 0` = the arb-delivered pairs; * round `k + 1` (`k + 1 < r`): once a quorum `Q ∈ Qs p` is "complete at level `k`" (all members' level-`k` messages received), send `RMsg.dist (k+1) (acc ib k)` once; `acc ib (k+1)` = union of all received level-`k+1` sets; * after `r` levels: once a quorum is complete at level `r - 1`, ag-deliver `acc ib (r-1)`. Algorithm 2 is `protocol Qs 3` (`DISTRIBUTES` = level 1, `DISTRIBUTET` = level 2). The model is the asynchronous interleaving model `Cslib.Byzantine.AsyncBroadcast`. The asymmetric reliable broadcast of the inputs is represented by the `val` messages; in the fault-free executions used here every delivery schedule of the reliable broadcast is possible, so this is exact. ## Main results * `reachable_run`: for a single-quorum system `q` and every `r ≥ 1`, the "everybody hears exactly its own quorum" schedule is a reachable execution in which every process ag-delivers the pairs of the processes in `R q (r-1) p` (`r`-fold quorum neighbourhood). * `not_commonCore_of_run`: if no quorum is contained in all these neighbourhoods, the run has no common core.
