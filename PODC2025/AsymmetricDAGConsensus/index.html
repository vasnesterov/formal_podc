DAG-based Consensus with Asymmetric Trust — PODC 2025

Ignacio Amores-Sesar, Christian Cachin, Juan Villacis, Luca Zanolini. DAG-based Consensus with Asymmetric Trust. PODC 2025. DOI 10.1145/3732772.3733527. Formalized version: arXiv 2505.17891 v1 (extended version); numbering follows it.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The gather part of the paper holds after local repairs: Lemma 3.2 is true (the 30-process system of Figure 1 satisfies B³ and makes the quorum-replacement gather, Algorithm 2, miss a common core), and the new constant-round asymmetric gather (Algorithm 3) is correct, with Lemmas 3.3–3.8 holding once Definition 3.1, line 62 and the proofs of Lemmas 3.5 and 3.7 are fixed. The claim in Appendix A that the quorum-replacement pattern reaches a common core within log n − 1 rounds is false, but it is an unproved side remark about the approach the paper rejects, and nothing depends on it. The DAG consensus protocol of Section 4 is not formalized, so that part of the paper's point was not checked.

Mistakes in the paper

❌ Appendix A, "common core in log n − 1 rounds" (also "would require log n rounds", §3)

The quorum-replacement pattern does not reach a common core in log n − 1 rounds: for n = 8 (log₂ 8 − 1 = 2 rounds) a fault-free B³ system has a run with no common core after 2 rounds (log_rounds_claim_false, two_rounds_five_processes).

Impact. An unproved side remark about the gather the paper rejects; Lemma 3.2 and the new gather (Algorithm 3) are unaffected. We proved no corrected round bound.

Details

Appendix A says that, by quorum consistency, the common core "can be obtained in log n − 1 rounds" of receiving messages from a quorum and sending them on. Counterexample: 8 processes with single quorums {1,2,4}, {3,4,5}, {1,4,5}, {1,5}, {1,3,4}, plus three processes that copy the first quorum. The quorums pairwise intersect, so the canonical fail-prone system satisfies B³. All processes are correct and each one hears exactly its own quorum. After 2 rounds no quorum lies inside every output. After 3 rounds a common core does exist. The first five processes alone already defeat 2 rounds (5 < 2³), so the §3.2 heuristic "3 rounds suffice below 16 = 2⁴ processes" does not carry over to 2 rounds. Rounds are counted as the paper counts them: "the 3 rounds of Algorithm 2", which waits for a quorum three times. With the floor reading, ⌊log₂ 30⌋ − 1 = 3, the claim is refuted by the paper's own Figure 1.

🔧 Definition 3.1 (asymmetric gather, no termination)

Definition 3.1 has no termination property, so a protocol that never ag-delivers satisfies it.

Impact. Lemma 3.8 and the text clearly intend that every maximal-guild member ag-delivers, and Algorithm 3 does. Adding the property is enough: we prove termination too (termination, lemma_3_8).

🔧 Algorithm 3, line 62 (delivery trigger)

Line 62 ("upon receiving DISTRIBUTET from a quorum, ag-deliver U") counts raw receptions, also those with T ⊄ Sᵢ that line 60 has not incorporated, so U may lack the core.

Impact. One added condition fixes the pseudocode, and Lemma 3.8 is proved for it (lemma_3_8).

Repair

Count only DISTRIBUTET messages already incorporated by line 60, that is, those with T ⊆ Sᵢ. We model this reading (QualT).

✏️ Slips

  • §2.4: "2f − 1 processes" should be 2f + 1.

  • Lemma 3.5: the statement's "the processes of Qᵢ receive DISTRIBUTES before sending DISTRIBUTET" only makes sense for the correct members of Qᵢ. We prove that version.

  • Line 148 of Algorithm 6 commits with "a quorum Q ∈ Qⱼ for some Qⱼ ∈ ℚ", a quorum of any process. The text says a quorum of pᵢ, and Lemma 4.2's intersection argument needs that. Not checked in Lean.

Typos

  • §3.2 says "3 rounds, fewer than 16 processes", then "n rounds, fewer than 2ⁿ processes". These two statements do not match: 2³ = 8.

  • §3.2 says Algorithm 2 gives a common core "after four rounds". Elsewhere it speaks of three rounds; "four" presumably also counts the input broadcast, as DAG-Rider's 4-round waves do. With that count the "log n − 1" claim is off by even more.

  • Lemma 4.3 writes strong_path(u, v) from round 1 to round 4, so the direction is reversed.

Proof gaps in true statements (3)Lemma 3.5 · Lemma 3.7 · Lemma 3.2

🔧 Lemma 3.5 (wise vs. maximal-guild process)

The proof goes "all quorums contain a wise process (Lemma 7 of Alpos et al.), so a wise process sent CONFIRM; apply Lemma 3.4", but Lemma 3.4 needs a maximal-guild member, and a wise process need not be one.

Impact. The lemma stands for the correct members of the quorum (see Slips), with one replacement fact (lemma_3_5, exists_candidate).

Repair

A quorum Q of a guild member g meets g's quorum inside the guild, so Q contains a guild member.

🔧 Lemma 3.7 (possibly Byzantine intersection process)

The proof picks a process in Qᵢ ∩ Qⱼ and uses that it put Sᵢ into its T, but that process may be Byzantine.

Impact. The lemma stands, with a one-line change (lemma_3_7).

Repair

Both pᵢ and pⱼ are wise, so consistency against the actual faulty set gives a correct process in the intersection.

🔧 Lemma 3.2 (Appendix A, "easy way to observe" no common core)

The argument is a non sequitur: "every S set has an element in [16,30]" plus "every U misses some element of [16,30]" does not imply that no S lies in all Us.

Impact. The conclusion is still true; checked directly (fig1_no_core).

The formalizationmodel, Lean names of the results, trust

Model.

  • Asynchronous message passing in CSLib-style Cslib.Byzantine.AsyncBroadcast (staged in Podc/). Interleaving semantics, authenticated channels, Byzantine faults with adaptive corruption (stronger than the paper's static faulty set F). The faulty set of an execution is the set of processes corrupted at some time, and wise processes and guilds are defined relative to it. No randomness.

  • Asymmetric trust (new, Podc/Computability/Distributed/AsymmetricQuorum.lean): fail-prone systems F i, B³, asymmetric quorum systems (consistency + availability), kernels (all sets meeting every quorum of i), wise processes, guilds, the maximal guild.

  • The asymmetric reliable broadcast of the inputs is a val message. For Byzantine senders its consistency and totality towards the guild are hypotheses on the execution (RBC). These are exactly the guarantees of the primitive of Alpos et al. that the paper uses. Validity and integrity for correct senders follow from the model.

  • Algorithms 2 and 3 are given by their handler guards. Liberal choices (e.g. which received T sets go into U) only add behaviours, so the safety results transfer. Liveness uses weak fairness: messages between correct processes are delivered, and a correct process whose guard for a message holds forever sends it.

  • Lemma 3.2 and the round claims: an explicit fault-free run of the r-round quorum-replacement gather (r = 3 is Algorithm 2) is reachable, with all processes ag-delivering. All processes form the maximal guild. Every possible core S (a set with a pair for each member of a quorum) misses some output. In a fault-free run every arb-delivery order can happen, so these runs are genuine.

  • Algorithm 3: results hold for every nonempty guild G with RBC for G, in particular for the maximal guild (as in the paper).
