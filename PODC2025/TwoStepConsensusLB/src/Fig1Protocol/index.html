import Mathlib /-! # The upper-bound protocol of Ryabinin–Gotsman–Sutra (PODC 2025), Fig. 1, as a transition system This file models the consensus protocol of Fig. 1 of *Revisiting Lower Bounds for Two-Step Consensus* (arXiv 2505.03627v2), in both versions: * `Version.task`: the black lines only; `initial_val` is the process's input, fixed forever; * `Version.object`: with the red lines; `initial_val` is `⊥` until `propose(v)` is invoked. ## Model: an abstract asynchronous transition system There is no time. A global state consists of the local states of all processes and the **set of all messages ever sent** (`State.msgs`). Every action is one handler of Fig. 1 executed atomically by one process; it is enabled when its triggering messages are in the set and its precondition (`pre:` in Fig. 1) holds. This over-approximates every execution of the real protocol (messages may be reordered, duplicated, delayed forever; a crashed process simply stops acting), so the safety results proved about it (`Fig1Safety.lean`) hold for every real execution, under any leader-election scheme and any timing. Values are a linear order `V`; `⊥` is `none : Option V`. `n = Fintype.card P` (the paper's `|Π|`). ## Interpretation choices (Fig. 1 is pseudocode; these are our readings) * Ballots: every ballot `b ≥ 1` has a unique owner `cfg.owner b` (the paper: `b ≡ i (mod n)`; any function `ℕ → P` is allowed here). Only the owner of `b` sends `1A(b)` (lines 21–23); **every** process may start any of its own ballots at any time (no leader election in the safety model). * Lines 9–10: `bal` is the receiver's **current** ballot variable. The fast path (first disjunct) needs `bal = 0` and counts the `2B(0, v)` messages addressed to `p_i` (replies to its own `Propose`); the slow path (second disjunct) counts `2B(bal, v)` messages addressed to `p_i` (replies to its own `2A(bal, v)`, so `p_i` is the owner of `bal`). The set `P` of senders is non-empty (the handler is triggered by receiving messages). * Line 24: the owner of `b` may run the `1B` handler for any set `Q` of `n − f` processes whose `1B(b, …)` messages it has received, as long as it has not yet sent a `2A(b, ·)` (a handler that ended with `val = ⊥` sent nothing, so it may run again later). Lines 26–38 are the relation `Select` (non-deterministic where Fig. 1 is: which `decided_q` at line 30, which `q` with `vbal_q = b_max` at line 32); a run of lines 26–38 that ends with `val = ⊥` sends nothing. * Lines 1–4 (object version): an invocation `propose(v)` (action `invoke`, at most once per process — well-formed clients) sets `initial_val ← v` if `val = ⊥`; the broadcast of `Propose(initial_val)` is the separate action `sendPropose`, enabled whenever `initial_val ≠ ⊥` (task version: at startup, or any time). Executing `invoke` immediately followed by `sendPropose` is the atomic handler of Fig. 1, so this is an over-approximation. * Line 6, object version: the red conjunct `initial_val ≠ ⊥ ⟹ v = initial_val` (`Accepts`). * `cfg.fallbackVal` (default `false` = the paper) selects a fixed variant of lines 37–38 in which a leader with `initial_val = ⊥` proposes its own `val` if `≠ ⊥` (`leaderIv`). All safety results hold for both variants. * Ghost data (not read by any handler): `Decide` messages carry the ballot `bal` of the sender at the moment of its decision (`0` = fast path, line 10 first disjunct), and each process records the argument of its `propose` invocation (`Loc.inv`), used to state Validity of the object version. -/ namespace TwoStepConsensus.Fig1 /-- The two versions of Fig. 1: consensus *task* (black lines) and *object* (with red lines). -/ inductive Version | task | object deriving DecidableEq /-- Parameters: version, the thresholds `e ≤ f`, the owner of each ballot, and (task version) the inputs. -/ structure Config (P V : Type*) where ver : Version e : ℕ f : ℕ /-- The process that owns ballot `b` (the only one that may send `1A(b)` and `2A(b, ·)`). -/ owner : ℕ → P /-- Inputs (task version; ignored by the object version). -/ input : P → V /-- `false` (default): Fig. 1 as in the paper. `true`: the *fixed* lines 37–38, where a leader with `initial_val = ⊥` falls back to its own `val` (see `leaderIv`). -/ fallbackVal : Bool := false /-- Local state of a process (Fig. 1 variables plus the ghost `inv`). -/ structure Loc (P V : Type*) where bal : ℕ vbal : ℕ val : Option V proposer : Option P decided : Option V initVal : Option V /-- Ghost: the argument of this process's `propose` invocation (object version). -/ inv : Option V /-- The payload of a `1B` message: `(vbal, val, proposer, decided)` of the sender (line 20). -/ structure Snap (P V : Type*) where vbal : ℕ val : Option V proposer : Option P decided : Option V /-- The `1B` payload reported by a process in local state `l`. -/ def Loc.snap {P V : Type*} (l : Loc P V) : Snap P V := ⟨l.vbal, l.val, l.proposer, l.decided⟩ /-- Messages.
