Revisiting Lower Bounds for Two-Step Consensus — PODC 2025

Fedor Ryabinin, Alexey Gotsman, Pierre Sutra. Brief Announcement: Revisiting Lower Bounds for Two-Step Consensus. PODC 2025, pp. 58–61. DOI 10.1145/3732772.3733541. Formalized version: arXiv 2505.03627 v2 (full version with appendices A–C; numbering follows it). Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. Both main theorems hold, and we prove them as "iff" statements in one model, given n ≥ 2, e ≤ f and two values: an f-resilient e-two-step consensus task exists iff n ≥ max {2e+f, 2f+1} (Theorem 1), and an f-resilient e-two-step consensus object exists iff n ≥ max {2e+f−1, 2f+1} (Theorem 2). The upper bound for objects, however, does not follow from the paper's protocol: the object version of Fig. 1 is not wait-free, and we prove Theorem 2 with a repaired protocol that replaces the leader mechanism by rotating ballots. The proofs of Lemma 4, Lemma 5 and §B also have gaps, all of which we repaired; Lemma 4 took a new invariant.

Mistakes in the paper

🛠️ Fig. 1 object version (§C.3, upper bound of Theorem 2; wait-freedom)

The object protocol (Fig. 1 with the red lines) is not wait-free: 1B messages do not carry initial_val and a leader at line 37 can only propose its own initial_val, so a value known only to a non-leader is never proposed (Fig1.object_not_wait_free_omega, Fig1.object_not_wait_free).

Impact. The paper does not establish the "if" direction of Theorem 2, but Theorem 2 itself is true: we prove it with a repaired protocol (Impl.theorem_2_upper, theorem_2).

Details

Two concrete executions show this.

  • Ω scenario, any admissible parameters. No process crashes, and Ω permanently outputs a correct l that never calls propose. Every process moves to ballot 1 before anybody invokes (the ballot timer runs from startup: "Initially it is set to 2Δ", §C.1). Later a correct r ≠ l invokes propose(v). Its Propose is ignored (bal ≠ 0), so l computes val = ⊥ in every ballot and never sends a 2A, and r never returns. (Fig1.object_not_wait_free_omega)

  • Crash scenario, any leader election, whenever n − f − e ≥ 2 (e.g. n = 7, f = 3, e = 2, which meets the paper's bound). p proposes v, only r accepts it, and p crashes. Everyone else moves to a slow ballot. r invokes propose(w) later; line 3 is skipped because r has already voted. Each 1B quorum shows at most one vote for v, which is below n − f − e, and no leader has an initial_val, so nobody ever decides. (Fig1.object_not_wait_free)

Repair

We fix lines 37–38 in the object version ("else, if initial_val = ⊥, propose the leader's own val"). We also replace Ω by clock-driven rotating ballots, so every correct invoker eventually leads a ballot after GST. The fix alone does not save the Ω version: the first scenario still applies. We prove the fixed protocol correct and two-step for n ≥ max {2e+f−1, 2f+1}. (Impl.theorem_2_upper, theorem_2)

✏️ Slips

  • Introduction: "EPaxos uses 2f+1 = 2e+f−1 processes, Lamport requires 2f+3" holds only for even f. For odd f, EPaxos's 2f+1 equals 2e+f, and Lamport's bound is 2f+2.

Typos

  • §B.2: decide(p, 1) in σ′ should be decide(p, 0), and "F ∪ {p,q} = f" should be a cardinality.

  • Brief announcement only (arXiv v2 is correct), lines 33 and 35: Q_f should be S.

Proof gaps in true statements (5)Lemma 4 · Lemma 5 · Lower bounds for smaller n · Lemma 3 base case and conclusion of Theorem 1 · Continuation of σ

🛠️ Lemma 4 (slow-path safety)

The induction on b′ claims that a process with vbal_q′ = b received its Decide from the leader of ballot b, which is false: Decide may come from a decision at a higher ballot.

Impact. Statement true; we prove agreement through a "potentially chosen" invariant over all fast and slow decisions (Fig1.lemma4, Fig1.task_agreement, Fig1.object_agreement).

Details

The Decide may be received before answering 1A(b′), and decided_q′ need not be the value of 2A(vbal_q′). Agreement between two fast-path decisions is never argued either.

🔧 Lemma 5 (object fast-path recovery)

The proof considers the line-33 case only when v itself has > n−e−f votes in Q, but with n = 2e+f−1 v can also have exactly n−e−f = e−1 votes while another w has e votes.

Impact. Statement true; repaired (Fig1.lemma5, Fig1.lemma1).

Details

Counting does not exclude this case. It is ruled out by the line-35 argument: all f processes outside Q voted for v, so w's proposer did as well, and in the object version it then never proposed w. In the task version (Lemma 1) the same case is excluded by counting, and the paper skips it silently.

🔧 Lower bounds for smaller n (§B, Theorems 1 and 2 "only if")

The proofs assume n = 2e+f−1 (Thm 1) and n = 2e+f−2 (Thm 2) without reducing smaller n to these cases.

Impact. Statements true; we prove both bounds for every n ≥ 2, using one generic merge lemma for all the indistinguishability arguments (theorem_1_lower, theorem_2_lower, merge_task, merge_object).

🔧 Lemma 3 base case and conclusion of Theorem 1 (§B.1)

"All correct processes propose 0, thus 0 is decided" does not follow from Validity, because the crashed processes propose 1.

Impact. Statements true; one extra step using the paper's own Lemma 2 closes it (syncRun_decides_eq).

🔧 Continuation of σ (§B.2, Theorem 2 "only if")

In §B.2 the correct processes never call propose, so wait-freedom forces no decision in the continuation.

Impact. Statement true; a correct r outside {p, q} invokes propose in the continuation (theorem_2_lower).

Details

Moreover, the "w.l.o.g. 1 is decided" ignores a third proposed value.

The formalizationmodel, Lean names of the results, trust

Model (our own; now in CSLib as Cslib.CrashPartialSync, Cslib/Computability/Distributed/CrashPartialSync/; Model.lean here keeps Definitions 3–5).

  • n deterministic crash-prone processes and point-to-point links, in the Dwork–Lynch–Stockmeyer partially synchronous model. Discrete time with one tick = Δ; GST is unknown.

  • At each tick an alive process takes one atomic step. The step receives the messages delivered now, in an adversary-chosen order, together with an optional invocation (the task input at time 0, or an object propose). Processes see the clock.

  • Links are reliable and timely after GST between correct processes; messages from or to faulty processes may be lost. The paper's proofs need this too.

  • E-faulty synchronous runs (Def. 2), "two-step" (Def. 3: decided in the state after the step at time 2), e-two-step task and object (Defs. 4, 5) are stated literally, quantifying over the delivery order.

  • Task: validity, uniform agreement, termination. Object: agreement of responses, "returned value was proposed before", wait-freedom.

  • Clocks and the restricted step granularity only strengthen the lower bounds. The upper bound holds in this model; with rotating clock-driven ballots instead of Ω, no synchronizer argument is needed.

Degenerate cases (outside the paper's assumption n ≥ 3; not an error). The lower bounds fail for n = 1: deciding one's own input is 1-resilient and 0-two-step (theorem_1_fails_n_one). The fast path of Fig. 1 is vacuous when n − e ≤ 1; this only matters for n ≤ 2, where f = 0.

Omitted steps (not errors). Lemma 2 is stated without proof; the proof is routine and we supply it (syncRun_st_eq). The paper also skips steps in the indistinguishability arguments, which merge_task and merge_object make precise.
