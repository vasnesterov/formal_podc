import Mathlib /-! # Algorithms, steps and executions (Jayanti, PODC 2025, §3–§4 and §6.1) A distributed algorithm (Definition 4.1) is a family of state machines; a *step* (Definition 4.2) is a quadruple `(π, σ, e, σ')` allowed by the transition relation of `π`. An execution is a set `S` of steps together with an order on it. The three kinds of executions of the paper only differ in the order: * classical executions (Definition 4.4): a strict total order induced by real times; * relativistic executions (Definition 4.4): a strict partial order induced by spacetime events (`Spacetime.lean`); * computational executions (Definition 6.1): Lamport's happens-before order. Orders are relations on the subtype `↥S`, so an execution is a pair `(S, r)` with `r : S → S → Prop` and nothing outside `S` matters. The order-independent part of the conditions on executions is `MsgValid` (validity and at-most-once delivery of messages, principle Φ3 / axiom A3). The order-dependent parts are * `ProcSeq S r` — for every processor `π`, the steps `S_π` of `π`, ordered by `r`, form a *rooted, consecutively permissible sequence* `s₁, s₂, …` (finite or of order type `ω`; we express "is a sequence" as: `r` is a strict total order on `S_π` in which every step has finitely many predecessors). This is principle Φ2 / property P2 / axiom A2; * `MsgForward S r` — messages are oriented forward: if `m` is sent in `s` and received in `s'` then `r s s'` (CP2 / RP3 / A3). -/ namespace RelativisticComputing /-- **Definition 4.1** (distributed algorithm), for a set of processors `Proc` and a universe of messages `Msg`.
