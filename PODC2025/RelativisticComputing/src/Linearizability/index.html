import Papers.PODC2025.RelativisticComputing.Central import Cslib.Computability.Distributed.SharedMemory.HerlihyWing.Defs /-! # Linearizability, relativistic and computational linearizability (Jayanti, PODC 2025, §5, Theorem 6.8, Appendix A) A distributed implementation of a shared object (Definition 5.1) is an algorithm some of whose events are invocation events `(π, invoke, op)` or response events `(π, respond, op, r)`. The history of a finite totally ordered execution is the list of its invocation and response events in order (Definition A.1). Linearizability of a history (Definition A.3) is taken from CSLib: `Cslib.SharedMemory.HerlihyWing.Linearizable` (Herlihy–Wing linearizability, in the amended form of Sela–Herlihy–Petrank; a single object, `X = Unit`). Following Definition A.3, an implementation is linearizable if the history of every *finite* classical execution is linearizable. We define relativistic (Definition 5.3 / A.4) and computational (Definition 6.1) linearizability for finite executions as well; see `differencies.md` for this choice. Theorem 6.8 is then the Central Theorem for the class of finite executions, which needs no assumption on the number of processors. -/ namespace RelativisticComputing open
