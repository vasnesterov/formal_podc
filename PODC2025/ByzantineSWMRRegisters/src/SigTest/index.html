The same properties hold for a verifiable register (`Write(v); Sign(v)` / `Verify(v)`), an authenticated register (`Write(v)` / `Verify(v)`, `v ≠ v₀`) and a sticky register (`Write(v)` / `Read ≠ ⊥`) (Observations 11–13, 16–18, 22–24). We capture the common structure as `SigTest`: * a distinguished process `s` (the setter/writer) and a sequence `setOps` of operations it invokes to "sign"; * a test operation `testOp` (allowed for every other process) with a positivity predicate `pos`; * a chain of *stable* state predicates `R 0 = ⊤, R 1, …, R m` (`m = setOps.length`): the `k`-th set operation moves from `R k` to `R (k+1)`, the test is positive iff `R m` holds, `R m` fails initially, and only operations allowed for `s` can establish `R m`. `SigTest.validity`, `SigTest.unforgeability`, `SigTest.relay` derive Lemma 28 (generalized to every `SigTest`) from Byzantine linearizability (Definition 7).
