We show that it fails whenever all primitive commands are deterministic (`theorem_24_false`). The counterexample: a single thread `t` and a single object method `o.f`. * `H_C` is the set of prefixes of `H = (t,txbegin) (t,OK) (t,call o.f(1)) (t,aborted)`; * `H_A` is the set of prefixes of `S_v = (t,txbegin) (t,OK) (t,call o.f(1)) (t,ret(v) o.f) (t,txcommit) (t,aborted)`, for all `v`. `H` is complete, but no complete history of `H_A` has the same length, so `H_C|complete ⋢ H_A|complete`. Still `H_C ⊑_state H_A`: in a trace with history `H` the abort of the call comes from the rule for aborted calls of Figure 2, `y := o.f(e)`. Replacing it with a successful call returning the current value `v` of `y` (and, if the call was the last command of its atomic block, letting the block request a commit that gets aborted) gives a trace of the same program with a history in `H_A` and the same final states: the assignment `y := v` does not change the (unique, by determinism) current state. -/ set_option linter.unusedSectionVars
