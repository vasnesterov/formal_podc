Optimal Deterministic Routing and Sorting on the Congested Clique — PODC 2013

Christoph Lenzen. Optimal Deterministic Routing and Sorting on the Congested Clique. PODC 2013. DOI 10.1145/2484239.2501983. Formalized version: arXiv 1207.1852 v4 (10 May 2013, the PODC version); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. Both main results hold for every n: routing (Theorem 3.7, 16 rounds) and sorting (Theorem 4.5, 37 rounds); we prove them with packets of a constant number of O(log n)-bit items, in 15 and 32 rounds. The square case n = s² follows the paper's algorithms after local repairs to the relay nodes of Corollary 3.3, the global information of the sorting algorithm's final step, and the "bundling" and "exactly f|W| messages" steps. The non-square case of Theorem 3.7 does not work as written and needed a different reduction through virtual nodes.

Mistakes in the paper

✏️ Slips

  • Problem 4.1 asks for the keys with indices i(n−1)+1, …, in; it should be (i−1)n+1, …, in, as in the introduction.

  • Proof of Corollary 3.3: node i receives exactly one message (not f) for each destination j. The nearby claim "each node will receive exactly one message of each color" is also wrong (node c receives only messages of colour c).

  • Corollaries 3.3/3.4 are stated for exactly f|W| messages per node but used with fewer or with upper bounds only (Corollary 3.4, Lemma 4.4, Theorem 3.7). The paper's "at most" remark and dummy messages cover this (we prove the "at most" version, mem_tagged_c33).

Proof gaps in true statements (5)Theorem 3.7, non-square n · Corollary 3.3 · Theorem 4.5, Algorithm 4 Step 8 · Theorem 4.5, Step 6 · Lemma 3.6, Algorithm 2 Steps 2–3

🛠️ Theorem 3.7, non-square n (the reduction to three sub-instances)

With s = ⌊√n⌋ the proof splits the messages into sub-instances on V₁ = {1..s²}, V₂ = {n-s²+1..n} and V₃, but the cover claim fails for n = 3 and Corollary 3.4 is applied outside its hypotheses (coverClaim_false_three, cor34_size_fails_eight, cor34_load_fails_seven).

Impact. The 16-round bound for every n survives, by a different reduction: we simulate the square algorithm on ⌈√n⌉² ≤ 2n virtual nodes, at most two per real node (theorem_3_7).

Details

Four things go wrong:

  • The cover claim fails only for n = 3: there the message from node 2 to itself belongs to none of the sub-instances (coverClaim_false_three). For n ≠ 3 the claim holds, because 2⌊√n⌋² ≥ n (kernel-checked for n ≤ 40 in coverClaim_small, elementary for larger n).

  • Corollary 3.4 is applied to W = V₁ ∩ V₃, but it requires |W| ≤ √n. This fails, e.g., for n = 8, where |W| = 4 (the arithmetic is recorded in cor34_size_fails_eight).

  • Corollary 3.4 also requires every node to hold exactly ⌊n/|W|⌋·|W| messages. This fails, e.g., for n = 7, where up to 21 messages must be spread over 3 nodes holding at most 6 each (the set identities and arithmetic are recorded in cor34_load_fails_seven; this is not a full execution).

  • The square algorithm run on V₁ (s² nodes) is built for s² messages per node, but nodes can have up to n > s² messages inside V₁. The paper's "factor 2" accounts for running the V₁ and V₂ instances in parallel. Its remark after Problem 3.1 (overloaded instances "can be split up into smaller ones") partly covers this, but how to split them without coordination is not worked out.

🔧 Corollary 3.3 (relay nodes lack routing information)

In round 1 the messages go to nodes 1..m, which need not be in W, but only nodes of W know the routing pattern.

Impact. The two-round routing survives, at a constant factor in message size (c33a/c33b).

Details

This causes no problem when a message's current target is its final destination, which the message header contains. It does in Step 5 of Algorithm 2 and Step 3 of Algorithm 1 (Corollary 3.5), where the targets are intermediate.

Repair

Attach the target (and the target group in Algorithm 2) to the message (c33a/c33b).

🔧 Theorem 4.5, Algorithm 4 Step 8 (global information never distributed)

To send a key to the node responsible for its global rank, a node must know the sizes of all buckets of the other groups, but no step announces these counts.

Impact. The round count survives: one extra round (P29) still fits easily into 37 rounds.

Details

Corollary 3.3 (with W = V) also requires everyone to know all sources and destinations.

Repair

We add one round in which every node broadcasts how many keys it holds (P29).

🔧 Theorem 4.5, Step 6 (bundling arguments)

"Bundling up to two keys in each message, nodes need to … receive at most n messages" does not follow.

Impact. The 37-round claim is kept, at the cost of constant factors (load_tgt, box_deliver).

Details

  • Step 6 of Algorithm 4: "receive at most 2n keys" is true. It follows from ⌈|K_{i,j}|/√n⌉ ≤ d_i + 1, not from the stated bound Σ|K_{i,j}| < 2n^{3/2}.

  • With per-sender bundling a node can need about 1.5 n messages.

Repair

We use packets with a few more slots and route Step 6 through the routing algorithm on a virtual clique of 4n nodes, which allows receiver loads up to 4n (load_tgt, box_deliver; box_spec in the docstring of RoutingBox.lean).

🔧 Lemma 3.6, Algorithm 2 Steps 2–3 (quotas not known in advance)

Nodes cannot know how many messages they "need to move to each set" before knowing the others' counts, so the group-level colouring must be distributed over the group members (a transportation problem).

Impact. The round count survives (HB_of_inp, Setup.q).

Details

The paper hands this to a footnote ("deferred completion"), which only half states it.

Repair

Step 3 announces counts per destination group, and the quota is settled afterwards by a transportation step among the group members.

The formalizationmodel, Lean names of the results, trust

Model.

  • Network. Synchronous congested clique (Model.lean) on nodes Fin n with known identifiers. Algorithms are deterministic and in full-information form: in round t node v computes its packet to each node from its identifier, its input and all packets received so far. The algorithm may depend on n. No failures, no randomness.

  • Packets. In every round every node sends every node (itself included) one packet of B slots. A slot carries one message/key or one number. The theorems fix B as an absolute constant (12 for routing, 384 for sorting) and bound numbers by 8n² resp. 32n². So packets have O(log n) bits, as in the paper.

  • Opaque messages and keys. They can only be forwarded: a node may send only items it holds, i.e. its own inputs or items it received (Holds, SortHolds). Keys can be compared.

  • Routing (Problem 3.1). Every node sends at most n messages and receives at most n (Solves). theorem_3_7_exact is the paper's "exactly n" version.

  • Sorting (Problem 4.1). Node i gets n distinct keys; the key of global rank r must reach node ⌊r/n⌋ (SortSolves). Distinctness is the paper's w.l.o.g. assumption.

  • Proof technique. Algorithms are built as intended runs (global formulas for all packets). We then prove that every packet is determined by its sender's view (IsLocal, Knowledge.lean), which yields a genuine distributed algorithm (synth_sent).

The round counts are 15 instead of 16 and 32 instead of 37. In Algorithm 2 we merge Steps 1 and 3 into one group announcement. In Algorithm 3 we use Corollary 3.3 instead of 3.4, since the counts are already known. Delimiters are announced in one round with larger packets.

Not formalized. Corollary 4.6 (ranks with repeated keys), Section 5 (local computation and memory, Theorem 5.4's 12-round variant) and Section 6 (other parameter ranges). Edge colourings are obtained by Classical.choice (deterministic, but not efficiently computable). For Theorem 4.5 with non-square n the paper gives a one-sentence sketch; we prove the theorem by the same virtual-node simulation (theorem_4_5) and did not check whether the sketch itself works.

Trust. No sorry; theorem_3_7, theorem_3_7_exact, theorem_4_5 and the square-case theorems use only the axioms propext, Classical.choice, Quot.sound. Non-vacuity: routing_not_zero_rounds and sorting_not_zero_rounds (Sanity.lean) show that the specifications cannot be met without communication. The paper-gap facts are checked by decide +kernel.

König/Birkhoff for ℕ-matrices (splitting into k parts, transportation) is shared code in CSLib, Cslib/Foundations/Combinatorics/Matrix/Birkhoff.lean. Remaining CSLib candidates (marked in the files): Assign.lean, Buckets.lean (ranks, samples, Lemma 4.3). Knowledge.lean, Simulation.lean and Compose.lean are specific to the congested-clique model.
