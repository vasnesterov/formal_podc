import Mathlib /-! # Chained HotStuff (Algorithm 3 of HotStuff, PODC 2019): model An asynchronous, interleaving model of the replica code of Algorithm 3 ("Chained HotStuff") of Yin, Malkhi, Reiter, Gueta, Abraham, *HotStuff: BFT Consensus with Linearity and Responsiveness* (PODC 2019, arXiv 1803.05069v6). * Replicas `P` (`n = Fintype.card P`), resilience parameter `f`, Byzantine set `F`. * Nodes form a tree; a node carries its parent, a command and its justify QC `(jv, jn)`. The genesis node `gen` carries the hard-coded QC `(0, gen)`. * Ideal threshold signatures: a QC `(v, x)` is valid iff it is the genesis QC or at least `n - f` replicas "signed" it, where every Byzantine replica signs everything (an over-approximation of the Byzantine behaviour) and a correct replica signs exactly the votes it cast. * The leader of a view may be Byzantine, so a replica may receive *any* proposal; the pacemaker (`nextView`) is arbitrary. The leader code of Algorithm 3 is therefore not modelled: everything a (possibly Byzantine) leader can do is covered. * Three variants of the replica code (`Variant`): the pseudocode as written (`literal`), with a monotone lock update (`monoLock`, as in Algorithm 4), and with a height check `b*.height = curView` (`heightCheck`), which the paper assumes ("view-numbers are equated with node heights") but never checks. -/ namespace HotStuff.Chained /-- Nodes of the tree. `mk parent cmd jv jn` is a node with parent `parent`, command `cmd` and justify QC `(jv, jn)`. -/ inductive Node (C : Type) where | gen : Node C | mk (parent : Node C) (cmd : C) (jv : ℕ) (jn : Node C) : Node C deriving DecidableEq namespace Node variable {C : Type} /-- The parent of a node (`none` for genesis). -/ def parent?
