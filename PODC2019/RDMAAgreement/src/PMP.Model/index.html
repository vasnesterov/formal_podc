This file is an asynchronous, interleaving model of Algorithm 7 (safety part only). ## Model * `P` processes, `p1 : P` the initial leader; `M` memories (finite); `V` values; `inp : P → V` the inputs. * Memory `i` holds one register `slot[i,p]` per process `p`, a triple `(minProp, accProp, value)` (`Slot`, with `accProp` and `value` merged into `acc : Option (ℕ × V)`; `minProp = 0` and `acc = none` encode `⊥`). Each memory has one region with exactly one writer, initially `p1` (`State.perm`). `getPermission(i)` gives the caller exclusive write permission (always legal). A write by a process without permission returns `nak` and has no effect. * **Asynchrony.** Each process has one thread per memory (the parallel-for of lines 18–37). A memory operation (`Op`: getPermission, write, read-all-slots) is *invoked* by a thread, *takes effect* atomically at the memory later (`eff*` steps) and its *response is delivered* later still (`dlv*` steps). A process has at most one outstanding operation per memory (`Proc.link`). When an attempt ends (abort or decision) its threads are killed (`pc := off`), but an operation already invoked still takes effect later ("zombie"), and the next attempt's thread on that memory can only invoke after the zombie's response has been discarded (`discard`). * Process and memory crashes are irrelevant for safety (a crashed agent is simply never scheduled). The failure detector `Ω` is arbitrary for safety: any process whose loop is not running may start a new attempt at any time (`start*`), including after it has decided (the loop of Algorithm 7 is `repeat forever`). * **Ballots** (`propNr`) are positive naturals (`0` encodes `⊥`). The paper only says "propNr = a higher value than any proposal number seen before"; we use the standard Paxos convention: every attempt uses a *fresh* ballot (never used before by anybody, `State.used`) larger than the process's previous ballot; `p1`'s first attempt (which skips phase 1, line 19) uses ballot `1`, all other attempts use ballots `≥ 2`. (E.g. `(round, id)` pairs.) * **Lines 24–26** are ambiguous in the pseudocode; we use the semantics fixed by the proof of Theorem D.2 and by Algorithm 12 (p. 17): the thread aborts if *any* slot read has `minProp > propNr`; otherwise it considers the slot with the highest `accProp` among the slots that hold a value (ties cannot occur, but we allow any maximal one). * Atomicity: local computation is merged into the adjacent memory step: a response delivery also performs the local code up to the next memory operation (and invokes it); lines 24–33 (including the `atomic` block and line 6 of `startPhase2`) are one step; passing the barrier (line 8) and invoking the line-35 write are one step; the line-35 `ack` that completes a majority also performs the decision (lines 37–39). * **Line 21** is a parameter (`Variant`): `literal` writes `(propNr, ⊥, ⊥)` as in the paper; `repaired` writes `(propNr, a, w)` where `(a, w)` is the last phase-2 pair the process issued (`Proc.lastIss`), keeping its own accepted value as in Disk Paxos. * Ghost state: `used` (ballots used), `p2val b` (value with which the attempt of ballot `b` entered phase 2), `votes` (successful line-35 writes),
