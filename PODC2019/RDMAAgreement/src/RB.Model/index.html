import Mathlib.Data.Fintype.Card import Mathlib.Data.Finset.Image import Mathlib.Data.Set.Insert /-! # Algorithm 2 (Reliable Broadcast) of "The Impact of RDMA on Agreement" — the model Aguilera, Ben-David, Guerraoui, Marathe, Zablotchi, PODC 2019 (arXiv:1905.12143v2), §4.1.1 and Appendix A. This file fixes the model; `Safety.lean` and `Liveness.lean` prove the four properties of Definition 1 (Lemma 4.1). ## Model * **Processes** `P` (a `Fintype`, `n = |P|`), Byzantine set `F : Finset P`; the thresholds of the algorithm ("majority") are `f + 1`. The resilience hypotheses `|F| ≤ f`, `2f + 1 ≤ n` are assumptions of the theorems, not of the model. * **Asynchronous shared memory** of SWMR registers `Value[p,k,q]`, `L1Proof[p,k,q]`, `L2Proof[p,k,q]` (`Reg`), all holding a `Val` (`⊥`, a signed copy, an L1 proof or an L2 proof; a value of the wrong shape is ignored by every reader, exactly like an ill-formed bit string). * **Regular registers.** A read or write by a correct process has an invocation and a response. A pending read of `r` keeps a *candidate set* (`St.cand`): at invocation it is the current value of `r` together with the values of all pending writes to `r`; every write to `r` invoked while the read is pending is added; at the response the adversary returns *any* candidate. This is exactly Lamport's regular register ("the last value written before the read started, or the value of a write overlapping the read"); it also covers two overlapping writes of the same owner to the same register, which happens in Algorithm 2 (see `differencies`). A write updates the current value at its response. * **Granularity.** Each step of a correct thread completes its pending memory operation, performs local computation, and invokes the next operation of that thread. (Invoking the next operation as early as possible only enlarges candidate sets, so it is no restriction on the adversary.) * **Correct processes** run Algorithm 2: one *broadcast thread* (`broadcast(k,m)` with consecutive keys `k = 1, 2, …`, the next one only after the previous returned) and, for every sender `q`, one *delivery thread* `(p,q)` looping `try_deliver(q)`. The loops `for i ∈ Π` read the slots one by one in an arbitrary (adversarial) order. * **Byzantine processes** (`p ∈ F`) write anything, at any time, any number of times, but only to their own registers (atomically). Their written values must respect unforgeability. * **Signatures** are unforgeable and transferable, modelled abstractly: a term is a structured value whose signatures are listed by `Val.sigs`; the ghost set `St.signed` contains the signatures correct processes actually produced. A Byzantine write must not contain a signature of a correct process outside `St.signed` (`SigOK`); Byzantine processes may sign anything. A process's signature on its own broadcast `(k,m)` also serves as its endorsement (counter- signature) of that copy, so that `Value[p,k,p]` holds a valid echo of `p` after line 12 as well as after line 40. * **Fairness** (for liveness only, `Exec.Fair`): every delivery thread of a correct process takes infinitely many steps and every pending broadcast write of a correct process completes. ## Charitable reading of the pseudocode (see `notes.md` / `differencies.md`) * `try_deliver(q)` works on key `k = last[q] + 1` (the paper uses `k = last[q]` with `last[q] = 0` initially and first key `1`, so nothing would ever be delivered); * `state` is per sender; line 30 delivers the message of the proof found at line 16; * line 38 accepts a value carrying `q`'s signature on `(k, m)`; line 40 writes `p`'s endorsement of that signed pair; line 47 accepts from slot `i` an endorsement by `i` of a pair signed by `q` with key `k`; * "majority" means `f + 1`; an L1 proof is valid for `(q,k,m)` if it has `≥ f+1` endorsements of `q`'s signed `(k,m)` (distinct, hence by distinct endorsers), an L2 proof if it has valid L1 proofs for one `(q,k,m)` by `≥ f+1` distinct authors; at line 62 the process signs any such subset of the L1 proofs it collected. -/ namespace Podc.RDMAAgreement.RB /-!
