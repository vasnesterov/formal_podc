import Papers.PODC2019.ConcurrentSketches.Objects /-! # Fast Concurrent Data Sketches (PODC 2019): the algorithm `ParSketch` The unoptimised generic concurrent algorithm `ParSketch` (Algorithm 2 of the PODC version without the gray lines; left column of Algorithm 3 of the full version): ``` variables: composable sketch globalS (init empty); constant b; for each update thread t_i: sketch localS_i (init empty), counter_i (init 0), hint_i (init 1), atomic prop_i (init 1) propagator (t₀): while true: for all t_i with prop_i = 0: globalS.merge(localS_i); localS_i ← empty sketch; prop_i ← globalS.calcHint() query(arg): localCopy ← globalS.snapshot(); return localCopy.query(arg) update_i(a): if ¬shouldAdd(hint_i, a) then return counter_i ← counter_i + 1; localS_i.update(a) if counter_i = b then prop_i ← 0; wait until prop_i ≠ 0; hint_i ← prop_i; counter_i ← 0 ``` Modelling choices (see `differencies.md`): * the paper's initial value `1` of `hint_i` and `prop_i` is a parameter `hint₀ : S.Hint`; * the propagator scans the threads round-robin (`pCheck j` reads `prop_j`; "for all `t_i` with `prop_i = 0`"); it is started by the (never-returning) operation `propagate`; * `globalS.merge(localS_i)` is split into reading `localS_i` and merging the value read into `globalS` (only `t₀` accesses `localS_i` at that time); * `hint_i ← prop_i` uses the value read by the last iteration of the wait loop; * `shouldAdd(hint_i, a)` (a local computation) is evaluated when `update_i(a)` is invoked. -/ namespace Podc.ConcurrentSketches open Cslib.SharedMemory variable (S :
