import Papers.PODC2019.ConcurrentSketches.Relaxation import Podc.Computability.Distributed.SharedMemory.HistorySpecLin /-! # Fast Concurrent Data Sketches (PODC 2019): sequential and composable sketches Sections 3–5.1 of the paper. * `Sketch`: a *derandomised* sequential sketch (Section 4: the coin flips are fixed by an oracle, so the sketch is a deterministic object): a state, `init`, `update`, `query`. `Sketch.run A` is the state after ingesting the stream `A` from `init`; a state *summarises* `A` iff it is `run A` (the paper: "a state summarizes two different streams iff that state is reached after ingesting each of them to an empty sketch"). * `Composable` (Section 5.1): a sketch with `merge`, `snapshot` and the pre-filtering API `calcHint`/`shouldAdd`, with the paper's semantic requirements as fields: - `merge_run`: if `S` summarises `A` and `S'` summarises `A'`, then `merge S S'` summarises `A ‖ A'`; - `snapQuery_snapshot`: a snapshot answers every query like the sketch it was taken from; - `shouldAdd_spec`: if `S` summarises `A` and `shouldAdd(S.calcHint(), a)` is false, then for all streams `B₁, B₂`, `A ‖ B₁ ‖ a ‖ B₂` and `A ‖ B₁ ‖ B₂` are summarised by the same state. The paper's requirement `calcHint() ≠ 0` is built into the algorithms' encoding of `prop` (`Option Hint`, `none` = 0). * `seqObj S`: the sketch as a CSLib `ObjSpec` (operations `update a`, `query arg`, and the never-returning `propagate` operation that starts the background propagator thread of the concurrent algorithms; it is a no-op in the sequential specification). * `SeqSketch S`: the sequential histories of the derandomised sketch (legal histories of `seqObj S`, stated directly); `SeqSketchR r S` (Definition 2): histories that have an `r`-relaxation in `SeqSketch S`. * `Safe h F`: the hint `h` is safe for the stream `F` (it was computed from a prefix of `F`), so filtering out `a` with `shouldAdd h a = false` does not change `run F`. -/ namespace Podc.ConcurrentSketches open
