import Mathlib /-! # Porting non-mutating optimizations (Section 4 of [paper]) Protocols are TLA+-style specifications: an initial predicate and a family of subactions (`Spec`). `B` refines `A` under a state mapping `f` (Section 4.1) if initial states map to initial states and every subaction `b_j` of `B` implies a subaction `a_{imp j}` of `A` on the mapped states, or a stuttering step (`imp j = none`). A *non-mutating optimization* `A∆` of `A` (Section 4.2) adds new variables `σD`, conjoins extra clauses `guard i` to the subactions of `A` (an unchanged subaction has `guard i = True`), and adds new subactions that do not change the variables of `A`. The porting recipe of Section 4.3 builds `B∆` from `B` and `A∆` (`port`): case 1, an added subaction of `A∆` with the variables of `A` replaced by `f` of those of `B` (and `B` unchanged); cases 2–3, every subaction `b_j` conjoined with the clauses added to the subaction it implies (evaluated at `f` of the states of `B`); a stuttering `b_j` keeps the new variables. `port_refines_opt` and `port_refines_base` are the two refinements claimed in Section 4.3 ("`B∆` refines `A∆`", "`B∆` refines `B`"); `Refines.reachable` transfers invariants along a refinement. The paper's argument, and these theorems, need *single-step* refinement (`b_j ⇒ a_i`). The refinement of Raft* into MultiPaxos is not single-step (Appendix C: one `AppendEntries` is several `Phase2a`/`Phase2b` steps). For multi-step refinements, conjoining the added clauses evaluated at the end points is unsound: `naive_multistep_port_unsound` is a two-line counterexample. -/ namespace ### Multi-step refinements In a multi-step refinement a `B` step implies a *sequence* of `A` steps. Conjoining the clauses added to those `A` subactions, evaluated at the end points of the `B` step, is not sound. `A`: a counter `x` with one subaction `x' = x + 1`; `B`: a counter with one subaction `x' = x + 2` (one `B` step = two `A` steps). `A∆` adds `d' = d + 1`, so `A∆` keeps `d = x`. The naive port `x' = x + 2 ∧ d' = d + 1` reaches `x = 2, d = 1`. -/ /-- The counter `A`. -/ def cntA : Spec ℕ Unit := ⟨fun x => x = 0, fun _ x y => y = x + 1⟩ /-- The optimization: a second counter `d` incremented with `x`. -/ def cntOpt : Opt cntA ℕ Empty where initD _ d := d = 0 guard _ x y := y.2 = x.2 + 1 added k := k.elim added_nonmut k := k.elim /-- The naive port to the double-step counter `B` (clauses evaluated at the end points). -/ def naivePort : Spec (ℕ × ℕ) Unit := ⟨fun x => x.1 = 0 ∧ x.2 = 0, fun _ x y => y.1 = x.1 + 2 ∧ y.2 = x.2 + 1⟩ theorem cntOpt_inv {x : ℕ × ℕ} (hx : cntOpt.spec.Reachable x) : x.2 = x.1 := by obtain ⟨x₀, ⟨h1, h2⟩, hp⟩ := hx induction hp with | refl => simp only [cntA, cntOpt] at h1 h2; omega | tail _ hst ih => obtain ⟨i, hi⟩ := hst rcases i with i | k · obtain ⟨ha, hg⟩ := hi simp only [cntA] at ha simp only [cntOpt] at hg omega · exact k.elim /-- The naive multi-step port violates the invariant `d = x` of `A∆`. -/ theorem naive_multistep_port_unsound : ∃ x, naivePort.Reachable x ∧ ¬ cntOpt.spec.Reachable x := by refine ⟨(2, 1), ⟨(0, 0), ⟨rfl, rfl⟩, ReflTransGen.single ⟨(), rfl, rfl⟩⟩, fun h => ?_⟩ have := cntOpt_inv h simp at this end Podc.PaxosRaftRefinement.Porting
