import Papers.PODC2019.PaxosRaftRefinement.Paxos /-! # Raft* (Figure 2 of [paper]), as an interleaving transition system Same network and failure model as `Paxos.lean`: asynchronous message passing, every message ever sent stays in a set (loss, duplication, reordering), crash-stop servers (a crashed server takes no further steps), any intersecting quorum system. A log is a list of entries `(term, value)`; index `i` of the paper is position `i` of the list (`lastIndex = length - 1`, `commitIndex = commit - 1`: we store the *number* of committed entries). The `bal` field of Figure 2 is not modelled: the refinement mapping of Appendix C uses the term of the last log entry as the accepted ballot of every entry (see `Refinement.lean`). The model is parametrised by `Rules`: * `voteOK L n t` — when a server with log `L` grants a `requestVote` of a candidate whose log has length `n` and last term `t` (Figure 2, lines 9–11). `Rules.fig2` is the rule as printed, which compares the voter's entry *at the candidate's last index* with the candidate's last term; `Rules.lastTerm` compares the voter's *last* term (as the TLA+ spec B.2 and Raft do); * `heartbeat` — whether `AppendEntries` may carry no new value (Figure 2 does not exclude `vals = []`; the TLA+ spec always appends exactly one value). Repairs of Figure 2 that are built in (see `differencies.md`): `RequestVote` resets `isLeader` and casts the candidate's own (implicit) vote, which carries its whole log; `BecomeLeader` needs that own vote among a quorum of votes and is guarded by `¬ isLeader` (as in the TLA+ spec); votes carry the voter's whole log (Appendix C, step 2.2/3.5: "we can still assume Raft* includes the full log"); an `append` message carries the leader's whole log `full` together with `prevLen` and the receiver only uses `prevLen`, the term at `prevLen - 1` (`pTerm`) and the entries after `prevLen` (`ents`), as in Figure 2. Two ghost (history) variables, `props` and `acks`, record the Paxos `accept`/`acceptOK` messages implied by Raft* steps (as `proposedValues` and `votes` in the TLA+ spec B.2); they do not influence
