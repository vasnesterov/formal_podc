VABA: Asymptotically Optimal Validated Asynchronous Byzantine Agreement — PODC 2019

Ittai Abraham, Dahlia Malkhi, Alexander Spiegelman. Asymptotically Optimal Validated Asynchronous Byzantine Agreement. PODC 2019. DOI 10.1145/3293611.3331612. Formalized version: arXiv 1811.01332 v1, the only arXiv version. Numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: ⚠️ Weakened. Agreement, validity and expected constant views are proved for all n > 3f, once the hard-coded 2f + 1 thresholds become n − f and two pseudocode bugs get local fixes. But the protocol never halts, so the total message bound behind the O(n²) claim fails as printed and no halting rule is proved, and Quality has no proof in the paper at all. The O(n²) word count itself was not checked.

Mistakes in the paper

❌ Definition 4 (Quality)

Definition 4 requires Quality, that a value proposed by an honest party is chosen with probability at least 1/2, but the paper never proves it.

Impact. The word occurs only in Section 2.2, and Appendix A proves only agreement, validity, termination and efficiency. Nothing we proved says anything about Quality, which is not formalized; we neither prove nor refute it.

⚠️ Lemma 20 and Definition 4 (termination proved vacuously; Efficiency fails as stated)

Algorithm 6 loops forever, because deciding does not stop a party, so termination holds only vacuously and honest parties send infinitely many messages, which violates Efficiency (Definition 4).

Impact. A halting rule is missing, and no halting rule or total message bound is proved. What survives is the content up to the decisions: every view completes (Lemma 19) and each view decides with probability ≥ 2/3, so an honest party is undecided after k views with probability at most (f/n)^k and the expected number of views is < 3/2 (view_progress, card_undecided_le, vaba_undecided_prob, vaba_expected_views).

Details

  • The proof of Lemma 20 says that honest parties never stop sending messages, "therefore, termination trivially follows". That uses the vacuity of "all messages have been delivered".

  • Lemma 24 only bounds the messages sent before everybody decides.

  • A party cannot just halt after deciding: others may only be locked and still need its messages.

🔧 Lemmas 3 and 13 (PB-provability, Agreement): 2f + 1 thresholds for f < n/3

The protocol hard-codes 2f + 1 thresholds although the paper allows any f < n/3, and with n = 5, f = 1 a corrupted leader makes honest parties decide true and false (Counterexample.agreement_fails).

Impact. Lemmas 3 and 13 are false for the algorithms as written whenever n > 3f + 1; the protocol is correct for n = 3f + 1. Theorem 1 itself, an existence claim, survives: with threshold n − f, all our results hold for every n > 3f.

Details

  • Signatures, skip shares and view-change waits all use 2f + 1. The paper never restricts to n = 3f + 1 (§2, §3 and Theorem 1 say f < n/3).

  • Lemma 3 (PB-provability) concludes that two sets of 2f + 1 signers share an honest party. That needs n = 3f + 1. Lemma 8 says "2f + 1 = n − f".

  • Take n = 5, f = 1. The corrupted party 4 is elected leader of view 1 and equivocates in every stage of its broadcast: 0 and 1 deliver true, 2 and 3 deliver false, and 4 signs both. The broadcasts of 0 and 1 complete normally, so the skip certificate forms, and honest parties 0 and 2 decide true and false.

  • This is a 58-step run of our model (Counterexample.agreement_fails).

Repair

Threshold n − f; everything (agreement, validity, view completion, expected views < 3/2) is proved for all n > 3f.

🔧 Algorithm 6, line 4 (key check: j ≠ 1 must be j ≠ 0)

Read literally, every honest proposal of view 1 fails validation, so view 1 never completes, and keys of view 1 would be accepted unchecked.

Impact. One condition changes; with the fix, honest proposals pass validation (proposal_valid).

Details

  • Here j is the key's view, and the initial key is ⟨0, ⊥⟩.

  • The proof of Lemma 15 reads j as the current view ("no key required in view 1"). That reading fails in view 2 whenever nobody got a key in view 1.

Repair

We use: the key view is 0, or it carries a stage-1 certificate of that view's leader, and in both cases it is ≥ LOCK.

🔧 Algorithm 7 (view-change messages that arrive early)

Algorithm 7 validates a view-change message against L[j], which is ⊥ until the receiver's own elect returns, so read literally, early messages lose their content but still count among the 2f + 1.

Impact. Lemmas 8, 9 and 14 assume that the content is processed, so Lemma 8 needs these messages buffered.

Repair

One guard: a view-change message is processed only once L[j] is known (recvVC in Model.lean), which buffers it. Agreement is proved for this algorithm (vaba_agreement).

✏️ Slips

  • Lemma 6 is stated for stages 2–4 but used for stage 1 in Lemma 12; the proof works for all stages (Inv.qc_agree).

Typos

  • Algorithm 3 has return σ for σ_in.

  • Algorithm 7 has lock and key.round for LOCK and KEY.view, and forwards unvalidated skip messages.

  • Lemma 21 has "2f = 1".

  • The proof of Lemma 3 has σ'_1 for σ'_j.

Lemma 14 is stated only for a lock set in view j, but locks can be set later and Lemma 15 needs the general form.

Impact. The general form is true: the same quorum argument proves it (Inv.key_of_lockQC).

The formalizationmodel, Lean names of the results, trust

Model (Model.lean):

  • Protocol and parties.

    • Algorithms 1–7 form an interleaving transition system on n = |P| parties.

    • The 4-stage provable broadcasts are inlined: an honest party delivers stage s of proposer k iff the message passes ex-sbc/ex-bc-validation and the sender could have sent it. An honest proposer sends only its proposal.

  • Asynchrony. The adversary schedules every enabled action in any order.

  • Adversary. It corrupts up to f parties adaptively. A corrupted party's local state is frozen, and it signs anything.

  • Threshold signatures are ideal: a certificate exists iff Q shares exist (QC is the shared Cslib.Byzantine.Certified, Cslib/Computability/Distributed/Byzantine/Certificate.lean). The paper's threshold is 2f + 1; theorems take n + f < 2Q for safety and Q + f ≤ n for liveness, i.e. Q = n − f for any n > 3f.

  • Common coin. It is ideal: a sequence of leaders, view j's revealed at the first honest elect(j).

  • View-change messages.

    • They are buffered until the receiver knows the leader.

    • A corrupted sender can include any existing certificates.

  • Probabilistic statements.

    • The adversary is a deterministic strategy on the full history of global states, which contain only revealed coins. That the adversary's "good set" of view j depends only on the coins of earlier views is proved (good_congr).

    • Probabilities are counts over uniform leader sequences, in the shared coin game Cslib/Probability/CoinGame.lean (also used for DAG-Rider).

  • All cryptographic "except with negligible probability" qualifiers disappear with ideal functionalities.

Not formalized.

  • Word/message complexity (O(n²) per view).

  • The cryptographic implementations and the negligible-probability accounting (Definition 3, Lemma 1).

  • Quality.

  • The Ω(n²) lower bound of Appendix B, which reduces to a cited theorem.

  • Liveness for all fair schedules; we prove that honest steps can always complete the view.

  • Whether the literal reading of Algorithm 7 (early view-change messages lose their content) breaks agreement: we did not check it.

Trust.

  • No sorry. The listed theorems use only the axioms propext, Classical.choice and Quot.sound.

  • Non-vacuity:

    • view_progress shows that views always can complete, so the probability bounds are not vacuous.

    • The counterexample run shows that the model's guards are satisfiable all the way to decisions.

  • The model is paper-local; quorum intersection and certificates come from the shared Cslib/Foundations/Data/Finset/Quorum.lean and Cslib/Computability/Distributed/Byzantine/Certificate.lean. The safety invariants (Inv, KInv, LInv) are proved action by action for every reachable state.
