Main results, for an algorithm correct on the restricted executions (`Restr.RCorrect`): * `Restr.agree'`: in a restricted execution all outputs are equal (also outputs of the same process): `b` never crashes and eventually outputs, so it must agree with everybody; * `Restr.biv_init`: the initial state with inputs `a ↦ 0`, `b ↦ 1` is bivalent; * `Restr.exists_crit`: there is a reachable bivalent schedule `σ` all of whose one-move extensions are univalent ("critical state") — the construction terminates because restricted executions have finitely many crashes; * `Restr.crit_values`: at a critical `σ`, `σ a` and `σ b` are univalent with different values; * `Restr.contra_a`, `Restr.contra_b`: two univalent schedules with different values cannot end in states that `a` (resp. `b`) cannot
