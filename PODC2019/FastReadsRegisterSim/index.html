How Fast Reads Affect Multi-Valued Register Simulations — PODC 2019

Soma Chaudhuri, Reginald Frank, Jennifer L. Welch. Brief Announcement: How Fast Reads Affect Multi-Valued Register Simulations. PODC 2019. DOI 10.1145/3293611.3331580. Formalized version: the 3-page brief announcement (author copy from NSF-PAR, retrieved via web.archive; no arXiv or full version), whose proofs are condensed; numbering follows it. The gaps in Section 3 below are of the kind expected from such compression; the Lemma 4.2 gap is not (its one-line justification is false). Copy of the paper: paper.pdf.

Verdict: 🛠️ Hard fix. All results hold: Theorem 3.1 (log₂ k reads are needed), Theorem 3.2 and Corollary 3.5 (a safe/regular simulation whose reads take log₂ k reads needs writes of log₂ k base writes), Lemmas 3.3/3.4, and Theorem 4.1 (no atomic simulation with two readers has reads of log₂ k steps; k > 2). The proof of Lemma 4.2, on which the paper's proof of Theorem 4.1 rests, has a genuine gap: it relies on a claim about decision trees that is false. We found no derivation of the lemma and prove Theorem 4.1 by a new case split.

Proof gaps in true statements (4)Lemma 4.2 · Theorem 4.1, Case 1 · Lemma 3.3 · Theorem 3.2

🛠️ Lemma 4.2 (same root of T₁ and T₂), used by Theorem 4.1

The proof's key step "a value z whose root-to-leaf path in T₂ does not include r₁ must exist since r₁ is not the root of T₂" is false for decision trees (lemma_4_2_gap).

Impact. Lemma 4.2 and Theorem 4.1 are true; we repair the proof of Theorem 4.1 with a case split (theorem_4_1, setting_false).

Details

The proof picks "a value z whose root-to-leaf path in T₂ does not include r₁. Such a value must exist since r₁ is not the root of T₂." This does not follow. In a complete decision tree of depth 2 whose root reads register 1 and whose two children both read register 0, every root-to-leaf path reads register 0, which is not the root (lemma_4_2_gap). The argument after this step is correct; it shows only "if some path of T₂ avoids the root ρ of T₁, contradiction" (lemma_4_2_core).

Lemma 4.2 itself is not false: like every step of a proof by contradiction, it is stated under the assumption that the simulation A exists, which Theorem 4.1 refutes, so once Theorem 4.1 is proved it holds trivially (lemma_4_2). This is not a defect of the reductio; the point is that the paper gives no valid derivation of it, and we found none from the facts available at that point. The gap example is about the inference inside the proof (abstract decision trees with the properties of Lemmas 3.3–3.4), not a counterexample to a stated lemma; it cannot be realized by a simulation satisfying the hypotheses, since none exists.

Repair

The main argument of Theorem 4.1 (writes W₀(a) W₁(z) W₂(b)) does not need "same root". It only needs that b's path in T₂ reads ρ (with value 0, while R₂ sees ρ = 1). So we split: if some path of T₂ avoids ρ, the Lemma 4.2 argument gives a contradiction (Sec4.caseA); otherwise every path of T₂ reads ρ, and the main argument goes through with ρ read at any depth instead of at the root (Sec4.caseB). (theorem_4_1, setting_false)

🔧 Theorem 4.1, Case 1 (main part of the proof)

The first write of 1 to x may lie inside W₁, and then the continuation of Case 1 (R₂ sees r = 1) is not justified.

Impact. Statement unaffected; the step is fixed in the formal proof (Sec4.caseB, Case 1a; theorem_4_1).

Details

  • (a) "The first write of 1 to x between the beginning of W₁ and the end of W₂" may lie inside W₁. Then R₁ returns b while only a and z have been written, which already violates regularity. We treat this as a separate case.

  • (b) A smaller point: in Case 2, "R₁ cannot return b, since R₁ read 0 in x" presumes that R₁ reads x. The correct argument: R₁ must return b by regularity, so it follows b's path, which reads x and needs x = 1; but x = 0 at that time.

  • The cases "first write of 1 to x before / after the first write of 0 to r" are exhaustive because one step writes one register.

🔧 Lemma 3.3 (depth of paths)

Lemma 3.3's proof bounds the depth of every path of T_i by the step bound, but the bound only constrains paths that occur in executions, and the code may do anything on other branches.

Impact. Statement unaffected (lemma_3_3, SeqReads.complete, complete_of_prefixFree).

Repair

Count the k paths realized by the executions σ_v: they form a prefix-free family of binary strings of length ≤ log₂ k, hence are exactly all strings of length log₂ k.

🔧 Theorem 3.2 (last step of the proof)

Theorem 3.2 counts only reads of the simulated read, so the read may also write, and the last step ("WP writes 1 to each of the log₂ k registers read") forgets that the reader might have written such a register itself.

Impact. Statement unaffected, with a stronger form of Lemma 3.4 (theorem_3_2, lemma_3_4, SeqReads.fresh).

Repair

The reader cannot have written it: the argument of Lemma 3.4 shows that every read accesses a register for the first time, so it returns the value left by the write. We prove this stronger form of Lemma 3.4.

The formalizationmodel, Lean names of the results, trust

Model.

  • CSLib's asynchronous shared-memory model (Cslib.SharedMemory.Impl). Processes are deterministic and there are no crashes. Executions are finite label lists (inv/tau/ret); a tau step is one access to one base object. Wait-freedom is CSLib's WaitFree; only its consequence obstruction-freedom is used.

  • A simulation I : Sim V v₀ ι P L implements a V-valued register with initial value v₀ from atomic binary registers indexed by an arbitrary type ι, with arbitrary initial contents. One writer w; the readers are any processes allowed to read.

  • Safe / regular / atomic (Sim.Safe, Sim.Regular, Sim.Atomic) must hold in every finite execution in which only w writes. Safe: a read overlapping no write returns the latest preceding write's value (or v₀). Regular: every read returns the value of an overlapping or the latest preceding write (or v₀). Atomic: linearizable (CSLib's IsLinearization). Atomic → Regular → Safe is proved.

  • Costs: Sim.accesses lists the base accesses of an execution. ReadReadsLE I r t / ReadStepsLE I r t: every read operation of r performs at most t base reads / steps. SomeWriteWritesGE I w t: some write operation performs at least t base writes. k = |V| = 2^m as in the paper.

  • The hypotheses are only needed for the readers named in the theorem (one reader in Section 3, two in Theorem 4.1) and only for their first reads, so the results are slightly stronger than the paper's.
