import Papers.PODC2019.StrongLinSnapshots.SnapSim import Cslib.Computability.Distributed.SharedMemory.Potential /-! # Algorithm 3: lock-freedom (Theorem 32, with atomic `S` and `R`) Section 4.4 of the paper argues lock-freedom through an amortized step bound. We give a direct proof by a natural-number potential that strictly decreases at every step that is not a response (`Impl.lockFree_of_potential`). Write `X` for the contents of `S` and `r` for the vector in `R`. The potential is the lexicographic combination (encoded in mixed radix) of 1. `U`: remaining steps of updates — `4` for every idle process (it may invoke an update), `3, 2, 1` before lines 43, 44, 45. Every invocation and every update step decreases `U`; scanner steps do not change it. Only update steps change `X`. 2. `Stale`: the number of scanners about to execute line 49 or 51 with a view `ℓ ≠ X`; each such scanner may write the stale `ℓ` to `R` once. A scanner reading `S` on line 48 gets `ℓ = X`, so scanner steps never increase `Stale`. 3. `Bad = [r ≠ X]`: with `X` fixed and no stale writes, `R` can only be written with `X`. 4. `W`: the number of scanners whose current iteration will execute `DWrite` on line 51 if `X` and `r` do not change (e.g. a scanner before line 47 iff `r ≠ X`). A `DWrite(X)` when `r = X` decreases `W` and changes neither `Stale` nor `Bad`. 5. `T`: steps until the current scan iteration ends, given the scanner's ABA flag (`3` before line 47; `2` or `5` before line 48, `1` or `4` before line 49, depending on the flag). Scanner steps that change neither `X`, `r` nor the flags of others decrease `T`; a failed iteration (flag set) restarts at `3 < 4`. `DWrite`s set all flags, increasing `T`, but each `DWrite` decreases `Stale`, `Bad` or `W`. The model has atomic base objects (see `README.md`), so this is lock-freedom of Algorithm 3 with `S` and `R` atomic, i.e. Theorem 32 in the case where `S` and `R` are atomic. -/ namespace
