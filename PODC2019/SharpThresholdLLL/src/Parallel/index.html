import Papers.PODC2019.SharpThresholdLLL.Process /-! # Parallel execution of the process (the combinatorial core of Corollaries 1.2 and 1.4) The distributed algorithms of Corollaries 1.2 and 1.4 run the sequential process in parallel. In each phase, several *groups* act at the same time. Each group fixes its own variables one after another (a sequential run from the common state at the start of the phase). The groups' *regions* (sets of events) are pairwise disjoint, and every variable of a group affects only events in the group's region. For Corollary 1.2, a group is a single variable (edge) of the current edge-colour class. For Corollary 1.4, a group is a node `v` of the current colour of a 2-hop colouring, with region `N[v]`. The paper's argument is: "Since Theorem 1.3 works for any order and due to the local nature of the fixing and bookkeeping ...". We make it precise. * `condProb_congr`: `Pr[E_t | ·]` depends only on the variables of `E_t`. * `Run.transport`: a run can be replayed from any state that agrees with its start state on what the run reads. * `phase_run`: the merged result of a parallel phase is reached by a sequential run, the concatenation of the groups' runs. Hence every execution of a valid schedule is an execution of the sequential process, and Theorem 1.3 applies (`schedule_correct`). * `corollary_1_2_core` and `corollary_1_4_core`: the phase schedules built from a conflict-free colouring of the variables (Corollary 1.2) or from a 2-hop colouring of the dependency graph (Corollary 1.4) can always be executed. Every execution fixes all variables and avoids all bad events, and the number of phases is the number of colours. The round complexity bounds (`O(d + log* n)` and `O(d² + log* n)`) also need the cited colouring algorithms ([PR01], [FHK16]) and a LOCAL implementation of each phase. These are not formalized. -/ open Finset set_option linter.unusedSectionVars false namespace SharpThresholdLLL variable {ι : Type} [Fintype ι] [DecidableEq ι] {α : ι → Type} [∀ i, Fintype (α i)] [∀ i, DecidableEq (α i)] {V : Type} [Fintype V] [DecidableEq V] @[ext] lemma State.ext' {s s' : State ι α V} (h1 : s.σ = s'.σ) (h2 : s.φ = s'.φ) : s = s' := by cases s;
