import Mathlib import Cslib.Computability.Distributed.SharedMemory.Spec /-! # The asset-transfer object type Guerraoui, Kuznetsov, Monti, Pavlovič, Seredinschi, *The Consensus Number of a Cryptocurrency*, PODC 2019 (DOI 10.1145/3293611.3331589; extended version arXiv 1906.05574), Section 2.2. The asset-transfer type associated with a set of accounts `Acct` and an owner map `μ : Acct → Finset Proc` (`Proc` = processes): * states: balances `q : Acct → ℕ`, initial state `q₀`; * `transfer(a, b, x)` invoked by `p` succeeds (response `true`) iff `p ∈ μ a` and `x ≤ q a`; then `x` is moved from `a` to `b`; otherwise the state is unchanged and the response is `false`; * `read(a)` returns `q a`. CSLib's sequential specifications (`ObjSpec`) do not see the caller, so the invoking process is an argument of `transfer` (`ATOp.transfer p a b x`); every use of the type requires processes to invoke transfers only under their own identity (`allowed` in the `Impl` model, `Honest` in the consensus model). **Self-transfers.** For `a = b` the paper's relation `Δ` requires `q'(a) = q(a) - x` and `q'(a) = q(a) + x`, which is unsatisfiable for `x > 0`, so `Δ` is not total (contradicting the paper's standing assumption). We use the sequential reading "debit `a`, then credit `b`": a successful self-transfer leaves the balances unchanged (`moveFunds`). -/ namespace CryptoCons open Cslib.SharedMemory /-- Operations of the asset-transfer type: `transfer p a b x` is `transfer(a, b, x)` invoked by process `p`; `read a` is `read(a)`. -/ inductive ATOp (Proc Acct : Type) where | transfer (p : Proc) (a b : Acct) (x : ℕ) | read (a : Acct) deriving DecidableEq /-- Balances after moving `x` from `a` to `b` (debit `a`, then credit `b`). -/ def moveFunds {Acct : Type} [DecidableEq Acct] (q : Acct → ℕ) (a b : Acct) (x : ℕ) : Acct → ℕ := fun c => q c - (if c = a then x else 0) + (if c = b then x else 0) /-- The asset-transfer object type with accounts `Acct`, owner map `μ` and initial balances `q₀`.
