Every process `p` owns component `p` of an atomic snapshot object `AS` and stores there the transfers it has performed successfully. `balance(a, S)` is the initial balance of `a` plus the incoming minus the outgoing amounts recorded in the snapshot `S`. * `transfer(a, b, x)` by `p`: `S := AS.snapshot()`; if `p ∉ μ(a)` or `balance(a, S) < x` return `false`; otherwise add `(a, b, x)` to `ops_p`, `AS.update(ops_p)`, return `true`; * `read(a)`: `S := AS.snapshot()`, return `balance(a, S)`. The paper's `ops_p` is a *set*. We define the implementation generically in the operation `add : ops → transfer → ops` that records a new transfer: * `impl` uses `add ops t = ops ++ [t]` (a sequence: repeated identical transfers are recorded repeatedly) — the **fixed** algorithm, which is linearizable (`Fig1.lean`); * `literalImpl` uses `add ops t = ops.insert t` (insert if absent, i.e. set union) — the algorithm **as written** in Figure 1, which is not linearizable (`Fig1Bug.lean`).
