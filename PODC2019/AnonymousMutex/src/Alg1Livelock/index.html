import Papers.PODC2019.AnonymousMutex.Alg1 import Mathlib.Tactic.FinCases import Mathlib.Tactic.IntervalCases /-! # Algorithm 1 is **not** deadlock-free: a livelock for `n = 4`, `m = 5` Theorem 2 of the paper claims that Algorithm 1 is deadlock-free for every `n` and every `m > 1` with `m ∈ M(n)`. This is false: for `n = 4` processes and `m = 5 ∈ M(4)` registers there is a fair infinite execution in which all four processes are in `lock()` forever, nobody is in the critical section and no operation ever completes. Processes `0,1,2,3` (identifiers = themselves); local → physical register maps `π 0 = [0,4,1,2,3]`, `π 1 = [1,2,3,0,4]`, `π 2 = [2,0,1,3,4]`, `π 3 = [3,0,1,2,4]`. From the configuration where all four are about to take a snapshot of the empty memory, the following 28 steps lead back to the same situation (memory written as physical registers `0..4`, `.` = `⊥`): ``` p0,p1,p2,p3 snapshot the empty memory; they will write 0,1,2,3 resp. p0 writes 0; p0 snapshot, writes 4 0 . . . 0 p1 writes 1; p1 snapshot, writes 2; snapshot, writes 3 0 1 1 1 0 (full) p0 snapshot: owns 2 < 5/2 → shrink; reads 0 (own) p2 writes 2 (stale write, based on its first snapshot) 0 1 2 1 0 p2 snapshot: owns 1 < 5/3 → shrink; reads 2 (own) p3 writes 3 (stale write) 0 1 2 3 0 p1 snapshot: owns 1 < 5/4 → shrink; p3 snapshot: owns 1 < 5/4 → shrink p0 erases 0; p2 erases 2; p0 reads 4, erases 4; p1 reads 1, erases 1; p3 reads 3, erases 3 . . . . . ``` The paper's proof (Claims 4–5) overlooks *stale* writes (a process writing into a register that was `⊥` in an old snapshot): Claim 4 only shows that at every time *some* competing process does not withdraw, which does not imply that one process never withdraws. The Lean proof below checks the two finite pieces of the execution by kernel evaluation (`decide +kernel`) and builds the infinite periodic execution with `Impl.exists_infExec_of_chain`. -/ set_option
