Composable CRN computation — PODC 2019

Eric E. Severson, David Haley, David Doty. Composable computation in discrete chemical reaction networks. PODC 2019. DOI 10.1145/3293611.3331615. Formalized version: arXiv 1903.02637 v2 (numbering follows it).

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: ✏️ Slip. The only mistake is a wrong formula in §1.2, and every checked statement holds as written: the 1D characterization (Theorem 3.1), the impossibility tool (Lemma 4.1) and max, the whole sufficiency direction of the main Theorem 5.2 (Lemmas 6.1, 6.2 with closure under composition), Observations 2.1, 5.3, 9.1 and the leaderless 1D characterization (Theorem 9.2). Two parts are cited or left unformalized and enter only as hypotheses: Lemma 2.7 (stably computable ⇒ semilinear, cited from [10]) and the necessity of the eventually-min condition (Theorem 7.1, the long geometric §7). So the main Theorem 5.2 is verified only in its "⇐" direction (plus conditions (i) and (iii) of "⇒"); its hardest part, the necessity of condition (ii), is not checked.

✏️ Slips

  • §1.2, second paragraph: "X1 + X2 → W (computing w = x1 + x2)" should say w = min(x1, x2). The same sentence has the intended version, and nothing else depends on it.

Model.

  • Discrete CRNs (Basic.lean): finite species type S, finite set of reactions (R, P), configurations S → ℕ, reachability = reflexive–transitive closure of reaction steps. No kinetics, no probabilities: stable computation is the paper's reachability definition (from every configuration reachable from I_x, a stable configuration with output f x is reachable).

  • A function-computing CRN has distinct input species X_i (i : ι, any finite index type; the paper's d is ι = Fin d), an output Y and a leader L (an Option: present in the main model, absent in §9). I_x has x i copies of X_i, one L, nothing else.

  • Output-oblivious: Y is never a reactant. ObliviouslyComputable f quantifies over all output-oblivious CRNs with a leader.

  • Semilinear function: the graph is a semilinear set in Mathlib's sense (finite union of linear sets), equivalent to the paper's Definitions 2.5/2.6.

  • Composition (Observation 2.2) uses a transfer reaction Y^{(k)} → X^{(g)}_k instead of renaming species; this delays the hand-over and changes nothing computed.

Leaderless.lean

The constructions of Theorem 3.1 and Lemma 6.1 are instances of one generic, once-proved leader-automaton CRN (obliviouslyComputable_of_automaton, Automaton.lean). It covers any function whose finite differences and next state are determined by a finite abstraction of the input consumed so far.

Proof remarks.

  • Lemma 4.1 assumes the sequence (aᵢ) is increasing; the proof never uses this, and we prove the lemma without it.

  • Observation 2.2 is stated for one upstream module; Lemma 6.2 needs the "more generally, g can take any number of inputs" remark (with fan-out of inputs and one leader per module). We prove that general form.

Not formalized. Lemma 2.7 (cited), Lemma 2.3, Observation 2.4, Theorem 5.4, §7 (Theorem 7.1) and §8 (scaling limits); the equivalent fairness/probability-1 semantics of footnote 2. We read the proofs of Lemma 2.3 and Observation 2.4, and they looked sound.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. Hypotheses are satisfiable: the gadgets, ⌊3x/2⌋ and Lemma 6.1 give concrete obliviously-computable functions, and max is a concrete semilinear nondecreasing function that is not. The CRN model is paper-local (CSLib candidate); it does not reuse CSLib's population-protocol framework, which has two-agent interactions and labelled agents. It overlaps with the vector Petri nets already in the project (Cslib.PetriNet in Podc/Computability/PetriNets/Rackoff.lean, the P → ℕ nets of Papers/PODC2022/PPLeadersStateComplexity/) and its Reach is a plain Relation.ReflTransGen rather than Cslib.TransitionSystem.Reach; these should be unified when upstreaming. Mathlib's IsSemilinearSet (Mathlib.ModelTheory.Arithmetic.Presburger.Semilinear) provides semilinear sets.

CSLib candidates. Basic.lean (CRN model and stable function computation), Automaton.lean (leader-automaton construction), Composition.lean (composition of output-oblivious CRNs).
