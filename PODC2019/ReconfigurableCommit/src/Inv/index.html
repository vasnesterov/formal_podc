The invariant contains the paper's Invariants 1–12 (Figures 3 and 5) in the following form: * Invariant 1 (follower arrays are a prefix with holes of the leader's): `loc_elog`, `loc_acked`; * Invariant 2 (accepted entries persist, with the same prefix): `inv2`, stated for every configured epoch `E` with respect to its *candidate* state (the base state if `E` started, otherwise the frozen state of its leader), and for all slots that may still be accepted (`AliveK`); * Invariant 3: `m_probeAck` and `loc_newEpoch`; * Invariant 5: `cfg_mem` (the probing record of every configuration), from which Invariant 5 is derived; * Invariants 4, 6, 9, 10, 11: `elog_dist`, `m_accept`, `m_prepareAck`, and their consequences; * Invariant 7: `elog_txn`; Invariant 12: `loc_dec`, `m_decision`; * : ℕ) : Prop := ∃ c, cfg st s e = some c ∧ ∃ q ∈ c.followers, e < (st.loc q).newEpoch ∧ ∀ k t d, ¬ Acked st q s e k t d /-- Slot `k` of epoch `e` may still become accepted: every follower has c, cfg st s e = some c → q ∉ c.members /-- The candidate state of a configured epoch `E` with configuration `c`: the base state if `E` started, otherwise the state of its leader (entries tagged with ((st.loc c.leader).epoch s) k else none /-- The payload of slot `j` of the log of epoch `o` (`ε` if empty). -/ def plAt (s : S) (o j : ℕ) : Pl := ((st.elog s o j).map (·.1.2.1)).getD Pa.σ.eps /--
