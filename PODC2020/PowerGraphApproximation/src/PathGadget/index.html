import Podc.Foundations.Combinatorics.SimpleGraph.Power import Mathlib /-! # Attaching path gadgets to a graph, and the square of the result This file contains the graph-theoretic core of Lemmas 21, 23 and 24 of Bar-Yehuda, Censor-Hillel, Maus, Pai, Pemmaraju, *Distributed Approximation on Power Graphs*, PODC 2020 (arXiv:2006.03746), in a form independent of the concrete lower-bound graphs. Given a "core" graph `core` on `V` (the edges that are kept, e.g. the clique edges), a set `E` of gadgets and an attachment relation `att e v` (the vertices to which the first vertex of gadget `e` is joined), `attach core att m` is the graph on `V ⊕ E × Fin m` in which * `inl u ~ inl v` iff `core.Adj u v`, * gadget `e` is a path `(e,0) – (e,1) – ⋯ – (e,m-1)`, * `(e,0) ~ inl v` iff `att e v`. For `m = 1` this is the weighted construction of Section 5.2 (the single vertex `p_e` of weight `0`), for `m = 3` the dangling/shared path gadgets of Section 5.3 (`DP_e[1], DP_e[2], DP_e[3]`). If `G` is a graph on `V` with `G.Adj u v ↔ u ≠ v ∧ (core-edge ∨ core-2-path ∨ common gadget)` (`IsSquareTrace`), then the square of `attach core att m` restricted to `V` is `G` (`attach_sq_inl_iff`), and: * `weighted_iff` (Lemma 21): the square has a vertex cover of weight `≤ W` (weight `1` on `V`, `0` on gadget vertices) iff `G` has a vertex cover of size `≤ W`; * `normalize` (Lemma 23, `m = 3`): every vertex cover of the square can be turned into one, not larger, that contains `(e,0), (e,1)` and not `(e,2)` for every gadget; * `unweighted_iff`, `vertexCoverNum_sq` (Lemma 24, `m = 3`): `τ(H²)
