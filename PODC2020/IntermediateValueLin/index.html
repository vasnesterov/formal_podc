Intermediate Value Linearizability — PODC 2020

Arik Rinberg, Idit Keidar. Brief Announcement: Intermediate Value Linearizability: A Quantitative Correctness Criterion. PODC 2020. DOI 10.1145/3382734.3405712. Formalized version: arXiv 2006.12889 v1 (full version). Numbering follows it.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. All results hold: locality of IVL, Theorem 1 (IVL preserves (ε, δ) error bounds), Lemma 1 (the concurrent CountMin sketch is IVL), Lemma 2 and Theorem 2 (an IVL batched counter with O(1) updates), Lemmas 3 and 4, the claim that PCM is not linearizable, and Theorem 3 (the Ω(n) bound for linearizable batched counters). Theorem 3 is proved conditionally: the cited Israeli–Shirazi lower bound for snapshots from SWMR registers is not formalized and enters as the hypothesis ISLowerBound. Only proofs needed changes, all of them local: the acyclicity step of the locality proof (Appendix A), the witness of Example 2, which is not well formed (one process has two operations pending at once), and the descriptions of H₁, H₂ in Lemmas 1 and 2.

Mistakes in the paper

✏️ Slips

  • Proof of Theorem 1 (p. 9): the first display should read ret(Q, τ_{A(c)}(H₁)) ≤ ret(Q, H(A′, σ, c)) ≤ ret(Q, τ_{A(c)}(H₂)), not A and H₁; "ret(Q, τ_{A(c)}(H₂)) ≤ v_max" should be τ_I(H₂); the last line should have ≤ v_max + ε, not ≥.

  • Definition of v_min/v_max: min{τ_I(L)} should be min{ret(Q, τ_I(L))}.

  • Proof of Invariant 1, case v = 0: "v′ᵢ = 1" should be v′ᵢ = 0.

  • Lemma 3: "the last update invocation" should be "the last updateᵢ invocation". The literal reading is also true but weaker.

Typos

  • Invariant 1 and Lemma 3 use H′ before it is defined (in Lemma 4's proof). The summation index i clashes with the process index i.

  • Lemma 1's proof starts "We next prove that i is IVL".

  • Appendix A: "H₂ of H 2" should be "of H?".

  • Example 2: the text says "P DC" where PCM is meant.

Proof gaps in true statements (4)Locality of IVL · Example 2 · Lemma 2 · Lemma 1

🔧 Locality of IVL (§3.2, Appendix A)

The proof asserts that the union of the per-object linearization orders and the real-time order is "a well defined partial order", but that union is not transitive and the acyclicity of its transitive closure is never argued.

Impact. The statement is true; our proof fills this step with CSLib's merge of per-object linearizations (HW.ivl_locality).

Details

The paper justifies the claim by the per-object orders respecting real time and being disjoint. The real work, as in Herlihy–Wing's locality proof, is showing that the transitive closure is acyclic, since cycles may alternate between objects and real-time edges.

Repair

Our proof uses CSLib's merge of per-object linearizations by explicit linearization points, which proves exactly this step.

🔧 Example 2 (the witness that PCM is not linearizable)

Example 2's execution is not well formed: process p invokes Q₁ = query(a) and Q₂ = query(b) while its own U = update(a) is still pending.

Impact. The claim that PCM is not linearizable (abstract, introduction, and the sentence before Example 2) is true; with a second process issuing the two queries the example works as claimed (Example2.pcm_not_linearizable, example2_not_lin).

Details

Well-formedness (Section 2.1) forbids a process to have two operations pending at once. We also reach the paper's initial matrix [[1,4],[2,3]] from the all-zero matrix of Algorithm 1 with the updates a, b, e, e, e. The responses force U before Q₁ and Q₂ before U, while Q₁ precedes Q₂ in real time.

🔧 Lemma 2 (the linearizations H₁, H₂)

The proof of Lemma 2 places reads "after all preceding operations and before concurrent ones" with ties broken arbitrarily, which is contradictory for two concurrent reads.

Impact. The statement is true; the intended orders work and the rest of the proof goes through as written (Alg2.alg2_sandwich).

Repair

Reads at their invocation and updates at their response, and the converse.

🔧 Lemma 1 (the count in H₁)

Lemma 1's proof describes c_{σ₁}(Q)[i] as "the value when the query starts", but the count in H₁ only lower-bounds the counter at the query's start, because pending updates may already have incremented it.

Impact. The statement is true; only the lower bound is used, and it still holds (pcm_sandwich).

The formalizationmodel, Lean names of the results, trust

Model.

  • CSLib's asynchronous shared memory with deterministic processes, atomic base objects and finite executions given as label lists. Correctness criteria are checked on every finite execution. Wait-freedom is CSLib's Impl.WaitFree, and step complexity counts the base-object accesses of each operation instance (Impl.StepsLE). There are no crashes; wait-freedom covers stopping processes.

  • We use the amended linearization of Sela–Herlihy–Petrank: real time also constrains pending operations that get linearized. This matches the paper's ≺_H, which is defined through inv(op₂). IVL (IsIVLFor S α) asks for two linearizations of the skeleton α? such that every completed operation's response lies between the responses the deterministic specification S gives it in them.

  • We compare all completed operations, not only queries. In every object of the paper, updates return a fixed dummy value.

  • Randomness: a randomized object is a family of deterministic specifications S : Ω → QSpec, with a probability measure on coin vectors. A concurrent randomized algorithm is given by its executions under each coin vector, and a schedule is identified with the common skeleton history, which is what uniform step complexity gives. The adversary is oblivious: the schedule is fixed independently of the coins, as in the paper. Events are measured with the outer measure, so no measurability assumptions are needed.

  • SWMR registers: base objects cannot see their caller in CSLib, so "single-writer" is a property of the code (Impl.SWMR owner). In Algorithm 2, process i keeps a local copy of v[i], so an update is a single write.

  • Theorem 3: the Israeli–Shirazi lower bound [21] for binary snapshots from SWMR registers is a hypothesis (ISLowerBound n b). The same bound b is derived for every wait-free linearizable batched counter from SWMR registers. The reduction inlines the counter implementation into Algorithm 3. It uses a variant without the line-4 shortcut (it adds 0 instead), which makes the simulation label-for-label exact and can only add steps. Lemma 4 itself is proved for the paper's Algorithm 3, with the shortcut, over an atomic counter.

Proof remarks. Applying the sequential Lemma 3 in Lemma 4's proof needs each process's operations to appear in program order in the linearization. This is true (each process's operations are ordered by real time) but not mentioned (alg3_linearizable).

Not formalized. The sequential error analysis of CountMin [7], and hence Corollary 1's concrete bound f_a^start ≤ f̂_a ≤ f_a^end + αn; it enters only as the hypothesis of pcm_concBounded. The Israeli–Shirazi lower bound itself. Infinite histories in the definition of v_min/v_max.

Trust. No sorry. The listed theorems use only the axioms propext, Classical.choice and Quot.sound. Non-vacuity: Algorithm 2 instantiates Definitions 2–4 and Theorem 1 with a trivial coin (Alg2.alg2_randIVL, Alg2.bc_seqBounded, Alg2.alg2_concBounded). Concrete executions are checked with CSLib's computable Impl.crun and decide (no native_decide).
