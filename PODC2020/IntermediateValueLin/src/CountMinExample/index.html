import Papers.PODC2020.IntermediateValueLin.CountMin import Mathlib.Tactic.FinCases /-! # Example 2 of Rinberg–Keidar: the concurrent CountMin sketch is not linearizable Rinberg, Keidar, *Intermediate Value Linearizability: A Quantitative Correctness Criterion*, PODC 2020, full version arXiv:2006.12889, Example 2 (Section 5). Elements `a`, `b`, `e`; `d = w = 2`; hash functions (0-based) `h₀(a) = h₁(a) = 0`, `h₀(b) = 1`, `h₁(b) = 0`, `h₀(e) = h₁(e) = 1` (the paper's `h₁(a) = h₂(a) = 1`, `h₁(b) = 2`, `h₂(b) = 1`; the paper does not need `e`). The paper starts from the matrix `[[1, 4], [2, 3]]`; we reach it from the all-zero matrix of Algorithm 1 by the sequential updates `a, b, e, e, e` of process `p`. Then (`σ` = `example2`): * `p` invokes `U = update(a)`, increments `c[0][0]` (to `2`) and stalls; * `q` runs `Q₁ = query(a)`, reading `c[0][0] = 2`, `c[1][0] = 2`, and returns `2`; * `q` runs `Q₂ = query(b)`, reading `c[0][1] = 4`, `c[1][0] = 2`, and returns `2`; * `p` increments `c[1][0]` (to `3`) and `U` returns. The paper lets the *same* process `p` invoke `U`, `Q₁` and `Q₂`; since `U` is still pending this is not a well-formed history, so we use a second process `q` for the queries. `example2_valid`: this is an execution of `pcm hEx`. `example2_not_lin`: it is not linearizable with respect to `cmSpec hEx`: `Q₁` returning `2` forces `U` before `Q₁`, `Q₂` returning `2` forces `Q₂` before `U`, while `Q₁` precedes `Q₂` in real time. -/ open Cslib.SharedMemory set_option linter.unusedSectionVars false namespace Podc.IntermediateValueLin /-! ### Counting updates -/ namespace CM section Counting variable
