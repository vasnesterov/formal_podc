import Cslib.Computability.Distributed.SharedMemory.HerlihyWing.Locality import Cslib.Computability.Distributed.SharedMemory.HerlihyWing.Bridge import Papers.PODC2020.IntermediateValueLin.Defs /-! # Locality of intermediate value linearizability (Section 3.2 and Appendix A of Rinberg–Keidar) Rinberg, Keidar, *Intermediate Value Linearizability: A Quantitative Correctness Criterion*, PODC 2020, full version arXiv:2006.12889. Claim (Section 3.2, proof in Appendix A): *a history `H` of a well-formed execution over a set of objects `X` is IVL iff for each object `x ∈ X`, `H|x` is IVL.* Locality is a statement about **multi-object** histories, so we work in CSLib's multi-object Herlihy–Wing history framework (`Cslib.SharedMemory.HerlihyWing`): a history is a list of events `inv p x o` / `res p x r`, operation instances are `OpId = (p, x, k)` (the `k`-th operation of `p` on `x`), and a linearization is a list of operation records `M` with `IsLinA spec H M` (the amended Herlihy–Wing definition of Sela–Herlihy–Petrank: real-time order is respected towards every linearized operation, including linearized pending ones). * `eraseH H` is the skeleton history `H?` (every response value replaced by `? = ()`). * A skeleton linearization of `H` is an `M` with `IsLinA (fun _ => Set.univ) (eraseH H) M`: every sequential skeleton history is legal. * `QSpec Op Res` (from `Defs.lean`): a deterministic sequential object (state, initial state, transition function); a multi-object specification is a family `S : X → QSpec Op Res`. * `tauHW S M a` is the paper's `ret(a, τ_H(M))`: the response of `a` when the operations of object `a.x` in `M` are run through `S a.x` from its initial state (objects are independent, so this is exactly the unique legal history of the multi-object specification with skeleton `M`). * `IVL S H` (Definition 1, for multi-object histories). * `ivl_locality`: the locality theorem. * `isIVLFor_iff_ivl_toHist`, `isIVL_iff_ivl_toHist`: for a single object, `IVL` agrees with the execution-level definition `IsIVLFor` / `IsIVL` of `Defs.lean` (via CSLib's `toHist`). ## Comparison with the paper * The paper's Definition 1 is stated for "a history `H` of an object"; locality needs it for multi-object histories, with the multi-object specification of Section 2.1 (`H|x ∈ H_x` for every `x`), whose `τ_H` acts on each object independently. `IVL` is that reading. * The paper compares only queries; updates return no value. Here every operation has a response and we compare all completed operations (for quantitative objects updates return a fixed dummy value both in histories and in specifications, so the comparison is trivial for them). * Definition of linearization (Section 2.1): "`H'` preserves the partial order `≺_H`", where `op₁ ≺_H op₂` iff `rsp(op₁)` precedes `inv(op₂)`. Since `≺_H` is defined via the invocation of `op₂` only, it relates a completed `op₁` to a pending `op₂` as well; we read it as the amended definition (`IsLinA`). Under the original Herlihy–Wing reading (`IsLinO`, `≺_H` only between completed operations) linearizability is not local (Sela–Herlihy–Petrank), and the same counterexample shape would apply to skeleton linearizations, so the reading matters. * Appendix A, "if" direction: the paper takes the union of the per-object orders `≺_{H_1^x}` and the real-time order of `H` and asserts that "this partial order is well defined" because the per-object orders respect real time and are disjoint. This is the non-trivial part of Herlihy–Wing locality: the union of these relations is not transitive and its transitive closure being acyclic needs an argument (cycles may alternate between objects and real-time edges). The formal proof uses CSLib's `mergedM` (operations ordered by explicit linearization points), which is a proof of exactly this step. Also "Let ... linearization `H_2` of `H 2`" is a typo for `H?`. * Appendix A, "only if" ("immediate"): the restriction of a skeleton linearization to `x` is a skeleton linearization of `H|x` (`IsLinA.restrictX`), and `τ` of an operation of `x` only depends on the operations of `x`. * We assume `H` well-formed (as the paper: histories of well-formed executions). -/ set_option
