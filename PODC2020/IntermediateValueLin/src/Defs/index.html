import Cslib.Computability.Distributed.SharedMemory.LinPoints import Cslib.Computability.Distributed.SharedMemory.Potential -- CSLib candidate: Cslib/Computability/Distributed/SharedMemory/ (IVL / skeleton linearizations) /-! # Intermediate value linearizability (Definition 1 of Rinberg–Keidar) Rinberg, Keidar, *Intermediate Value Linearizability: A Quantitative Correctness Criterion*, PODC 2020 (brief announcement), full version arXiv:2006.12889, Section 3. We work in CSLib's asynchronous shared-memory model (`Cslib.SharedMemory`): a history is a list of labels `List (Label P A)` (invocations `inv p o`, responses `ret p r`, internal steps `tau p`), operation instances are `OpId P = P × ℕ` (`(p, k)` = the `k`-th operation of `p`), and a linearization of `α` is a list `L : List (OpId P × A.Op)` (`IsLinearization α L`, the amended Herlihy–Wing definition of Sela–Herlihy–Petrank). * `skelSpec A` (`= skelOf A.Op`): the object with the operations of `A`, a single state and the single response `()` — the paper's "`?`" response. `skel α` (the paper's `H?`) replaces every response of `α` by `()`. * `IsSkelLin α L`: `L` is a linearization of the skeleton history `skel α` (no constraint on responses). * `QSpec Op Resp`: a deterministic sequential specification (states, initial state, transition function) over given operations and responses. It is decoupled from the `ObjSpec` that fixes the interface of an implementation, so that one implementation (or a family of implementations indexed by coin flips) can be compared with several specifications; `ObjSpec.toQSpec A` is the specification of `A` itself. * `tau S L a` (the paper's `ret(a, τ_S(L))`): the response that the deterministic sequential specification `S` gives to the instance `a` in the sequential skeleton `L`. * `IsIVLFor S α` / `IsIVL A α` (**Definition 1**): there are two skeleton linearizations `L₁`, `L₂` such that every completed instance returns a value between the values `τ_S(L₁)` and `τ_S(L₂)` assign to it. * `Impl.IVLFor S` / `Impl.IVL` (**Definition 1**, second part): every execution of the implementation is IVL. * `isIVL_of_isLinearization`: a linearizable history is IVL (remark after Definition 1). The paper compares only the return values of *queries*; the updates of a quantitative object return no value. In CSLib every operation has a response, so we compare all completed instances: for the objects of the paper the updates return a fixed dummy value, both in the implementations and in the specifications, so the comparison is trivial for them. -/ open Cslib.SharedMemory set_option linter.unusedSectionVars false namespace Podc.IntermediateValueLin variable {P : Type} [DecidableEq P] {A : ObjSpec} /-- The skeleton object over the operations `Op`: one state and the single response `()` (the paper's "`?`").
