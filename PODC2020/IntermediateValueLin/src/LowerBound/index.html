import Papers.PODC2020.IntermediateValueLin.Snapshot import Mathlib.Data.List.Forall2 /-! # Theorem 3: the `Ω(n)` lower bound for linearizable batched counters (conditional) Rinberg–Keidar, PODC 2020, Section 6.2, Theorem 3: *for any linearizable wait-free implementation of a batched counter object with `n` processes from SWMR registers, the step complexity of `update` is `Ω(n)`.* The paper derives this from the lower bound of Israeli and Shirazi [21] for (binary) snapshots from SWMR registers, by the reduction of Algorithm 3. We do not formalize [21]: it is the hypothesis `ISLowerBound n b` ("no linearizable wait-free implementation of the binary snapshot with `n` processes from SWMR registers has all its updates performing at most `b` base-object accesses"). `theorem3` shows that the same bound `b` then holds for batched counters: the reduction adds no base-object accesses at all. ## The reduction Given a batched-counter implementation `C` from registers, `Reduction.comp C` is Algorithm 3 with `C`'s code inlined for the counter accesses: a process keeps its bit `v_p`, the current snapshot operation, and `C`'s local state; its base objects are `C`'s registers. A snapshot `update_p(v)` runs `C.update(enc)` and a `scan` runs `C.read()` and returns the bits `0, …, n-1` of the result. **Difference from the paper's Algorithm 3.** The composed algorithm has *no* shortcut on line 4: if `v = v_p` it still runs `C.update(0)` (legal: `0 ≥ 0`) instead of returning at once; `v_p` is updated when the operation returns. This does not matter for the reduction: Invariant 1 still holds (adding `0` keeps the counter), and the shortcut could only *decrease* the number of accesses of an update. It makes the simulation exact: every label of the composed execution corresponds to exactly one label of an execution of `C` (`Reduction.LRel`: invocation ↦ invocation with the encoded counter operation, internal step ↦ the same internal step, response ↦ response), so operation instances, real-time order and per-process access counts coincide. ## Proof structure * `Reduction.step_sim`: a composed step is a step of `C` on the projected configuration (`projCfg`, `projLbl`). * `Reduction.sim_of_run`: every composed execution `α` has a corresponding execution `β` of `C` (`Sim`): same shape, `C`'s operations are the encodings of the snapshot operations along each process (`encOps`), and the snapshot responses are the decodings of `C`'s responses. * `Reduction.isLinearization_lift`: a linearization of `β` gives one of `α` (legality by Invariant 1 along the linearization, using that every process's instances appear in program order, `IsLinearization.procIds_eq`). * Transfer of the access discipline (`comp_allowed`), of SWMR (`comp_swmr`), wait-freedom (`comp_waitFree`, projecting infinite executions), linearizability (`comp_linearizable`) and of the step bound (`comp_stepsLE`). -/ open Cslib.SharedMemory set_option linter.unusedSectionVars false namespace Podc.IntermediateValueLin /-- **The Israeli–Shirazi lower bound [21] (hypothesis, not proved here)**, for bound `b`: there is no linearizable, wait-free implementation of the binary snapshot object with `n` processes (process `p` updates only component `p`) from SWMR registers in which every `update` performs at most `b` base-object accesses.
