import Papers.PODC2020.StoreCollectChurn.Spec import Cslib.Computability.Distributed.SharedMemory.History /-! # Algorithm 7 (atomic snapshot from store-collect), Section 6.2 of the paper We model Algorithm 7 on top of an **abstract** store-collect object: the only assumption on the object is that the schedule of its invocations and responses satisfies `Regular` (Section 2, `Spec.lean`). This is exactly what the paper's proof uses ("The regularity of store-collect ensures …"). * Nodes `P` (any type: under churn there may be infinitely many), snapshot values `V`. * A store-collect value (`SCVal`) is the 5-tuple `⟨val, usqno, ssqno, sview, scounts⟩` of the paper (`ValSC = Val_AS × ℕ × ℕ × 𝒫(Π × Val_AS) × 𝒫(Π × ℕ)`); a snapshot view and the set `scounts` (pairs without duplicate node ids) are partial functions. * An execution is a list of events `Ev`: high-level invocations/responses of `SCAN`/`UPDATE` and low-level store-collect events. Every node runs the code of Algorithm 7 as a deterministic automaton (`lstep`); the environment chooses the interleaving and the views returned by collects. The choice of `q` at Line 77 ("if ∃ q such that …") is an arbitrary choice function `Pick` (any rule is allowed). * Line 71 stores `⟨−, −, ssqno, −, −⟩`, "with all the other components unchanged": we read the `−` components as those of the value the node stored last (`stored`). With the other reading (the current local variables, where `scounts` was already overwritten at Line 79 of an enclosing `UPDATE`) the algorithm is not linearizable: see `differencies.md`. -/ namespace
