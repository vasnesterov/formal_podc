import Papers.PODC2020.StoreCollectChurn.CCC import Papers.PODC2020.StoreCollectChurn.Constraints /-! # CCC is not regular: counterexamples to Theorem 6, Corollary 7, Lemma 10 and Observation 5 **The bug.** In a collect, the client broadcasts `⟨store, LView⟩` at Line 36 (store-back) but at Line 47 returns the *current* `LView`, which may meanwhile have been enlarged by the server thread of the same node (Line 48 merges the views of `store` messages of *other* clients into the same variable `LView`). So a collect can return a value of a concurrent `STORE` that it never wrote back to a quorum, and a later collect can miss that value. Likewise `view(φ)` is the value of `LView` at the *end* of the phase (Section 4), which is not the view that the phase stored, so Lemma 10 fails. **The execution** (static system, `S₀` = five nodes `r = 0, p₁ = 1, p₂ = 2, a = 3, b = 4`, no `ENTER`/`LEAVE`/`CRASH`; `D = 20`; `β = 3/5`, so `threshold = β · |Members| = 3`): * `t = 1`: `p₁` invokes `COLLECT` (broadcast #0, the collect query); `p₁`, `a`, `b` answer with empty views (#1–#3, received by `p₁` at `t = 3`); `p₁` broadcasts the store-back `⟨store, ∅⟩` (#4) at `t = 3`. * `t = 4`: `r` invokes `STORE(1)` and broadcasts `⟨store, {⟨r, 1, 1⟩}⟩` (#5). * `t = 5`: `p₁`, `a`, `b` receive the store-back #4 and acknowledge it (#6, #8, #10). * `t = 6`: `p₁` receives `r`'s store #5 (Line 48): now `LView_{p₁} = {⟨r, 1, 1⟩}`. * `t = 7`: `p₁` receives the three acks and **returns `V₁ = {⟨r, 1⟩}`** (Line 47). * `t = 8`–`12`: `p₂` invokes `COLLECT` (#14); `p₂`, `a`, `b` answer with empty views (they have not heard of `r`'s store yet); the store-back `⟨store, ∅⟩` (#18) is acknowledged by `p₂`, `a`, `b`, and **`p₂` returns `V₂ = ∅`** at `t = 12`. * Afterwards all remaining broadcasts are delivered (FIFO, delays in `(0, D]`); the messages carrying `r`'s value reach `p₂`, `a`, `b` only at `t = 24 = 4 + D`. `r`'s store completes at `t = 25`. `COLLECT_{p₁}` precedes `COLLECT_{p₂}`, `V₁(r) = 1` and `V₂(r) = ⊥`, so `V₁ ⋠ V₂`: part 2 of regularity fails.
