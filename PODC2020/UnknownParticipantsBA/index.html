Byzantine Agreement with Unknown Participants and Failures — PODC 2020

Pankaj Khanchandani, Roger Wattenhofer. Brief Announcement: Byzantine Agreement with Unknown Participants and Failures. PODC 2020. DOI 10.1145/3382734.3405740. Formalized version: the BA, with the proofs and Algorithm 3 of the full version, arXiv 2102.10442 v1. BA Lemmas 1–4 / Theorem 1 are full-version Lemmas 2, 4, 6, 7 / Theorem 2. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. Both algorithms keep n > 3f and their round bounds, but the rotor-coordinator's Lemma 4 and Theorem 1 are false as written, and saving them took a changed stopping rule and a new good-round argument. The consensus algorithm needed only local repairs. The full version's extra sections (approximate agreement, impossibility results, dynamic networks) were not checked.

Mistakes in the paper

🛠️ Lemma 4 (BA) / Lemma 7 (full version): good round

A correct node can terminate without witnessing a good round: with n = 7, f = 2, every correct node "reselects" and breaks in iteration 1, and no iteration was ever good (Cex.lemma4_false, Cex.no_good).

Impact. The good-round lemma behind Theorem 1 is false; the repaired rule below restores a good round among the first f + 1 iterations (rotor_fixed).

Details

Take n = 7 with correct nodes 2,…,6 and Byzantine nodes 0, 1. Both Byzantine nodes make themselves known to everybody in round 1, so the thresholds are 3 and 5 copies. They then play their init/echo messages so that:

  • in iteration 0, only node 2 gets 5 copies of echo(1); so node 2 selects 1 and the others select 2;

  • in iteration 1, the others add 1 and node 2 adds 0. Node 2 now has C_2 = {0,…,6} and selects C_2[1] = 1 again; the others have C = {1,…,6} and select C[1] = 2 again.

The proof's last step treats C_v as fixed ("a reselected node is in {C_v[r mod |C_v|] : r < r_c}"). But C_v is kept sorted, and inserting a smaller identifier shifts the index back onto the previous coordinator.

Repair

Break once 2r > n_v instead of on reselection. Since n_v ≥ g > 2f, nobody stops before iteration f + 1. The paper's counting does not carry over, so the good round needs a new argument: as long as iterations are bad, the number of identifiers below the smallest correct one grows, and those are all faulty. So some iteration r ≤ f is good (exists_good_round, layer_good). Every node stops by iteration ⌊n/2⌋ + 1. The bound r ≤ f is tight in a bounded search. (rotor_fixed)

🔧 Theorem 1 (BA) / Theorem 2 (full version): rotor-coordinator

There need not be a round in which every correct node accepts the opinion of a common correct coordinator: in the n = 7, f = 2 run of Lemma 4 above no correct node ever accepts any opinion, and an independent gap already appears for n = 4, f = 1 (Cex.theorem1_false, Cex4.theorem1_false).

Impact. One of the two algorithms the abstract presents fails as written. The termination half of Theorem 1 does hold (everybody breaks within n iterations, paper_terminates), and the one-line change of the termination rule above repairs the rotor-coordinator with the claimed O(n) rounds (rotor_fixed).

Details

For n = 4, f = 1, iteration 1 is a good round, but two correct nodes reselect in that very iteration and break. The coordinator's opinion would only be accepted in the next iteration, so they never accept it.

Repair

With the rule above nodes run past the good iteration r, and in iteration r + 1 every correct node accepts exactly the coordinator's opinion. (rotor_fixed)

🔧 Full version, Algorithm 3 (the fill rule)

Algorithm 3's fill rule is under-specified, and under its natural reading silent correct nodes count as support for the receiver's value, which breaks agreement for n = 4, f = 1 (FillCex.fill_rule_breaks_agreement).

Impact. Agreement fails under this reading of the rule. The same adversary achieves nothing without the rule (FillCex.without_fill).

Details

The rule says that a node v that sends nothing is assumed to have sent what the receiver itself sent in the previous round. It is meant for terminated nodes. But correct nodes are also silent when they miss a threshold. With n = 4, f = 1 and inputs 0, 0, 1:

  • node 1 alone sends prefer(0);

  • it counts the two silent correct nodes as prefer(0) and then as strongprefer(0), and decides 0;

  • the others adopt the Byzantine coordinator's 1, and in the next phase one of them decides 1 by the same mechanism.

Repair

Drop the fill rule and let decided nodes keep participating; agreement, validity and O(f) are then kept (consensus_correct).

✏️ Slips

  • Lemma 3 (BA) / Lemma 6 (full version), relay, silently assumes that no correct node has terminated yet: a terminated node no longer echoes or adds p. Our relay assumes it.

  • BA Section 4: the prose says a node "selects the coordinator with the next larger identifier", which is a different rule from line 14, C_v[r mod |C_v|]. The proof of Lemma 4 uses line 14.

🔧 Full version, Theorem 3 (consensus)

The proof relies on the false Theorem 2, takes the coordinator's opinion from the previous phase although Lemma 11 needs the current one, and does not specify a rotor break inside the consensus.

Impact. Statement true: we verify a repaired Algorithm 3, which confirms both the BA's O(n) and the full version's O(f) (consensus_correct, consensus_validity_bool).

Repair

The coordinator broadcasts its current opinion in the same phase, there is no fill rule, and decided nodes keep participating. This satisfies agreement, validity, and termination within 3f + 7 rounds.

The formalizationmodel, Lean names of the results, trust

Model. (Model.lean, paper-local, CSLib candidate)

  • Synchronous lock-step rounds. A protocol is a single state machine that knows only its own id and input, so n and f are unknown by construction. Identifiers come from any type (ℕ in the counterexamples) and need not be consecutive.

  • Correct nodes broadcast a finite set of messages per round, to everybody including themselves. Receivers see (true sender, message) pairs, and duplicates collapse.

  • Static Byzantine set F, G ∩ F = ∅. Byzantine nodes send arbitrary per-receiver message sets (possibly none), may mention non-existent identifiers, and are adaptive (any function of the round, sender and receiver). Since protocols are deterministic, this covers adaptive adversaries. There is no Sybil behaviour and no forging of the direct sender, as in the paper.

  • Resilience hypothesis: 2|F| < |G|, i.e. n > 3f with f = |F|.

  • The candidate-set mechanism (lines 1–13 of the rotor) is a shared layer (withRotor). The rotor (rotor rule) and the consensus (cons) are extensions of it. Coordinator selection follows line 14, C_v[r mod |C_v|] (as the proof of Lemma 4 does), not the prose's "next larger identifier", which is a different rule. n_v counts the senders heard from so far, including the current round.

Trust. No sorry. All listed theorems use only the axioms propext, Classical.choice and Quot.sound. The counterexamples are concrete runs checked by decide +kernel. The repaired results are non-vacuous: the hypotheses are only n > 3f, and FillCex.without_fill runs the verified consensus on a concrete instance. The abstract searches over rotor schedules are in modelcheck/: they found the n = 7 instance and the tight bound r ≤ f.
