import Cslib.Computability.Distributed.MessagePassing.Async import Papers.PODC2020.FastMWMRImpossibility.Lin /-! # The W2R1 algorithm of §5.2 / Appendix A (Algorithms 1 and 2) is not atomic The paper's fast-read multi-writer algorithm, as an asynchronous message-passing protocol (`Cslib.AsyncMP`), for `S = 4` servers, `t = 1`, `R = 1` reader and `W = 2` writers. The paper claims it is atomic whenever `R < S/t − 2` (here `1 < 2`). We exhibit a reachable execution with a non-linearizable history (`w2r1_not_linearizable`): a read that starts after `write(1)` returned returns the initial value `0`. This contradicts property MWA2 / Lemma 5. **The algorithm** (Algorithms 1–2), values tagged `(ts, wid)` and ordered lexicographically. * A server keeps a `valuevector`: for each tagged value it received, the set `updated` of clients that have been recorded with it. `update(val, c)` adds `c` to `updated[val]` (creating the entry if needed; if `val` exceeds the current value this is line 9–11). * A writer queries all servers for their current timestamp (first round-trip). It writes `(maxTS + 1, wid)` to all servers (second round-trip), waiting for `S − t` replies each time. * A reader sends `(read, valQueue)`. A server does `update(val, r)` for every `val` in `valQueue` (line 20) and replies with its `valuevector`. The reader waits for `S − t` replies and returns the largest value `v` that is `admissible(v, rcvMsg, a)` for some `a ∈ [1, R + 1]`: some set `μ` of replies, all containing `v`, with `|μ| ≥ S − a t` and `|⋂_{m ∈ μ} m.updated(v)| ≥ a` (lines 23–32). The pseudo-code is ambiguous on one point: does a read request also record the reader with the server's *current* value, as in the single-writer algorithm of Dutta et al. that the paper extends? The flag `markCur` covers both readings. The counterexample works for both. **The execution.** 1. `w₁` and `w₂` both query and see `ts = 0`, so they write `(1, w₁)` (value `1`) and `(1, w₂)` (value `2`). 2. `(1, w₁)` reaches `s₀, s₁, s₂`, and `write(1)` returns. 3. The read is invoked. `(1, w₂)` reaches `s₀` and `s₁`. 4. The read request reaches `s₀, s₂, s₃`, and the reader uses these three replies. * `(1, w₂)` is only in `s₀`'s reply, so it is not admissible (`a = 3` would be needed). * `(1, w₁)` is in the replies of `s₀` and `s₂`, but at `s₀` its `updated` set is `{w₁}`. The reader was not recorded there: `(1, w₁)` is neither in its `valQueue` nor `s₀`'s current value.
