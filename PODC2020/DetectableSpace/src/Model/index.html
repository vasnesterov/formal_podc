import Mathlib.Data.List.Pairwise import Mathlib.Data.List.Nodup import Mathlib.Data.Fintype.Card import Mathlib.Logic.Function.Iterate import Cslib.Computability.Distributed.SharedMemory.Spec /-! # Recoverable implementations with system-wide crashes (Ben-Baruch–Hendler–Rusanovsky, PODC 2020) A self-contained model of Section 2 of *Upper and Lower Bounds on the Space Complexity of Detectable Objects*: asynchronous processes `P`, non-volatile memory, system-wide crashes, and recoverable operations with recovery functions. * The implemented object is given by a deterministic sequential specification `O : Cslib.SharedMemory.ObjSpec`. * An implementation `A : RImpl O P` has non-volatile **shared** memory `A.Sh`, a non-volatile **private** memory `A.Pv` per process, and volatile local states `A.L`. A step of a process either applies an arbitrary atomic transformation to the *whole* shared memory (`Act.sh`: any primitive operations, even multi-word ones), or accesses only its own private non-volatile memory (`Act.pv`), or returns (`Act.ret r`, `r = none` is the special value `fail`). Steps never access both kinds of memory at once. * Invoking operation `o` at an idle process `p` sets its local state to `A.start p o` and lets the *system / caller* modify `p`'s private non-volatile memory by `A.aux p o` (this is how auxiliary state is provided "via NVM", e.g. `Ann_p.CP := 0`; Definition 1). Invocations never touch shared memory. * A system-wide crash resets the local state of every process that is in the middle of an operation `o` to the initial state `A.recov p o` of the recovery function `o.Recover` (called with the same arguments); idle processes stay idle; memory is unaffected. * Each invocation gets a fresh identifier (the counter `cnt`); the history of an execution is the list of invocation, response and crash events (`HEv`). Correctness is durable linearizability together with detectability (`DLin`, `DurLinDet`): there is a sequential order of a subset of the invoked operations which contains every operation that returned a value (with that value as its sequential response), contains no operation whose recovery returned `fail`, may contain pending operations, and respects real-time order. An operation can only return `fail` from its recovery function. Progress: `ObstructionFree` (from every reachable configuration a process running solo without crashes completes its operation / recovery function) and `WeakOF` (Definition 2: the same, but only from
