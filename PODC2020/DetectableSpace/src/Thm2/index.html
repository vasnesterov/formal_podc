import Papers.PODC2020.DetectableSpace.Lin import Papers.PODC2020.DetectableSpace.Perturbing /-! # Theorem 2: detectable implementations of doubly-perturbing objects need auxiliary state In our model an implementation `A : RImpl O P` receives exactly the arguments of the abstract operations (`O.Op`), so auxiliary state can only be provided via non-volatile memory, by the system / caller at invocation time (`A.aux`). "No auxiliary state" is `∀ p o v, A.aux p o v = v`. `theorem2`: in a weakly obstruction-free, durably linearizable and detectable implementation, an operation witnessing that the object is doubly-perturbing must receive auxiliary state (`theorem2_exists`: some operation of a doubly-perturbing object does). The proof follows the paper (Figure 2): executions `D` (crash just before `p` returns from its first `Op_p`) and `E` (`p` returns, invokes `Op_p` again and the system crashes immediately) are indistinguishable after the crash; `p`'s recovery returns the same value `x` and `q`'s operation `Op_q` returns the same value `y` in both. In `D`, `Op_p` must be linearized before `Op_r` (it perturbed `Op_r`), so `x ≠ fail` and `y` is the response of `Op_q` after `H₂`; in `E`, `x ≠ fail` means the second `Op_p` was linearized before `Op_q`, so `y` is the response after `H₂ ∘ Op_p` — these differ since `Op_p` is perturbing after `H₂`. (The paper derives "`Op_q` returns `u` after `E₁`" from linearizability of `E`; that step is not justified as stated — the second `Op_p` is pending there — but it is not needed: we use the
