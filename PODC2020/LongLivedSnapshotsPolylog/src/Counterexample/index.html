import Papers.PODC2020.LongLivedSnapshotsPolylog.BoundedIncrement /-! # Lemma 3.3 is false: linearization rules (1)–(3) do not respect the max-array semantics Section 3.1 of the paper linearizes the operations of Algorithm 1 by three rules; Lemma 3.3 claims that the resulting order "respects the semantics of the 2-max array object". We formalize rules (1) and (3) for arbitrary executions of `alg1 n m X` (`Rule1Point`, `Rule3Point`) and give an execution (`n = 4`, `m = 16 = n²`, `4`-bounded-increment, every `X`) in which * rule (3) linearizes `MaxUpdate(right, 3)` of process `B` at a step `s` (`Q`'s line-16 write of the right side of `MA_0`, after `Q` read `MR_right = 3`), * rule (1) linearizes the `MaxScan` of process `S` at its line-17 step `t > s`, * but `S` returns `(16, 0)`: its right component `0` is smaller than `3`. Since in the sequential specification every `MaxScan` that follows a `MaxUpdate(right, 3)` returns a right component `≥ 3` (`scan_right_ge`), the sequential history given by rules (1)–(3) is not legal (`lemma_3_3_false`). The execution (processes `A = 0`, `B = 1`, `Q = 2`, `S = 3`; `αex`): 1. `A` runs `MaxUpdate(left, 4)`, `(left, 8)`, `(left, 12)` solo. 2. `Q` invokes `MaxScan`, reads `MR_right = 0` (line 10) and `MR_left = 12` (line 11). 3. `A` invokes `MaxUpdate(left, 16)` and writes `MR_left := 16` (line 4). 4. `S` invokes `MaxScan`, reads `0`, `16`, `0` (lines 10–12): index `h = 1`. 5. `B` invokes `MaxUpdate(right, 3)` and writes `MR_right := 3` (line 4) — step `w`. 6. `Q` reads `MR_right = 3` (line 12), `h = 0`, writes `MA_0.left := 12`, `MA_0.right := 3` (lines 15, 16) — the latter is step `s`. 7. `S` writes `MA_1.left := 0`, `MA_1.right := 0`, `MaxScan(MA_1) = (0, 0)` (line 17, step `t`), passes line 18 (`MR_left = 16`, `MR_right = 3` have the same high-order bits as before), writes `H[3]` and returns the direct view `(16, 0)` (step `e`). The flaw: rule (3) linearizes `B`'s update at a write to the *old* array `MA_0` although the active array is already `MA_1` (`S` committed to `h = 1` before reading `MR_right` changed). Equivalently, Claim 4 fails after step `s`: the value of `O` (Definition 3.2, active array `MA_1`) is `(16, 0)`, while a `WriteMax(MR_right, 3)` is already linearized. The history itself is linearizable (linearize `B`'s update after `S`'s scan); only the paper's rules are wrong. The concrete facts are checked by kernel evaluation of the computable step function (`Impl.crun`); as the execution never reaches the failure branch of lines 23–29, the evaluation does not depend on
