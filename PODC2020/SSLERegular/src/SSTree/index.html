We transcribe SS-Tree (with its sub-protocols SS-TwoHop, CycleDetector and MultipleRootDetector) as a nondeterministic population protocol `ssTree k R` for `k`-regular graphs, parameterised by an arbitrary ring protocol `R` (the paper uses the Ring-Protocol of [11] as a black box; nothing below depends on it). Colours `1, …, k²` are encoded as `Fin (k ^ 2)` (value `c + 1`); the colour variables with an extra value `0` (`counterColor`, `loopColor`) are `Fin (k ^ 2 + 1)`. Randomized rules are resolved by an explicit `TChoice` (all choices are allowed). Interpretation choices (see `differencies.md`): the SS-TwoHop guard is read as `u.prevColor = v.color ∧ v.prevColor = u.color ∧ u.colorBit ≠ v.colorBit` (the printed tuple equality is garbled); the cycle-detector leader test and the opposite-coin test of MultipleRootDetector are applied to every interacting pair (outside the parent–child guard), the reading most favourable to error detection; unqualified `errFlag ← True` means `u.errFlag`. **Main result** (`ssTree_not_solvesSSLE`): for every `k ≥ 2`, every graph of maximum degree `≤ k` with at least two nodes and every colouring in which the neighbours of each node have distinct colours (what SS-TwoHop is meant to produce), there is a configuration in which **every node is a root (a leader) forever**: all nodes are roots whose `parentColor` is the colour of no neighbour, so no parent–child pair exists, MultipleRootDetector never moves a coin, CycleDetector never runs the ring protocol, and no error is ever raised.
