Self-Stabilizing Leader Election in Regular Graphs — PODC 2020

Hsueh-Ping Chen, Ho-Lin Chen. Self-Stabilizing Leader Election in Regular Graphs. PODC 2020. DOI 10.1145/3382734.3405733. Formalized version: the proceedings version (no arXiv version exists); numbering follows it. Copy of the paper: paper.pdf.

DOI · PDF · All differences · Lean source · GitHub

Verdict: ⚠️ Weakened. SS-EulerCycle (Theorem 3.3), which answers the open question, fails as printed because no configuration is output-stable, but a natural one-line repair saves it: we prove Theorem 3.3 on every connected 2k-regular graph, assuming (as the paper does) that the Ring-Protocol of [11] solves SSLE on directed rings. SS-Tree (Theorem 4.3), the O(k¹²) protocol, is false: there is a configuration in which every node is a root, hence a leader, forever, no detector ever fires, and no repair is proved. The odd-degree and general-graph extensions (Section 3.5) were not checked.

Mistakes in the paper

❌ Theorem 4.3 and Lemma 4.2 (SS-Tree, MultipleRootDetector)

SS-Tree does not detect multiple roots: in a configuration where every node is a root with a "ghost" parent colour and all coins are +1, every node stays a leader forever (ssTree_all_roots_forever, ssTree_not_solvesSSLE).

Impact. The detector needs a redesign, not a typo fix, and no repaired SS-Tree is proved, so the O(k¹²) protocol is not saved. The failure occurs for every k ≥ 2, every graph of maximum degree ≤ k (e.g. K_{k+1}, ssTree_fails_on_complete), every neighbourhood-injective k²-colouring and every ring protocol; it also fails with probability 1 (ssTree_prob_zero).

Details

MultipleRootDetector only moves coins between a parent and its child. A root tosses only when its coin is 0, and a root's coin never returns to 0 (only a child is reset), so the re-tossing that the proof relies on ("there must be a time when two roots toss different coin values") never happens. Counterexample: let every node be a root whose parentColor is the colour of none of its neighbours, with all coins +1, counters 0, ring states and copies non-leaders, and SS-TwoHop memory consistent. Then there is no parent–child pair. No coin ever moves. The ghost parents are never checked, because roots do not count. CycleDetector never runs the ring protocol and only copies non-leader states. Every node stays a leader forever.

❌ Lemma 4.2, proof (case analysis)

Lemma 4.2's case analysis is incomplete: it forgets the invalid configurations that already have one leader but are not output-stable (a cycle elsewhere in the pedigree graph, ghost parents, a bad colouring).

Impact. The lemma is not repaired, because SS-Tree itself is not; no remedy can exist without a working detector.

❌ Lemma 4.1, proof (chain argument; existence of a stable SS-Tree configuration)

Lemma 4.1's proof does not cover CycleDetector's dynamics, so the lemma is unestablished (not formalized, not refuted).

Impact. The step stands unrepaired, and SS-Tree already fails by Theorem 4.3. Whether a leader can appear depends on the internals of [11].

Details

The proof cuts a chain out of a stable ring of [11]: such a chain never creates a leader. But nodes unmark at random and leave stale loopChild/loopParent flags. A re-marked parent then copies a fresh ringState and runs the ring protocol with a child whose copy has already evolved. These mixed configurations are not reachable on the static chain.

🔧 Theorem 3.3 and Lemma 3.1 (SS-EulerCycle, Protocol 1 as printed)

No configuration of Protocol 1 as printed is output-stable on any 2k-regular graph (k ≥ 1), because the coherence check raises an error whenever the scheduler lets the head of a virtual edge initiate (literal_not_solvesSSLE, literal_fails_on_complete).

Impact. The printed protocol fails whatever the ring protocol, but a one-line change fixes it: use the virtual edge in either role. With this repair we prove Theorem 3.3 (repaired_solvesSSLE).

Details

The coherence check accepts an interaction only if there is a virtual edge from the initiator to the responder; otherwise u.errFlag ← True. An Euler cycle traverses each edge in one direction, but both nodes of an edge get to initiate. We show that from every configuration an error is reachable. Either some ordered pair of neighbours has no forward virtual edge (one interaction suffices). Or all of them have one; then a node has 2k neighbours but only k successor slots, so two neighbours share a colour, and the paper's own sequence (A,B),(A,C),(A,B) makes SS-TwoHop recolour and break a virtual edge. The erroneous initiator then takes a random state, so its output changes.

Repair

If there is no virtual edge u → v but there is one v → u, run the Ring-Protocol and SS-Token on it with v's virtual node as the ring initiator. With this repair we prove Theorem 3.3 (repaired_solvesSSLE).

✏️ Slips

  • Lemma 2.1 omits two hypotheses that the paper states only in the prose: a valid output-stable configuration exists, and error-detected configurations can reach it. We prove the lemma with both hypotheses explicit (derc_lemma).

  • The SS-TwoHop guard is garbled: it demands v.prevColor = v.color instead of u.prevColor = v.color. We use Sudo et al.'s "matching colours, different bits".

  • "2-hop colouring" must mean "the neighbours of each node have distinct colours"; for that, 4k² colours suffice.

Typos

  • The indentation of Protocols 5–6 is lost.

Model.

  • Population protocols on a graph G (GProtocol). An interaction is an ordered pair of adjacent nodes (initiator, responder); both orders are scheduled. There are no IDs and no orientation.

  • Randomized transitions are modelled by their support: δ p q is the set of possible outcomes. This includes the paper's RandState, random bits and random colours.

  • Self-stabilization follows the paper. Global fairness is the standard notion of Angluin et al. SolvesSSLE: from any initial configuration, every globally fair execution reaches a valid output-stable configuration. We prove this is equivalent to reachability (solvesSSLE_iff) and to stabilization with probability 1 under any random scheduler supported on the steps (Cslib.TransitionSystem.tendsto_compl_of_reach, prob_eq_zero_of_not_reach).

  • The Ring-Protocol of [11] is an arbitrary nondeterministic protocol with a leader output. For the repaired theorem it must satisfy RingSpec: SSLE on every directed ring of size ≥ 3, with the initiator being the predecessor, as in Protocol 1. The negative results need only a leader state and a non-leader state.

  • SS-Tree (ssTree) and SS-EulerCycle (ssEuler false as printed, ssEuler true repaired) are transcribed sub-protocol by sub-protocol.

Not formalized. We do not formalize the Ring-Protocol of [11] itself; RingSpec is assumed. Also not formalized: the odd-degree and general-graph extensions (Section 3.5), so "arbitrary k-regular graphs" is established only for even degree; the general correctness of SS-TwoHop [20], of which only the facts used are proved; and a repair of SS-Tree.

Trust. No sorry. All listed theorems use only propext, Classical.choice and Quot.sound. Non-vacuity:

  • globally fair executions exist (Cslib.TransitionSystem.exists_globallyFair), so the negative results are not vacuous;

  • the counterexamples are explicit configurations on K_{k+1} / K_{2k+1};

  • the hypotheses of the repaired theorem are met by every connected 2k-regular graph, given a ring protocol satisfying RingSpec. That such a ring protocol exists is the result of [11], which we do not formalize.
