# formal_podc: Lean 4 formalizations of PODC papers

Machine-checked formalizations of papers from the ACM Symposium on Principles of Distributed Computing
(PODC), 2010–2026, in [Lean 4](https://lean-lang.org/) with [Mathlib](https://github.com/leanprover-community/mathlib4)
and [CSLib](https://github.com/vasnesterov/cslib).

The goal is to **verify the results and the proofs** of each paper. Every formalized paper has its own folder
`Papers/PODC<Year>/<ShortName>/` with

- the Lean files (no `sorry`, no extra axioms: the main theorems depend only on `propext`,
  `Classical.choice` and `Quot.sound`),
- `README.md`: the paper reference, the model (synchrony, failures, adversary, randomness), and a table
  mapping the paper's theorems to Lean names,
- `differencies.md`: **every** difference between the formalization and the paper — missing assumptions,
  false or imprecise statements, gaps in proofs, changed constants — with Lean counterexamples where a claim is
  false, and the repaired statements that we proved instead.

General infrastructure developed along the way (Byzantine round models, asynchronous shared memory and
linearizability, population protocols, the LOCAL model, self-stabilization, Menger's theorem, the Moore bound,
graph minors, spanners, Markov-chain absorption, social choice, …) lives in the CSLib fork
[`vasnesterov/cslib`](https://github.com/vasnesterov/cslib), branch `podc` (see [Layout](#layout)).

The formalizations were produced by AI agents (Claude) under human direction. Each paper was then checked by an
independent reviewer agent for faithfulness of definitions and statements and for over-claimed errors.
The Lean kernel checks every proof; whether a Lean statement faithfully captures the paper is a judgment, and
the reasoning is recorded in each `differencies.md`.

## Responses from the authors

If you are an author of a paper here, you can respond to our findings: open the paper's page on the
[website](https://vasnesterov.github.io/formal_podc/) and follow the link under "Authors' response", or add a file
`author-response.md` to the paper's folder in a pull request. Plain Markdown; we show it on the paper's page as written,
with a 💬 mark on the list of papers. You can also [open an issue](https://github.com/vasnesterov/formal_podc/issues).

## Building

```bash
# requires elan (https://github.com/leanprover/elan)
lake exe cache get   # Mathlib cache
lake build
```

The toolchain is pinned in `lean-toolchain` (it matches CSLib's).

## Formalized papers

Each paper has one label: how hard it is to save what the paper set out to convey, judged as a whole.

- ✅ **correct** — no labeled mistakes;
- ✏️ **slip** — only slips: the paper is right apart from typos, degenerate cases and implied assumptions;
- 🔧 **easy fix** — the paper's point is saved by local changes, and anything lost is minor;
- 🛠️ **hard fix** — the paper's point is saved, but it takes a new argument or a redesign;
- ⚠️ **weakened** — the paper keeps real value, but part of what it set out to convey is lost or holds only in a weaker
  form;
- ❌ **intent lost** — the paper's main point does not survive, even if other parts of it are correct; see
  [below](#papers-with-critical-mistakes).

The label covers only what was checked. The rules are in [mistakes-labeling.md](mistakes-labeling.md) (each mistake) and
[paper-labeling.md](paper-labeling.md) (the paper).

## Papers with critical mistakes

The main point of these papers does not survive: a claim they set out to make fails and we could not save it,
even if other parts of the paper are correct. Sorted by citation count.

- **Signature-Free Asynchronous Byzantine Consensus with t < n/3 and O(n²) Messages** (PODC 2014, 160 citations) —
  [SignatureFreeBA](Papers/PODC2014/SignatureFreeBA). The algorithm of Figure 2 does not terminate: for `n = 4`, `t = 1` and inputs `0, 0, 1`, an adversary that controls the schedule and the Byzantine process prevents every decision for every coin sequence. So Theorem 2, Lemma 5 and the four expected rounds of Theorem 3 and the abstract are false; safety holds.
- **Generalized Lattice Agreement** (PODC 2012, 48 citations) —
  [GeneralizedLatticeAgreement](Papers/PODC2012/GeneralizedLatticeAgreement). Theorem 5.15 is false: with three processes, one of which crashes, there are fair executions of Algorithm 2 in which a value received by a correct process is never learnt, even with reliable channels. So the algorithm does not solve generalized lattice agreement, and the O(N) message-delay bound falls with it.
- **Synchrony Weakened by Message Adversaries vs Asynchrony Restricted by Failure Detectors** (PODC 2013, 41 citations) —
  [MessageAdversariesVsFD](Papers/PODC2013/MessageAdversariesVsFD). Theorems 2, 4, 5, Corollary 1 and the Figure 1 arrows QUORUM → TOUR, (SOURCE, QUORUM) → (SOURCE, TOUR) are false, because the simulations leave reliable weakly correct processes without output. Theorem 3 is unestablished, and the other reading of "solve" breaks Lemmas 1, 3 and 5.
- **Optimal Synchronous Approximate Agreement with Asynchronous Fallback** (PODC 2022, 26 citations) —
  [HybridApproxAgreement](Papers/PODC2022/HybridApproxAgreement). Theorem 4.1 and Theorem 3.1(1) are false: a Byzantine sender delivering conflicting proposals at 2Δ breaks the consistency of Π_rBC when tₛ ≥ n/3, and for n = 3, tₛ = 1, tₐ = 0 Π_AA keeps the honest parties at 0 and 1. So the claimed first AA protocol tolerating more than n/3 synchronous corruptions is not established.
- **Eventually Linearizable Shared Objects** (PODC 2010, 23 citations) —
  [EventualLinearizability](Papers/PODC2010/EventualLinearizability). Algorithm 1 over an Eventual Consensus layer is not even weakly consistent, and with Eventual Stability read per run no implementation over such a layer is eventually linearizable, so the claimed equivalence with Eventual Consensus fails. Eventual Linearizability is also not nonblocking for a fixed t.
- **Group Mutual Exclusion in O(log n) RMR** (PODC 2010, 21 citations) —
  [GroupMutexLogRMR](Papers/PODC2010/GroupMutexLogRMR). Starvation freedom (Theorem 1, Lemma 3) is false: with two processes and two sessions, a fellow's successful `SC(Ex, false)` kills the last exiter's link on `Ex`, its `SC` at line 16.9 fails, and a waiting process of the other session is stuck at line 8 forever. The O(min(log n, k)) RMR bound (Lemma 5, the title claim) is also false: with four processes, repeated line-7 writes of `Out[s]` force unboundedly many remote reads in one attempt. Mutual exclusion holds.
- **Minimal Synchrony for Byzantine Consensus** (PODC 2015, 17 citations) —
  [MinimalSynchronyBC](Papers/PODC2015/MinimalSynchronyBC). Lemma 2, Theorem 3 and the termination part of Theorem 4 are false: with n = 7, t = 2 and a coordinator crashed at the start, no correct process decides in a synchronous run. The proof of Lemma 3 also fails, so the sufficiency of an eventual <t+1>bisource is not established.
- **Information-Theoretic Lower Bounds on the Storage Cost of Shared Memory Emulation** (PODC 2016, 17 citations) —
  [StorageCostLowerBounds](Papers/PODC2016/StorageCostLowerBounds). Theorems 4.1, 5.1, B.1 and Corollaries 4.2, 5.2, B.2 are false with reliable FIFO channels: a gossip-free atomic live relay keeps the value in the reader's incoming channels with constant server state. Their proofs assume that servers send nothing to an idle reader, an assumption on the algorithm that the paper says it does not make.
- **Synchronous Byzantine Agreement with Nearly a Cubic Number of Communication Bits** (PODC 2013, 17 citations) —
  [CubicBitsBA](Papers/PODC2013/CubicBitsBA). Theorem 2 and Lemma 5 are false: with n = 7, t = 2 and binary values, two Byzantine processes make correct processes decide differently, for either default value. So the protocol of the paper is not a Byzantine agreement protocol, and its O(n^3 log n) bound is not established.
- **Stabilizing Server-Based Storage in Byzantine Asynchronous Message-Passing Systems** (PODC 2015, 17 citations) —
  [StabilizingByzStorage](Papers/PODC2015/StabilizingByzStorage). Theorem 3 and Lemma 13 are false: with `n = 9` servers, `t = 1` Byzantine and sequence numbers modulo `2^64 + 1`, the register of Fig. 3 has a fair execution in which, every few writes, a read returns the value of a write and the next read returns the value of the preceding write, forever. The sanity check of line N6 lowers the reader's `pwsn` to stale helping values, not only after a wrap-around. The SWMR and MWMR registers of Section 5 are built on this register.
- **Optimal Mobile Byzantine Fault Tolerant Distributed Storage** (PODC 2016, 15 citations) —
  [MobileByzantineStorage](Papers/PODC2016/MobileByzantineStorage). Theorems 8/9 and 11-13 are false: at the paper's thresholds a read with no concurrent write can return a never-written value, in both the CAM and the CUM protocol. The claimed optimal emulation therefore has no proved upper bound.
- **A Recursive Early-Stopping Phase King Protocol** (PODC 2022, 13 citations) —
  [RecursivePhaseKing](Papers/PODC2022/RecursivePhaseKing). Lemma 4.2 is false as printed, and the proof of Theorem 1.2 does not hold: correct nodes that have returned take no part in later calls of Algorithm 7, which can then let the remaining nodes split, even after the repair of Lemma 4.2. Theorem 1.2 itself is neither refuted nor proved.
- **On the Amortized Communication Complexity of Byzantine Broadcast** (PODC 2023, 13 citations) —
  [AmortizedByzantineBroadcast](Papers/PODC2023/AmortizedByzantineBroadcast). Algorithm 4, the honest-majority protocol, is not a correct multi-shot Byzantine broadcast: with n = 6, f = 2 an honest node can be given a corrupt-proof, so an honest sender's value is never committed and an honest leader's epoch fails.
- **The Multi-Agent Rotor-Router on the Ring: A Deterministic Alternative to Parallel Random Walks** (PODC 2013, 12 citations) —
  [RotorRouterRing](Papers/PODC2013/RotorRouterRing). The printed proofs of Theorem 3.2 (worst case Θ(n²/log k)) and Theorem 3.5 (best case O((n/k)²)) are wrong: the first computes with a contradictory identity and only reaches its bound because two errors cancel, the second uses an inconsistent deployment. Neither statement is refuted, but neither is proved.
- **From Sequential to Concurrent: Correctness and Relative Efficiency** (PODC 2012, 9 citations) —
  [OptimismConcurrency](Papers/PODC2012/OptimismConcurrency). Theorem 3 (`I_RM` accepts every observable schedule) is false. From `{1, 3, 4}`, `contains(4)` reads `head` and `X₁`, then `remove(3)` runs to completion, then `contains(4)` reads `X₃` and `X₄`. This schedule is observable, but `I_RM` always aborts the read of the marked `X₃`. The claim that `I_RM` supersedes `P` and `SM` (Corollary 4) loses its proof. Theorem 2(2) is also false: a deadlock-free pessimistic LS-linearizable implementation accepts σ of Figure 2(a).
- **Brief Announcement: Gracefully Degrading Consensus and k-Set Agreement under Dynamic Link Failures** (PODC 2014, 8 citations) —
  [GracefulKSetAgreement](Papers/PODC2014/GracefulKSetAgreement). Theorem 11 is false: Algorithm 4, the paper's gracefully degrading k-set agreement algorithm, decides two values with `k = 1` in runs admissible for `VSRC(n, 3D + H) + MAJINF(1)` (`n = 5`, `D = H = 1`, and `n = 8`, `D = H = 2`). Majority influence ignores locks and initial values spread during a root's own stability interval, so the key Lemma 26 fails.
- **Brief Announcement: Classifying Trusted Hardware via Unidirectional Communication** (PODC 2021, 4 citations) —
  [TrustedHardwareUnidirectional](Papers/PODC2021/TrustedHardwareUnidirectional). The Claim of Section 4.1, that sequenced reliable broadcast cannot implement unidirectional rounds for n > 2f and f > 1, is false: an echo protocol implements them. So unidirectionality does not separate shared-memory from message-passing trusted hardware.
- **The k-Bakery: Local-Spin k-Exclusion Using Non-atomic Reads and Writes** (PODC 2010, 4 citations) —
  [KBakery](Papers/PODC2010/KBakery). Theorem 10 is false: the non-atomic algorithm of Figure 3 does not satisfy k-exclusion, since a legal execution with safe registers, N = 3 and k = 1 puts two processes in the CS. No repair of the algorithm is proved.
- **Efficient Bounded Timestamping from Standard Synchronization Primitives** (PODC 2023, 3 citations) —
  [BoundedTimestamping](Papers/PODC2023/BoundedTimestamping). The algorithm of Figures 1–2 is not linearizable: helpMoveTS() shares its LL/SC links with the process's other LL()s, so a stale line-73 SC() succeeds and reverses a dominance order. Lemmas 6, 8, 9 and Corollary 10 are false, and Theorem 1 is not established.
- **K-set agreement bounds in round-based models through combinatorial topology** (PODC 2020, 3 citations) —
  [RoundBasedKSetTopology](Papers/PODC2020/RoundBasedKSetTopology). Theorems 5.4 and 6.11, the general lower bounds, are false: on the closed-above model of a single star they make (n-1)-set agreement impossible, though consensus is solvable. The computation of the distributed domination number for unions of stars is also wrong, so the claimed tight (n-s) bound does not follow.
- **Brief Announcement: Collect in the Presence of Continuous Churn with Application to Snapshots and Lattice Agreement** (PODC 2020, 1 citations) —
  [StoreCollectChurn](Papers/PODC2020/StoreCollectChurn). A COLLECT of CCC can return a value merged during its store-back phase that was never written back, so a later COLLECT misses it. Theorem 6, Corollary 7, Lemma 10 and Observation 5 are false.
- **Brief Announcement: Fault Tolerant Coloring of the Asynchronous Cycle** (PODC 2022, 0 citations) —
  [AsyncCycleColoring](Papers/PODC2022/AsyncCycleColoring). Algorithms 2 and 3 are not wait-free: on every C_n with n >= 3, if two processes stop after one round and their neighbours keep taking simultaneous rounds, those neighbours never return. So Theorems 3.11 and 4.4 are false, and no wait-free 5-coloring in O(log* n) rounds is established.
- **Brief Announcement: It Does Not Matter How You Define Locally Checkable Labelings** (PODC 2026, 0 citations) —
  [LCLDefinitions](Papers/PODC2026/LCLDefinitions). Theorem 5.1 is false as stated (Lean counterexample on the gadgeted K_{3,3}), and Lemma 5.4 needs its local form, so the proof of the main Theorem 7.1 does not stand. Theorem 7.1 itself is not refuted, and a local repair with a larger r_D, though plausible, is not proved.
- **Brief Announcement: Strong and Hiding Distributed Certification of k-Coloring** (PODC 2025, 0 citations) —
  [HidingColoringCertification](Papers/PODC2025/HidingColoringCertification). Theorem 4.2 is false already for r = 1: a counter modulo M > 2N gives a strong, hiding, anonymous LCP with O(log n)-bit certificates, hidden on the 1-forgetful graph θ(5,5,5). The constant-size LCP of Lemma 4.1 also refutes it for the class of all bipartite graphs, through a false reduction step in its proof.

## Layout

- `Papers/PODC<Year>/<ShortName>/` — one folder per paper (Lean library `Papers`): the Lean files, `README.md` and
  `differencies.md`.
- `Podc/` — Lean library `Podc`, now only `Podc/Basic.lean` (`import Cslib`). The shared library that used to live here
  (~19k lines) has been upstreamed to the CSLib fork; the papers import the CSLib modules directly.
- `lakefile.toml` — depends on CSLib (`vasnesterov/cslib`, branch `podc`), which pins Mathlib.
