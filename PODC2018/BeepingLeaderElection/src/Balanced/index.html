A variable is *`k`-balanced* if neighbouring values differ by at most `k`. To send a `k`-balanced message `m_u` it suffices to send its remainder `r_u = m_u mod M`, `M = 2k + 1`; the receiver `v`, knowing its own message `m_v` (and remainder `r_v`), decodes `m_u = m_v + r_u − r_v − ⌊(r_u − r_v)/(k+1)⌋ · M`. * `decodeTrunc_correct` — the decoding formula is correct when the rounding `⌊·⌋` is read as rounding **toward zero** (`Int.tdiv`); * `decodeFloor_table2` / `decodeFloor_false` — read literally with the floor, the formula is wrong: in the paper's own Table 2 (`k = 4`, `m_v = 19`, `m_u = 18`, so `r_u = 0`, `r_v = 1`) it decodes `27` instead of `18`; `decodeFloor_eq` shows that the floor formula is correct iff `r_v ≤ r_u` or `r_u − r_v = −(k+1)`, and decodes `m_u + M` otherwise (also for some `m_u > m_v`, `decodeFloor_wrap`); * `balancedDecode` — a clean decoder (the unique `m ≡ r_u (mod M)` with `|m − m_v| ≤ k`), with its correctness (`balancedDecode_eq`), specification and uniqueness, and a natural-number variant `decodeNat` (the paper uses it for prefix lengths with `k = 6`, `M = 13`). -/ namespace Podc.BeepingLeaderElection /-! ### The paper's decoding formula -/ /-- The paper's decoding formula of Section 3.1.2, with the rounding read as truncation toward zero: `m_v + r_u − r_v − tdiv(r_u − r_v, k+1) · (2k+1)`. -/ def decodeTrunc (k : ℕ) (mv ru rv : ℤ) : ℤ := mv + ru -
