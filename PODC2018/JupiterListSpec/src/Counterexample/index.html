With two clients: 1. `c₀` inserts `x` at position 0; it reaches the server and `c₁`; 2. `c₀` invokes `Del(5)` on `[x]` (deletes the last element `x`), `c₁` invokes `Ins(b, 1)` on `[x]` (appends `b`); 3. the server processes `Del(5)` first, then `Ins(b, 1)` (transformed against `Del(5)`: `1 ≤ 5`, unchanged); `c₀` applies `Ins(b, 1)` to `[]` and gets `[b]`; `c₁` transforms `Del(5)` against its own `Ins(b, 1)`: `5 ≥ 1`, so `Del(6)`, which on `[x, b]` deletes the last element `b`; 4. both clients read: `c₀` reads `[b]`, `c₁` reads `[x]`, although both have seen all three updates. This violates the convergence property (with visibility = happened-before), hence the weak list specification, for Jupiter (`jupiter_raw_counterexample`) and for CJupiter (`cjupiter_raw_counterexample`). The violation of `A_weak` does not depend on the choice of the abstract execution: no well-formed abstract execution complying with the run is in `A_weak` (`cjupiter_raw_not_weak_any`, `jupiter_raw_not_weak_any`), because `c₁`'s final `Read` misses `c₁`'s own insertion of `b`.
