For odd `k = 2t + 1` this says that `t` rounds do not suffice. But `t` rounds suffice, even for a proper **2**-colouring: in the `(2t+1) × (2t+1)` grid, the numbers of nodes at distance `0, 1, …, t` from a node `u` (which `u` knows after `t` rounds) determine the colour class (`(row + column) mod 2`) of `u`. This file proves it for `k = 3, 5, 7, 9, 11` by a finite computation (`decide +kernel`); `Theorem26General.lean` proves it for every odd `k` (`theorem_2_6_false_odd`), using only the number of nodes at distance exactly `t`. The algorithm is a genuine `t`-round LOCAL algorithm in CSLib's sense (`Cslib.Local.IsLocal`: a node only uses the edges at distance `< t` and nothing about identifiers), so it is also `BallLocal t`. The lower bound that the paper's argument actually proves is `2r + 3 ≤ k` (`theorem_2_6`); for odd `k` it is tight by the present counterexample. -/ namespace Podc.SparseColoringLB open SimpleGraph
