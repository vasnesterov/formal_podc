Silence — PODC 2018

Guy Goren, Yoram Moses. Silence. PODC 2018. DOI 10.1145/3212734.3212768. Formalized version: arXiv 1805.07954 v1 (the only version, with Appendices A–D); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. The Silent Choir Theorem, the lower bounds of Theorem 3 and the three matching AC protocols (STEALTH, D2, D1f1) hold, and so do the Appendix D bounds and protocol. The protocol proofs treat the consensus sub-protocol as a black box, which does not work: saving them took a concrete max-floodset consensus and a new argument across six lemmas. The rest needs local changes: Theorem 3 lacks the bound for D = 1, which "completely characterize" needs, and Appendix D's 1-bit encoding of huh? does not say how it is decoded.

Mistakes in the paper

🔧 §4.2, "completely characterize" (Theorem 3 for D = 1)

§4.2 says the three protocols make the bounds of Theorem 3 tight, but for f = 1 and D = 1 Theorem 3 gives only M ≥ n, while D1f1 uses n² − n.

Impact. The claim is incomplete, and true after adding the missing bound: if all processes decide by time 1, then M ≥ n(n − 1). It follows from the Silent Choir Theorem (theorem3_D1).

✏️ Slips

  • §4.2, STEALTH and D2: self-messages are under-specified. Under readings the text allows, STEALTH violates Commit Validity: if process 0 checks only "n − 1 first-round messages", ignoring its own vote, then with v₀ = 0 and no failures everyone commits (Stealth.literal0_not_solvesAC, Stealth.literalErr_not_solvesAC). Separately, suppose a choir member that sent err but received none still commits. With n = 3, f = 1, v₂ = 0, and process 0 crashing in round 3, process 1 commits. Both runs violate Commit Validity. Fig. 3 (D2) has the same self-message ambiguity. These are under-specified descriptions, not wrong protocols: the intended reading is "sent or received", as the D2 prose says, and we verify that reading (Stealth.solvesAC, D2.solvesAC).

  • Lemma 2 and Corollary 2 fail when the receiver i has crashed by time m: a crashed i "receives nothing", but its state is ⊥ and it knows nothing (corollary2_literal_false). Counterexample: n = 3, f = 1, S = {1, 2}, φ = (v₁ = 1 ∨ v₂ = 1). Process 0 crashes in round 1, and every value is 1. We prove both results for an i that is alive at time m; Lemma 1 is unaffected (lemma2, corollary2, lemma1).

  • The D1f1 prose (§4.2) says "all[1] message in the second round" where it means the third round.

  • Theorem 2's proof says "k_y < ℓ − 1" where it needs k_y ≤ ℓ − 1.

Typos

  • Theorem 3(c)'s proof says "chain from j" where it means "from i".

  • Fig. 1 sends all[1] to {0, …, f} instead of {1, …, f}.

Proof gaps in true statements (5)STEALTH, D2, 1.5D · Appendix D, 1.5D · Lemma 11 · Lemma 18 · Theorem 2

🛠️ STEALTH, D2, 1.5D (consensus used as a black box; Lemmas 5, 8, 9, 11, 17, 18)

The protocols call B.1.Consensus(f − 1), which tolerates only f − 1 crashes, but the Commit Validity proofs (Lemmas 5, 9, 17) need its Validity in runs where f crashes can happen during the consensus, and the Agreement proofs (Lemmas 8, 11, 18) never check the f − 1 bound.

Impact. Statements true; repaired with a concrete max-floodset consensus (Stealth.solvesAC, D2.solvesAC, MidRound.OnePointFive.solvesACMid).

Details

The bad runs include e.g. v_j = 0 with nothing failed earlier.

Repair

With a concrete max-floodset everything works. Its validity holds for any number of crashes. When the inputs are mixed, a crash happened before the consensus, so its f rounds contain a round with no crash.

🔧 Appendix D, 1.5D (the 1-bit encoding of huh?)

The paper sends huh? as "quiet to {i+1..i+f}, 1 to the rest" but never says how a receiver decodes it, and the natural decoding that ignores silence from a predecessor breaks Agreement (MidRound.OneBit.oneBit_not_solvesACMid).

Impact. The encoding is under-specified: a decoding that also reads silence from a predecessor as huh? makes the 1-bit protocol correct (MidRound.OneBitFixed.solvesACMid); with huh? as a separate message 1.5D is correct as well (MidRound.OnePointFive.solvesACMid). The appendices appear only in the arXiv version.

Details

  • Decoding "a 1 from a non-predecessor means huh?" (silence from a predecessor ignored). Agreement fails. Counterexample: n = 5, f = 2, all values 1. Process 4 crashes in round 1 reaching only processes 1 and 2; process 3 crashes silently in round 2. Processes 1 and 2 commit at time 1½ and halt, while process 0 runs the consensus alone and aborts.

  • Decoding that also reads "no all[1] from a predecessor" as huh?. The 1-bit protocol is correct.

🔧 Lemma 11 (D2 agreement)

The process c_j that received j's vote need not "send j's id to all": if it committed, it is silent in round 3.

Impact. Statement true: agreement then follows from the biased-to-1 property instead (D2.solvesAC).

🔧 Lemma 18 (1.5D agreement)

"This correct process will start the consensus protocol with v̂ = 1" assumes that it takes part in the consensus, which is not shown.

Impact. Statement true: any uncommitted process that later decides reaches everybody with its huh? (MidRound.OnePointFive.solvesACMid).

🔧 Theorem 2 (Silent Choir)

A process h ∈ S_j^r(m−1) may already have crashed in r before it is reached, and the paper's r′ makes h crash later, so h behaves differently in r′.

Impact. Statement true; fixed by keeping h's earlier crash (silent_choir).

Details

Messages to crashed processes count in chains, so this can happen.

The formalizationmodel, Lean names of the results, trust

Model (Cslib/Computability/Distributed/SyncCrash/Model.lean in CSLib, built on CSLib's LockStep).

  • Network and timing: a complete network, synchronous rounds; round t + 1 runs from time t to time t + 1.

  • Protocols are deterministic and history based: the local state is (initial value, received inboxes). The state becomes ⊥ after a crash.

  • Crashes: a run is given by its inputs and its crash pattern. A process crashing in round c ≥ 1 reaches an arbitrary subset reach p in round c and nothing afterwards. γ_f allows at most f crashes.

  • Decisions are taken at the start of a round from the current state; crashed processes do not decide.

  • Knowledge is semantic: K_i φ holds iff φ holds in every admissible run where i has the same state.

  • Messages are counted with Set.encard, so runs with infinitely many messages are included.

  • There are no self-messages; protocols read their own state instead, and counts agree with the paper's.

  • AC (Defs.lean): Decision, uniform Agreement, Commit Validity and Abort Validity on every admissible run. The common case is the nice run, where all values are 1 and nobody fails.

  • Appendix D (MidRound.lean): the same runs, with mid-round decisions. Such a decision is performed only if the process finished its sending phase.

  • Consensus inside the protocols: max-floodset (Cslib/Computability/Distributed/SyncCrash/Floodset.lean).

Not formalized. The rules S1–S3 appear only as Lemmas 1, 2 and Corollary 2. The remark that the γ_f protocols are also correct in γ̃_f is not proved. The GW and Dwork–Skeen protocols are not formalized.

Trust. There is no sorry. The listed theorems use only the axioms propext, Classical.choice and Quot.sound. The lower bounds' hypotheses can be satisfied: STEALTH and D2 solve AC in γ_f for every 1 ≤ f < n, and D1f1 does so for f = 1. Each protocol is verified in all admissible runs, not just the nice run. The model reuses CSLib Cslib.Byzantine.LockStep (Protocol, hist). The crash model with knowledge and message chains, and the floodset lemmas, are in CSLib (Cslib/Computability/Distributed/SyncCrash/); its message chains are journeys and its knowledge operator is the K of an interpreted system (Cslib/Computability/Distributed/SyncCrash/System.lean).
