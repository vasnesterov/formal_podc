import Papers.PODC2018.Silence.MidRound15D /-! # A 1-bit decoding of `huh?` under which 1.5D is incorrect Appendix D of Goren–Moses says that, as in STEALTH, all messages of the 1.5D protocol (Figure 5) can be single bits: "The only non-trivial one is `huh?`, implemented in 1-bit by: quiet to `{i+1, …, i+f} % n`; `1` to the rest." So in round 2 a process that is not `ok` sends `1` only to the processes outside its successor set `nb i`. The paper does not say how receivers decode this. This file takes the decoding where a round-2 `1` from `j` counts as `all[1]` if the receiver is in `nb j`, and as `huh?` otherwise; silence from a predecessor `j` (receiver in `nb j`) is ignored. Under this decoding the protocol violates Agreement (`oneBit_not_solvesACMid`): `n = 5`, `f = 2`, `nb i = {i+1, i+2}`, all values `1`; process `4` crashes in round 1 reaching only `1, 2`; process `3` crashes in round 2 sending nothing. Processes `1, 2` are `ok` and commit in mid-round 2. Process `0` is not `ok`; its `huh?` goes only to `3, 4` (crashed), so `1` and `2` hear no `huh?` and halt. Process `0` received no `all[1]` (`0 ∈ nb j` only for `j ∈ {3, 4}`), so it runs the consensus alone with value `0` and aborts at time `f + 2 = 4`. The counterexample covers only this decoding. If silence from a predecessor is also read as `huh?` (an `ok` predecessor would have sent `all[1]`), the 1-bit protocol is correct: `Papers.PODC2018.Silence.MidRound.OneBitFixed.solvesACMid` (`MidRound1BitFixed.lean`).
