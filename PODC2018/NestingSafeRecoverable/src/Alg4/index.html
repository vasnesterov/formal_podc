import Mathlib import Cslib.Computability.Distributed.SharedMemory.Linearization /-! # Algorithm 4 of [ABH18] (recoverable counter): two counterexamples Algorithm 4 builds a recoverable counter from an array `R[1..N]` of recoverable read/write objects (Algorithm 1). The paper's model (Section 2): a crash resets *all* local variables of the crashed process to arbitrary values; if the crash happens inside a nested recoverable operation, the system invokes the recovery function of the *innermost* pending recoverable operation, and when it completes the caller continues after the call ("once its recovery is completed, INC returns in line 5"). We give a concrete interpreter for Algorithm 4 composed with Algorithm 1, for `N = 2` processes, with exactly these semantics (volatile variables are reset to `0`, the most benign choice of "arbitrary values"), and two executions whose counter history is not linearizable: * `read_not_nrl`: process 1 crashes inside the nested `R[2].READ` called by the counter's `READ` (line 14). `R[2].READ.RECOVER` returns `R[2]`'s value, but the caller's `val` and loop index `i` are lost; the counter's `READ` returns `0` although an `INC` completed before it started. * `inc_recover_not_nrl`: process 0 crashes in `INC` when it is about to execute line 4 (invoke `R[p].WRITE`), so `LI_p = 4`; `INC.RECOVER` tests `LI_p < 4` and returns `ack` without incrementing (the prose says "before line 4 – INC is re-executed": the test should be `LI_p ≤ 4`). A later `READ` returns `0`. -/ namespace Podc.NestingSafeRecoverable.Alg4 open Cslib.SharedMemory /-- Counter operations. -/ inductive COp where | inc | read deriving DecidableEq /-- The counter object; `INC` returns `ack` (encoded as `0`). -/ abbrev counterObj : ObjSpec where State := ℕ Op := COp Resp := ℕ init := 0 δ s o := match o with | .inc => (s + 1, 0) | .read => (s, s) /-- Operations of the nested recoverable read/write objects (Algorithm 1). -/ inductive IOp where | read | write (v : ℕ) deriving DecidableEq /-- A frame of a nested Algorithm 1 operation on `R[obj]`: line `pc`, local `temp`, and the locals `flag, curr` of `WRITE.RECOVER`. -/ structure Inner where obj : Fin 2 op : IOp pc : ℕ temp : ℕ flag : Bool curr : Option ℕ deriving DecidableEq /-- A frame of a counter operation: line `pc`, `LI_p` (`li`, set at a crash), locals. -/ structure Outer where op : COp pc : ℕ li : ℕ temp : ℕ val : ℕ i : ℕ deriving DecidableEq /-- Configurations: Algorithm 1's shared variables of `R[1], R[2]` (the register `R` and the per-process pairs `S_p`), the counter's `Resp_p`, the frames of each process and the counter history (without crash/recovery steps). -/ structure then process 1 reads, crashing inside the nested `R[2].READ`. -/ def schedRead : List Ev := [.inv 0 .inc] ++ List.replicate 15 (.step 0) ++ [.inv 1 .read] ++ List.replicate 8 (.step 1) ++ [.crash 1] ++ List.replicate 20 (.step 1) /-- Process 0 crashes in `INC` about to execute line 4;
