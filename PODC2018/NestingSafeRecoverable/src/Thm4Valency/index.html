import Papers.PODC2018.NestingSafeRecoverable.Thm4Basic /-! # Theorem 4 of [ABH18], part 2: valency Valency is defined with crash-free extensions, as in the paper: `Val C x` — some crash-free extension of `C` (steps only) in which `x` has returned `0` (`false`). Main facts: * `val_or`: every reachable configuration is `p`-valent or `q`-valent; * `Biv.running`: in a bivalent configuration both processes are still running; * `agree_val`: configurations that look the same to one process `y` (memory and `y`'s local state), in both of which `p` and `q` are running, share a valency (run `y` solo, then the other process solo); * `exists_crit`: from a bivalent configuration, a crash-free extension leads to a *critical* configuration (bivalent, both successors univalent) — otherwise there is an infinite crash-free execution in which nobody returns, contradicting wait-freedom. -/ namespace Podc.NestingSafeRecoverable open Cslib.SharedMemory Cslib.SharedMemory.NRL Cslib.SharedMemory.NRL.Alg variable {P : Type} [DecidableEq P] {A : Alg P tasObj} {p q : P} /-- `x`-valency (paper: "`C` is `x`-valent if there exists a crash-free execution starting from `C` in which `x` returns `0` or has already returned `0`"). -/ def Val (C : A.Cfg) (x : P) : Prop := ∃ xs : List P, Ret (C.run (steps xs)) x false /-- Bivalence. -/ def Biv (p q : P) (C : A.Cfg) : Prop := Val C p ∧ Val C q lemma val_ext {C : A.Cfg} {xs : List P} {v : P} (h : Val (C.run (steps xs)) v) : Val C v := by obtain ⟨ys, hy⟩ := h exact ⟨xs ++ ys, by simpa [steps, Cfg.run_append] using hy⟩ lemma val_ext1 {C : A.Cfg} {x v : P} (h : Val (C.ev (.step x)) v) : Val C v := val_ext (xs := [x]) h lemma val_of_equiv {C D : A.Cfg} (h : Equiv C D) {v : P} (hv : Val C v) : Val D v := by obtain ⟨xs, hx⟩ := hv refine ⟨xs, ?_⟩ unfold Ret resps at hx ⊢ rw [← (h.run (steps xs)).2.2 v];
