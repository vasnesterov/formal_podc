Verdict: 🔧 Easy fix. Theorem 1 (RGA implements the strong list specification) fails for the protocol as literally written, because its insert procedure counts tombstones when it locates the insertion position, but a local index change that the paper's own definition of ins(a, k) dictates makes it hold. The main lower bound holds: any push-based protocol with at least three replicas that satisfies the weak list specification has metadata overhead Ω(D) (PODC Theorems 4 and 5), and we formalized the encoding/decoding proof completely, with two local repairs. The O(D lg k) upper bound for RGA was not checked.

Mistakes in the paper

🔧 Theorem 1 (RGA of Section 4.2 implements the strong list specification)

RGA as written violates condition (1c), because its insert locates the parent in s(N), which still contains tombstones: at one replica, ins(x,0); ins(y,1); del(x); ins(b,1) returns b y, while (1c) requires b at position 1 (RGA.literal_not_weak, RGA.literal_not_satisfies).

Impact. A local index fix that the paper's own definition of ins(a, k) dictates; with it Theorem 1 holds (RGA.theorem1_strong). State, messages and tree rule stay the same.

Details

The RGA do transition builds the new node "as described in the Insert procedure of Section 4.1". That procedure takes the parent p = a_{k−1} of s(N) = a₀ … a_{n−1}, a list that still contains the deleted (tombstoned) elements. However, ins(a, k) and condition (1c) count positions in the user-visible list s(N) \ T. In the example, before the last insert, s(N) = x y and the visible list is y. The parent of b is a₀ = x, so s(N) = x b y and the response is b y. But (1c) requires b at position min(1, 1) = 1. No abstract execution of this execution is in A_weak, let alone A_strong. The proof says only that "(1c) follows directly from the properties of the TI data structure". The same counterexample works with any number of replicas.

The intent is recoverable from the paper: Section 3 defines positions on the returned list, and Insert's prose says "the element to the left of the insertion position". The proof never reasons with the tombstone-counting index.

Repair

Take the parent in the visible list, p = w_{min(k,|w|)−1} with w = s(N) \ T. This is what the original RGA does, and it is what the meaning of ins(a, k) in Section 3 requires. With this fix we proved Theorem 1 (RGA.theorem1_strong).

✏️ Slips

  • Definition 10 (eventual visibility, TCS version only) lacks the network-connectivity assumption, so the TCS claim that RGA guarantees eventual visibility fails when replica 0 runs ins(a,0) and never sends its message while replica 1 reads forever (RGA.def10_needs_connectivity). Every read returns [], so by (1a) the insertion is visible to none of them, and no abstract execution in A_weak satisfies eventual visibility. Definition 10 asks that every execution with causal broadcast comply with such an abstract execution, but no protocol can do better. The assumption is evidently intended: the remark after Definition 10 says so, the proof of Theorem 1 relies on it, and under Definition 1 the claim holds (RGA.theorem1_eventualVisibility). PODC 2016 does not claim eventual visibility.

Typos

  • Section 4.1 is inconsistent about how a node names its parent. PODC 2016 declares p ∈ C ∪ {◦} (the parent's timestamp, with n′.p = n.t, as in the node (b, t_b, t_a) in the proof of appendix Lemma 15). Fig. 2 and the Insert procedure (p = a_{k−1}) instead name the parent by its element. The TCS version switches the declaration to p ∈ U ∪ {◦} but keeps n′.p = n.t and (b, t_b, t_a). We name parents by their element.

Proof gaps in true statements (2)Theorem 9, Claim 12 · Theorem 9

🔧 Theorem 9, Claim 12 (PODC Theorem 5, Claim 8): adjacency of the brackets

Claim 12 (PODC Claim 8) says that R₂'s read returns …[ᵢ₋₁ ]ᵢ₋₁… with the two brackets adjacent, because R₂ must be able to insert x "between" them, but the weak specification alone gives only the set of elements.

Impact. A few lines fix it, with no new idea (recover_correct).

Details

Adjacency follows because lo orders the read's response and also R₁'s response at ins ]ᵢ₋₁, which has the same elements, and lo is transitive on the read's response. We prove the read returns exactly R₁'s list (recover_correct, step hv).

🔧 Theorem 9 (PODC Theorem 5): the choice of σ_w

The paper takes σ_w to be R₁'s state after the final read, but in the general model a read may change the state, including the send buffer, so distinct pairs (q, m) need not have distinct internal states q.

Impact. Moving σ_w one step earlier repairs the counting (theorem9).

Repair

We take σ_w before the read, right after send(m_{d+3}), so its buffer is empty and its user-visible content is [∗]. The read only witnesses this content.

The formalizationmodel, Lean names of the results, trust

Model.

  • Asynchronous message passing, with no failures and no randomness (Section 2). A replica is a deterministic state machine. Its state is (q, buf) with a one-slot send buffer. A do(op, v) event is always enabled; its response is a function of the whole state (q, buf), and it may change the whole state. A send moves to (q′, ⊥) where q′ = sendStep r (q, buf) is arbitrary. This is exactly the protocol class of PODC 2016 (the TCS version is narrower: responses depend on q only and sends keep q), so Theorems 8–9 cover every protocol of either version. A send broadcasts the buffered message to every replica, the sender included, and empties the buffer. A receive is always enabled. All replicas use one common type Q.

  • An execution is a list of actions (an infinite sequence ℕ → Act for eventual visibility). A receive names the position of the send whose message it delivers; this makes messages unique, as the paper assumes. HB is Lamport's happens-before on positions. We formalize causal broadcast (Def. 2) and causal atomic broadcast (Def. 3), and sufficient connectivity (Def. 1) for infinite executions.

  • An abstract execution is a visibility relation vis on the positions of the do events. It must contain the replica order and be transitive and irreflexive (Def. 4). The execution and its abstract execution share event ids, so compliance (Def. 5) is built in. We drop the linearization H: on the hypothesis side this only weakens the hypothesis, and for RGA we show vis ⊆ <.

  • The user assumptions of Section 3 (UserOK): inserted elements are unique, and del(a) only deletes an element returned by the replica's previous operation.

  • Lower bound. PushBased P S Adm is Def. 13, relative to a class Adm of executions. Theorem 9 assumes push-based only on executions with causal atomic broadcast that respect the user assumptions. This hypothesis is weaker than the paper's, so the theorem is stronger; theorem9_causal is the paper's form. The list universe is infinite. The size of an internal state is the length of its code under an arbitrary injective encoding Q → List Bool.

  • RGA. TI trees are duplicate-free lists of nodes (a, (x, i), parent). s is the paper's DFS (children in decreasing timestamp order). A replica's state is (N, T) plus a buffer (A, K), and the new node's parent is taken in the visible list (see above).
