User operations `do(op, v)` are always enabled; their response `v = resp r σ op` is a function of the whole replica state `σ` (as in PODC 2016; the TCS version additionally requires it to depend on `q` only), and they may change the whole state (`doStep`). A `send` is enabled iff the buffer is non-empty; it broadcasts the buffered message, empties the buffer and moves to the internal state `sendStep r σ`, an arbitrary function of the state (PODC 2016: `Δ((q, m), send(m)) = (q′, ⊥)` for some `q′`). A `receive` is always enabled (`recvStep`). One common type `Q` serves all replicas (a family `Q r` embeds into a sigma type), so nothing is lost. * An **execution** is a list of actions. Messages are instrumented with unique ids: a receive names the *position* of the send event whose message it delivers (`Act.recv r src`). Broadcast goes to every replica, including the sender. * `exec P α` replays `α` from the initial configuration; `WF P α` is well-formedness: every send is enabled, every receive refers to an earlier send. * `HB α` is Lamport's happens-before on positions (replica order, send → receive, transitivity); `CausalBroadcast`, `CausalAtomic` are Definitions 2 and 3. -- CSLib candidate: the whole file is
