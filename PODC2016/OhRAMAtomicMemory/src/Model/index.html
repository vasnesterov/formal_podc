Processes are writers `W`, readers `R` and replica servers `S` (`Node`); the implemented object is CSLib's `register V v₀`. One protocol `proto Vr next` covers the four algorithms of the paper: * `Vr.mw = false`: the single-writer write protocol of OhSam (Algorithm 1, lines 18–31, 41–44): the writer picks the tag `next w tag` (`ts + 1`) and sends `writeRequest` to all servers; * `Vr.mw = true`: the multi-writer write protocol of OhMam (Algorithm 2, lines 73–94, 118–124): a `discover` phase, then the tag `next w maxTag` (`⟨maxTS + 1, w⟩`), then a `writeRequest` phase; servers update only if `tg < tg' ∧ write_ops[w] < write_op`; * `Vr.fast = false`: the read protocol of OhSam/OhMam (three exchanges: `readRequest`, server-to-server `readRelay`, `readAck`; the reader returns the value of the *minimum* tag among a majority of `readAck`s); * `Vr.fast = true`: the revised read protocol of OhSam'/OhMam' (Algorithm 3): servers also relay to the reader, who may return after a majority of relays carrying the same tag. * `Vr.fixAck`: `false` is the printed code, where the test of line 53 (`relays[r] = |S|/2 + 1`) is *outside* the `if` of line 51, so a stale `readRelay` re-sends a `readAck`; `true` nests it (our repair of the message complexity, see `Complexity.lean`). Tags live in any linear order `T` with bottom `⊥` (the tag of the initial value `v₀`) and are created by `next : W → T → T`: `fun _ t => t + 1` on `ℕ` for OhSam(') and `nextTag` on `Tag W = WithBot (ℕ ×ₗ W)` for OhMam(') (`⊥` stands for the initial server tags `⟨0, sᵢ⟩`). Each block of code between two `wait`s runs atomically. All waits (`wait until |ack| = |S|/2+1` and the fast-read condition) are evaluated in the message handler right after the reception that may make them true, so they are exactly the paper's `=` tests.
