Space Bounds for Reliable Storage — PODC 2016

Alexander Spiegelman, Yuval Cassuto, Gregory Chockler, Idit Keidar. Space Bounds for Reliable Storage: Fundamental Limits of Coding. PODC 2016. DOI 10.1145/2933057.2933104. Formalized version: arXiv 1507.05169 v1 (the only arXiv version); numbering follows it.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: ⚠️ Weakened. The main lower bound (Theorem 2, Corollary 2: unbounded storage, or a time when f + 1 objects each hold D bits of one write) is proved, after several repairs, only in the paper's own storage model ("every stored bit belongs to one write"), not for "any reliable storage algorithm": Theorem 1 ("every write adds at least log₂|U_s| bits") is false as stated, and it does not justify that model. Algorithm 2 (Section 3.1, the safe erasure-coded register) is not safe as written when k ≤ f, e.g. for replication with n = 3, f = 1 (Lean counterexample), and with the reader decoding the largest qualifying timestamp, Corollary 3 is proved. The adaptive algorithm of Section 5 was not checked, and whether the bound holds for algorithms that code across writes is open.

Mistakes in the paper

❌ Theorem 1 ("every write adds at least log₂|U_s| bits")

Theorem 1 (a write of u_s ∈ U_s adds at least log₂|U_s| bits) is false: with |U₁| = 5, |U₂| = 3 and an object that stores the minimum each time (⌈log₂ 5⌉ = 3, then ⌈log₂ 15⌉ = 4 bits), the second write adds one bit, less than log₂ 3 (theorem1_false).

Impact. The per-write property is lost: the cumulative bound of Lemma 1 is what is true in general (theorem1_cumulative), and it says nothing about a single write. The paper's main use of Theorem 1 is the storage model of Section 4 (next item).

Details

With padding, a write can add no bits at all. The proof subtracts two lower bounds, which is invalid. Its induction hypothesis ("the object stores exactly log₂(|U₁|⋯|U_{s−1}|) bits") assumes minimal storage. The statement holds only for minimal encodings and power-of-two set sizes, the simplification made in Lemma 1's proof.

⚠️ Section 4 storage model ("each stored bit is associated with a particular write")

The paper adopts this model "without loss of generality" on the strength of Theorem 1, but neither Theorem 1 nor its correct cumulative version justifies it, so the abstract's lower bound for "any reliable storage algorithm" is proved only for algorithms that do not code across writes.

Impact. The main lower bound (Theorem 2, Corollary 2) holds in the paper's own model (theorem2, corollary2), which covers replication and per-value erasure coding.

Details

Lemma 1 concerns one object that must keep all its inputs recoverable from its own bits. A register emulation may discard old values, spread a value over several objects, or store functions of several values (e.g. v₁ ⊕ v₂). Section 4's bookkeeping (C⁺, F(t), Observation 1, Lemma 3) depends on this attribution. Our black-box model makes it hold by construction: values are opaque, and stored data are blocks, each a fixed function of one written value, which clients only copy. Re-encoding another client's value is excluded as well.

🔧 Algorithm 2 (Section 3.1, line 16) and Lemma 9 (safety for k ≤ f)

Algorithm 2 is not safe when k ≤ f: with replication (k = 1, n = 3, f = 1) a read with no concurrent write may return the stale value of an earlier write, because line 16 lets the reader decode any timestamp with k pieces (Safe.not_stronglySafe, Safe.not_weakRegular).

Impact. A local fix to the reader: decoding the largest qualifying timestamp makes Algorithm 2 wait-free and strongly safe with at most n stored pieces, so Corollary 3 holds (Safe.corollary3).

Details

Replication is explicitly allowed by the paper. Write w₁ stores on objects 1 and 2 and returns. Then w₂ reads objects 1 and 2, stores on 2 and 3, and returns. A later read hears from objects 1 and 2. Both timestamps have one piece, so the reader may return w₁'s value. This violates safety, since the read has no concurrent write. Lemma 9's proof misses this case. For k > f a stale timestamp cannot collect k pieces. The Lean counterexample uses the "smallest qualifying timestamp" reading of line 16.

Repair

The reader takes the largest qualifying timestamp; then Corollary 3 is proved (Safe.corollary3).

🔧 Observation 1 (under-specified storage measure)

C⁺(t) counts writes whose bits are in base objects or in other clients, so Observation 1 (storage ≥ |C⁺(t)|) holds only if the storage also counts copies of other writers' data held by clients, which the paper does not say.

Impact. We use that measure in the hypothesis of Theorem 2 (Alg.storage, obs1). The conclusion of Corollary 2 is about base objects only.

✏️ Slips

  • Theorem 3 / Corollary 4 (Section 5, not formalized): "with at most c < k concurrent writes the storage is bounded by (c + 1)D/k bits" is false as written, since the initial configuration already stores (2f + k)D/k bits. Lemma 12 has the intended (2f + k)(c + 1)D/k, and it assumes c < k − 1.

  • Theorem 2 (number of clients): the bound needs at least S + 1 clients, S concurrent writers and a reader, while the paper only says Π is finite. The assumption is in the opening of Section 4 and in the abstract ("no bound on the concurrency level"); we prove the theorem with S + 1 clients (theorem2, theorem2_run).

  • Lemma 12's proof writes ts' ≥ ts₁ > ts₁, meaning ts' ≥ ts₁ > ts₂.

Typos

  • Lemma 12's proof cites itself (meant Lemma 11).

  • Corollary 5 says "WF-termination" for FW-termination.

  • In Observation 2's proof, |B| = N − f should be n − f.

Proof gaps in true statements (3)Lemma 2 · Lemma 3 · Observation 2

🔧 Lemma 2 (adaptive choice of encoders)

The proof says that choosing adaptively among m encoders forces log₂ m extra bits, which is false: two encoders of a 4-element set into 2 bits, chosen adaptively, decode without an extra bit (lemma2_no_extra_bits).

Impact. The lemma is trivially true: an adaptive choice of encoders is one fixed function (lemma2).

🔧 Lemma 3 (copies of a write's bits)

The proof ignores copies: a client may read another writer's bits and spread them over several objects.

Impact. The lemma holds in the black-box model (inv_exec, lemma3).

Repair

The claim holds because Ad never lets an RMW touch an object of F(t). A batch of D bits is frozen in its object the moment it is stored, and smaller batches never add up to D. Our invariant states exactly this.

🔧 Observation 2 (reads returning a completed write)

The proof says "no value satisfying weak regularity can be returned", which ignores that the read may return the value of an earlier completed write concurrent with w, not only one in C(t), so the argument works only at the first completion.

Impact. Corollary 1, the only use, applies it at the first completion, where this does not matter.

Repair

Alg.reader_restore concludes that the objects of B hold D bits of some write of the history, which covers both cases.

The formalizationmodel, Lean names of the results, trust

Model.

  • Asynchronous fault-prone shared memory (Section 2.1). Deterministic clients C (finite) trigger arbitrary atomic RMWs on base objects N. A triggered RMW stays pending until an exec event applies it and delivers the response, and a client may have several pending RMWs. Taking effect and responding are one event. This only restricts the runs, which makes the hypotheses weaker and the lower bound stronger.

  • Crash failures of clients and of at most f base objects. Failures are not events: a failure pattern enters the fairness predicate Fair (crashed clients take finitely many steps, crashed objects execute finitely many RMWs, correct clients are scheduled infinitely often, RMWs of correct clients on correct objects eventually take effect). Lock-freedom and weak regularity (MWRegWeak) are as in Section 2.2, quantified over all runs and all value assignments. No randomness. f < n/2 is not needed for the lower bound.

  • Black-box storage. A write carries no value; write w has value val w for an arbitrary value assignment. Data are blocks (w, j) of sz j ≥ 1 bits with contents enc j (val w), where enc is the algorithm's code (e.g. erasure-code pieces or full replicas). Blocks only flow: they are stored by RMWs from the client's holdings, carried back by responses, and created only by their writer. A read's output depends only on the contents of the blocks it holds. D = ⌈log₂|V|⌉; F(t) = objects holding D bits of one write. Storage = bits in base objects plus copies held by clients other than the writer.

  • Proof structure as in the paper: the adversary Ad (Definition 1) runs S writes. The information-theoretic step (restore): a reader that, for every value assignment, returns the value of one of finitely many writes holds D bits of one of them.

Lemma 4's proof can be simplified: iterating the growth of T_cᵢ is unnecessary; it suffices to crash F(t) itself in the solo run (solo_progress, rule1_infinitely_often).

Theorem 2's fair run r' cannot be literally "identical to r", because clients that receive finitely many responses must stop taking steps. We remove the later steps of those clients and show by simulation that nothing else changes. Liveness of each RMW of the other clients uses the oldest-first rule of Ad.

Not formalized. Section 5 (the adaptive strongly regular algorithm, the corrected Theorem 3, Lemmas 10–22, and the case c = k − 1 that Lemma 12 leaves out); Section 3.2 (intuition); the remark that the same bound applies to message passing systems with limited channel capacity. Whether the lower bound holds for algorithms that code across writes, or re-encode another client's value, is not settled by the paper and not addressed here.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. The model is self-contained (Mathlib only). The hypotheses of Theorem 2 are satisfiable: a single-object atomic register algorithm is lock-free and weakly regular in the model (NonVacuity.lean); for f ≥ 1 no algorithm satisfying them was formalized.
