import Papers.PODC2016.RWLockRMRTradeoff.Alg.Model /-! # Two bugs in Algorithm 1 of Hendler (PODC 2016), with explicit executions 1. **Mutual exclusion fails for the literal line 51.** If `C[i].read() = W[i].read()` (line 51) is evaluated left to right (`C` first), a helping reader can read `C[i]` while a reader that entered the CS without waiting is still counted, and then read a `W[i]` that has meanwhile caught up because *other* readers started waiting. With `f(n) = 1` and three readers the writer then enters its CS together with a reader (`mutex_violation_literal_order`). This holds for either version of line 47. 2. **Deadlock freedom fails for the literal line 47.** Line 47 tests `op` (the opcode read on entry, line 32) instead of `op'` (read on exit, line 41). A reader that entered the CS while `RSIG = <seq, PREENTRY>` then never calls `HelpWCS` on exit, although the writer waits for it in line 21. With one reader the writer waits in line 21 forever while the reader stays in the remainder section (`deadlock_literal_line47`). This holds for either order in line 51. -/ namespace Podc.RWLockRMRTradeoff.Alg open Who /-! ### Mutual exclusion violation -/ /-- Three readers in a single group (`f(n) = 1`), literal order in line 51. -/ def cfgME (l47 : Line47) : Cfg 3 1 := ⟨.cw, l47, fun _ => 0⟩ /-- The schedule: the writer runs lines 6–16 (reading `C[0] = 0`); reader 0 starts and reads `RSIG = <0, PREENTRY>` in line 32, so it enters the CS; the writer writes `<0, WAIT>` to `RSIG` (line 18), reads `C[0] = 1` (line 20) and waits in line 21; reader 1 starts, reads `WAIT`, increments `W[0]` and reads `C[0] = 2` in line 51; reader 2 starts, reads `WAIT` and increments `W[0]` to 2; reader 1 reads `W[0] = 2 = C`-value and CASes `WSIG[0]` to `<0, CS>` (line 52); the writer enters the CS. -/ def schedME : List (Who 3) := [writer, writer, writer, writer, writer, reader 0, reader 0, reader 0, writer, writer, reader 1, reader 1, reader 1, reader 1, reader 1, reader 2, reader 2, reader 2, reader 2, reader 1, reader 1, writer] /-- **Line 51 as written violates Mutual Exclusion (Lemma 8 / Lemma 9 fail).** With the literal left-to-right evaluation of `C[i].read() = W[i].read()`, there is a reachable configuration in which the writer and reader 0 are both in the critical section (for either version of line 47). -/ theorem mutex_violation_literal_order (l47 : Line47) : ∃ s, Reachable (cfgME l47) s ∧ s.writerInCS ∧ s.readerInCS 0 := by refine ⟨run (cfgME l47) schedME init, reachable_run _ .init _, ?_⟩ cases l47 <;> (unfold State.writerInCS State.readerInCS; decide) /-- Hence the literal algorithm does not satisfy Mutual Exclusion. -/ theorem not_mutualExclusion_literal_order (l47 : Line47) : ¬ MutualExclusion (cfgME l47) := by intro h obtain ⟨s, hs, hw, hr⟩ := mutex_violation_literal_order l47 exact h s hs hw 0 hr /-! ### Mutual exclusion violation caused by line 47 -/ /-- One reader, one group, literal line 47, either order in line 51. -/ def cfgME47 (order : ReadOrder) : Cfg 1 1 := ⟨order, .op, fun _ => 0⟩ /-- The schedule: writer passage 0 runs to its exit (line 26 pending); the reader starts, reads `RSIG = <0, WAIT>` and is about to wait (line 34); the writer completes passage 0 and starts passage 1 up to line 11 (`WSIG[0] = <1, ⊥>`, `RSIG = <1, NOP>`); the reader helps in vain, stops waiting, passes through the CS and in its exit section reads `RSIG = <1, NOP>` in line 41;
