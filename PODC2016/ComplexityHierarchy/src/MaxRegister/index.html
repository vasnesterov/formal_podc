import Mathlib import Cslib.Computability.Distributed.SharedMemory.Valency /-! # One max-register is not enough (Theorem 4.1 of EGSZ'16) A *max-register* (Aspnes–Attiya–Censor) over a linearly ordered set `X` supports `read-max()` (returns the value) and `write-max(x)` (sets the value to `max value x`, returns nothing). `theorem_4_1`: obstruction-free binary consensus for `n ≥ 2` processes cannot be solved with a single max-register. Proof (the paper's interleaving argument). Let `p` have input `0` and `q` input `1` (all other processes input `1`, they never move). From the initial configuration, `p` alone decides `0` and `q` alone decides `1`. We interleave the two solo runs so that each process sees exactly what it sees in its own solo run: the real memory is always `max mp mq`, where `mp`, `mq` are the values of the register in the two solo runs. Scheduling rule: a process whose next step is a read (or its decision) moves whenever it is safe, i.e. when its own solo value dominates the other one; otherwise both unfinished processes are poised to `write-max`, and the one with the smaller argument moves. The invariant (`Inv`): * (A) a process that is not poised to write has `m_other ≤ m_self`; * (B) a process poised to `write-max(x)` has `m_other ≤ max m_self x`. When both have finished, both `0` and `1` have been decided: contradiction. The paper describes the schedule in segments ("let `p` take steps until it is next poised to perform `write-max`"); our step-by-step rule is equivalent. -/ set_option linter.unusedSectionVars false
