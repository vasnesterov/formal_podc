import Papers.PODC2016.ComplexityHierarchy.BufferLB import Cslib.Computability.Distributed.SharedMemory.Model import Cslib.Computability.Distributed.SharedMemory.LinPoints /-! # A history object from a single ℓ-buffer (Lemma 6.1 of Ellen–Gelashvili–Shavit–Zhu, PODC 2016) [EGSZ16] F. Ellen, R. Gelashvili, N. Shavit, L. Zhu, *A Complexity-Based Hierarchy for Multiprocessor Synchronization*, PODC 2016 (arXiv 1607.06139), Section 6.1. A *history object* supports `append x` and `get-history`, which returns the sequence of all values appended so far. Lemma 6.1: a single `ℓ`-buffer simulates a history object with at most `ℓ` appending processes and any number of readers. **Algorithm.** Each value written to the buffer is a pair `(h, x)` of a history `h` and an appended value `x`. * `append x`: perform `get-history` to obtain `h`, then `ℓ-buffer-write (h, x)` (linearization point: the write). * `get-history`: `ℓ-buffer-read` gives `a₁, …, a_ℓ` (`a_ℓ` most recent, `aᵢ = (hᵢ, xᵢ)`); if the buffer holds fewer than `ℓ` entries return their `xᵢ`; otherwise let `h` be the longest `hᵢ`; if `x₁ ∈ h` return the prefix of `h` before `x₁` followed by `x₁, …, x_ℓ`, else return `h, x₁, …, x_ℓ` (linearization point: the read). The paper assumes w.l.o.g. that no value is appended twice, "achieved by having a process include its process identifier and a sequence number". We implement this: internally every appended value is tagged `(p, c, x)` (`p` the appender, `c` its number of previous appends); `get-history` strips the tags. Helper definitions live in the namespace `HistBuf`. ## Main results * `recon_correct`: the combinatorial heart of the proof — if the writes so far satisfy the invariant `GoodW` (each recorded history is a prefix of the earlier writes, a process's later append read after its earlier write, at most `ℓ` appenders, distinct tags), then the reconstruction of the buffer content is exactly the sequence of all writes. * `lemma_6_1`: the implementation `histImpl ℓ S` (appenders restricted to `S`, `|S| ≤ ℓ`) is linearizable (CSLib's `Impl.Linearizable`). ## Notes on the proof The paper argues by induction on the number `k` of writes before a read, applying the induction hypothesis to the `get-history` operations inside the `ℓ` appends whose entries are in the buffer. We instead keep a ghost list `W` of all writes and prove the step invariant `HistBuf.Inv`: the history stored by every write is the prefix of `W` read by its append (`GoodW.pre`); then `recon_correct` (the paper's case analysis, including the "Figure 1" case where the longest history does not contain `x₁`) shows that every read reconstructs all of `W`. The key combinatorial step: if the longest stored history `h_m` had fewer than `k - ℓ` entries, the `ℓ` appends in the buffer would be pairwise concurrent, hence by `ℓ` distinct processes, hence by all appenders; the owner of write number `|h_m|` (before the window) is one of them, so its later append read after that write, contradicting the maximality of `h_m`. Model checking (exhaustive, all interleavings; `ℓ ≤ 4`, up to `ℓ` appenders with up to 6 appends each) confirms the lemma, and finds that the bound on appenders is tight for this algorithm: with `ℓ + 1` appenders a reader can miss an append (e.g. `ℓ = 1`: `p` and `q` both read `⊥`, `q` writes `([], b)`, then `p` writes `([], a)`; a reader then reconstructs `[a]` instead of `[b, a]`). ## Deviations from the paper * Values are tagged internally with `(process, sequence number)` (the paper's w.l.o.g.). * The buffer content is a list (most recent first) of length `≤ ℓ` instead of a vector padded with `⊥`; the initial content is empty. * The tie-breaking among equally long histories is "first in the buffer" (the paper leaves it open; all candidates are equal anyway). -/ set_option linter.unusedSectionVars false namespace Cslib.SharedMemory.ComplexityHierarchy open Cslib.SharedMemory Impl /-!
