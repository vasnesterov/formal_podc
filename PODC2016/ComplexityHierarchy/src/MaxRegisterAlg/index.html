Zhu, *A Complexity-Based Hierarchy for Multiprocessor Synchronization*, PODC 2016 (arXiv 1607.06139), Section 4. `theorem_4_2`: obstruction-free `n`-valued consensus can be solved by any set of processes using two max-registers `m₁`, `m₂` over `S = ℕ × {0, …, n-1}` ordered lexicographically, both initially `(0, 0)`. ## Main results * `theorem_4_2`: Theorem 4.2 (`n` values, processes `Fin n`). * `theorem_4_2_general`: the same for `m ≥ 1` values and an *arbitrary* type of processes (the paper: "for any number of processes"). * `TwoMax.alg_safe`: agreement and validity in every finite execution (not only one-shot ones); `TwoMax.alg_obstructionFree`: CSLib's `Impl.ObstructionFree` (from every reachable configuration). * `TwoMax.encode_strictMono`: the paper's encoding is an order embedding. ## The algorithm (paper's description) A process first performs `write-max (0, x)` on `m₁` (`x` its input). Then it alternates between a *scan* of `(m₁, m₂)` and a `write-max`: if the scan returns `m₁ = (r+1, x)`, `m₂ = (r, x)` it decides `x`; if `m₁ = m₂ = (r, x)` it performs `write-max (r+1, x)` on `m₁`; otherwise it performs `write-max` on `m₂` with the value of `m₁` in the scan. The scan is the *double collect*: read `m₁` then `m₂` repeatedly until two consecutive collects return the same pair. ## Modelling choices / deviations from the paper * The max-registers are over the lexicographic order `ℕ ×ₗ Fin n` directly (`Val n`), as the paper itself says "we may assume". The paper's encoding `(r, x) ↦ (x+1)·yʳ` (`y > n` prime) is an order embedding into `ℕ` (`encode_lt_encode_iff`, `encode_strictMono`), so this is no restriction. * The local state of a process is just its program counter `Ph n`; after a `write-max` a new scan starts from scratch (no previous collect). * As in the racing-counters files, a process that has decided and is invoked again returns its decision immediately; processes never invoked do nothing. All inputs are allowed. ## Proof (differs from the paper's presentation, same idea) The double-collect scan returning `(a, b)` is linearized at the read of `m₂` in its *first* collect: at that moment `m₂ = b` and, by monotonicity of `m₁` (read `a` before and after), `m₁ = a`. Instead of reasoning about times we keep a *ghost set* `Snap` of all pairs `(m₁, m₂)` present at *every* read of `m₂` (whether or not the scan later succeeds). The invariant (`Inv`) says: `Snap` is a chain for the componentwise order and lies below the current memory; `m₂ ≤ m₁`; whenever `m₁` (or the first component of a snapshot, or a pending `write-max` to `m₁`) is `(j+1, x)`, the pair `((j, x), (j, x))` is in `Snap` (`Good`); and every process's program counter is justified by a snapshot (`LocOK`), in particular a decided process has a snapshot `((r+1, x), (r, x))`. Agreement then follows from the chain property by the paper's downward induction (`agree_aux`). ## Remarks on the paper's proof The argument is correct. Minor issues: the sentence "Note that `(r, x) ≺ (r′, x)`, so `j ≤ r′`" is a typo for `(r, x) ≺ (r′, x′)` (established a few lines earlier); and the proof's "this scan occurred after the scan by `p`" implicitly uses linearization points of the (non-atomic) double-collect scans, which exist because both registers are monotone. Validity needs a small extra observation not spelled out in the paper: a value `(0, 0)` in `m₁` may come from the initialization rather than from an input, but a scanning process has already written `(0, x)` with its own input `x`, so if it sees `m₁ = (0, 0)` then `0` is an input. -/ set_option linter.unusedSectionVars false namespace Cslib.SharedMemory.ComplexityHierarchy open Cslib.SharedMemory
