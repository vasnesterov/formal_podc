Ellen, R. Gelashvili, N. Shavit, L. Zhu, *A Complexity-Based Hierarchy for Multiprocessor Synchronization*, PODC 2016 (arXiv 1607.06139), Section 6.1. The processes are split into `k` groups of at most `ℓ` processes; group `g` uses the `ℓ`-buffer `g` as a history object (Lemma 6.1, `BufferAlg.lean`) to which its members append their increments. The racing-counters algorithm (Lemma 3.1) is run on the `m`-component counter whose component `v` is the number of `v`-increments in all histories; a `scan` is an obstruction-free *double collect* of the `k` histories. The algorithm is flattened (CSLib has no composition theorem): `BufCons.alg` inlines the history-object operations of Lemma 6.1 (`HistBuf.recon`) and the double collect into the racing-counters algorithm. Helper definitions live in the namespace `BufCons`. ## Main results * `BufCons.alg_safe`: agreement and (strong) validity in every finite execution (one-shot or not), for any grouping with at most `ℓ` processes per buffer and threshold `n ≥ |P|`. * `BufCons.alg_obstructionFree`: CSLib's `Impl.ObstructionFree`. * `theorem_6_3`: Theorem 6.3 — `⌈n/ℓ⌉` initially empty `ℓ`-buffers suffice for obstruction-free `m`-valued consensus among `n = |P|` processes (`ℓ ≥ 1`). ## Proof idea The invariant `BufCons.CInv` combines Lemma 6.1's per-buffer invariant (`GoodW`, so that every read reconstructs the full history, `recon_correct`) with the racing-counters agreement invariant, stated for *virtual* phases `BufCons.vph`: a process in the middle of a double collect whose previous collect `c₁` still matches everything read so far and all buffers not yet re-read (`BufCons.Valid`) is treated as having already performed an atomic scan returning `c₁` (linearized when the current collect started). Validity can only be lost (never regained), which only removes processes from the decided/"bad" sets (`AgreeV.mono`); it is gained only when a collect ends and the memory equals the new `c₁`, which is exactly an atomic scan (`AgreeV.scan`). ## Deviations from the paper * The paper composes Lemma 6.2 (single-writer registers from a history object), the double-collect snapshot and Lemma 3.1. We skip the register layer: a process appends its increments (tagged `(p, seq, v)`) to its group's history object and the counts are read off the histories; this is the same information as the paper's per-process registers. * Double collect: the first "previous collect" is empty; after a failed comparison the current collect becomes the previous one. * If a scan returns all-zero counts the process promotes its own input (instead of an arbitrary `argmax`); this simplifies the validity invariant and never happens (a process scans only after its own increment). * As in `RacingCounters.lean`: ties in `argmax` broken arbitrarily, decision threshold `n = |P|`, re-invoking a decided process returns its decision. -/ set_option linter.unusedSectionVars false namespace
