import Papers.PODC2016.ComplexityHierarchy.SwapAlgAbstract import Cslib.Computability.Distributed.SharedMemory.Objects.Swap import Cslib.Computability.Distributed.SharedMemory.Task /-! # Swap and read (Section 8 of [EGSZ16]): Algorithm 1 with double-collect scans — safety [EGSZ16] F. Ellen, R. Gelashvili, N. Shavit, L. Zhu, *A Complexity-Based Hierarchy for Multiprocessor Synchronization*, PODC 2016 (arXiv 1607.06139), Section 8, Algorithm 1. The algorithm `swapAlg k m P` for processes `P`, values `Fin k` and `m` locations supporting `read` and `swap` (the library's readable swap object `rswapObj`). A location stores a *tagged* lap vector `(tag, laps)`, where the tag `some (p, c)` identifies the `c`-th swap of process `p` (the paper's "process identifier and strictly increasing sequence number") and `none` the initial value. The scan of the `m` locations is the double collect: read `X_1, …, X_m` one by one, repeatedly, until two consecutive collects return the same values; then the local computation of lines 4–12 (`after`) is performed. ## Main results * `swapAlg_safe`: in every finite execution (one-shot or not) decisions agree and are inputs of participating processes, provided `|P| ≤ m + 1`. * `swapAlg_solves`: `(swapAlg k m P).Solves (consensus P (Fin k))`. ## Proof: reduction to atomic scans A process `q` in the middle of a double collect is `Ready` if its previous collect `pv` is complete, the reads of the current collect so far returned `pv`, and the locations not yet read still contain `pv`. Because tags are never reused, a ready process's scan, if it succeeds, returns `pv` = the memory at the end of its previous collect, so it can be linearized there. `simInv` states that for *every* set `Q` of ready processes, the abstract configuration in which the processes of `Q` have already performed their (atomic) scan, returning `pv`, and all other scanning processes are about to scan, satisfies the abstract invariant `AInv` of `SwapAlgAbstract.lean`. This is proved by induction on executions: a read is either invisible in the abstract system or (when a collect completes and the memory equals it) an abstract scan; a swap is an abstract swap; it destroys the readiness of every process that has not yet re-read the swapped location in its current collect (tags are fresh). ## Modelling choices and differences from the paper * Processes: any finite type `P` with `|P| ≤ m + 1` (the paper: `n` processes, `m = n − 1`); values `Fin k` for any `k ≥ 1` (the paper: `k = n`); `m ≥ 1` locations. The bound `|P| ≤ m + 1` is necessary: with `3` processes, `2` values and `1` location there is a 10-step execution (with atomic scans, hence also with double collects) in which two processes decide differently (found by model checking). * Asynchronous deterministic processes, atomic `read`/`swap` on each location, consensus as a one-shot task (CSLib `Cslib.SharedMemory` + `Cslib/Computability/Distributed/SharedMemory/Consensus.lean`). A process that has decided and is invoked again returns its decision again; safety is proved for all executions, not only one-shot ones. * Anonymity: as in the paper, swap arguments carry `(process id, sequence number)`; identifiers are used for nothing else. Strictly speaking this is not an anonymous protocol (the paper calls it anonymous); without unique tags the double collect is not a linearizable scan. * Lemma 8.2 is false as stated for every scan `S` with `ℓ_v(S) = 1`: it would require an earlier scan `T` with `ℓ_v(T) = 0` in which all laps are `0` (since `ℓ_{v'}(T) ≤ ℓ_v(T)`), but every scanner has `ℓ_{input} ≥ 1`, so no such `T` exists. It is only applied with `ℓ_v(S) ≥ 2` (Lemma 8.4), where the proof works. Here it is replaced by the invariant "every lap value in the system is at most the floor plus one" (`Bnd`). * Lemma 8.6 proves only weak validity ("if all inputs are `x`, only `x` is decided"); we prove the standard validity (every decision is the input of a participating process). * The paper obtains linearizable scans from the double collect with `(id, seq)` tags, citing [AAD+93], and then argues with scans as atomic steps (Lemmas 8.3–8.5); only the composition step (that the algorithm with double-collect scans behaves like the one with atomic scans) is left implicit. Here it is proved by the simulation `SInv.sim`. * Lemma 8.7's bound of `3n − 2` scans in solo runs is not formalized; we prove termination of solo runs from every reachable configuration
