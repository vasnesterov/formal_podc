import Cslib.Computability.Distributed.SharedMemory.Valency import Papers.PODC2016.ComplexityHierarchy.Packing /-! # ℓ-buffers and multiple assignment (Sections 6–7 of Ellen–Gelashvili–Shavit–Zhu, PODC 2016) An *ℓ-buffer* stores the inputs of its `ℓ` most recent `ℓ-buffer-write`s; `ℓ-buffer-read` returns them. We represent its content as a list, most recent write first, of length `≤ ℓ` once it has been written (the paper pads with `⊥`; the initial content is arbitrary here, `memInit`). **Memory model.** To also cover *multiple assignment* (Section 7: a process atomically performs one `ℓ-buffer-write` on each location of an arbitrary subset), the whole memory is modelled as a single base object `multiBuffer R ℓ V` of the CSLib model (`ι = Unit`), with locations `R`: * `MOp.read r`: returns the content of location `r`; * `MOp.write w` (`w : R → Option V`): for every `r` with `w r = some x`, performs `ℓ-buffer-write(x)` on `r`; returns `[]` (nothing). Plain (single-location) writes are the `w` with at most one `some` (`SingleWrites`). Section 6's per-location model (`ι` locations, each an `ℓ-buffer` base object) is reduced to this one in `BufferLB.lean`. ## Main definitions * `bufWrite`, `applyW`, `multiBuffer R ℓ V`, `MB R ℓ V` (the base-object family). * `Impl.Poised C p w`, `Impl.MCovers C p r` (paper: `p` covers `r`), `Impl.WritesIn C p S` (`p`'s next step writes nowhere outside `S`), `Impl.SingleWrites`, `Impl.wOf`. ## Main results * `foldl_bufWrite`, `foldl_bufWrite_eq`: `ℓ` writes obliterate an `ℓ-buffer`. * `Impl.runFrom_block`: effect of a block of (multi-)writes (from the library's `Impl.runFrom_poised_block`). * `Impl.block_agreeOn`: indistinguishability after a block that writes `≥ ℓ` times to every location on which two configurations differ. -/ set_option linter.unusedSectionVars false namespace
