Zhu, *A Complexity-Based Hierarchy for Multiprocessor Synchronization*, PODC 2016. -- CSLib candidate Processes `P` cover locations `Loc` according to a relation `cov : P → Loc → Prop` (a process may cover several locations). A `k`-packing of a finite set `S` of processes assigns to each process of `S` a location it covers, with at most `k` processes per location. A location `r` is *fully `k`-packed* by `S` if every `k`-packing of `S` packs exactly `k` processes into `r`. ## Main results * `fullyPacked_of_cov` (Lemma 7.2): a process packed (by some packing) into a fully packed location only covers fully packed locations. * `isPacking_insert`, `card_le_of_isPacking`, `card_lt_of_not_fullyPacked`, `exists_blocks`, `isPacking_congr`, `fullyPacked_congr`: auxiliary facts used in the paper's Section 7. * `lemma71_trail_counterexample`: the re-packing step of the paper's proof of Lemma 7.1 (along a maximal trail) does not always decrease the number of processes packed in the start location of the re-packed suffix when the trail revisits a location. ## Implementation notes Instead of the paper's Eulerian-trail argument (Lemma 7.1) we use an augmenting-path argument on the *residual relation* `resid cov S π x y` ("some process packed into `x` by `π` covers `y`"): * if every location reachable from `r` is full, all of them are fully packed (counting); * if `x` reaches an under-full location, then re-packing along a shortest path gives a packing in which `x` is under-full. -/ namespace Cslib.SharedMemory.ComplexityHierarchy open Finset the paper's proof of Lemma 7.1 The proof of Lemma 7.1 takes a *maximal* trail `r₁ → ⋯ → r_t` in the multigraph with an edge `g p → h p` for every process `p`, and claims that, for every `1 ≤ j < t`, Example: locations `A, B, C` (`0, 1, 2`), processes `p₁, p₂, p₃` (`0, 1, 2`), `g = (A, B, C)`, `h = (B, C, B)`, each process covering its `g`- and its `h`-location, `k = 2`.
