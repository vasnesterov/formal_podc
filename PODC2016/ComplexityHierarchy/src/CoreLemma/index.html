import Papers.PODC2016.ComplexityHierarchy.Buffer import Cslib.Foundations.Data.Nat.Descent /-! # The key lemma for block (multi-)writes: Lemmas 6.5 and 7.3 of EGSZ'16 Setting: binary consensus algorithms over the memory `MB R ℓ V` (`ℓ`-buffers, possibly with multiple assignment), see `Buffer.lean`. A *block* `(T1, T2)` for a set of locations `Lset` in a configuration `C` (`IsBlock`) consists of two lists of distinct processes, all poised in `C` to perform (multiple) assignments that only write locations of `Lset`, such that * `T1` writes every location of `Lset` at least `max ℓ 1` times (so it obliterates `Lset`), and * either the algorithm only uses single-location writes, or `T2` also writes every location of `Lset` at least `max ℓ 1` times. In Section 6 (single-location writes), `T1` = the processes `ℓ`-covering the locations of `Lset` and `T2 = []`; in Section 7 (multiple assignment), `T1`/`T2` are the two halves `R1`/`R2` of a `2ℓ`-packing of the fully packed locations (Lemma 7.2 guarantees that they only write `Lset`). `key_lemma` is the common core of Lemma 6.5 and Lemma 7.3: if `Q` is bivalent from `C` and the block processes and a process `p` belong to a set `Rs` disjoint from `Q`, then some `Q`-only execution `ξ` leads to a configuration `Cξ` such that `Q ∪ Rs` is bivalent after the block write `T1` from `Cξ`, and in `Cξ` some process of `Q` covers a location outside `Lset`. Unlike the paper (which picks `p ∈ R`), we need `Rs` to contain *some* process `p`; the case `R = ∅` (only possible for `n = 2`) is treated separately by the callers. -/ set_option
