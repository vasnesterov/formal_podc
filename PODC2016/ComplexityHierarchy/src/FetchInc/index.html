import Mathlib import Cslib.Computability.Distributed.SharedMemory.Valency import Cslib.Foundations.Data.Nat.Descent /-! # One read/write/fetch-and-increment location is not enough (Theorem 5.1 of EGSZ'16) A single memory location supporting `read()`, `write(x)` and `fetch-and-increment()` (values in `ℤ`, arbitrary initial value) cannot be used to solve obstruction-free binary consensus for `n ≥ 2` processes (`theorem_5_1`). Proof (as in the paper): let `p ≠ q`. Run `p` alone, with input `x`, until it is about to write (or has decided); during this write-free prefix the location only grows by one per `fetch-and-increment`. Choose `x` such that the value `M x` reached with input `x` is at most the value `M (!x)` reached with input `!x`. Starting from the configuration where *everybody* has input `!x`, stop `p` when the location holds exactly `M x` (discrete intermediate value theorem); there `q` must decide `!x` (weak validity), and `q` cannot distinguish this configuration from the one reached by `p`'s write-free prefix with input `x`. If `p` has already decided `x` there, this contradicts agreement; otherwise `p` is poised to write, and its write hides `q`'s whole solo run, after which `p` still decides `x`.
