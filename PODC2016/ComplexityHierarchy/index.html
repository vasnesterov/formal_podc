A Complexity-Based Hierarchy for Multiprocessor Synchronization — PODC 2016

Faith Ellen, Rati Gelashvili, Nir Shavit, Leqi Zhu. A Complexity-Based Hierarchy for Multiprocessor Synchronization. PODC 2016. DOI 10.1145/2933057.2933113. Formalized version: arXiv 1607.06139 v2 (2018). Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. All formalized theorems hold: the space lower bounds (⌈(n−1)/ℓ⌉ ℓ-buffers, ⌈(n−1)/2ℓ⌉ locations with multiple assignment, one max-register / one read-write-FAI location insufficient, unboundedly many test-and-set locations) and the matching algorithms. Several proofs needed only local repairs: Lemma 9.1 has a real gap, Lemma 7.1's proof is wrong (statement true), and Lemma 8.2 is false as stated, though never used in the false case. What is lost is minor: Theorem 8.8's n − 1 swap/read protocol is proved only with process identifiers, not as anonymous.

Mistakes in the paper

⚠️ Theorem 8.8 ("anonymous", Section 8)

The protocol is called anonymous, but every swap argument carries a process identifier, and without unique tags the double collect is not a linearizable scan.

Impact. The n − 1 location bound is proved, but only with identifiers (theorem_8_8), so the word "anonymous" is not saved. The space hierarchy depends only on the bound.

✏️ Slips

  • Lemma 8.2 (swap/read algorithm): for a scan S with ℓ_v(S) = 1, it asks for an earlier scan T in which all laps are 0, but no such T exists, since every scanner has lap ≥ 1 on its own input from line 1. This is an unused edge case: the lemma is applied only with ℓ_v(S) ≥ 2 (Lemma 8.4), where it holds, and Theorem 8.8 is unaffected (invariant SwapRead.AInv).

  • The Section 7 introduction says ⌈n/2ℓ⌉ locations are necessary; Theorem 7.5 and the proof give ⌈(n−1)/2ℓ⌉.

  • Lemma 7.3: "Cζβ1β2" should be "Cξβ1β2".

  • Theorem 4.2: "(r,x) ≺ (r′,x)" should be "(r,x) ≺ (r′,x′)".

Typos

  • Lemma 7.4: "at mostwot two".

Proof gaps in true statements (5)Lemma 9.1 · Lemma 7.1 · Lemmas 6.5 and 7.3 for R = ∅ · Lemma 3.2 · Lemma 8.6

🔧 Lemma 9.1 (test-and-set)

The proof runs z's preliminary steps of β after p_1's steps ψ, ψ', which may set locations to 1, so z need not perform β at all, and the claims that "β sets r to 1" and that the two configurations are indistinguishable to p_0 are unjustified.

Impact. Statement true; Lemma 9.1 and Theorem 9.2 hold as stated (lemma_9_1).

Details

The proof takes β, the shortest prefix of z's solo execution from Cα_kξ that ends with a test-and-set on a location r ∉ L_k. It then reasons about Cα_kξψβ and Cα_kξψψ'β, where ψ, ψ' are steps of p_1. But in those executions z's preliminary steps of β (reads, test-and-sets on L_k) run after ψ. They may then return different values.

Repair

Run z's preliminary steps first (they change no memory), so that z is poised on r; its single remaining step commutes with any single step of p_0/p_1. This also removes the case analysis on ψ'.

🔧 Lemma 7.1 (re-packing along an Eulerian trail)

The proof re-packs along any maximal Eulerian trail r_1, …, r_t from each r_j to r_t, which does nothing if the trail visits r_t earlier (lemma71_trail_counterexample).

Impact. Statement true; taking a shortest such sequence fixes the proof.

Details

Example: locations A, B, C, processes p1, p2, p3, 2-packings g = (A, B, C) and h = (B, C, B). The unique maximal trail from A is A→B→C→B, and re-packing from j = 2 leaves B unchanged.

Repair

We prove Lemma 7.2, the only use of Lemma 7.1, directly, by an augmenting-path argument (fullyPacked_of_cov).

🔧 Lemmas 6.5 and 7.3 for R = ∅ (used by Theorems 6.8 and 7.5)

The proofs of Lemmas 6.5 / 7.3 start from a process p ∈ R, but Theorems 6.8 / 7.5 use them for n = 2, where R = ∅.

Impact. Theorems true; the needed conclusion (at least one location) follows from a separate easy argument: with no locations, two processes cannot communicate (no_locations).

🔧 Lemma 3.2 (validity)

Validity is not argued, and it needs every scan to see a nonzero component: otherwise the argmax of an all-zero vector could be an unproposed value, since decrements lower counts.

Impact. Statement true (lemma_3_2).

Repair

One invariant (pending decrements + 1 ≤ total count) closes the step, with no change to the algorithm.

🔧 Lemma 8.6 (validity)

Section 8 announces validity, defined as "equal to the input of one of the processes", but Lemma 8.6 proves only weak validity: if all inputs are x, then only x is decided.

Impact. Statement true; standard validity also holds (theorem_8_8, SwapRead.AInv.valid).

The formalizationmodel, Lean names of the results, trust

Model (CSLib asynchronous shared memory, Cslib.SharedMemory).

  • Deterministic processes, arbitrary interleavings, no randomization; a process may stop taking steps. Every location supports the same atomic instruction set. Initial memory is arbitrary, and the lower bounds hold for every initialization.

  • Multiple assignment (Section 7): the whole memory is one base object with an atomic multi-location ℓ-buffer write. Section 6's per-location model embeds into it, so both lower bounds are instances of one theorem (lowerBound_core).

  • Consensus as a one-shot task: a process participates by invoking it with its input. Lower bounds assume only weak validity ("all inputs v ⇒ decide v") and only one-shot obstruction-freedom (solo termination). Upper bounds prove agreement, standard validity and full obstruction-freedom. Both directions are thus at least as strong as the paper's.

  • Lower bounds are proved for binary consensus and transferred to n-valued consensus (*_multivalued).

Steps left implicit in the paper (routine, filled in here).

  • Lemma 6.6: one must truncate α after its first decision, so that U' stays undecided.

  • Theorem 4.2 and Section 8: the step from linearizable double-collect scans to atomic-scan reasoning is left implicit; we prove it (a ghost chain of observed pairs for Theorem 4.2, a step-by-step simulation for Section 8).

  • Theorem 4.2: validity needs the observation that a process seeing m1 = (0,0) itself wrote (0, input).

Not formalized. Lemma 5.2 / Theorem 5.3 (needs composition of consensus protocols), Theorems 9.3–9.4, Table 1 entries cited from other papers, the remarks on heterogeneous capacities, and the 3n−2 scan bound of Lemma 8.7 (only solo termination is proved).

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. The upper bounds (Theorems 6.3, 8.8) also show that the lower bounds are not vacuous. Model, consensus tasks, valency framework (Lemmas 6.4, 6.6) and the binary reduction come from CSLib Cslib/Computability/Distributed/SharedMemory/, including the parts first developed in this project's shared library (now upstreamed): the readable swap object rswapObj (Theorem 8.8's locations), poised processes and blocks (Impl.PoisedAt, Impl.runFrom_poised_block, behind Impl.Poised and Impl.runFrom_block), reachability of solo steps (Impl.Reachable.soloStep), the "last index" argument of valency proofs (Nat.exists_lt_and_not_succ_of_not), Fintype.sum_update_add, the current operation instance curOp (Cslib/Computability/Distributed/SharedMemory/History.lean, in BufferAlg.lean), and the walks of the packing argument are CSLib's Relation.RelatesInSteps, cut at the first visit of their target by Relation.RelatesInSteps.exists_le_first_visit (Cslib/Foundations/Combinatorics/Digraph/Walk.lean).
