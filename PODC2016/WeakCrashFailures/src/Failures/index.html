import Podc.Computability.Distributed.SWMR.Basic import Mathlib.Data.Set.Card import Mathlib.Data.Fintype.Card /-! # Weak crash failures (m-failures of type 1) G. Taubenfeld, *Computing in the presence of weak crash failures*, PODC 2016 (brief announcement); full version *Weak Failures: Definitions, Algorithms and Impossibility Results* (2018), §1.1. Executions are described by their infinite schedule `σ : ℕ → P` (`σ t` takes the `t`-th step), as in `Cslib.SWMR`: a process is *correct* if it takes infinitely many steps (`InfOften`) and *faulty* otherwise (`Faulty`). A process that has terminated keeps taking (no-op) steps, so it is correct; hence "participation is required": every correct process takes steps. * A process *participates* at time `t` if it has taken a step before `t` (`started σ t`). * The *point contention* at time `t` is the number of participating processes (`contention σ t`). It never decreases (`contention_mono`). * An *m-failure of type 1* (`WeakFailure m σ p`): `p` stops taking steps from some time `t` on, and at that time the point contention is at most `m` (the crash "occurs" at time `t`). Since the contention never decreases, the most permissive choice of `t` is right after `p`'s last step. * An *initial failure*: the process never takes a step. With `m ≥ |P|` an m-failure is an ordinary crash failure (`weakFailure_iff_faulty`). -/ namespace Podc.WeakCrashFailures open Cslib.SWMR variable {P : Type} [DecidableEq P] /-- The processes that have have taken a step before `t`. -/ def contention (σ : ℕ → P) (t : ℕ) : ℕ := (started σ t).card /-- `p` takes no step at time `t` or later. -/ def StoppedFrom (σ : ℕ → P) (p : P) (t : ℕ) : Prop := ∀ s,
