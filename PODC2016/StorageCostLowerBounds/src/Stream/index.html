import Papers.PODC2016.StorageCostLowerBounds.Model /-! # The streaming relay: an I/O-automaton-faithful counterexample In the paper's I/O-automaton model every send is a separate output action, so a server must keep in its state the messages it still has to send. `IOASends` formalizes this: a server step that receives a message (or an invocation) sends nothing, and a spontaneous step sends at most one message. The relay algorithm of `Relay.lean` does not satisfy it. The **streaming relay** does, and its servers still have only `36` states, independent of the value set. Values are bit vectors `V = Fin B → Bool`; the writer streams the bits of its values, in order, one bit at a time to every server (stop-and-wait per server). * Writer: keeps the whole stream `strm` (bits of all written values) and, per server, the number of bits sent (`sentc`) and acknowledged (`ackc`). A server is sent the next bit `W b` when its previous bit is acknowledged. Write `K` returns once `qs` servers acknowledged the whole stream. * Server, state `(pf, pa, pd, turn)`: receiving `W b` sets `pf := some b`, `pa := true`; receiving the query `Q` sets `pd := true`. Spontaneous steps take turns: turn 0 sends `F b` to the reader (if `pf = some b`), turn 1 sends the acknowledgement `A` to the writer (if `pa` and the bit was forwarded), turn 2 sends the answer `D` to the reader (if `pd`). * Reader: keeps all bits received from each server (`got`); whenever a server's bits complete a block of `B` bits, block number `t`, and `t > best`, it records `best := t` and the decoded value. Read `q` sends `Q` to every server without an outstanding query (`sentAt i = none`). An answer `D` to a query of the current read counts; an answer to an older query triggers a new `Q`. The read returns the recorded value once `qs` servers answered. -/ namespace Podc.StorageCost.Stream open Cslib.ChannelFailures Cslib.SharedMemory variable {n B : ℕ} /-- Values: bit vectors of length
