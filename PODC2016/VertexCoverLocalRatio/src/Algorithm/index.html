The current neighbourhood `N_i(v)` of a running vertex is the set of its running neighbours (`actN`); `Correctness.lean` shows this agrees with the bookkeeping of lines 9, 16, 29–31 of the pseudocode (a neighbour is dropped exactly when it returns `InCover`). In iteration `i`, a running vertex `v` * requests `request_i(v,u) = vault(v)/d_i(v)` from every running neighbour `u`, where `vault(v) = a·w_0(v)` (`a = ε'` in the paper); * answers the requests of its running neighbours from `bank(v) = w_i(v) - vault(v)` by a **response rule** `R` (`budget_i(v,u)`); * sets `w_{i+1}(v) = w_i(v) - ∑_u budget_i(u,v) - ∑_u budget_i(v,u)`; * returns `InCover` if `w_{i+1}(v) ≤ θ·w_0(v)` (`θ = ε'`), otherwise `NotInCover` if all its running neighbours returned `InCover` in this iteration, otherwise keeps running. The response rule is abstract (`Rule.Spec σ`): every answer is in `[0, request]`, the answers sum to at most `bank(v)`, and if some request is not answered in full then the answers sum to at least `bank(v) - σ·w_0(v)`. The paper's rule (line 20: answer `min(request, remaining bank)` in an arbitrary order) satisfies `Spec 0` for every order (`greedy_spec`); the CONGEST variant of Section 4 satisfies `Spec (θ/2)` with
