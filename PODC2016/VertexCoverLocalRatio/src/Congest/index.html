import Papers.PODC2016.VertexCoverLocalRatio.Main /-! # The CONGEST variant (Section 4) Section 4 modifies Algorithm 1 so that answers fit in `O(log n)` bits: the vault becomes `ε' w_0(v)/2`, and a request that cannot be answered in full is answered with `t·ε' w_0(v)/2` for the largest integer `t` with `t·ε' w_0(v)/2 ≤ budget_i(v,u)` (where `budget_i(v,u)` is the remaining bank, line 20). We read this as: `v` grants (and deducts) exactly the rounded amount, and continues with the remaining bank (the paper does not say what happens to later requests). Formally this is the response rule `congestRule` (`congest_spec`: it meets `Rule.Spec (θ/2)`), with vault factor `a = θ/2`, so `a + σ = θ` and all results of the generic analysis apply: * `congest_correct`: `(2+ε)`-approximation (Lemma 3.2 carries over); * `congest_small`, `congest_large`: the round bounds of Lemma 3.3 with `c = 4` instead of `2` (`3(68+2E)/ε` and `3(4+3E)·log d/(ε log log d)` rounds). Message sizes are not modelled (the LOCAL implementation sends whole states); only the arithmetic of the modified rule is checked. -/ set_option linter.unusedSectionVars false namespace
