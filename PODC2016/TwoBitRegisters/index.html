Two-Bit Messages Suffice for Atomic Registers — PODC 2016

Achour Mostéfaoui, Michel Raynal. Two-Bit Messages are Sufficient to Implement Atomic Read/Write Registers in Crash-prone Systems. PODC 2016. DOI 10.1145/2933057.2933095. Formalized version: arXiv 1602.02695 v1 (the only version); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The algorithm of Figure 1 implements a linearizable SWMR register in CAMP_{n,t}[t < n/2], every operation of a correct process terminates, and messages carry a two-bit type, plus a value for two of the four types. FIFO channels are not needed, as the paper itself states (§2.1 assumes non-FIFO channels): the parity bit and the wait at line 11 form an alternating-bit protocol. The algorithm stands unchanged under the standard convention that code between two waits runs atomically; the proofs of Lemmas 5 and 10 need only an extra case, an extra invariant conjunct and two corrected steps.

Mistakes in the paper

✏️ Slips

  • Figure 1 / Section 3: the paper never says that code between two waits runs atomically with respect to the message handlers. This is the implied, standard convention, and the algorithm is wrong without it (see "Implicit convention" below).

  • Claim 3: "computed by p_i" should be p_j.

Typos

  • Claim 2: i and j are mixed in the quorum Q_w.

  • Lemma 8: w_sync_i[i] ≥ w_sync_w[i] = wsn is awkward, but every part of it is true (Lemmas 2 and 6). What line 3 needs is w_sync_w[i] ≥ wsn.

Proof gaps in true statements (3)Lemma 5 · Lemma 10, Claim 2 · Lemma 10, Claim 3

🔧 Lemma 5 (alternating-bit invariant)

The case analysis for a pair (i, j) omits p_i receiving a WRITE from a third process p_k, and the induction lacks the hypothesis "at most two unprocessed WRITEs per channel, with different parities".

Impact. Statement true; we prove an exact invariant covering both points (lemma5, lemma5_sent).

Details

The paper considers p_i invoking write and p_i receiving a WRITE from p_j. A reception from p_k may raise w_sync_i[i] (line 14) and send a WRITE to p_j (line 15), changing the premises of the paper's counts R1/R2 of the WRITEs sent to p_j. The missing hypothesis is what makes the parity test of line 11 pick the right message.

🔧 Lemma 10, Claim 2

Claim 2 says w_sync_k[k] = x when the read starts, but only ≥ x is true, because a later write may already have started.

Impact. Only ≥ x is used (lemma10).

🔧 Lemma 10, Claim 3

Claim 3 asserts a correct process in the intersection of two (n − t)-quorums, which does not follow.

Impact. Correctness of that process is never used (lemma10).

Details

With n = 3, t = 1, quorums {1,2} and {2,3}, p_2 may be faulty.

The formalizationmodel, Lean names of the results, trust

Model.

  • Finitely many asynchronous deterministic processes; the writer w and readers p ≠ w. The writer does not read; the paper only remarks that its reads are local.

  • A complete network of reliable, unordered channels (a multiset of in-transit messages).

  • Crash failures. Messages of crashed senders may be dropped (a crash mid-broadcast), but dropping is never forced.

  • Safety is proved for any number of crashes. Liveness assumes at most t crashes, 2t < n, and weak fairness for steps of correct processes (this includes reliable delivery).

  • Each block of code between waits is one atomic transition. A WRITE that fails the parity test of line 11 stays in the channel.

  • Atomicity is CSLib's linearizability (amended Herlihy–Wing) for a register. Pending operations may or may not be linearized. No randomness, no timing.

Implicit convention: code between two waits is atomic. The paper never says how an operation's code interleaves with the message handlers. We use the standard convention for this pseudo-code (last Model bullet); it is a convention, not an error, but it is necessary: without it the algorithm is wrong. Suppose a WRITE handler runs between lines 1 and 2 of write(). Then the writer can send the same WRITE(b, v_x) twice to one process: once at line 16, while it handles a late echo of v_{x−1}, and again at line 2. The stale copy later passes the parity test as message x + 2, and the receiver appends a wrong value to its history. Our model checker found a 14-step execution with n = 3, t = 1, no crashes, no reads and three writes, in which p2 accepts the stale WRITE(0, v2) as its 4th value.

Lemma 9. Channels are not FIFO and READ()/PROCEED() carry no sequence number, so "r_sync_i[j] = rsn means p_j answered the current request" needs a counting argument, which the paper only asserts. It is routine: each READ() is at all times in exactly one place (in transit, a pending handler, a PROCEED() in transit, or already counted) (read_terminates).

Theorem 2's message complexity (O(n) per read, O(n²) per write) holds when messages are attributed to the operation (value) they belong to, as the paper's proof does, i.e. amortized; it does not bound the messages sent during an operation. Catch-up messages for old values (line 16) may be sent long after the write returned. We prove the amortized bounds.
