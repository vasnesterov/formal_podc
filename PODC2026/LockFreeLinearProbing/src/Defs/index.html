The table `table[0..m-1]` is modelled in CSLib's asynchronous shared-memory model (`Cslib.SharedMemory.Impl`): base object `i : Fin m` is an LL/SC object (`llscObj`) holding a `Cell`. Following Algorithm 5, `Read` is `LL`, `Modify(loc, old, new)` is `SC(loc, new)` and the plain reads `table[i]` of lines 94, 102 and 105 are `VL` (which returns the current value and does not touch any link). Indices are `Fin m`, so `i + 1` and `i - 1` wrap around (the paper: "we use modular arithmetic that wraps at the m-th cell"); the comparison `i − h(v) < j − h(v)` of line 51 is `dist v i < dist v j` with `dist v i = (i - h v).val ∈ [0, m)`. Each process runs the pseudocode as a state machine: the program counter `PC` names the next shared-memory access (one primitive per step, as in Section 3); the local computation between two accesses (control flow of Algorithms 1–4, including the `goto`s and the returns of the helper functions) is done by the functions `fsBody`, `vcRet`, `dsBody`, … below.
