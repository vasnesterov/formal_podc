import Mathlib set_option linter.unusedSectionVars false /-! # Blink (Algorithm 1): Representative Binary Consensus on top of a black-box Binary Consensus Monti, Camaioni, Roman. *Fast Byzantine Total Order Broadcast.* PODC 2026 (arXiv:2412.14061v2). ## Model * `P` is the finite set of servers, `F : Finset P` the (static) set of Byzantine servers. * Asynchronous interleaving semantics: a run is a sequence of global states `st : ℕ → P → LState P`; at each step either nothing happens (stutter) or one correct server performs one *action* whose guard holds. Safety does not depend on timing, so no clocks are needed. * Authenticated links: a correct server records `suggestions[σ] = v` only if `σ` is Byzantine (who may send anything, any number of times, also changing its mind) or `σ` is correct and proposed `v` (correct servers send `[Suggest, v]` to all upon proposing, so "`σ` sent `[Suggest, v]`" is exactly "`σ.input = some v`"; messages may be delivered several times — harmless, only more general). * The underlying Binary Consensus `dep` is a black box: `dep.Decide` events reach correct servers as unconstrained environment actions (`Act.depDecide`). Its specification (`DepValidity`, `DepAgreement`, …) is a hypothesis about the whole run. Validity is stated over the whole run (a value may be decided before it is proposed): this is the weakest reading of a black-box spec. * The algorithm's thresholds are parameters: `W` (suggestions needed before proposing to `dep`; `4f+1` in the paper), `M` (majority threshold, `2f+1`) and `Q` (fast-path threshold, `4f+1`). The choice "the value suggested at least `2f+1` times" (line 16) is modelled by a nondeterministic guard; for `W = 2M - 1` (as in the paper) there is exactly one such value. The state records history variables: `input` (the `con.Propose` value), `depProp` (the `dep.Propose` value), `depDecs` (all `dep.Decide` events), `decs` (all `con.Decide` events). -/ namespace
