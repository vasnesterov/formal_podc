Committed orderings only grow (`L r i <+: L (r+1) i`); a Byzantine replica's committed ordering is otherwise arbitrary. The committed ordering of an honest replica is a prefix of the order `recv i` in which it received transactions (consensus property (3)), and every transaction received by an honest replica is eventually committed by all honest replicas (property (4)). * `W r a b` is the number of replicas whose committed ordering at round `r` *places `a` before `b`*: it contains `a`, and either not `b` or `b` after `a` (`Before`). This is the reading used in the proof of Lemma 6.3 ("committed `z` but not `m`"). * `pcmp r a b` is the weight-based round-`r` comparator (rules (1)–(4) of §5.1, with the tie-break `tb`); `W ≥ τ_dec = (n−f)/2` is written `n − f ≤ 2W`. `cmpT a b` is its value at the *first* round where it is defined (§4.1). * Transactions are classified by a score; `solid` means `score ≥ τ_solid = n − f`, non-blank means `score ≥ τ_shaded = (n−f)/2`. The paper defines the score as the number of **honest** replicas whose committed orderings include the transaction (`scoreHonest`); we prove correctness for the score counting **all** replicas (`scoreAll`) and show in `Counterexample.lean` that the paper's definition breaks Lemma 6.3 and Theorems 6.4/6.6. ## Algorithm `run` is FEAT with all comparisons answered by the global comparator `cmpT`. In the protocol every comparison that FEAT acts on is answered by `pcmp^(r')`, which equals `cmpT` once defined (monotone refinement), and an undefined answer only delays the action (deferral of a shaded insertion, waiting in the merge). So FEAT's outputs are those of `run` for the order in which insertions eventually succeed; we quantify over all insertion orders `ins r` (any order of the transactions newly non-blank in round `r`) and over all in-order-preserving rebalancings `bal`.
