Task Completion in Crash-Prone Congested Cliques — PODC 2026

Orr Fischer, Ran Gelles. The Task Completion Problem and its Application to Crash-Resilient Computation. PODC 2026. DOI 10.1145/3796701.3815916. Formalized version: arXiv:2605.17961v1.

DOI · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. Lemma 3.1, the analysis of Algorithm 1 (Lemmas 4.3–4.5), the O(R⌈M/n⌉ log n) deterministic task-completion algorithm (Theorem 4.1) and the Ω(log n / log log n) lower bound (Theorem B.1) are all true as written. The proof of Lemma 3.1 has two errors: a backwards Chernoff step, which Markov's inequality replaces, and a union bound that fails for ε ≥ 0.53, which took a different tail argument but does not matter for Theorem 4.1, since the paper uses only a small ε. The robust congested-clique simulation of Section 5 was not checked.

Mistakes in the paper

✏️ Slips

  • The proof of Lemma 4.3 runs the loop "until k_i < 1", but k_i = ⌈(1−ε)^{i−1}m⌉ ≥ 1 always. The correct stopping rule is the one in footnote 3: stop after the first iteration with k_i ≤ 2B, at which point N_{i+1} = 0. We formalize that rule (numIter, lemma_4_3_1).

  • Claim B.2's proof negates "at most 2n'/k'" as "at least 2n'/k'+1".

Typos

  • The proof of Lemma 3.1 says "for any i ∈ [m]"; it should be i ∈ [2m].

Proof gaps in true statements (2)Lemma 3.1, second half · Lemma 3.1, first half

🛠️ Lemma 3.1, second half (union bound for large ε)

The union bound over the k-subsets is below 1 only when 2ε ln 2 < 1 − ε/2, i.e. ε < 0.53, but the lemma claims every ε ∈ (0,1).

Impact. Statement true; repaired with a second-moment argument for all ε and all n (lemma_3_1, lemma_3_1_all_n). The gap does not affect Theorem 4.1, which needs only a small ε (we use ε = (1−α)/8 < 1/8).

Details

The proof bounds Pr(|J| < (1−ε)n) for one k-subset by a Chernoff bound around the mean, which is e^{−ε²(1−ε/2)n/8}. It then takes a union bound over the at most 2^{2m} ≤ 2^{2cn} subsets, with c = ε³/8. (The displayed inequality also silently drops the /2 of the exponent; even then it needs ε < 0.84.)

Repair

Our proof uses only second moments. Chebyshev shows that each element is bad with probability a ≤ 2/(ε²B) ≤ ε/288. The bad events are independent across elements. So the probability that ⌊εn⌋+1 elements are bad is at most C(n,t)a^t ≤ (e a/ε)^t, which beats 2^{2cn} for every ε. (lemma_3_1, lemma_3_1_all_n)

🔧 Lemma 3.1, first half (wrong inequality direction)

To show that at least m of the 2m random sets have the right size, the paper writes Pr(M < m) ≤ Pr(M < (1−0.98)E[M]), but the right-hand event M < 0.04m is smaller than M < m, so this is backwards.

Impact. Statement true; repaired (lemma_3_1).

Details

A correct Chernoff bound gives only Pr(M ≥ m) ≥ 0.22 for m = 1.

Repair

Markov's inequality on the number of bad sets: each set is bad with probability ≤ 1/576.

The formalizationmodel, Lean names of the results, trust

Model.

  • Network. n nodes Fin n and M abstract tasks. The model is synchronous and deterministic. A task takes R rounds and is completed iff its executor does not crash during them (executor-safe, idempotent). At most αn crashes over the whole execution, α ∈ [0,1).

  • Algorithm 1 (Algorithm.lean), iteration-level model. An iteration is a task phase of 2BR rounds plus one broadcast round of the bits s_{i,v}, so it costs 2BR + 1 rounds.

  • Adversary. It is adaptive and arbitrary. For every node it fixes:

    • the iteration in which the node crashes;

    • whether the node survived that iteration's task phase;

    • which nodes receive its last broadcast bit (any subset, as in the paper's crash model).

  • Knowledge and completion. C_{i,v}, "fully verified" and N_i are defined as in the paper. Completed tasks (Done) are under-approximated, which only strengthens the result.

  • Theorem 4.1 (Main.lean). It runs ⌈M/m⌉ batches of m = ⌊cn⌋ tasks sequentially against one global adversary. The covering families come from Lemma 3.1, and ε = (1−α)/8.

  • Lower bound (LowerBound.lean). R = 1; each node attempts one task per round. The algorithm is a full-information strategy: crash history ↦ attempted task per node. This is stronger than the paper's message-passing algorithms, and even than an oracle for the incomplete tasks, so the lower bound is at least as strong as the paper's.
