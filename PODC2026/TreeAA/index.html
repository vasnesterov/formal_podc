Approximate Agreement on Trees and Block Graphs — PODC 2026

Marc Fuchs, Diana Ghinea, Zahra Parsaeian, Joel Rybicki. Round and Resilience-Optimal Approximate Agreement on Trees and Block Graphs. PODC 2026. DOI 10.1145/3796701.3815967. Formalized version: arXiv 2502.05591 v5; numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: ⚠️ Weakened. The reductions are correct: AA on trees reduces to real-valued AA plus gradecast (Theorems 3 and 5), and AA on block graphs reduces to AA on trees (Theorem 8); we proved them in the synchronous lock-step model with the black boxes as hypotheses. The resilience c ∈ [1/3, 1/2) with signatures rests on a refuted protocol (Theorem 7), and the block-graph round bound R_TreeAA(4·D(G)) on the unproved Lemma 15; both are unestablished, not refuted. The cited real-valued AA protocols and Fekete's lower bound construction were not checked.

Mistakes in the paper

❌ Theorem 7 (authenticated RealAA, t = c·n, c ∈ [1/3, 1/2))

For small D/ε the protocol RealAA^PKI of Theorem 7's proof runs Theorem 10 (Theorem 3.1 of [25], PODC 2022), which is false for t ≥ n/3, so it fails already for n = 3, t = 1, D = 1, ε = 1/2 (AA.theorem_3_1_sync_false).

Impact. Theorem 7 is unestablished, not refuted: its statement (existence of some protocol) is probably still true. Corollaries 3 and 5 depend on Theorem 7; our reductions use RealAA as a black box and are unaffected. Not formalized.

Details

For constant D/ε the proof uses Theorem 10, i.e. Theorem 3.1 of [25] with t_a = 0. That theorem is false in synchronous networks when n ≤ 3t. This project's formalization of [25] has a run with n = 3, t = 1, t_a = 0 in which the honest values stay at 0 and 1 forever (Papers/PODC2022/HybridApproxAgreement/, AA.theorem_3_1_sync_false). With n = 3, t = 1 (c = 1/3), D = 1, ε = 1/2 the test log₂((1−2c)/c) + log₂log₂(D/ε) > 0 fails, so RealAA^PKI runs exactly that broken protocol and the honest outputs 0 and 1 are not ε-close.

Repair

Proposed, not proved in Lean: run the Proxcensus-based RealAA₁^PKI for a constant number R of iterations with (c′R)^R ≥ D/ε.

❌ Lemma 15 (D(T) ≤ 2·D(G) for a minimum-diameter clique tree)

The proof says that if a longest path passes ≥ 4 consecutive cliques sharing a vertex, then "replacing them by a star strictly decreases the diameter", but another longest path may survive the change.

Impact. The lemma is unestablished, not refuted, and not formalized. Theorem 8's bound R_TreeAA(4·D(G)) and Corollaries 4 and 5 rest on it; we state Theorem 8 with the round bound of the tree protocol on T_S and prove D(T_S) ≤ 2·D(T).

Details

Counterexample to this step: the path x₀ … x₆ with two pendant vertices at x₃. Exhaustive enumeration (scripts/lemma15_check.py) finds minimum-diameter clique trees (diameter 5) whose longest path has the separators x₁, x₂, x₃, x₃, x₃. The final counting is also off by one, and |P_G| ≤ D(G) is justified only by "P_G is a path" (it holds because such a path is a shortest path in a block graph).

Repair

Sketch, not proved in Lean: the statement is believed true; compare with the clique tree in which the cliques at each cut vertex form a star.

✏️ Slips

  • Theorem 2's round bound: for 1 < D/ε < 2 the bound 7 log₂δ / log₂log₂δ + 3 is below 3 rounds, i.e. below one iteration, and at D/ε = 2 it divides by zero (theorem2_bound_degenerate). The arithmetic is correct for D/ε > 2 (theorem2).

  • Theorem 8's bound silently assumes R_TreeAA is monotone; blockGraphAA_solves is stated with the rounds on T_S, which avoids this.

  • §4.1 says "the k := D(P) vertices of P", but there are D(P)+1.

  • The proof of Lemma 6 claims k_max ≤ D, but in fact k_max ≤ D+1; the inputs are still D-close.

  • The proof of Theorem 3 writes R_RealAA(|V(T)|,1) where the statement has 2·|V(T)|.

Proof gaps in true statements (2)Lemma 13, Case 3 · Lemma 12

🔧 Lemma 13, Case 3 (validity on block graphs)

For a clique output c that does not contain the party's input v_in, the proof says the output (the vertex of c closest to v_in) is the separator between c and its neighbour towards the honest clique c_b, but it is the separator towards the party's own clique.

Impact. The case as argued picks the wrong separator; validity on block graphs still holds (blockOut_spec).

Details

Example: the path x₀–x₁–x₂–x₃ with cliques {x₀x₁}, {x₁x₂}, {x₂x₃}. Take honest inputs x₀ (this party) and x₃, and the tree output {x₁x₂}. The party outputs x₁, while the separator towards {x₂x₃} is x₂.

Repair

By the tripod property of trees, c lies between the own clique and one of the two honest cliques, and Lemma 12 puts the correct separator on a shortest path. (blockOut_spec)

🔧 Lemma 12 (Appendix D, clique-tree edge separator)

The proof assumes the first clique of the walk lies on c's side, and asserts without justification that some walk vertex lies in both cliques of the crossing edge.

Impact. Both steps are closed in a few lines (sep_mem_support, sep_btw).

Repair

Our proof is an induction along the walk with the invariant "every clique containing the current vertex is on c's side". (sep_mem_support, sep_btw)

The formalizationmodel, Lean names of the results, trust

Proof remarks. The proofs of Lemma 3 (Euler tour) and Theorem 3 are sketchy but correct. Properties 3–4 of Lemma 3 are argued informally; Theorem 3's validity step k* ∈ [i_min, i_max] needs the unstated remark that the short-path party's own projection index is at most k*. Lemma 3.1 does not need |V(T)| > 1. (subtree_iff_indices, exists_median_between, treeAA0_spec)

Model.

  • CSLib's synchronous lock-step Byzantine model (Cslib.Byzantine.LockStep) on the complete network, with n = |P| parties. Protocols are deterministic and history-based, and channels are reliable. A static adversary corrupts at most t parties (atMost t) and sends arbitrary messages; this covers rushing. The paper allows adaptive corruption. Our reductions never use static-ness, but adaptivity is not modelled.

  • Ideal signatures are the abstract CSLib tokens (Auth), and every theorem holds for arbitrary token structures. This covers both of the paper's settings: t < n/3 unauthenticated (Auth.none), and t < n/2 with PKI.

  • Black boxes are hypotheses on lock-step protocols. SolvesAuthWithin … pre spec R means: the spec holds and all honest parties decide within R rounds, in every admissible run whose inputs satisfy pre.

    • Gradecast (Def. 4): one protocol per sender, run in parallel. Gradecast snd is the shared Problem.Gradecast (Cslib/Computability/Distributed/Byzantine/Specs.lean) with grades Fin 3; gradecast_iff unfolds it.

    • RealAA (Def. 1, ε = 1): the shared Problem.ApproxAgreement (termination, range validity, ε-agreement; realAA_iff unfolds it), only required for D-close inputs (pre = Close D), matching R_RealAA(D, ε).

  • Sequential composition ("wait until round R ends") is Protocol.seq in Cslib/Computability/Distributed/Byzantine/LockStep/Sequential.lean. Phase 2 starts at round R for everybody.

  • Graphs are Mathlib SimpleGraphs. The hull ⟨S⟩ is the union of all shortest paths between vertices of S (hull, via Btw a w b := d(a,w)+d(w,b) = d(a,b)). A block graph is a graph whose distinct maximal cliques share at most one vertex, given together with a clique tree (IsCliqueTree); chordality is the existence of the clique tree, as in the paper. The root v_start is an arbitrary fixed vertex.

Trust. No sorry. The listed theorems use only the axioms propext, Classical.choice and Quot.sound. Non-vacuity:

  • The black boxes are satisfiable. Simple t = 0 gradecast and RealAA protocols satisfy the hypotheses, and instantiate Theorem 5 on a 3-vertex path (treeAA_nonvacuous, NonVacuity.lean) and Theorem 8 on K₂ (blockGraphAA_nonvacuous, NonVacuityBlock.lean).

  • For t ≥ 1 the gradecast hypothesis is discharged by the verified BDH gradecast (treeAA_bdh_solves).

  • The lock-step model, parallel composition and signatures come from CSLib. Sequential composition and wrapping are new (Cslib/Computability/Distributed/Byzantine/LockStep/Sequential.lean, now in CSLib). The threshold adversary atMost t is shared (Cslib/Computability/Distributed/Byzantine/LockStep/Parallel.lean), and the gradecast vote counting uses Finset.countEq and the quorum lemmas of Cslib/Foundations.
