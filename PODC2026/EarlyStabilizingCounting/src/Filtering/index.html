Node `v` keeps `m_v, M_v ∈ [K] ∪ {⊥}` and a cooldown counter `X_v`. In every round it receives from every node `w` the pair `(C_w, m_w)`, where `C_w` is the clock input of `w` (meaningful for `w ∈ T`): 1. `m_v :=` the value received from a strict majority of `T` (else `⊥`) (line 2) 2. if some `m` was received from at least `n - t` nodes: (line 3) `X_v := X_v - 1` if `m = M_v + 1 mod K`, else `X_v := X`; `M_v := m` (lines 4–5) otherwise `X_v := X` (line 6) 3. output `F_v := M_v` if `X_v = 0`, else `⊥` (line 7) Modelling notes. Values are compared modulo `K`. The paper's compiler resets out-of-range state variables to an in-range default; here a cooldown value above `X` is clamped to `X` before decrementing (`min X_v X - 1`), and outputs are reduced modulo `K`. The selectors of lines 2–3 (`majT`, `quorum`) are computable scans; `majT_eq_majority?` and `quorum_eq_threshold?` identify them with the library selectors `Finset.majority?` and `Finset.threshold?`. An execution (`IsFiltExec`) is any sequence of states in which every correct node applies `filtStep` to some received vectors that agree with the true values on the correct nodes; the clock inputs `ci t w` (the clock of `w` at time `t`) are arbitrary.
