import Papers.PODC2026.ForgetIT.Defs /-! # Forget-IT as an asynchronous transition system The global state records the local states of the processes, the set of messages ever broadcast by correct processes (`sent`, as `(sender, message)` pairs) and all decision events (`(process, view, value)`). A step is one of: * `act`: a correct process executes an enabled rule of Algorithms 1–3 (`En`, `exec`); * `vol`: a correct process changes its *volatile* state: it receives any message broadcast by a correct process or any message from a faulty process, and it may forget received messages and accepted `vote-2` messages (this covers message delivery, and the loss of volatile state in a crash; a crash is `vol` with empty volatile state followed by the `recover` rule); * `aux`: a correct process changes the bookkeeping fields used only by the timed implementation (`clk`, `entered`, `active`, `out`). There are no timing constraints at all, and timers may fire at any time, so every execution of the paper's model (partial synchrony, unreliable channels, crash–recovery of correct processes before GST, constant persistent memory) is an execution of this system, as far as the actions of correct processes are concerned. Safety proved here therefore holds in the paper's model. Persistent memory is modelled with unbounded arrays indexed by views instead of the paper's window of three views (line 18); every rule only reads views in the window (`view_i − 2 ≤ V ≤ view_i`) or sets the guard of the view it enters, and views only grow, so forgotten entries would never be read again. -/ namespace Podc.ForgetIT variable {P Val : Type} [Fintype P] [DecidableEq P] [DecidableEq
