Colors live in an arbitrary type `Col` with decidable equality (agents can only compare colors for equality); labels live in `Fin k`. An agent stores its initial color `ic`, a leader bit `ld` and a label `d`. Initially `ld = 1`, `d = 0`. The transition function (pseudocode of 8.6, `a` is the initiator, `b` the responder; only `a` changes): ``` if ic_a = ic_b then if ld_a = 1 and ld_b = 1 then ld_a ← 0 if ld_a = 0 and ld_b = 1 and d_a ≠ d_b then d_a ← d_b else if d_a = d_b and ld_a = 1 and ld_b = 1 then d_a ← (d_a + 1) mod k ``` Results: * `ordering_correct` (**Theorem 5.1**): if at most `k` colors occur, then under weak fairness for *ordered* pairs (`Execution.OrderedFair`) the configuration eventually never changes and contains a valid ordering: exactly one leader per color, and two agents have the same label iff they have the same color. * `ordering_not_weaklyFair`: under weak fairness for *unordered* pairs (`Execution.WeaklyFair`) Theorem 5.1 fails (3 agents, 2 colors, `k = 2`): a non-leader only copies the label of its leader as the *initiator*, and the scheduler may always choose the other orientation. * `orderingSymm_correct`: the symmetrized protocol (`Protocol.symm`) is correct under (unordered) weak fairness. * `card_ordState`: `|Col| · 2 · k ≤ 2k²` states. Proof: instead of the potential `R` of Lemmas 8.6–8.8 we use (after leader election) the set `S` of labels used by leaders, which only grows, and then, once `S` is constant, the sum over the leaders of the cyclic distance of their label to a fixed unused label, which strictly decreases at every increment. -/ set_option linter.unusedSectionVars false namespace RankingOpinions.Unordered open Finset
