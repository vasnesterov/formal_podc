Every node holds a bit string (MSB first) and an `active` flag (the participants). The algorithm first finds the minimum length `m` of the participants' strings by calls `ComputeOR(active ∧ B ≥ len)` for `B = 1, 2, …`, keeps active the participants of length `m`, and then determines the minimum bit by bit: in phase `p` the call `ComputeOR(active ∧ bits[p] = 0)` tells whether some remaining candidate has a `0`; if so the candidates with a `1` drop out. **Pseudo-code fix.** Line 8 of Algorithm 10 loops `while phase < len(bits)`, with the node's *own* length: nodes whose strings are longer than `m` would call `ComputeOR` more often than the others, so the calls would no longer match. The text says "we assume that every input is represented as a bit string of equal length B"; we loop `while phase < B` (the common value `m`).
