The input of a node is `(ID, isLeader)`; IDs are distinct and exactly one node `ℓ` is the leader (`Admissible`). An algorithm is a single program `P : Prog (ℕ × Bool)` used for every ring size (*processes do not know `n`*), with an output map `out : P.State → Option ℕ` (the leader's count). `CountingCorrect P out` is the safety part of counting: whenever the leader has an output, it is the ring size. (No termination requirement is needed for the per-execution bound.) **Results.** * `count_lower_bound`: in *every* execution of a correct counting algorithm at the end of which the leader has an output, the number `M` of delivered pulses satisfies `n * log₂ n ≤ 14 * M + 4 * n`; in particular `n * log₂ n ≤ 28 * M` for `n ≥ 2^10` (`count_lower_bound'`). This is stronger than the paper's statement. * `theorem3`: the paper's form — if moreover the leader has an output in every final configuration, then on every ring of size `n` with admissible inputs some execution sends at least `(n * log₂ n - 4 n) / 14` pulses. **Proof** (as in the paper, with different constants): choose a sparse edge `{s-1, s}` among the `⌊n/2⌋` edges following the leader clockwise; among the intervals `I_t = (s, …, s+t-1)`, `1 ≤ t ≤ ofs s ℓ` (the clockwise distance from `s` to `ℓ`), which avoid the leader, at least half have a sparse right edge; their interface traces are short, so two of them coincide (Observation 27) and Lemma 28 yields an execution on a smaller ring in which the leader ends in the same state, hence outputs the same count — contradicting correctness.
