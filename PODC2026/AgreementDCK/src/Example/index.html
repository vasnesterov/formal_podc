import Papers.PODC2026.AgreementDCK.Sufficiency /-! # A concrete AoN protocol: dynamic common knowledge without common knowledge Non-vacuity check for the definitions and theorems of David–Moses (PODC 2026), and an illustration of the paper's motivation (Halpern–Moses: common knowledge needs simultaneity). Two processes, no failures, asynchronous delivery of one message. Runs are pairs `(b, d)`: process `0` starts with the bit `b` (its local state is `some b` at all times) and sends it to process `1`, which receives it at time `d + 1` for an arbitrary `d` chosen by the adversary (its local state is `none` before delivery and `some b` afterwards). A process decides `v` when its local state is `some v`. * The protocol has local decisions, is AoN, and satisfies Agreement, Validity (`valid(v)`: the initial bit is `v`) and Decision (`example_spec`). * Hence (Theorem 1.5) `all_decide(b)` is dynamic common knowledge w.r.t. `𝛅(b)` in every run (`example_CN`), and the decision facts satisfy all hypotheses of Theorem 1.7 (`example_sufficient`). * But the classical common knowledge of `b = v` (even `E²`) holds at no point (`example_not_C`). -/ open Cslib.Knowledge Cslib.Knowledge.RunFact Cslib.Knowledge.System
