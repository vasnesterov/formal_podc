The input of a node is `(isLeader, bit)`. **Protocol** (the paper's description, made precise). * The leader starts a clockwise pulse. * A non-leader with input `0` forwards the first clockwise pulse clockwise and waits. A second clockwise pulse means output `0`; it forwards it clockwise and terminates. A counter-clockwise pulse (a reflection, or the leader's broadcast) means output `1`; it forwards it counter-clockwise and terminates. * A non-leader with input `1` reflects the first clockwise pulse (sends it back counter-clockwise), outputs `1`, absorbs the next counter-clockwise pulse and terminates. * Any non-leader whose *first* pulse is counter-clockwise outputs `1`, forwards it counter-clockwise and terminates (this also happens to nodes with input `1` lying clockwise after the first node with input `1`). * The leader: if the reflection comes back (counter-clockwise), it outputs `1`, broadcasts it counter-clockwise and terminates (the broadcast is absorbed by the reflector). If its own pulse completes the cycle, then with own input `0` it outputs `0`, sends a second clockwise pulse and terminates when it returns; with own input `1` it outputs `1`, sends a counter-clockwise pulse and terminates when it returns. The last rule (the leader's own input) is not in the paper; the literal reading, in which the leader ignores its input, computes the wrong OR (`literal_wrong`). **Proof method** (as in `ComputeOR` of the concurrent PODC 2026 counting paper): in every reachable configuration, node `v` has completed `π v` receptions, on the ports of a fixed *role* `typ v` determined by the inputs and the position of `v`.
