import Papers.PODC2026.RandomizedWaitFreeLocks.Trace /-! # Algorithm 3 (non-abortable `Lock` for the weak adaptive adversary): safety Section 3.3 and Section 4.3.1 (Lemmas 4.31, 4.32, Corollary 4.33, Lemma 4.34) of Aeini, Bencivenga, Giakkoupis, Woelfel, *Simple and Efficient Randomized Wait-Free Locks* (PODC 2026). ## Model * Asynchronous shared memory; one atomic shared-memory operation per step. The adversary (`Act`) chooses which process takes the next step (`sched p j`) or makes an idle process invoke `Lock(d)` (`invoke p d`). Every step also gets a coin `b : Bool`. * Processes `P`, non-dummy descriptors `D`; a descriptor value is `Option D` with `none` the dummy descriptor (`isDone() = True`; executing it is a `tau` step). * Shared objects: the FAID object `C : ℕ`, the registers `R : ℕ → Option D` (the array `R[0..⌊log n⌋]`, over-approximated by an unbounded array), the CAS object `L : Option D × ℕ` (fields `desc`, `level`), and the `isDone` registers `done : D → Bool` (set by the last step of `execute()`). * Ghost state: `started : D → Bool` (some `execute()` of the descriptor was invoked), `used : D → Bool` (descriptor already passed to a `Lock` call), `clock` (number of steps, incremented by *every* step, including stutter steps), and per process its current call `call : Option D` (`none` = idle) and the invocation index `callIdx`. * `pc` is the line about to be executed. Each step executes one line of the pseudocode (lines 48–54 and 35–47); lines without a shared-memory operation (line 51 when the coin says "do not write") are stutter (`tau`) steps. This only inserts `tau` events, which do not affect (S1), (S2). * `invoke p d` is line 48 (`C.FAI()`, the first shared step of the call); it emits `inv p d`. It is allowed iff `p` is idle and `d` was never used (the paper's "each `Lock()` call takes a distinct descriptor"; the safety proof below does not actually use this assumption). * `w.execute()` (line 36) consists of two steps: its invocation (`exS w`, sets `started w`) and its response (`exE w`, sets `done w`); the thunk's internal steps are not modelled. * The response of `Lock(D)` is its last shared step, line 54 `C.FAD()`, which emits `resp p D (done D)`; we prove the value is always `true` (Lemma 4.34). ## Over-approximations (sound for safety) The randomness is replaced by nondeterminism: the write-or-not decision of line 51 is the step's coin `b`; the level `μ = ⌊log C⌋` of line 50 and the new level `ℓ'` of lines 42–46 are chosen by the adversary (the `j` of `sched p j`). Hence every execution of the real algorithm (with any coin outcomes) is a run of this system, and all safety statements transfer. Invalid actions (scheduling an idle process, invoking a busy process or a used descriptor) leave the configuration unchanged except for `clock`, and emit `tau`. -/ namespace
