import Mathlib /-! # Executions of a lock object with helping, and the safety properties (S1), (S2) Section 2.2 of Aeini, Bencivenga, Giakkoupis, Woelfel, *Simple and Efficient Randomized Wait-Free Locks* (PODC 2026). An execution is recorded as the list of its *events* (`Ev`), one per step: * `inv p d` — process `p` invokes `TryLock(d)` / `Lock(d)` (its first shared-memory step); * `resp p d r` — the call responds (its last shared-memory step) with return value `r` (for a non-abortable `Lock` the value is always `true`); * `exS d` — some `d.execute()` call is invoked; * `exE d` — some `d.execute()` call responds; * `tau` — any other step. The *execution interval* of `d`'s thunk begins with the first `exS d` and ends with the first `exE d` (or with the end of the execution). `InInterval es d t` says that the event with index `t` lies in it. * `S1 es` — (S1) mutual exclusion: the execution intervals of distinct thunks are disjoint. * `S2 es` — (S2): the execution interval of `d`'s thunk lies within a single call on `d` (there is an invocation `inv p d` before it and `p` does not respond before the interval ends), and a call returns `true` iff it responds after `d`'s thunk has been executed. The second half of the file is a generic *bridge*: for a transition system with ghost flags `started`/`done` and a "current call" map, three state invariants imply (S1) and (S2) for all its executions
