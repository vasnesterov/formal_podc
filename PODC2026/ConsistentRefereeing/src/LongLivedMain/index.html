import Papers.PODC2026.ConsistentRefereeing.LongLivedLemmas /-! # No wait-free strongly linearizable long-lived contest (Theorems 25 and 30 of [ACE26]) The final arguments of Sections 5.1 and 5.2 of [ACE26], treated uniformly (`LLCtx.main`), and the two theorems: * `theorem25` — no wait-free strongly linearizable long-lived contest implementation from read/write registers (every primitive is read-only or a blind write), `n ≥ 3`; * `theorem30` — none from `w`-window registers and test&set objects (every base object is window-like with window `w` or test&set-like), `n ≥ 4`, `3w ≤ n`. Both assume wait-freedom and strong linearizability only on admissible executions (`LLAdm`); `theorem25'`, `theorem30'` use the unrestricted notions. `register_rw`, `windowObj_hyp30`, `tasObj_hyp30`: the standard objects satisfy the hypotheses. ## Map of Section 5 Definition 15: `LLCtx.W`, `LLCtx.Closed`; Proposition 16: `W_eq_of_dec`, `W_ext_subset`, `Closed.ext`, `exists_super_ext1`, `not_decIn_of_super`, `super_of_not_invoked`; Lemma 17: `lemma17`; Definition 18: `Helping`; Lemma 19: `lemma19`; Lemma 20: `lemma20`; Lemmas 21/27: `lemma27` (`lemma21`); Lemmas 22/28: `lemma28` (`lemma22`); Lemma 23: the first cases of `main`; Lemmas 24/29: `lemma24_1`, `lemma24_2`; the case analyses of Lemmas 20/27/28: `pair`, `window_final`; Theorems 25/30: `main`. Structure of `LLCtx.main` (after Lemmas 19, 27, 28, 24(1)): `α` helping with `W(α) = ∅` and `β` with `W(αβp) ∩ W(αβqp) = ∅` for all competitors `q`. Case analysis of the referee's next step: * invocation (`decide` not yet invoked): it commutes with any competitor step (Lemma 23); * response: `αβp` and `αβqp` both contain the response, so they share their valency; * a primitive on `R`: by Lemma 23 every competitor is poised to write `R`; then - `R` test&set-like: **new argument** `const_valency_contra` (the paper's argument for this case has a gap, see below); - `R` window-like, referee writes: `αβpγ` vs `αβqpγ` (case "all processes write to `R`"); - `R` window-like, referee reads: Lemma 24(2)/29(2) and the paper's final argument. ## Differences from the paper * **Model.** Schedules (`LLCtx.ext`) instead of arbitrary label sequences: in an admissible execution every process has at most one possible next label, so this loses nothing. Indistinguishability is agreement of the final configurations (memory, local states and pending operations of the observers: CSLib's `AgreeOn`). Invocations and responses are steps that do not access memory; all case analyses treat them (like reads, or as commuting steps). * **Lemma 17** additionally assumes that `decide` is pending in `α` (under the paper's history-based indistinguishability the excluded case — `decide` already returned — is trivial; with configuration-based indistinguishability it is needed). In its proof, the operations of `q` must be counted inside the extension `β'` (`α'` may contain a different number of operations of `q`). * **Lemma 19, 22, 24, 28, 29**: "due to wait-freedom" is `resps_unbounded` (a competitor scheduled infinitely often in an infinite competitors-only extension completes infinitely many operations) and `exists_solo_return`; the infinite executions are built as limits of chains (`chain_infExec`). * **Theorem 25, last paragraph** ("We have that αβp is closed. Otherwise, if ... then by Lemma 23 ... contradicting Lemma 24(1). Thus, it must be that ...") is garbled; the intended argument (Lemma 23 contradicts Lemma 24(1) unless every competitor writes to `R` and the referee reads `R`) is the one formalized. * **Lemma 28, test&set case**: "αβq and αβq′ are closed" — `αβq′` is supervalent there; only `αβq` closed is needed (typo). * **Lemma 29**: the proof's last sentence cites Lemma 21 instead of Lemma 27 (typo); for `w = 0` the required sequences (`|γ| = w`, `γ = qλ`) do not exist — we use window `max w 1`. * **Theorem 30, case "all processes T&S the same test&set object R" — proof gap.** The paper claims that `αβγpγ′₁q′ᵏγ′₂` and `αβγ′₁q′ᵏγpγ′₂` end with the same shared memory and are indistinguishable to every `q″ ≠ q, q′`. This holds if `R` is already set after `αβ`, but if `R` is unset, `q` wins the test&set in the first execution and `q′` wins it in the second; `q′` then takes `k` more steps (and the processes of `γ′₂` more steps) whose effect on the memory, and on what `q″` observes, depends on that outcome. The theorem is true: we replace the argument (`const_valency_contra`): once a competitor's step has set `R`, every later step of the referee (on `R`) leaves the memory unchanged and commutes with every competitor step, so by Lemma 17 the singleton `W(αβq u p)` does not depend on the competitors-only extension `u`; choosing `u` in which some competitor completes more than `y = W(αβqp)` operations contradicts the specification (no extension can output `y`). This argument does not use Lemma 29(2). * **Generality.** Theorem 25 holds for any base objects whose primitives are read-only or blind writes; Theorem 30 for any window-like objects (`ObjSpec.WindowLike`) and test&set-like objects (`ObjSpec.TASLike`: every primitive sets the object to a fixed state; readable test&set objects are *not* covered, as in the paper). * Lemma 14 is formalized in `LongLivedPossible.lean` for an atomic counter (readable fetch&increment), max register and snapshot (`lemma14_counter`, `lemma14_maxRegister`, `lemma14_snapshot`); the fetch&increment-only / fetch&add variants are not.
