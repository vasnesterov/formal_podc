The algorithm: the window register `X` is initially empty (`⊥`). A competitor `p` invoking `compete` writes its identifier into `X`; the referee invoking `decide` reads `X` and returns the first (oldest) identifier of the window (`false`, i.e. `winner none`, if the window is empty). In our model every process may invoke its operation any number of times (the contest object is one-shot in the paper; we prove strong linearizability on *all* executions). To keep the window from overflowing, a competitor writes only at its first `compete` and remembers that in a persistent local bit; its later `compete`s read `X` and ignore the result. Every operation accesses the register exactly once, so the implementation is a single-access implementation (`OneAccess`), linearized at the access. Abstraction relation: the window is a duplicate-free list of competitors, it contains exactly the competitors that have written, and the contest state (the first competitor) is its head. Since at most `n − 1` distinct competitors write, the window never overflows (`windowContest_sim`). This shows that the bound `n − 2` of Theorem 5 is tight: `windowContest_hyps` checks that this implementation satisfies all hypotheses of Theorem 5 except that its window is `n − 1`, and `windowObj_not_windowLike` that an `(n − 1)`-window register is not `(n − 2)`-window-like. -/ namespace Cslib.SharedMemory namespace Referee variable {P : Type} [DecidableEq P] [Fintype P] /-- The single-access scheme of the algorithm of Theorem 4.
