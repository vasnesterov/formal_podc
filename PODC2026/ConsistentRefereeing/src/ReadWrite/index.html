The algorithm: a register `X` (values `Option P`, initially `none` = `false`). A competitor invoking `compete i` reads `X` and, if it reads `none`, writes `some i`; it returns `true` (`ok`). The referee reads `X` and returns what it read (`winner`). We prove wait-freedom and linearizability (`theorem3`) on all executions in which the referee invokes at most one operation. That restriction is necessary (the contest object is one-shot): if two competitors both read `none`, the first writes, the referee decides (returning the first writer), and then the second competitor writes, a second `decide` returns the second writer, which no sequential history allows. Competitors may invoke `compete` any number of times. *Decisive* linearizability (prefix-monotonicity up to subsequences) is not defined in our framework and is not proved. The linearization is built along the execution, following the paper's proof: * a `compete` that reads a non-`none` value is appended at its read; * a `compete` that writes is linearized at its write: at the *front* of the linearization if no `decide` has been linearized yet, appended otherwise; * a `decide` is appended at its read. Invariant (`Inv`): as long as no `decide` is linearized, the abstract state (the first competitor of the linearization) is the value of `X` (so the linearization is empty while `X = none`), and a competitor about to write was not preceded by any linearized operation (it read `none` before any linearized operation completed), which makes the insertion at the front respect the real-time order.
