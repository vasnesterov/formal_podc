Given a queue implementation `Q : Impl (queueObj V) B P L` and an injective encoding `e : P → V` of process identifiers, `contestOfQueue Q ref e` is the contest implementation running directly on `Q`'s base objects with `Q`'s local states (the composition is flattened): a competitor `p` runs `Q`'s code for `enq (e p)` and returns `true` (`ok`), the referee runs `Q`'s code for `deq` and returns the decoded dequeued value (`false` = `winner none` if the queue is empty). The paper's proof says "due to strong linearizability, we can assume that the queue is atomic"; we do the composition argument concretely: * every execution of the contest implementation translates label by label into an execution of `Q` (`trFrom`): invocations `compete p ↦ enq (e p)`, `decide ↦ deq`, internal steps unchanged, and a response is replaced by the queue response that `Q`'s program returns at that point (read off the current configuration, `trLbl`), with matching configurations (`runFrom_trFrom`); * a linearization of the translated execution translates back (`isLinearization_back`): the contest state is simulated by the queue state as long as the referee has not dequeued (the winner is the decoded head of the queue). This needs the referee to invoke `decide` at most once (the contest object is one-shot): with two `decide`s the second `deq` would return the second enqueued value. Results (`proposition11`): the contest implementation is lock-free (on all executions), wait-free on the one-shot executions `Adm ref` (lock-freedom of `Q` and the one-shot discipline bound the number of operations), and strongly linearizable on executions in which the referee invokes at most one operation (in particular on `Adm ref`). -/ set_option linter.unusedSectionVars false namespace
