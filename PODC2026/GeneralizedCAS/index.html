Generalized CAS and a space-efficient universal construction — PODC 2026

Vassos Hadzilacos, Myles Thiessen, Sam Toueg. Generalized Compare-and-Swap and Space-Efficient Universal Constructions for the Infinite-Arrival Model. PODC 2026. DOI 10.1145/3796701.3815968. Formalized version: arXiv 2605.19237 v1 (full version with appendices); numbering follows it.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. Theorems 4 and 5 for Algorithm 1 hold: it is a linearizable, wait-free universal construction for any (possibly infinite) set of processes, its space is at most 4 plus the number of processes that have participated, and an operation takes O(c) steps, where c is the point contention when it obtains its timestamp. The flaws are local steps of the counting argument: a non sequitur in the induction of Lemma B.2.14, repaired by a pigeonhole argument, and an additive constant in the proof of Theorem B.2.15. Algorithm 2 (Theorem 6), the paper's second construction, was not checked.

Mistakes in the paper

✏️ Slips

  • Lemma B.2.6 uses Proposition B.2.5 ("not pending ⇒ complete") also for Noop, which is not an operation execution. The case is easy: no process ever writes Noop into A. We treat it separately (OpStart.old_out).

Proof gaps in true statements (2)Lemma B.2.14 · Theorem B.2.15

🔧 Lemma B.2.14 (counting periods; inductive step)

The inductive step concludes "o' = o_{3n+2} = o_{3n+3} = o_{3n+4} for some o' ∈ O_n" from the set not growing, which is a non sequitur: the three new operations can be three different elements of O_n.

Impact. Statement true; repaired by a pigeonhole argument (OpStart.it_le).

Details

The lemma bounds the number of non-initial periods of an operation o by 3|S(o)|. The proof shows |{o₁,…,o_{3n+1}}| ≥ n+1 by induction, where oᵢ is the operation identified by the i-th period. In the inductive step it assumes the set did not grow, so o_{3n+2}, o_{3n+3}, o_{3n+4} all lie in O_n. It then applies Proposition B.2.13 to four periods identifying one operation.

Repair

Proposition B.2.13 says that no operation is identified by four periods. So each operation of S(o) is identified by at most three periods, and pigeonhole gives at most 3|S(o)| periods. In Lean we count differently. A rise of an operation τ is a step after which τ is done and not in A. Every operation rises at most 3 times, because its owner writes it into A at most twice after it is done (Trace.card_RE_le). Every non-initial period contains a rise of an operation of S(o), and disjoint periods give distinct rises (OpStart.useful, OpStart.it_le).

🔧 Theorem B.2.15 (number of iterations)

At most 3c disjoint periods allow up to 15c + 4 complete non-terminal iterations after the first, not 15c, so the total is 15c + 6 iterations, not 15c + 2.

Impact. Statement true: linearity is unaffected. We prove that an operation completes at most 15|S(o)| + 5 iterations and takes at most 105c + 44 memory steps (step_bound).

The formalizationmodel, Lean names of the results, trust

Model.

  • Asynchronous shared memory (CSLib Impl, Cslib.SharedMemory). The processes form an arbitrary type P, possibly infinite: this is the infinite-arrival model with unbounded concurrency. The adversary chooses the schedule. A crash is a process that stops taking steps. There is no randomness.

  • Base objects. C is a fetch&increment object, initially 1. A is a GCAS object (Podc/.../Objects/GCAS.lean) on triples (time, op, ptr), compared lexicographically as in footnote 2; this needs a linear order on operations. S is a CAS object. The dummy cell holds (0, ⊥). Further cells are CAS objects with arbitrary initial contents, handed out by a memory manager in the order 0, 1, 2, …. Since Algorithm 1 never frees cells, every allocation order has this form up to renaming.

  • The target type T is a deterministic sequential specification (CSLib ObjSpec).

  • Each line that accesses a shared object is one step, and local computation is merged into steps. Line 2 is a step only when the process allocates. Line 16 returns the response read on line 5.

  • Correctness notions are CSLib's Linearizable and WaitFree. The point contention is the number of processes with a pending operation. The space is the number of static objects (C, A, S, the dummy cell) plus the number of allocated cells.

  • Proof method. Linearizability is a state invariant (Invariant.lean, about 30 clauses) over the algorithm augmented with ghost variables (Ghost.lean). The linearization is the order of the successful CAS operations on S, as in the paper. The step bound follows the time-based arguments of Appendix B.2 on Traces. A trace is an execution indexed by time, with ghost records of when each line of the current iteration was executed. exists_trace turns any finite execution into a trace.
