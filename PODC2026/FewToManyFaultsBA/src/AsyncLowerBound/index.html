import Mathlib /-! # Theorem 3.3: an `Ω(t²)` message lower bound for asynchronous Byzantine agreement Constantinescu, Dufay, Paramonov, Wattenhofer, *From Few to Many Faults: Optimal Adaptive Byzantine Agreement*, PODC 2026 (arXiv:2505.19989), Theorem 3.3 / Appendix A. ## Model Message-driven asynchronous message passing among the parties `Fin n`. * **Randomness and setup.** Everything that is fixed before the inputs are known — shared randomness, private coins, a PKI, the outcome of an arbitrary setup phase — is encoded in one random element `ω : Ω` drawn from a measure `μ`. No measurability assumption is made on the protocol (all statements use `∀ᵐ`, which only needs a null set containing the bad event). * **Protocol** (`Protocol`). Party `p` with input `b` starts in state `(init p b ω).1` and sends the messages `(init p b ω).2` (pairs destination / payload). Upon receipt of a message `m` from `q` it moves to `(recv p ω s q m).1` and sends `(recv p ω s q m).2`. Asynchronous parties have no clocks, so all local computation between two receipts is folded into the receipt step. Self-addressed messages are discarded (a party can simulate them locally). `decision s` is the output of the party in state `s` (`none` = undecided); the *first* decision is recorded in the configuration (`Config.dec`) and never changes afterwards (irrevocable decisions). * **Configurations** (`Config`): local states, the global log of all sent messages in sending order, the set of delivered log indices and the recorded decisions. * **Scheduler** (`Scheduler`). The message scheduler is a function of the *metadata* of the current configuration only (`Obs`: source/destination of every sent message, which ones were delivered, who has decided — no payloads, no states, no `ω`). At every step it either delivers one pending message or does nothing. A scheduler that sees `ω` would defeat every protocol (FLP), so this restriction is essential; restricting the scheduler (memoryless, metadata only) weakens the requirement `Solves` on the protocol and hence strengthens the lower bound, and the scheduler built in the proof is of this restricted kind anyway. * **Faults** (`Fair`, `Solves`). A static set `F` of at most `t` faulty parties. Faulty parties run the protocol code, but messages from or to them need not ever be delivered: these are Byzantine behaviours (follow the code, omit/ignore messages), so every protocol that is resilient to `t` Byzantine parties satisfies `Solves`. A run is `F`-fair if every message between two parties outside `F` is eventually delivered. * **Correctness** (`Solves A μ t`): for every scheduler, input vector and fault set of size `≤ t`, for `μ`-almost every `ω`, if the run is `F`-fair then (termination) every party outside `F` decides, (agreement) any two decisions of parties outside `F` coincide and (strong unanimity validity) if all parties outside `F` have input `v` then they can only decide `v`. * **Message complexity**: `msgsAtDecision` = the number of messages sent until the first moment at which all parties have decided (`⊤` if never); `totalMsgs` = all messages ever sent. ## Main results * `lower_bound_general`: for `n ≥ 2`, a set `C` of `c` parties and `d` with `c ≤ t` and `c - 1 + d ≤ t`, the scheduler `mainSched C d` (execution `Main` of the paper, with `t/2` replaced by `c` and `d`) is such that with all inputs `false`, almost surely the run is fault-free fair, everybody decides `false`, and at least `c * (d + 1)` messages are sent before everybody has decided. * `theorem_3_3`: with `c = t/2 + 1`, `d = (t+1)/2` (for `1 ≤ t < n`): almost surely `M ≥ (t/2 + 1) * ((t+1)/2 + 1) ≥ t²/4`, hence also `E[M] ≥ t²/4`. ## Proof structure (differences from the paper) The bound holds *almost surely*, not only in expectation: the paper's Markov/union-bound step is replaced by a pointwise argument on the intersection of finitely many full-measure events: * setup `Final` (`no_init_decision`): a.s. no party with input `false` decides without having received a message (i.e. at initialization; in this message-driven model this replaces the paper's "within time `T`"), since otherwise agreement fails with positive probability; * setups `S_B` and `S_Q` (`main_fair_C`, `main_fair_Q`): a.s. everybody decides in `Main`; * counting (`main_count`): hence every `p ∈ C` decides only after receiving a non-held message, i.e. after at least `d + 1` messages were sent to it. (The paper's inclusion `⋂ E_pᶜ ⊆ {M ≥ t²/2}` should read `{M > t²/4}`; this is harmless there.) Non-vacuity: `Solves A μ t` is satisfiable for `n > 3t` by known randomized asynchronous BA protocols with a trusted setup (e.g. Cachin–Kursawe–Shoup), since our faults are a special case of Byzantine faults; no such protocol is formalized here. The hypothesis `n ≥ 2` of `lower_bound_general` cannot be dropped: for `n = 1`, "decide your own input at initialization" satisfies `Solves` for every `t`. -/ namespace Podc.FewToManyFaultsBA.Async
