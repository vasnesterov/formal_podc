From Few to Many Faults: Optimal Adaptive Byzantine Agreement — PODC 2026

Andrei Constantinescu, Marc Dufay, Anton Paramonov, Roger Wattenhofer. From Few to Many Faults: Optimal Adaptive Byzantine Agreement. PODC 2026. DOI 10.1145/3796701.3815964. Formalized version: arXiv 2505.19989 v3 (17 Jun 2026); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. Theorem 3.1 (synchronous BA, t < n/2, O(n·f) messages, O(f) rounds) holds for the paper's protocol SyncBA against a static adversary, with the quadratic fallback (Momose–Ren) taken as a black box, once the proofs of ViewByzantineAgreement sign the view. Theorem 3.3 (Ω(t²) expected messages in asynchrony) holds, in fact almost surely, and Theorem 3.8 (committee assignment) holds, and we also prove the disperser existence the paper only cites; each needed one local repair of its proof. The partially synchronous and QAB protocols were not checked.

Mistakes in the paper

🔧 Appendix B.1 (ViewByzantineAgreement: key/lock/commit proofs must sign the view)

The pseudocode forms proofs as tcombine((KEY, value), ρ) without the view, so a Byzantine leader can replay a key proof under a larger claimed view, bypass the lock check, and get commit proofs for two values.

Impact. The protocol is unsafe as written, but the intent is evident and the fix is local (sign the view): the paper's proofs speak of "a key proof with view number view3" and "a commit proof contains a view number". Theorem 3.1 holds with the fix.

Details

A party stores key ← (v, view, proof), and the key phase compares the claimed view of a proposed key with the view of its own lock. With unsigned views, a Byzantine leader can re-use a key proof for v₂ from view 3, claim it is from view 9, and pass the lock check of parties locked on v₁ in view 5. Lemma B.2 then fails, and two values can get commit proofs.

Repair

Our statements key b v, lock b v, commit b v include the view (Stmt, key_after_commit).

✏️ Slips

  • SyncBA (Appendix B.3), line 30 sets the fallback input to v_in, which may have become ⊥; we use the original input, as the proof of Theorem B.14 says. This only matters when the honest inputs are not unanimous.

  • Theorem 3.8 for f̂ = 0: the construction has M = 0 committees, so every party is vacuously blocked. The paper uses f̂ ≥ 1 only.

Typos

  • SyncBA (Appendix B.1): whether a party that already has a commit answers RunRetrieval is ambiguous. Lemma 10.1 needs every honest party to answer an honest leader's retrieval. We take "a party is active in a view iff it had no commit when suggesting". Then an honest leader that runs the retrieval sees every honest party active, since otherwise it would have received a commit.

  • Theorem 10.5 says f < ⌊(n−t−1)/2⌋, Theorem 7.2 says f ≤; ≤ is what holds.

  • The Section 7 overview says a party accepts if its lock has a lower view than the proposed key (strict), while the pseudocode of Appendix B.1 rejects only a strictly smaller key view.

Proof gaps in true statements (2)Theorem 3.3 · Theorem 3.8

🔧 Theorem 3.3 (asynchronous Ω(t²) lower bound, Markov step)

The proof claims ⋂_{p∈C} E_pᶜ ⊆ {M ≥ t²/2}, but with |C| = t/2 parties each receiving more than t/2 messages one only gets M > t²/4.

Impact. Statement true, even stronger: the bound holds almost surely (Async.theorem_3_3, Async.lower_bound_general).

Details

So P(⋃ E_p) ≥ 1/2 and "P(E_p) ≥ 1/t for some p" are unjustified. Positive probability is enough for the final contradiction, so the theorem survives. The proof also silently assumes t even (|C| = t/2). Its "decides within time T" step has no meaning in an asynchronous model.

Repair

No probability estimate is needed: the Final-setup argument applies pointwise to almost every random string. Hence a.s. every p ∈ C receives more than t/2 messages, and M ≥ (⌊t/2⌋+1)(⌈t/2⌉+1) ≥ t²/4 almost surely. We replace "decides within time T" by "decides before receiving any message" (Async.no_init_decision).

🔧 Theorem 3.8 (committee assignment; Theorem 6.2 used outside its range)

The proof takes a disperser with N = n left and M = 4c_d·f̂·log n right vertices, but Theorem 6.2 is stated only for M ≤ N, which fails once f̂ is close to n / log n.

Impact. Statement true; repaired by proving the disperser existence directly, for all N, M (theorem_3_8, exists_disperser, theorem_6_2).

Repair

We prove the disperser existence by a union bound, for all N, M. This gives Theorem 3.8 for every n, f̂ with explicit constants: (4f̂+1)(⌈log₂ n⌉+1) committees, at most 2(⌈log₂ n⌉+1) committees per party, and at most 4f̂ blocked parties.

The formalizationmodel, Lean names of the results, trust

Model.

  • Theorem 3.1. CSLib's synchronous lock-step model (Cslib.Byzantine.LockStep) on the complete network of Fin n; one round is one Δ. The adversary is static and Byzantine, with f ≤ t < n/2 parties, rushing, and sends arbitrary messages. Signatures are ideal tokens (LockStep.Auth): the adversary may forge only Byzantine signatures, and may replay any signature an honest party has emitted. A k-threshold signature is a set of at least k partial signatures on one statement. We count messages, not bits; a party gets its own messages by self-delivery, which is not counted. The protocol syncBA is deterministic and defined as a local state machine (SyncBA/Defs.lean). Stage A runs ViewByzantineAgreement with the synchronous retrieval for n views of 11 rounds each, round robin, so every party leads once, then the HELP / PROOF / FALLBACK / LOCK rounds. Stage B runs the fallback among the parties holding a fallback certificate. The fallback is a hypothesis (Fallback): an unforging authenticated BA protocol for t faults, deciding within Rfb rounds, in which every honest party sends at most mfb messages whatever the others do. This is the paper's Theorem B.15 ("even if not all honest parties join").

  • Theorem 3.3. Message-driven asynchronous message passing. All randomness, a PKI and any setup are one random element ω, with no measurability assumed. The scheduler sees only metadata: who sent to whom, which messages were delivered, who decided. Faults are static, at most t parties, which run the code but whose links need not be fair. These are Byzantine behaviours, so a Byzantine-resilient protocol satisfies our requirement Solves. The weak adversary and scheduler make the lower bound stronger.

  • Theorem 3.8. Pure combinatorics; log n is ⌈log₂ n⌉ + 1.

  • Complexities. O(n·f) / O(f) are meant with the convention f ≥ 1 (footnote 2); we state O(n(f+1)), O(f+1).

  • Weaker than the paper: Theorem 3.1 is proved against a static adversary. The paper claims a dynamic one. Correctness transfers for deterministic protocols. For the message bound, messages a later-corrupted party sends while still honest are not counted. Local timers / null steps are not modelled in asynchrony.
