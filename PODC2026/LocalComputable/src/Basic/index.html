import Mathlib.Order.Filter.Ultrafilter.Basic import Mathlib.Order.Filter.Finite import Mathlib.Order.Filter.AtTopBot.Basic import Mathlib.Computability.Partrec import Mathlib.Data.ENat.Basic /-! # The ball-growing LOCAL model, abstractly Cruciani, Das, Equi, Lievonen, Luong-Le, Modanese, Suomela, *Is a LOCAL algorithm computable?* (PODC 2026 brief announcement; arXiv 2602.21022). The paper's equivalence results (Section 5) use only the following features of the LOCAL model (Definitions 3.1, 3.5): every node `v` of a network `G` has, for every radius `t`, a *view* `view G v t` (its radius-`t` rooted neighbourhood up to isomorphism), and the radius-`t` view determines all smaller views. A (deterministic) LOCAL algorithm in the *ball-growing formalism* is a map `A : View → ℕ → Option Out`; node `v` outputs `A (view G v t) t` for the least `t` with a non-`⊥` (here: non-`none`) value. We therefore work with an abstract `Model Net View`: a type of networks, their sizes, and their views, subject to the restriction property `Model.restrict`. The concrete port-numbered networks with identifiers of Section 3 are an instance (`Concrete.lean`). A *problem* is an arbitrary predicate on output labellings (LCLs are a special case; the paper remarks that its equivalences hold "for LCLs and beyond"). The only property of LCLs that is used is that the output alphabet is finite (Theorem 5.4) and that validity is decidable (Theorem 5.3). Knowledge of `n`: in the model with an upper bound, every node additionally receives a common natural number `N`; an algorithm is then a family `A : ℕ → Alg View Out`, and the *promise* `Adm N G` says which pairs `(N, G)` are legal inputs (`n ≤ N`, or `n ≤ N ≤ f(n)`). -/ namespace LocalComputable /-- An abstract family of networks for the ball-growing LOCAL model: networks have a size (number of nodes, the nodes being `0, …, size G - 1`) and every node has a view of every radius.
