import Papers.PODC2026.LocalComputable.Concrete import Mathlib.Tactic.IntervalCases /-! # The paper's "maximally `T`-safe" neighbourhoods are not a property of the view Definition 5.1: `t` is *`T`-safe* for `v` in `G` if no network `G'` with a node `v'` whose radius-`t` view equals that of `v` has `t > T(|V(G')|)`; `t` is *maximally `T`-safe* if `t` is safe and `t + 1` is not. The paper then "extends these notions to the rooted neighbourhoods themselves", and the algorithms of Theorems 5.3 and 5.4 let every node grow its view "until it reaches a maximally `T`-safe neighbourhood" and stop there. Whether `t` is maximally safe depends on the radius-`(t+1)` view, which the node does not know after `t` rounds. We show in the concrete model of Section 3 (any `Δ ≥ 2`, `c ≥ 1`, `k ≥ 1`) and for the computable non-decreasing bound `T(n) = ⌊(n-1)/2⌋`: the node `0` of a triangle `C₃` and the node `0` of a 5-cycle `C₅` have the same radius-`1` view, radius `1 = T(3)` is maximally safe in `C₃` but not in `C₅`. Hence no ball-growing algorithm stops exactly at the (first) maximally safe radius (`no_alg_stops_at_maxSafe`); in `C₃` a node needs radius `2 > T(3)` to recognise that radius `1` is maximally safe. The fix is our notion `Model.Critical` ("the radius-`t` view occurs in a network whose time bound is `≤ t`"), which is a property of the radius-`t` view and is implied by maximal safety
