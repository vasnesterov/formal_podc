Conflict-Freedom as a Progress Condition — PODC 2026

Petr Kuznetsov, Pierre Sutra, Guillermo Toyos-Marfurt. Conflict-Freedom as a Progress Condition. PODC 2026. DOI 10.1145/3796701.3815956. Formalized version: extended version, arXiv 2605.19531 v1; numbering follows it.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The progress hierarchy (Prop. 3.3), the invariance of return values on traces (Lemmas 4.1–4.2), the read-write generalized commit-adopt (Alg. 2, Thm. 5.1) and the weakly conflict-free universal construction built from it (Alg. 1, Thms. 4.3, 4.4) hold, and their proofs need only local corrections. The proof of the direction lock-freedom ⇒ weak conflict-freedom in Proposition 3.4 stays broken, but nothing depends on it. The conflict-free construction of Section 6, which the abstract announces, was not checked.

Mistakes in the paper

❌ Proposition 3.4, second item (lock-freedom implies weak conflict-freedom; not formalized)

The proof argues that "a suffix where Φ runs pending and alone contradicts lock-freedom", which it does not, because an idle process is correct and vacuously completes all its operations.

Impact. No later result uses this direction. The other direction, weak conflict-freedom ⇒ lock-freedom for empty ≍, is proved (WeakConflictFree.lockFreeP_of_empty).

Repair

The fix is to let idle processes invoke and crash. This is not proved in Lean.

✏️ Slips

  • GCA Commitment (Section 4.2) and Lemma A.3: taken literally, Commitment fails when nobody participates (P = P_r = ∅), because all inputs are vacuously compatible but no process exists. The case is never used; GCA.commitment_of_reach assumes at least one participant.

Typos

  • Proof of Lemma A.2, first case split: "B_j ⊂ B_j" should read B_j ⊂ B_i.

Proof gaps in true statements (4)Lemma A.3 · Lemma A.2 · Algorithm 2 · Theorem 4.4

🔧 Lemma A.3 (Commitment of Algorithm 2)

The proof follows a chain i ↦ f(i) of processes whose candidate was missing and claims that f(i) again wrote the least output β into B ("B_{f(i)} = β, therefore f(i) ∈ P_β"), which fails with three processes.

Impact. Statement true; we replace the chain by a maximality argument (GCA.commitment_of_reach).

Details

Inputs a, ε, c over independent letters:

  • p₁ reads A = {a, ε}, writes (a, True) and sees only its own entry. It adopts a, because the input ε ≤ a of p₂ has no B entry yet.

  • p₂ reads A = {a, ε, c} later and writes ac ≠ a.

Repair

Among the processes whose input is ≤ β₀ (the least candidate) and whose B-view contains β₀, one with a maximal B-view must commit (GCA.commitment_of_reach).

🔧 Lemma A.2 (Adoption of Algorithm 2)

The case w_i = True asserts that no flag in B_i is False, which is false.

Impact. Statement true; our proof is a direct case analysis on the comparability of the A- and B-views (GCA.adoption_of_reach).

Details

Let p₁ (input a) write A and snapshot {a} first. A process p₂ whose later snapshot holds a, b, c with b ≍ c (and a independent of both) writes (a, False). Then p₁ has w₁ = True and sees that False flag. Adoption still holds, because all entries seen by p₁ equal its input.

🔧 Algorithm 2 (coherence of the trace order used but never stated)

Algorithm 2's proofs need that a pairwise compatible finite set of traces has an upper bound, which the paper never states.

Impact. Statement true; we prove coherence for traces of duplicate-free schedules (NTrace.compat_of_pairwise).

Details

It is needed in two places: in "A_i^co contains only compatible traces", and in Lemma A.4, to go from incompatible least upper bounds to incompatible elements. The paper cites Aalbersberg–Rozenberg only for the existence of GLBs and of LUBs of compatible sets.

🔧 Theorem 4.4 (invariant (I))

Invariant (I) is claimed for every round r > r₀, which the argument does not give: "u_i contains only commands from pending operations" fails for operations that complete between τ and τ'.

Impact. Statement true; the proof only needs (I) at round r* + 1, where it holds (Alg1.Setup.compat_round).

Details

Operations that complete between τ and τ' commit at rounds above r₀. At round r* + 1 every operation is pending forever, and there (I) holds: completed operations committed at rounds ≤ r*, so by Lemma A.1 their commands lie in the common prefix (Alg1.Setup.compat_round).

The formalizationmodel, Lean names of the results, trust

Model.

  • Base model. CSLib's asynchronous shared memory (Cslib.SharedMemory.Impl): n deterministic processes, atomic base objects, any number of crash failures, and an adversarial scheduler with arbitrary invocations. There is no randomness.

  • Progress conditions. They are stated verbatim on CSLib infinite executions (Progress.lean).

    • Two operations are concurrent iff they are pending at a common time.

    • A process is correct iff it takes infinitely many steps or is eventually idle.

  • Algorithm 1 as an implementation. Algorithm 1 is a CSLib implementation of an arbitrary sequential object (Alg1.impl).

    • Every GCA_r is Algorithm 2 on its own two atomic snapshot objects, flattened, since CSLib has no composition theorem. The proofs only use the GCA properties of each round (Theorem 5.1 applied to the per-round state gst C r), as in the paper.

    • The registers S[j] are read one by one (a collect).

    • Two ghost variables are used: the per-round GCA history and the commit round of each operation.

  • Domain of the GCA objects. Mazurkiewicz traces of duplicate-free command schedules (NTrace), which is all the algorithms ever handle. Algorithm 2 is proved for any GCADomain: a meet-semilattice with least upper bounds of compatible finite sets that is coherent.

Not formalized.

  • The converse lock-freedom ⇒ weak conflict-freedom in Proposition 3.4.

  • Section 6: Algorithm 3, Lemmas 6.1–6.2, Theorems 6.4 and 6.6. The proof of Lemma 6.2 repeats invariant (I) for all r > r₀ and may share the imprecision of Theorem 4.4; we did not check it.

  • Definition 3.2 (2) as worded is satisfied by any process that stays idle, so it says less than the introduction's "ensures progress for one of them". Our Lean definitions are the paper's, verbatim, and we did not check whether Algorithm 1 meets the stronger reading.

Trust. There is no sorry. The listed theorems use only the axioms propext, Classical.choice and Quot.sound.

  • Non-vacuity. Example.lean instantiates Theorems 4.3–4.4 for the shared counter of Figure 1. Reads conflict with updates, and updates commute.

  • Model checking. A model checker of Algorithm 2 (2–4 processes, traces over 3 letters) found no violation.

  • Model origin. The model comes from CSLib's Cslib/Computability/Distributed/SharedMemory/ (Model, Progress, History).

  • CSLib candidates. The Mazurkiewicz-trace library (Podc/Foundations/Data/Mazurkiewicz/) and the progress definitions of Progress.lean.
