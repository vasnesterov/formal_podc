import Mathlib import Papers.PODC2023.RuntimeVerification.Similarity /-! # The interactive model of Section 3 and the impossibility results (Theorem 5.1, Theorem A.1) Castañeda, Rodríguez, *Asynchronous Wait-Free Runtime Verification and Enforcement of Linearizability*, PODC 2023 (arXiv 2301.02638v3). ## The model (Section 3, Figure 2) `n` asynchronous processes run a *verifier* `V`. Each process repeats forever: * Lines 03–05: the environment (adversary) chooses the next operation `o` (never chosen before by this process); the process updates its local state and the shared memory (`Verifier.pre`); * Line 06: it invokes `Apply(o)` of the black-box implementation `A` (`Ev.inv`); * Line 07: it receives the response `y` of `A` (`Ev.res`); * Lines 08–12: it updates its local state and the shared memory, and possibly reports `(ERROR, w)` (`Verifier.post`). Strengthenings with respect to the paper (they make the impossibility stronger): * the shared memory is an arbitrary type `M` and each block is one *atomic* transition on it, so base objects of any consensus number (indeed an atomic snapshot-and-update of the whole memory) are allowed; * each block may read a perfectly synchronized clock (the global time `t`); * a verifier block that takes several (wait-free) steps, when run solo, is a function of the starting time, local state and memory, so it is subsumed (our executions run blocks solo, as the paper's proof does); * the verifier may report at the end of any iteration. `A` is an *abstract implementation*: a prefix-closed set `𝒜` of well-formed histories; in an execution, the history of `A` (`Cfg.hist`) stays in `𝒜` at all times (`IsExec.legal`). The verifier `V` does not depend on `A` (the quantifier order is `∃ V, ∀ A`): `A` is a black box and "the only way `V_O` can obtain information of `A` is by invoking high-level operations of it". The paper also says that this is "modeled as conceptually `V_O` taking `A` as its input"; read literally (`V` may depend on `A`), Definition 6.1 becomes trivially solvable (`trivialVerifier_predictive`), so Theorem A.1 needs the black-box (uniform) reading. ## Results * `thm_5_1` — Theorem 5.1 (generic form): for every sequential object admitting operations `a, b, c₁, c₂, …` with `⟨a:ra⟩⟨b:rb⟩⟨c₁:rc⟩⟨c₂:rc⟩…` legal but `⟨b:rb⟩` illegal, no verifier (with `n ≥ 2`) runtime verifies linearizability; even the weak version of completeness (some process reports something) fails. Instances for queues, stacks, sets, priority queues, counters and consensus are in `Objects.lean`. * `thm_A_1` — Theorem A.1: the same objects are not predictively verifiable either (uniform verifiers). * `trivialVerifier_predictive` — under the non-uniform reading, a trivial verifier solves predictive verification for every correctness condition. -/ namespace
