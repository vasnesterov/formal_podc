import Mathlib -- CSLib candidate /-! # The synchronous KT0 clique with port numbers Model of Section 2 / 3.1 of Kutten, Robinson, Tan, Zhu, *Improved Tradeoffs for Leader Election* (PODC 2023). * There are `n = m + 1` nodes. Every node has `m` ports `Fin m`. A node is identified with its ID (a natural number); the ID assignment is a finset `I : Finset ℕ` with `I.card = m + 1`. * A **(partial) port map** `p : PortMap m` says that port `j` of node `u` leads to node `v` when `p u j = some v`. A port map for the ID assignment `I` (`IsPortMap p I`) is total on `I`, injective at every node and has no self-loops; since `I.card = m + 1`, port `j ↦ p u j` is then a bijection from `Fin m` onto `I \ {u}` (`IsPortMap.surj`). This is exactly the paper's port mapping (KT0: a node knows nothing about the IDs behind its ports). * A deterministic synchronous algorithm (`Algorithm m`) has an initial state computed from the node's own ID, sends in every round at most one message per port (computed from the current state), and then updates its state from the vector of messages received on its ports (LOCAL: messages are unbounded). All nodes wake up simultaneously (round 0, 0-indexed). * `run A p r u` is the state of node `u` after `r` rounds when the ports are wired by `p`. Messages sent by `v` in round `r` (0-indexed) are computed from `run A p r v`. The definition makes sense for *partial* port maps too: messages are only delivered along defined links. A partial port map `p` is *valid through round `r` on `S`* (`Valid A p r S`) if during rounds `< r` no node of `S` sends a message over an undefined port. Such partial executions are the paper's "execution prefixes with a partial port mapping" and "restricted execution prefixes" `Exec_r(X)` (Definition 3.4); `run_eq_of_extends` says that every port map compatible with `p` (the paper's "compatible" port mapping) produces the same execution prefix. -/ open Classical Finset namespace LeaderTradeoffs /-- A deterministic algorithm for the synchronous
