import Papers.PODC2023.LeaderTradeoffs.Model /-! # Leader election for small ID universes (Algorithm 1, Theorem 3.15) Section 3.4.2 of Kutten, Robinson, Tan, Zhu, *Improved Tradeoffs for Leader Election* (PODC 2023). IDs are drawn from `U = {1, …, n·g}` (`n = m + 1`). For a parameter `d ≥ 1`, the IDs are split into blocks of `d·g` consecutive IDs: block `r` (0-indexed) is `[r·d·g + 1, (r+1)·d·g]`. In round `r` (0-indexed; the paper's round `i = r + 1`), every undecided node whose ID lies in block `r` sends its ID on all ports. A node that receives messages (or sends) in a round selects the smallest ID among the received IDs and its own (if it sent) as the leader, and stops: it never sends again (the paper's pseudocode leaves this implicit; without it, nodes of later blocks would keep broadcasting and the message bound would fail, and later rounds would overwrite the selected leader). The clause "or sends" matters only for `n = 1`, where the paper's literal rule (select only upon receiving messages) never selects a leader. The paper's assumption `d ≤ n` is not needed; `d ≥ 1` is. Main results (for every `I ⊆ U` with `|I| = n` and every port map): * `run_of_ge`: after `T = ⌈n/d⌉` rounds every node has selected `min I` (explicit leader election); * `electsBy`, `terminatesBy`: exactly one leader, termination by round `⌈n/d⌉`; * `msgs_le`, `msgBound`: at most `(n-1)·d·g ≤ n·d·g` messages in total. -/ open Classical Finset namespace LeaderTradeoffs namespace SmallIds variable
