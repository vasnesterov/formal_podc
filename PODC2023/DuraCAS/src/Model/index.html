full version *Durable Algorithms for Writable LL/SC and CAS with Dynamic Joining*, arXiv:2302.00135v1 (Algorithms 1 and 4, Appendix A). ``` DurEC (handle h = record {DetVal, Val}; object = hardware CAS words X = (hndl, seq), Y = (seq, val)) ECLL(h): 4 return Y ECSC(h, s, v): 6 if Y.seq ≠ s then return false 7 h.Val ← v 8 ĥ ← X.hndl 9 ŝ ← max(h.DetVal, s) + 1 10 r ← CAS(X, (ĥ, s), (h, ŝ)) 11 FORWARD(h) 12 return r FORWARD(h): 13 x ← X 14 ŝ ← x.hndl.DetVal 15 if ŝ < x.seq then CAS(x.hndl.DetVal, ŝ, x.seq) 16 v̂ ← x.hndl.Val 17 y ← Y 18 if y.seq < x.seq then CAS(Y, y, (x.seq, v̂)) RECOVER(h): 20 FORWARD(h) DETECT(h): 22 return (h.DetVal, true) DuraCAS (handle h = {Critical, Casual : DurEC handles}; the full version numbers the lines of `WRITE` 12, 13, 13*, 14–17, of `TRANSFER-WRITE` 18–20 and of `RECOVER` 21–26.) ## Model * Asynchronous shared memory (NVM) with individual crash–restart failures: any process may crash at any time, any number of times; a crash erases the process's local state (program counter and local variables), shared memory is unaffected. * Processes form an arbitrary type `P` (dynamic joining: no bound on the number of processes; the handles `(p, crit)`, `(p, cas)` of process `p` exist from the start with `DetVal = 0` — creating a handle is pure allocation). DuraCAS objects form an arbitrary type `K` (each with its two DurEC objects `(k, W)` and `(k, Z)`), values an arbitrary type `V`. * **The DurEC code is inlined**: every step of a process executes exactly one hardware operation (read or CAS of `X`, `Y`, a `DetVal` or a `Val` field) of the DurEC algorithm, together with the local computation that follows it (DuraCAS-level bookkeeping included). A call of `ECLL` is a single read of `Y`; a call of `ECSC` starts with line 6 and a call of `RECOVER` with line 13. * The `Val` fields are arbitrarily initialised (`hv0`), as in the paper. * `x.hndl = null` (no install yet) in `FORWARD`: the paper dereferences the null pointer at lines 14 and 16. We use the evident fix "if `x.hndl = null` then return" (then `x.seq = 0` and the `if` at line 18 is false anyway). * Every process runs a *most general client*: when idle it may invoke any operation on any object. A crash of a busy process restarts it at line 22 of `RECOVER` of the object of its pending operation; the operation ends (event `rdone`) when `RECOVER` completes. This is the **per-process** recovery discipline (the process recovers before invoking anything else). The brief announcement allows the weaker **per-object** discipline (recover `O` before the next operation on `O`); it is modelled by `StepPO` and refuted in `Counterexample.lean`. * The history records invocations (with the value `d₁` returned by `DETECT` just before), responses and recovery completions (with `d₂` returned by `DETECT` just after) and crashes. -/ namespace Podc.DuraCAS /--
