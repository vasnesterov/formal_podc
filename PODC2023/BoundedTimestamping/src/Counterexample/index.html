import Papers.PODC2023.BoundedTimestamping.Machine /-! # The MTS algorithm is not linearizable **Main result (refutes Corollary 10 / Lemma 8, hence Theorem 1 for this algorithm).** For `n = 3` processes and `κ = 4` (the smallest `κ` with "a complete `helpMoveTS()` call requires at most `n · κ` steps": a call takes up to `2n + 4 = 10` steps), the algorithm of Figures 1–2 has a *sequential* execution (every operation runs solo, from invocation to response) whose responses violate the MTS specification. The script (`script3`): 1. process `0` performs 371 `updateTS()` (`Counter` reaches `δ = 371`, cluster 1 becomes active; `TS[0] = (0, 370)`); 2. process `1` performs 62 `updateTS()`; after the 60th the cluster-1 invalidation phase is over, the last two run in the move phase, and the `helpMoveTS` of process `1` moves `TS[2]` (the `≪`-dominant old entry, index `⊥`) to cluster 1; 3. process `2` calls `isEarlier(0, 1)`; its `κ = 4` `helpMoveTS` steps are `TS[2].LL()`, `Counter.read()` (move phase), `TS[0].LL()` (cluster 0, index 370), `TS[1].LL()`: the coroutine stops between line 61 and line 62 of a `helpMoveTS()` call; 4. process `0` performs two `updateTS()`: `TS[0] = (1, 63)`, and its flag is back to the value process `2` saw; 5. process `2` calls `isEarlier(0, 2)`: line 35 performs `TS[0].LL()`, which *renews process `2`'s link* on `TS[0]`; the `helpMoveTS` steps in line 39 then execute lines 62, 65 (`TS[0].VL()` succeeds — it validates the new link, not the one of line 61), 66 and the `SC` of line 73, which writes `(1, -1)` into `TS[0]` from the stale local copy: process `0`'s latest timestamp is now dominated by process `1`'s; 6. process `2` calls `isEarlier(1, 0)` and gets `false`, although the latest `updateTS()` of `1` precedes both latest `updateTS()` calls of `0` (the specification answers `true`). The cause: `helpMoveTS()` is executed `κ` steps at a time across several operations of the same process, and these operations perform their own `LL()`s on the same `TS` entries; with one link per process and object (the paper's LL/SC definition, Section 3), the `VL()`s of line 65 no longer certify that the local copies of line 61 are current. Giving `helpMoveTS` its own link (e.g. `2n` LL/SC "identities") removes this execution.
