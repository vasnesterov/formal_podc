If `0 ≤ v + d < B`, `faa d` sets the value to `v + d`; otherwise (overflow, "arbitrary behaviour" in the paper) it sets it to `ovf v d` for an **arbitrary** function `ovf`, a parameter of every theorem. * Implemented object `modFaiObj φ` (CSLib catalog): state `s ∈ {0, …, φ-1}`, initially `0`; `read()` returns `s`, `FAI()` returns `s` and sets `s := (s + 1) mod φ`. * Algorithm (Fig. 3, lines 75–78), program counters explicit (`Loc`): ``` FAI(): tmp ← Counter.read() -- pc `fai` if tmp ≥ φn − n then tmp ← Counter.FAA(1 − φ) -- pc `dec` (line 76) else tmp ← Counter.FAA(1) -- pc `inc` (line 77) return tmp mod φ -- pc `done` read(): return Counter.read() mod φ -- pc `rd` ``` The paper only gives `FAI`; `read()` is our (obvious) addition. ## Results * `lemma63` (Lemma 63) and its sharpening `lemma63_sharp`: `(φ-1)·k⁻ ≤ v` and `v + k⁺ ≤ φn − 1` (the paper has `v ≤ φn − k⁺`). * `corollary64` (Corollary 64): no `faa` ever overflows, already for `B ≥ φn` (the paper assumes `B > φn`); hence `ovf` is irrelevant. * `theorem11_linearizable`, `theorem11_waitFree`, `theorem11_steps` (Theorem 11). * Tightness of `B ≥ φn` for `φ ≥ 2`, `n ≥ 1`: `exists_overflow` (with `B < φn` some `faa` overflows), `exists_reach_max` (the counter reaches `φn − 1`). -/ namespace Cslib.SharedMemory.BoundedTS.FAI open Cslib.SharedMemory /-! ## Objects and the algorithm -/ /-- Operations of a fetch-and-add object. -/ inductive FAAOp where | read | faa (d : ℤ) /-- A bounded fetch-and-add object with values in `{0, …, B-1}`, initially `0`.
