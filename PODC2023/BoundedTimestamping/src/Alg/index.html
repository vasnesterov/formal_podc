Every shared-memory operation of the pseudocode is one base-object access; local computation is folded into the continuations. Process identifiers inside local states are natural numbers (converted with `Fin.ofNat`). Procedure calls are encoded by program counters and one return address per procedure (`hret`, `cret`, `enested`): the call graph is `updateTS → helpUpdateTS, helpSystem, helpActiveCluster`, `helpSystem → helpUpdateTS, isEarlier`, `isEarlier → helpUpdateTS, helpActiveCluster`, so each procedure has at most one active instance per process. **`helpMoveTS` is a coroutine.** Line 23 ("perform `κ` steps from `helpMoveTS()`") executes the next `κ` shared-memory steps of a *persistent* `helpMoveTS()` call (field `mv`); when a call finishes, the next step starts a new call. This is the only reading compatible with constant step complexity and with the proof of Lemma 33 ("only one of these calls can be invoked before `t`, and a complete `helpMoveTS()` call requires at most `κ · n` steps"). **Lines 70–72 with `⊥` indices** are not specified by the paper.
