import Papers.PODC2023.AmortizedByzantineBroadcast.DishonestMajorityConsistency /-! # Section 5 of [WXMRS23]: Algorithm 5.2 read literally violates validity (and consistency) Algorithm 5.2 invokes `TrustCast(G_u, n, k)`, whose rules (Algorithm 5.1) run in rounds `1..n` of the slot, and whose equivocation rule only concerns proposals of the current slot `k`. With the trust graph shared across slots this is not enough: equivocation evidence that one honest node `x` receives in the last maintained round of a slot reaches the other honest node `u` only when the evidence is no longer processed, so `x` and `u` keep *different* trust graphs forever (transferability fails), and in the next slot with a silent Byzantine sender `u` accuses `x` (integrity fails), later isolating itself; when `x` is the sender, `u` commits `⊥`. Execution (`N = Fin 3`, `x = 0`, `u = 1` honest, `a = 2` Byzantine, `f = 1`, `n = 3`, `T = 7`; slots `0, 1` have sender `a`, slot `2` has sender `x`): * round 0: `a` sends `⟨prop, true, 0⟩_a` to everybody (delivered in round 1); * round `δ - 1`: `a` sends `⟨prop, false, 0⟩_a` to `x` only (delivered in round `δ`), where `δ = n = 3` is the last TrustCast round (literal reading); `x` removes `a`, forwards both proposals, but `u` receives them in round `4`, outside TrustCast, and never removes `a`; * slot 1 (`a` silent): in round 1 of the slot `u` accuses `a`; in round 2 the edge `x – a` is still in `G_u` (but not in `G_x`), so `dist_{G_u}(x, a) = 1 < 2` and `u` accuses the honest `x`; in round 3 `u` removes the edge `u – x` and is isolated; * slot 2 (sender `x` honest): `x ∉ G_u`, so `u` votes `⟨corrupt, x⟩_u` and commits `⊥`. In slot 0 already `x` votes `⟨corrupt, a⟩_x` (as `a ∉ G_x`) and commits `⊥`, while `u` never removes `a` and commits `true`: consistency (Lemma 5) fails as well.
