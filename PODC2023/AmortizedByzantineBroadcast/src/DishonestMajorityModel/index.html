import Mathlib /-! # Section 5 of [WXMRS23]: multi-shot Byzantine broadcast under dishonest majority — the model [WXMRS23] J. Wan, Z. Xiang, A. Momose, L. Ren, E. Shi. *On the Amortized Communication Complexity of Byzantine Broadcast.* PODC 2023. This file is a lock-step model of Algorithm 5.2 (multi-shot BB, `f < n`), which runs, in every slot, the simplified TrustCast of Algorithm 5.1 followed by a Dolev–Strong phase on `⟨corrupt, S_k⟩`. * Nodes: a finite type `N`, `n = Fintype.card N`. A static set `H` of honest nodes; the others are Byzantine. The bound `|N \ H| ≤ f` is only needed for consistency (Lemma 5), not for validity. * Time: global lock-step rounds `r : ℕ`; slot `k` (we index slots from `0`, the paper from `1`) consists of the rounds `k T, …, k T + T - 1` with `T = n + f + 3`; `loc r = r % T` is the round number inside the slot and `slot r = r / T`. A message multicast in round `r` is received by every honest node (including the sender itself) in round `r + 1`. * Messages are signed atoms (`Msg`): `⟨prop, m, k⟩_{S_k}`, `⟨accuse, v⟩_w`, `⟨corrupt, v⟩_w`. Signatures are ideal: the adversary may deliver to an honest node, in round `r`, any atom signed by a Byzantine node, and an atom signed by an honest node only if some honest node multicast it in a round `< r` (rushing, eavesdropping adversary) — `AdvValid`. * Honest state (`State`): the cumulative set `know` of received atoms, the trust graph `G` (a `SimpleGraph N`; the trust graph `G_u` of the paper is the connected component of `u` in `G`, so "remove all vertices unconnected with `u`" is implicit), and the set `out` of atoms multicast in the current round. States are computed from the adversary's deliveries (`cfg`). * The trust graph is shared by all slots (Algorithm 5.2: "each node uses the same trust graph across all slots"). ## The reading parameter Algorithm 5.2 invokes `TrustCast(G_u, n, k)`, i.e. the TrustCast rules run in rounds `1..n` of the slot only. Read literally, accusations and equivocation evidence arriving later are never processed in that slot, and equivocation evidence for slot `k` is never processed after slot `k`. `Reading` makes this explicit: `maint t` says in which in-slot rounds the graph-maintenance rules (process and forward accusations, detect and forward equivocations, remove vertices) run, and `eqSlot j k` which slots' equivocation evidence is considered during slot `k`. * `Reading.charitable`: graph maintenance in every round, equivocation evidence of every slot. The correctness proofs are for this reading. * `Reading.literal n`: graph maintenance only in rounds `1..n` of the slot, only evidence of the current slot (the text of Algorithms 5.1/5.2).
