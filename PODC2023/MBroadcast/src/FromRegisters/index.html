import Papers.PODC2023.MBroadcast.FromRegistersTrace /-! # Algorithm 2: MBroadcast on top of atomic SWMR registers (full version, Section 5.1) The brief announcement states (end of Section 5) that MBroadcast can be implemented on top of atomic read/write registers, for any number of crashes. The algorithm is given in the full version (DISC 2023, Algorithm 2, proof in Appendix A.1): ``` shared: SENT[1..n], SWMR registers, SENT[i] = list of messages mbroadcast by pᵢ (initially empty) local: deliveredᵢ[1..n] (counters, initially 0) operation mbroadcast(m): (1) SENT[i] ← SENT[i] ⊕ m; (2) catch_up(); (3) mdelivery of m from pᵢ periodically do catch_up(). internal uninterruptible routine catch_up(): (4) for j from 1 to i − 1 and then from i + 1 to n do (5) msg_j ← SENT[j]; (6) for k from deliveredᵢ[j] to |msg_j| − 1 do mdelivery of msg_j[k + 1] from p_j end for; (7) deliveredᵢ[j] ← |msg_j| ``` ## Model * `n` asynchronous processes `Fin n` (the loop order "1..i−1, then i+1..n" is the increasing order skipping `i`); messages of any type `M` with decidable equality. * `n` **atomic** SWMR registers `sent : Fin n → List M`; one register access is one atomic step. Any number of processes may crash (`Act.crash`, at any time; a crashed process takes no further step). * A configuration also holds the local counters `delivered`, the control position of each process (`Phase.idle`, or `Phase.catchUp own j`: inside `catch_up`, the next register to read is `j`, and `own = some m` iff this `catch_up` is the one of line 2 of `mbroadcast(m)`), and the **MBroadcast trace** `log` of the `bc`/`dl` events, in real-time order. The safety theorems are stated on `log` with the definitions of `Spec.lean`. * Atomic steps (`step`): - `invoke p m`: invocation of `mbroadcast(m)` together with line 1 (one atomic write of `SENT[p]`, which `p` knows locally since it is its only writer); appends `bc p m`. It is enabled only when `p` is idle (no `catch_up` runs: the routine is uninterruptible, and an invocation has no effect before line 1, so this loses no behaviour), and only if `p` has not already mbroadcast `m` (the paper's assumption that all messages are different, per sender). - `tick p`: the next local step of `p`. When idle: start a periodic `catch_up`. In `catchUp own j` with `j < n`: if `j = p`, skip it; otherwise one atomic read of `SENT[j]` (line 5) together with the local lines 6–7, which append the `dl p j _` events of the messages not yet mdelivered, in order. In `catchUp own n`: the loop is over; if `own = some m`, line 3 (`dl p p m`, i.e. `mbroadcast(m)` returns). Executing the local lines 6–7 in the same atomic step as the read only fixes how the local steps of `p` interleave with steps of other processes, which is irrelevant for the abstraction (they touch only the local state of `p`). - `crash p`. * The register accesses themselves are not logged: the theorems only need the MBroadcast events (the write of line 1 coincides with the `bc` event). * The full version assumes only *regular* registers; we model atomic ones (as in the brief announcement's claim). ## Results * `safe`, `fifoOrdering` (this file): every reachable configuration (any number of crashes) satisfies unique broadcasts, Validity, No-duplication, Mutual ordering and FIFO ordering. Mutual ordering follows the proof of Appendix A.1, via the trace invariant `MOInv` (`FromRegistersTrace.lean`) and the invariant `Inv.cu`. * `localTermination`, `globalCFTermination`, `globalCSTermination` (`FromRegistersLiveness.lean`): under weak fairness, for correct processes. * `not_causalOrdering` (`FromRegistersCausal.lean`): Algorithm 2 is not causal. * `Causal.safe`, `Causal.causalOrdering`, `Causal.fifoOrdering`, `Causal.globalCFTermination`, … (`FromRegistersCausalVariant*.lean`): a variant (ours) implementing causal-MBroadcast. -/ namespace
