import Papers.PODC2023.MBroadcast.Spec import Mathlib.Data.Fintype.Card /-! # Algorithm 2 (MBroadcast on top of causal message delivery): the model Model `CAMP_{n,t}[t < n/2]` enriched with causal message delivery, running Algorithm 2 of Déprés, Mostéfaoui, Perrin, Raynal, *Brief Announcement: The MBroadcast Abstraction*, PODC 2023: ``` operation mbroadcast(m): (1) causal_broadcast init(m); (2) wait (ack(m) received from at least n − t − 1 processes); (3) mdelivery of m from p_i when init(m) is causally-delivered from p_j do (4) if i ≠ j then (5) causal_send ack(m) to p_j; (6) mdelivery of m from p_j end if ``` ## Model choices * Processes `P` (`[Fintype P]`, `n = Fintype.card P`), protocol parameter `t : ℕ` (the waiting threshold of line 2 is `n - t - 1`, natural subtraction), messages `M`. * **One global, append-only event log** `Cfg.log : List (GEv P M)`, in real-time order; "before" is comparison of positions. It contains the events of the MBroadcast abstraction (`GEv.mb`), the network sends (`GEv.snd`) and the network receptions (`GEv.rcv`). The *id* of a network message is the log position of its `snd` event. The MBroadcast trace is the projection `Cfg.trace = log.filterMap mbOf`; all correctness theorems are stated about it, with the definitions of `Papers.PODC2023.MBroadcast.Spec`. * A network message record (`Rec`) has a sender, a set of destinations (a causal broadcast is one network message with destinations `univ.erase sender`, a causal send has one destination), a body (`init m` or `ack m`) and a ghost field `dep`: the ids of all messages that causally precede this send. `dep` is the sender's causal past `Cfg.past src` at sending time; `past p` contains the ids of `p`'s own sends, of the messages `p` received, and their `dep`s (this is the transitive closure of the paper's relations (i) and (ii)). * **Causal delivery** (`CausalReady`): a process `p` may receive message `x` only if it has already received every message `y ∈ dep x` of which it is a destination. This is exactly the paper's causal delivery guarantee ("if send(m1) causally precedes send(m2) and both have the same destination, m1 is delivered there before m2"), for causal broadcasts and causal sends alike. Channels are otherwise unordered (not FIFO). * **Self-delivery.** The causal broadcast of line 1 does not include the sender in its destinations: in Algorithm 2 the handler of a self-delivered `init(m)` does nothing (test of line 4), so this is a no-op; it does not affect causality either, since every own send is in the sender's causal past anyway. * **Atomicity.** Each step executes a block of code between two `wait`s atomically: an invocation (line 1: the whole causal broadcast is one step), the end of the wait of line 2 (line 3, `Action.own`), the reception of a message together with its handler (lines 4–6 for `init`; for `ack(m)`, the receiver records the sender in its set of acknowledgers if it is currently waiting for acknowledgements of `m`). * **Local state**: `Phase.idle` or `Phase.wait m acks` (inside `mbroadcast(m)`, waiting at line 2, `acks` = the processes from which `ack(m)` was received); crashed processes `crashed`. * **All mbroadcast messages are different** (the paper's assumption, per sender): `invoke p m` is enabled only if `p` never invoked `mbroadcast(m)` before. A process invokes a new `mbroadcast` only when the previous one returned (processes are sequential). * **Crashes and reliability.** A crash is a step (`Action.crash`); crashed processes take no further steps. Messages are never lost: the messages of a crashed sender stay in transit and may still be received (reliable channels). Since a whole broadcast is one atomic step, the paper's possibility "a process crashes in the middle of a broadcast and only some destinations ever receive the message" is covered for safety: every finite behaviour of that model is a finite behaviour of ours in which the remaining receptions simply have not happened yet, and the safety properties are properties of finite traces. For liveness (`Exec.Fair`), a message to a correct process whose causal predecessors (with the same destination) have been received is eventually received, also when its sender has crashed. The liveness proofs use this only for messages of correct senders and for messages in the causal past of a message sent by a correct process (a process that has delivered or sent them); this is what an implementation of causal delivery on top of reliable channels provides (by piggybacking the causal past), and it is needed anyway for causal delivery to be live in the presence of crashes. *
