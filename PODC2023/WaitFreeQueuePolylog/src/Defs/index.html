import Cslib.Computability.Distributed.SharedMemory.LinPoints import Cslib.Computability.Distributed.SharedMemory.Potential import Cslib.Computability.Distributed.SharedMemory.Objects.Queue import Mathlib.Tactic /-! # The unbounded-space queue of Naderibeni and Ruppert (Fig. 4) The queue is an implementation (`Cslib.SharedMemory.Impl`) of the sequential FIFO queue `queueObj V` from one base object, the shared memory `memObj V`, whose operations are the shared-memory accesses of Fig. 4. **The ordering tree.** A complete binary tree of height `H ≥ 1` in heap numbering: the root is node `1`, the children of `n` are `2n` (left) and `2n+1` (right), the parent of `n` is `n / 2`; the leaves are the nodes `2^H, …, 2^(H+1) - 1`, and process `p : Fin np` (`np ≤ 2^H`) owns the leaf `2^H + p`. (The paper uses height `⌈log₂ p⌉`.) **Shared memory.** For every node `n`: `head n` (the field `v.head`), the blocks array `blk n : ℕ → Option (Blk V)` (`none` = `null`), and the only mutable block field `super`, stored separately as `sup n i : Option ℕ`. All other block fields are written when the block is created, before it is installed, and never change (Section 4.1). **Atomicity.** Every access to a *mutable* shared location (a `head` field, an entry of a `blocks` array, a `super` field) is a separate step. Reads of fields of blocks that are already installed are reads of immutable data; they are grouped with the preceding step of the same line (the values read are the same whenever they are read). In particular one step of `IndexDequeue`, of `FindResponse` (including the search of line 91) and of `GetEnqueue` (including the binary search of line 114) is one access each. **Variants.** `Variant.paper` is Fig. 4 as printed: `Append` increments `leaf.head` by a plain write (line 13), so the `super` field of a leaf block is not set by `Append`, and line 78 reads `v.blocks[…]`.
