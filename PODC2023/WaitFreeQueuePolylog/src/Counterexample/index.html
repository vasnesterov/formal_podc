import Papers.PODC2023.WaitFreeQueuePolylog.Defs /-! # Counterexamples for the printed pseudocode of Fig. 4 All examples use the tree of height `H = 1` (root `1`, leaves `2` and `3`), two processes (process `0` owns the left leaf `2`, process `1` the right leaf `3`) and values in `ℕ`. * **Line 13 (`Variant.paper`).** As printed, `Append` increments `leaf.head` by a plain write and never sets `leaf.blocks[h].super`. A solo `Enqueue(7)` of process `0` leaves `leaf.head = 2` but `leaf.blocks[1].super = null`, so the third claim of Invariant 3 ("if `v ≠ root`, `v.blocks[i].super ≠ null` for `0 < i < v.head`") fails (`invariant3_false`). This breaks `IndexDequeue`: in the solo sequential execution `Dequeue → null; Enqueue(7); Dequeue` the last `Dequeue` reads the null `super` field of its leaf block (as `0`), computes a wrong root block, and returns `null` instead of `7`; the printed algorithm is therefore not linearizable (`paper_not_linearizable`). With line 13 replaced by `Advance(leaf, h)` (and line 78 corrected) the same operations behave correctly (`fixed_example`). * **Line 78 (`Variant` `⟨true, false⟩`: leaf `Advance` repaired, line 78 as printed).** Line 78 reads `v.blocks[…]`, indexed by `endleft` fields, which index the blocks of the *left sibling*. Process `0` enqueues `7`; then processes `0` and `1` both invoke `Dequeue`, process `1` writes its leaf block, and process `0` runs to completion, propagating both dequeues into the same root block (it helps advance leaf `3`). Process `0`'s dequeue precedes process `1`'s in that block and correctly returns `7`. Process `1` (a right child) must add the number of dequeues from the left child in the root block (line 78), but the printed line 78 takes the difference of two `sumdeq` fields of its *own* leaf, misses process `0`'s dequeue, computes rank `1` instead of `2` in the root block, and also returns `7` (`line78_not_linearizable`). With line 78 corrected it returns `null` (`line78_fixed_example`). Non-linearizability is reduced to a finite check by `not_isLinearization_of_check`: every linearization of a history in which all operations completed is a permutation of these operations, so it
