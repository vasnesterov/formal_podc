The admissible executions are one-shot with required participation. Proof of `resilient_withOutput` (`A` weakly `t`-resilient ⇒ `A'` `t`-resilient, `t ≤ n - 2`): let `p` be starved in an admissible infinite execution `e` of `A'`. 1. `starved_step`, `starved_infinitely`: from some time on `p` alternates between reading `⊥` from `output` and taking an *access* step of `A` (reading a value would make it adopt and return; `A` returning would make it write and return). 2. `outReg_eq_none_of_starved`: `output` is never written (once written it stays non-`⊥`, but `p` keeps reading `⊥`). Hence nobody adopts, nobody writes and nobody returns (`no_ret`, `not_write`) — in particular no process is a "crash" of `A` caused by adopting. 3. `projE`, `exists_projExec`: the simulated labels of `e` form an infinite execution `eA` of `A` (`p`'s infinitely many steps of `A` make it infinite); it is one-shot (`oneShotExec_proj`), has the same participants, no returns, and every process crashed in `eA` is crashed in `e` (a process that is not crashed in `e` is starved there and takes infinitely many steps of `A`). 4. Weak resilience of `A` on `eA` (≤ `t` crashes; with a crash, ≥ `n - t ≥ 2` correct processes) yields a correct process of `eA` that returns — impossible. -/ set_option linter.unusedSectionVars false
