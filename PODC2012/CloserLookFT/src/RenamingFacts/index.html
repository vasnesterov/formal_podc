import Papers.PODC2012.CloserLookFT.ElectionLiveness /-! # Per-object facts behind Theorem 4.1 (perfect renaming from election objects) Theorem 4.1 builds partially-wait-free perfect renaming from `n - 1` election objects: a process tries objects `1, 2, …` in order and takes the name of the first object that elects it (or `n`). Its proof uses two facts about one election object `i`: 1. "at most `n - i + 1` processes participate in object `i`", so object `i` may be implemented with `⌈log (n - i + 1)⌉` levels. The paper derives this from the *abstract* election specification ("in the absence of faults exactly one process is elected"); read literally this is not enough (a fault elsewhere in the run would allow an object to elect nobody while all its participants move on). What the argument really needs, and what the algorithm of Section 2 guarantees, is the per-object fact `card_outFalse_lt`: in every state of one object, the processes that returned `0` are strictly fewer than those that started — the last process to write `turn` never returns `0` unless somebody has been elected (and then the elected process does not return `0`). 2. safety of object `i` when only `n - i + 1 ≤ 2^L` processes ever participate, although more processes exist: `Inv.elected_unique_of_started` (two elected processes need more than `2^L` *started* processes).
