Process `p`'s program: ``` function election (e: object name) return:value in {0, 1}; 1 e.turn := p; 2 for level := 1 to ⌈log n⌉ do 3 repeat 4 if e.done = 1 then return(0) fi; 5 if e.turn ≠ p then 6 for j := 1 to level − 1 do if e.V[j] = p then e.V[j] := 0 fi od; 7 return(0) fi 8 until e.V[level] = 0; 9 e.V[level] := p; 10 if e.turn ≠ p then 11 for j := 1 to level do if e.V[j] = p then e.V[j] := 0 fi od; 12 return(0) fi 13 od; 14 e.done := 1; return(1). ``` This file models one election object as a transition system over the shared registers `turn`, `done`, `V[·]` (`EMem`) and the local states of the processes (`ELoc`); every step of a process accesses exactly one register atomically. The CSLib `Impl` wrapper is in `Election.lean`. Modelling choices: * levels are `0`-based: the paper's level `k` is our level `k - 1`, `V[k]` is `V (k - 1)`; the number of levels is a parameter `L` (the paper takes `L = ⌈log₂ n⌉`); * the value `0` of a register is `none`, identifiers are elements of an arbitrary type `P` that are only compared for equality (the algorithm is *symmetric*); * a `for` loop that clears `V[0..b-1]` is the sequence of states `clr k b j` (read `V[j]`) and `clw k b j` (write `V[j] := 0`), the `return(0)` after it is folded into the last step; * the returned states `out r a w c` record ghost information about the process's past (`a` levels passed, registers `V[0..w-1]` written, registers below `c` cleared); the algorithm never reads it. -/ namespace Podc.CloserLookFT /-- The shared registers of one election object: `turn`, `done` and the array `V` (`none` = the value `0`). -/ structure EMem (P : Type) where /-- `e.turn` -/ turn : Option P /-- `e.done` -/ done : Bool /-- `e.V[k + 1]` is `V k` -/ V : ℕ → Option P /-- The initial memory: all registers `0`. -/ def EMem.init (P : Type) : EMem P := ⟨none, false, fun _ => none⟩ /-- Local states (program counters) of a process.
