import Mathlib /-! # Algorithm 2 (S-SP) of [HW12] and counterexamples to Theorem 5 Holzer–Wattenhofer, *Optimal Distributed All Pairs Shortest Paths and Applications*, PODC 2012 ([HW12]), Section 6.1. Algorithm 2 grows the BFS trees `T_u`, `u ∈ S`, simultaneously; on every edge the smaller ID has priority. **Theorem 5** claims that after `|S| + D'` time slots (`D' = 2 · ecc(1)`) every node `v` knows `δ_v[u] = d(u, v)` for all `u ∈ S`. ## The model Synchronous message passing (CONGEST), no failures, deterministic. Vertices are `Fin n`, the ID of vertex `v` is `v` itself (the paper's ID `k` is our vertex `k - 1`). A network is given by the neighbour lists `nbrs v = [v₁, …, v_{d(v)}]` in the order of the paper's neighbour indices `i`. ## The algorithm (lines 13–29), faithfully * `NodeState`: the local variables `L`, `L₁, …, L_{d(v)}` (as lists) and `δ` (`none` = `∞`). `parent` (line 23) is not modelled: it does not influence `L`, `Lᵢ`, `δ`. * `init` (lines 1–6): `L = Lᵢ = {v}` and `δ[v] = 0` if `v ∈ S`, else `L = Lᵢ = ∅`, `δ ≡ ∞`. Lines 7–12 only compute the number of rounds `D' = 2 · ecc(1)`; it is a parameter here. * `minId` (lines 14–16): `lᵢ = min Lᵢ`, or `∞` if `Lᵢ = ∅`. * `NodeState.out` / `msgTo` (line 17): node `w` sends `(l_j, δ[l_j] + 1)` to its `j`-th neighbour. * `process` (lines 19–27), for one neighbour index `i`: if `rᵢ < lᵢ` then (if `rᵢ ∉ L` then `δ[rᵢ] := δ_{rᵢ}`, `L := L ∪ {rᵢ}`, `L_j := L_j ∪ {rᵢ}` for all `j ≠ i`), else `Lᵢ := Lᵢ \ {lᵢ}`. In particular (literally as in the pseudocode) a received ID `rᵢ < lᵢ` that is already in `L` is ignored, and a received ID `rᵢ ≥ lᵢ` is dropped (the sender keeps it in its own list). * `loop` (line 18): the indices `i = 1, …, d(v)` are processed in this order, so if a new ID arrives from several neighbours in the same slot, the one with the lowest index wins (as the paper says right before Theorem 5). `TieRule.minDelta` is a repaired variant in which `δ[r]` is the minimum of all values received for `r` in that slot. * `run rule nbrs S t`: the global state after `t` synchronous time slots; the algorithm outputs `run rule nbrs S (|S| + D')`. ## Results * `delta_stable`: once set, `δ_v[u]` never changes (so wrong values are final). * (A) `triangle_wrong`: triangle, `S = {1, 3}`: node 1 ends with `δ[3] = 2`, but `d(1, 3) = 1`. * (B) `exB_wrong`: nodes `1..4`, edges `1-3, 1-4, 3-4, 2-4`, `S = {2, 3, 4}`: node 3 ends with `δ[4] = 2` although `3` and `4` are adjacent — for **every** numbering of the neighbours and for **both** tie rules; the executions are tie-free (`exB_tieFree`), so the error is not a tie-breaking artefact. (`exB0_wrong`: the counterexample of the task description, edges `1-2, 1-3, 1-4, 2-3`, `S = V`, which works for the min-δ rule but only for some orderings.) * (C) `exC_late`: `K₄` on `1..4` plus a pendant `5` at `1`, `S = {1,2,3,4}`: after `|S| + D' = 4 + 2 = 6` slots node `5` still has `δ[4] = ∞`. * `theorem5_false`: Theorem 5 (correctness after `|S| + D'` slots) is false for both tie rules;
