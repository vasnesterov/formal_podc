import Papers.PODC2012.TMLiveness.Main /-! # The PODC paper's own framework is too weak: a TM that never answers In the PODC version (§2.2–§3.1), a TM implementation is an I/O automaton whose actions are the invocation and response events; histories are the sequences of events of its runs; the liveness notions are evaluated on its *infinite histories*, and a process crashes in an infinite history `H` iff `H|p_k` is finite and non-empty. There are no internal steps and no fairness requirement, so nothing forces the automaton to answer an invocation: a process whose invocation is never answered simply has a finite projection, i.e. counts as crashed. We formalize this framework (with the well-formedness condition of the chapter version, which allows a final pending invocation; the PODC version requires `H|p_k ∈ Σ_k^∞`, which, histories being prefix-closed, would forbid accepting any invocation at all) and show that the *silent* TM, which accepts every well-formed invocation and never responds, ensures opacity and local progress in every fault-prone system (`silent_ensures`): with finitely many processes it has no infinite history, so the liveness requirement is vacuous. Hence Theorem 1 is false if read literally in the PODC formalism. The intended statement — in the step-based model of the chapter version, where a process that keeps taking steps inside an operation that never returns is correct — is `theorem_1`. -/ namespace
