Weak Models of Distributed Computing, with Connections to Modal Logic — PODC 2012

Lauri Hella, Matti Järvisalo, Antti Kuusisto, Juhana Laurinharju, Tuomo Lempiäinen, Kerkko Luosto, Jukka Suomela, Jonni Virtema. Weak models of distributed computing, with connections to modal logic. Verdict: 🔧 Easy fix. Both linear orders hold as stated: SB ⊊ MB = VB ⊊ SV = MV = VV ⊊ VVc (1) and the same for the constant-time classes (2), together with every numbered result on the way (Theorems 4, 8, 9, 11, 13, 17, Lemmas 5, 6, 15, 16, Corollaries 3, 7, 10, 12, 14, 18). The two simulation proofs (Theorems 4 and 8/9) ignore nodes that have already stopped: a stopped node sends the empty message m0, so the simulating node cannot receive the extra information it needs from it, and a local change to each simulation closes this with the claimed running times. The modal-logic characterisation (Theorem 2) was not checked.

Mistakes in the paper

✏️ Slips

  • Theorem 17, proof: the step "there are nodes u, v with t(u) < t(v) and t(v) maximal; this means S(u) = 0" is loose: S(u) = 0 needs a neighbour of larger type. Connectivity, which the paper invokes, gives an edge whose endpoints have different types, and its smaller endpoint outputs 0 (thm17_mem).

  • In Theorem 11, Π(G) is undefined for stars with k ≤ 1: they are stars, but not k-stars with k > 1. We leave the output unrestricted there.

Typos

  • Lemma 6's consequence silently uses order k = 2 (the pair u, w itself).

  • Theorem 11, proof: the algorithm tests "the set of messages {1}", but the received set also contains m0 when Δ > 1; the padding is notational, and the algorithm works when m0 is ignored.

  • In Theorem 17 the local type is defined through out-ports (p((v, i))), but a node can only learn the in-port version (p⁻¹((v, i))). Under consistency the two agree, which is all the proof uses.

Proof gaps in true statements (2)Theorems 8 and 9 · Theorem 4

🔧 Theorems 8 and 9 (Multiset simulation; stopped neighbours)

The simulating algorithm B sorts the full message histories received from neighbours, but a neighbour w that has stopped sends m0, so u no longer receives w's history and cannot place w's m0 in the sorted order.

Impact. Statements true; repaired with a small extra mechanism, same time T (theorem8, theorem9).

Details

B "augments each outgoing message with the full message history" and sorts the received histories lexicographically. But once a neighbour w of u has stopped in A, its copy in B has stopped too and sends m0.

Repair

B stores at each node the multiset H of the full histories received so far. In each round it sets H' = R + (H − R.map dropLast).map (· ++ [m0]), where R is the multiset of histories actually received. So the stopped neighbours' histories are extended by m0; this update is exact for multisets. The paper's refinement P₀ ⊇ P₁ ⊇ … of compatible port numberings is replaced by a single port numbering p*: it copies the out-ports of p₀ and sorts the in-ports by the time-T histories of B's own run, so it is not circular. We show by induction that A on p* follows B on p₀ exactly, using that truncation is monotone for the lexicographic order. Time T is kept, as claimed. (theorem8, theorem9)

🔧 Theorem 4 (Set simulation; "all messages received are distinct")

The proof's claim "now all messages received by a node are distinct" is false: stopped neighbours and padding all deliver m0.

Impact. Statement true; repaired locally with running time T + 2Δ + 1 = T + O(Δ) (theorem4).

Repair

The non-m0 messages are pairwise distinct by Lemma 6, so the number of m0s is Δ − #(distinct non-m0 messages), and the multiset of A's messages can be rebuilt from the set. Our Set algorithm runs C_Δ for 2Δ + 1 rounds and then simulates A. (theorem4)

The formalizationmodel, Lean names of the results, trust

Model. (Model.lean)

  • Deterministic synchronous anonymous networks. There are no identifiers, no randomness and no failures; each node initially knows only its degree.

  • Graphs are finite simple graphs G : SimpleGraph V, [Finite V]; deg v is Nat.card of the neighbour set.

  • A port numbering is literally the paper's p : P(G) ≃ P(G) with A(p) = A(G), where Port G = Σ v, Fin (deg v) (ports are 0-based). It is not required to be an involution; Consistent means p ∘ p = id.

  • A state machine Machine Δ Y has stopping states Y and arbitrary intermediate states and messages, with m0, z0 : ℕ → Y ⊕ Z, μ and δ : Z → (Fin Δ → M) → Y ⊕ Z. The execution is the paper's §1.3 verbatim: the received vector is ordered by in-port and padded with m0, and stopped nodes send m0 and keep their state.

  • Multiset/Set/Broadcast are the paper's conditions on δ/μ. An algorithm is a sequence (A_Δ). "Solves Π in time T" quantifies over all Δ, all finite G ∈ F(Δ) and all (resp. all consistent) port numberings. Constant time means T(Δ, n) = T'(Δ). The 14 classes VVc … SB, VVc1 … SB1 are defined from these.

  • Output sets Y are arbitrary types: the equalities hold for every Y, and the separating problems use Bool.

  • Bisimulation (Bisimulation.lean) is defined on the paper's relations R(i,j), R(i,*) and R(*,*) = E. Instead of Theorem 2 (modal-logic characterisation, not formalized), we prove directly that bisimilar nodes run through identical states for every algorithm of the matching class; Corollary 3 follows.

Lemma 5 is stated for rounds t ≥ 4; it holds for t ≥ 3 (PortNumbering.lemma5').

Trust. No sorry; linearOrder, linearOrder1 and the listed theorems use only the axioms propext, Classical.choice, Quot.sound. Non-vacuity: every port-numbering quantifier is over a nonempty set (exists_portNumbering, exists_consistent_portNumbering in PortExists.lean).
