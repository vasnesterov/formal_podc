import Papers.PODC2012.LimitedUseSnapshots.SnapshotMain import Cslib.Computability.Distributed.SharedMemory.Linearization import Mathlib.Data.Fin.VecNotation import Mathlib.Tactic.FinCases /-! # The linearization points of Section 4.1 are wrong Section 4.1 of the paper linearizes an `Update` whose own root pointer is `d` (Line 16 at the root) at "the first time any process performs `WriteMax(root.mr, ptr)` on Line 18 with `ptr ≥ d`", and a `Scan` at its `ReadMax(root.mr)`. The proof then claims: "if there is no `Update` operation by process `j` that is linearized before `op`, `count_j = 0` and `v_j = leaf_j.view[0]`". This fails: another process can propagate `j`'s new leaf pointer to the root with a *smaller* root pointer than `j`'s own. Concretely (three processes, tree `((0, 1), 2)`): 1. process 0 starts `Update(5)`: writes its leaf, propagates to its parent `u` (`u.ma = (1, 0)`, `u.view[1]`), and performs `MaxUpdate₀(root.ma, 1)`; 2. process 1 performs a complete `Update(6)`: `u.ma = (1, 1)`, `u.view[2] = (5, 6)`, `root.ma = (2, 0)`, `root.view[2] = (5, 6, 0)`, `WriteMax(root.mr, 2)`; 3. process 2 starts `Update(7)` and performs `MaxUpdate₁(root.ma, 1)` (`root.ma = (2, 1)`); 4. process 0 scans `root.ma = (2, 1)`, so its own root pointer is `d = 3`, writes `root.view[3]` and is poised at `WriteMax(root.mr, 3)`; 5. process 1 performs a complete `Scan`: `ReadMax(root.mr) = 2`, returns `root.view[2] = (5, 6, 0)`. No `WriteMax` with argument `≥ 3` has happened, so the paper linearizes the `Scan` before process 0's `Update`, yet the `Scan` returns process 0's new value `5`. Every linearization must order process 0's `Update` before the `Scan` (`paper_linearization_points_fail`). The algorithm is still linearizable (Theorem 4.2, `theorem_4_2`), with the corrected points of `SnapshotInv.lean`: an `Update` is linearized as soon as `root.seq[root.mr]` covers its leaf pointer. -/ namespace Podc.LimitedUseSnapshots.Snapshot.Counterexample open Cslib.SharedMemory /-- The tree `((0, 1), 2)`. -/ abbrev Tex : BTree (Fin 3) := .node (.node (.leaf 0) (.leaf 1)) (.leaf 2) /-- Initial values `0`. -/ abbrev vex : Fin 3 → ℕ := fun _ => 0 /-- The algorithm instance. -/ abbrev Iex := alg3 Tex vex /-- The argument of a pending `WriteMax(root.mr, ·)`. -/ def wmArg {P V : Type} : PC P V → Option ℕ | .wm d => some d | _ => none /-- The execution described in the module docstring. -/ def αex : List (Label (Fin 3) (swSnap (Fin 3) ℕ vex)) := [.inv 0 (.update 0 5)] ++ List.replicate 7 (.tau 0) ++ [.inv 1 (.update 1 6)] ++ List.replicate 12 (.tau 1) ++ [.ret 1 none] ++ [.inv 2 (.update 2 7)] ++ List.replicate 2 (.tau 2) ++ List.replicate 4 (.tau 0) ++ [.inv 1 .scan] ++ List.replicate 2 (.tau 1) ++ [.ret 1 (some ![5, 6, 0])] lemma crun_αex : (Iex.crun αex).map (fun C => (C.mem .mr, wmArg (C.loc 0).pc)) = some ((2 : ℕ), some 3) := by decide +kernel lemma run_αex : ∃ C, Iex.run αex = some C ∧ C.mem .mr = 2 ∧ (C.loc 0).pc = .wm 3 := by have h := crun_αex rw [← Iex.run_eq_crun] at h cases hC : Iex.run αex with | none => rw [hC] at h;
