import Papers.PODC2012.LimitedUseSnapshots.Spec import Cslib.Computability.Distributed.SharedMemory.LinPoints import Cslib.Computability.Distributed.SharedMemory.StrongLin import Mathlib.Algebra.BigOperators.Group.List.Basic import Mathlib.Algebra.Order.Pi import Mathlib.Algebra.Group.Pi.Basic /-! # Section 4 of Aspnes–Attiya–Censor-Hillel–Ellen: single-writer snapshots from max arrays Aspnes, Attiya, Censor-Hillel, Ellen, *Limited-Use Atomic Snapshots with Polylogarithmic Step Complexity* (PODC 2012 / J. ACM 62(1), 2015), Section 4, **Algorithm 3**: a single-writer snapshot object built from 2-component max arrays (one per internal node of a binary tree whose leaves are the processes), registers (the `view` arrays) and a max register at the root. ## Model * Asynchronous shared memory, deterministic processes, no failures needed for safety (the model of CSLib, `Cslib.SharedMemory.Impl`; crashed processes are processes that stop taking steps). * **Base objects are atomic**: the paper uses `MaxArray` as a black box (its linearizable implementation is Section 3), so every max array `u.ma` is one atomic `maxArrObj` (with unbounded components), `root.mr` is one atomic `maxRegObj` and every entry `u.view[k]` is one atomic register. The arrays are unbounded families indexed by `ℕ`; the bound `b` of the paper is recovered by `Snapshot.indices_le_updates` (all indices are at most the number of invoked `Update`s). * The tree is an arbitrary binary tree `T : BTree P` whose leaves are exactly the processes (each once). Nodes are addressed by *reversed* paths `a : List Bool` (`[]` = root, `b :: a` = child `b` of node `a`, `false` = left). The paper's strict balanced tree is one instance (depth `⌈log₂ n⌉`, see `SnapshotCost.lean`). * A partial snapshot (the content of `u.view[k]`) is represented by a full vector `P → V`, of which only the components of the leaves below `u` are meaningful; concatenation `lview · rview` is "take the components of left leaves from `lview`, the others from `rview`" (`concat`). A leaf stores the value `v` as the constant vector `fun _ => v`. All view registers initially hold the initial vector `v₀`, so `u.view[0]` is the concatenation of the initial values. * `count_i` is the persistent local counter of the paper. The local assignment `count_i ← count_i + 1` (Line 2) is performed together with the leaf write (Line 5) instead of at invocation; since `count_i` is local, this is invisible to other processes. * The single-writer discipline (`Update(s, i, v)` only by process `i`) is `Impl.allowed`. -/ namespace Podc.LimitedUseSnapshots.Snapshot open Cslib.SharedMemory /-! ### Binary trees with processes at the leaves -/ /-- A binary tree with processes at the leaves. -/ inductive BTree (P : Type) where | leaf (p : P) | node (l r : BTree P) deriving DecidableEq namespace BTree variable {P : Type} /-- The leaves of a tree, from left to right. -/ def leaves : BTree P → List P | leaf p => [p] | node l r => l.leaves ++ r.leaves /-- Child `b` of a node (`false` = left). -/ def child : BTree P → Bool → Option (BTree P) | leaf _, _ => none | node l _, false => some l | node _ r, true => some r /-- The subtree at the reversed address `a` (`[]` = the tree itself, `b :: a` = child `b` of the subtree at `a`). -/ def sub (t : BTree P) : List Bool → Option (BTree P) | [] => some t | b :: a => (t.sub a).bind (fun u => u.child b) /-- The (reversed) address of the leaf of process `j`. -/ def path [DecidableEq P] : BTree P → P → List Bool | leaf _, _ => [] | node l r, j => if j ∈ l.leaves then l.path j ++ [false] else r.path j ++ [true] /-- The depth of a tree. -/ def depth : BTree P → ℕ | leaf _ => 0 | node l r => max l.depth r.depth + 1 /-- Well-formed trees for the process set `P`: every process is exactly one leaf. -/ structure WF (t : BTree P) : Prop where nodup : t.leaves.Nodup mem : ∀ p, p ∈ t.leaves /-- The leaves below the node at address `a` (`[]` if there is no such node). -/ def leavesAt (t : BTree P) (a : List Bool) : List P := ((t.sub a).map leaves).getD [] end BTree /-! ### The implemented object: a single-writer snapshot over arbitrary values -/ /-- Operations of a single-writer snapshot: `update i v` (only by process `i`) and `scan`. -/ inductive SOp (P V : Type) where | update (i : P) (v : V) | scan deriving DecidableEq /-- Sequential specification of a snapshot object with one component per process `P`, values `V` and initial vector `v₀`. `update` returns `none` (an acknowledgement), `scan` returns `some` of the current vector. -/ abbrev swSnap (P V : Type) [DecidableEq P] (v₀ : P → V) : ObjSpec where State := P → V Op := SOp P V Resp := Option (P → V) init := v₀ δ q | .update i v => (Function.update q i v, none) | .scan => (q, some q) /-!
