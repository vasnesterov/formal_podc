import Mathlib.Data.List.Basic import Mathlib.Data.Fin.Basic /-! # Section 4: the generic translation of Figure 2 is unsound Section 4 claims a translation of every protocol tolerating `f` crash faults into one tolerating `f` Byzantine faults with the same number of processes, using non-equivocation and transferable authentication (Figure 2, correctness argument in Appendix B). We model Figure 2 literally and give a crash-tolerant protocol whose translation is **not** Byzantine-tolerant: with `n = 3` processes and a single Byzantine process, a correct process reaches a state that no crash execution of the original protocol can reach. ## The translation (Figure 2) A B-message is `((k, m, R, S), σ_p)` (`TMsg.mk p k m R S`, the signature of `p` being symbolic): `k` is the sequence number (non-equivocation key), `m` the payload, `R` the B-messages `p` received (with their own proofs), `S` the B-messages `p` sent before. Upon B-receiving it from `q`, a process checks (`check`): the signature is `q`'s; `k = |S| + 1`; the messages of `S` are `q`'s; replaying `q`'s state machine on the inputs `R` from the initial state produces the outputs `S` followed by `m`; and recursively the same checks for every message in `R`. If all checks pass, `m` is T-received from `q`, the B-message is added to `R`, and every resulting T-send `m'` to a set of processes is B-sent as `((k+1, m', R, S), σ)` and added to `S`. **The gap.** Neither the signed tuple nor the checks mention *recipients*: a message of `R` is only checked to be authentic and valid, not to have been sent *to* `q`. So a Byzantine process can feed its own replayed state machine a message that a correct process sent to somebody else (it learns it, with its signature, from the `R` field of any later message of that recipient), and its resulting messages pass every check. The paper's own Integrity requirement (§4.1, "`m` is valid if it corresponds to the output of applying a sequence of valid messages to the state machine") has the same blind spot, so Appendix B's argument does not exclude it. ## The counterexample (`grantProto`, `n = 3`, `f = 1`) Process `0` (a server) grants a token to process `1` only. A client that receives the grant from `0` multicasts `use` to the two other processes; the server records every `use` sender. In every crash execution the server only ever records `1` (`crash_safe`), since only `1` is ever granted. In the translated system with Byzantine process `2`: 1. `1` receives the grant `g` and multicasts `u₁ = ((1, use, [g], []), σ₁)` to `0` and `2`; 2. `2` extracts `g` (signed by `0`) from `u₁` and sends `u₂ = ((1, use, [g], []), σ₂)` to `0`; 3. `u₂` passes all checks of `0` (it is exactly what a *correct* `2` would send after receiving `g`, `attack_eq_honest`), so the correct server records `2` (`translation_unsafe`).
