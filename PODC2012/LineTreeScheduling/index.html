Scheduling on Line and Tree Networks — PODC 2012

Venkatesan T. Chakaravarthy, Sambuddha Roy, Yogish Sabharwal. Distributed Algorithms for Scheduling on Line and Tree Networks. PODC 2012. DOI 10.1145/2332432.2332503. Formalized version: arXiv 1205.1924 v2 (Oct 2012). This version corrects the conference version's ratios for arbitrary heights (20 → 80 on trees, 11 → 23 on lines); numbering follows it.

Verdict: 🔧 Easy fix. All approximation guarantees of v2 are proved. They are Lemma 3.1, Lemma 5.1 / Claim 5.2, Theorem 5.3 (7/(1-ε)), Lemma 6.1, Lemma 6.2 (73/(1-ε)), Theorem 6.3 (80/(1-ε)), Theorems 7.1 / 7.2 (4/(1-ε), 23/(1-ε)) and Appendix A (3), together with the tree-decomposition Lemmas 4.1–4.3 and Observation A.1, with the right constants. The local fixes concern depth/length bounds that fail in small cases, degenerate cases of the ideal-decomposition construction, and an imprecise length grouping for line networks; rounds are counted as MIS calls, since message passing is not modelled.

Mistakes in the paper

🔧 Lemma 4.1 and §4.2 (depth bounds of the tree decompositions)

The claimed depth bounds fail in small cases: BuildIdealTD has depth 1, not ≤ 2⌈log|C|⌉ = 0, for |C| = 1, the overall bound 2⌈log n⌉ is false for n = 1, and the balancing decomposition has depth 3 > ⌈log n⌉ = 2 on a path with 4 vertices.

Impact. None of this affects the O(log n) claims, which are all that is used; we prove depth ≤ 2⌊log₂ n⌋ + 1 for the ideal decomposition (lemma_4_1) and Lemma 4.3 with length 2⌊log₂ n⌋ + 1 (lemma_4_3).

Details

  • The induction "recursive inputs have size ≤ ⌊|C|/2⌋, hence depth ≤ 2⌈log|C|⌉" therefore breaks at its base. For |C| = 2 it only gives 3. The bound is true for |C| ≥ 2 (argued on paper, not in Lean), but that needs the extra base case f(2) = 2.

  • On the path with 4 vertices the balancer leaves pieces of sizes 2 and 1. The correct bound for the balancing decomposition is ⌊log₂ n⌋ + 1. The balancing decomposition is not formalized.

🔧 Section 7 (length groups of the line-network decomposition)

The groups Gᵢ = {d : 2^{i-1}L_min ≤ len(d) ≤ 2^i L_min} overlap at the boundaries, so they do not form a partition, and ℓ = ⌈log(L_max/L_min)⌉ is 0 when all lengths are equal, so then there are no groups at all.

Impact. An under-specified definition with an evident fix; Theorems 7.1 and 7.2 hold with half-open classes (LineInput.lineLayered).

Repair

We use the half-open classes grp d = ⌊log₂(len(d)/L_min)⌋ and ℓ = ⌊log₂(L_max/L_min)⌋ + 1, and we prove the layering property, which the paper leaves as "not difficult". It holds because len(d₁) < 2 len(d₂) within the order. (LineInput.lineLayered, interval_hits)

✏️ Slips

  • The introduction of Section 6 still announces the conference ratios: (20+ε) overall and (13+ε) for narrow instances. Lemma 6.2 and Theorem 6.3 give 73 and 80.

  • Theorem 7.2 says "tree-networks", and its round bound has (1/h_min) log n instead of (1/h_min) log(L_max/L_min).

  • §4.2: "the path between x and z" should read "x and y".

Typos

  • "inference property" should read "interference property".

Proof gaps in true statements (1)Lemma 4.1

🔧 Lemma 4.1 (degenerate cases of BuildIdealTD)

Cases 1 and 2 assume that the node u′ᵢ ∈ C adjacent to the outside neighbour uᵢ lies in some component Cᵢ, but u′ᵢ may be the balancer z itself, and in Case 2(b) the three distinct components C′₁, C′₂, C′₃ need not exist.

Impact. Statement true; the construction works once empty or missing components are allowed (IdealTD.exists_good).

Details

  • In Case 2(b) the claim "there exist three distinct components C′₁, C′₂, C′₃" fails when the junction j equals u′₁ or u′₂ (or both, if u′₁ = u′₂). It also fails when z is adjacent to j, since then C′₁ is empty.

  • The equalities Γ(C₁) = {u₁, z} etc. are only inclusions.

Repair

Our proof splits into "no component of C∖{z} touches two outside neighbours" (Cases 1, 2(a) and u′ᵢ = z) and the junction case. We define the junction as the median of u′₁, u′₂, z. (IdealTD.exists_good)

The formalizationmodel, Lean names of the results, trust

Model.

  • The problem after the reformulation of Section 2. There is a finite set D of demand instances, each owned by a demand dem d and using an edge set path d; edges of different networks are distinct. Feasible solutions:

    • unit heights: independent sets (no two instances of one demand, no two overlapping instances);

    • with heights: one instance per demand and capacity 1 on every edge.

    Tree networks (TreeInput) and line networks with windows (LineInput, a finite timeline) are concrete instances of this. Profits are positive.

  • Synchronous distributed algorithm abstracted to its steps. Each step of the first phase computes a maximal independent set of the candidate set U in the conflict graph. An arbitrary, adversarial MIS oracle mis : ℕ → Finset D → Finset D supplies it (step-dependent, so it covers Luby's randomized algorithm and network decompositions alike). We count steps (= MIS calls), not communication rounds; message passing and Time(MIS) are not modelled.

  • Each stage runs a fixed number K of steps with p_max < 2^K p_min (this is the paper's distributed implementation). Lemma 5.1 shows that U = ∅ after K steps, so this coincides with "until U = ∅". There are ℓ epochs and b stages with ξ^b ≤ ε. The first phase thus has ℓ·b·K steps, matching the paper's O(log n · log(1/ε) · log(p_max/p_min)) (with 1/h_min and L_max/L_min where applicable). exists_stages and exists_steps give explicit b, K.

  • All raises of a step use the dual values from the start of the step. In the second phase all members of a popped set are tested against the solution built so far; for independent sets this is the paper's one-by-one test.

  • Results are stated as (1-ε)·p(Opt) ≤ c·p(S), i.e. ratio c/(1-ε) (= c + ε′ for ε = ε′/(c+ε′)). The framework lemmas and the unit and narrow algorithms are even proved against the LP optimum.

Proof remarks. Lemma 4.2, Cases 1–2, says "path(d₂) must include one of the wings". This needs the convexity of path(d₁) ∩ path(d₂) in a tree (wings_inter_nonempty). The appeal to property (ii) in Case 2 is unnecessary: a path leaving any vertex set passes through its neighbourhood. So Lemma 4.2 holds for every rooted tree with the LCA property. Lemma 6.1's pigeonhole step is fine; we replace it by the equivalent double count ∑_{e∈π(d′)} ∑_{d∼e} h(d) = ∑_d h(d)|π(d′) ∩ path(d)|.

Trust. No sorry. All listed theorems use only the axioms propext, Classical.choice and Quot.sound. Non-vacuity:

  • MIS oracles exist (Inst.exists_isMIS, Inst.exists_misOracle).

  • Admissible b and K exist (exists_stages, exists_steps).

  • The algorithms' runs are shown to be valid framework runs with the interference property (alg_validRun, alg_interference), so the hypotheses of Lemmas 3.1 and 6.1 are discharged, not assumed.
