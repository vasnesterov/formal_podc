import Mathlib /-! # Executions of links with local clocks (Section 8, Theorem 20) The network of Figure 1: `K = m - 1` short links and one long link. A transmission on a short link always succeeds; a transmission on the long link succeeds only if no short link transmits in the same slot. Packets arrive at every link with probability `λ` per slot. **Model.** An acknowledgement-based protocol with only a local clock gets no information from the rest of the network on a short link (its transmissions always succeed), so the execution of short link `i` is a random process of its own randomness (arrivals and coins) in its *local* time, independent of the other links. The local clocks are not synchronised: link `i` is switched on at global time `d i` (chosen by the adversary), so its global behaviour is its local execution shifted by `d i` (it is silent before). We therefore model * each short link by a `LinkExec` on its own probability space `(Ω i, μ i)` (transmission indicator `tx`, arrivals `arr ≤ 1`, deliveries `dlv ≤ tx`, queue `q` with `q 0 = 0`, `q (τ+1) + dlv τ = q τ + arr τ`), * the joint randomness of the short links by the product measure `Measure.pi μ`, * the long link by an arbitrary `LinkExec` on any probability space `G` carrying a measure-preserving map `π` to the short links' randomness; its *successful* transmissions (`tx`) can only happen in slots in which no short link transmits. This allows arbitrary dependence of the long link on everything (it is stronger than the paper needs). Stability = bounded expected queue length (the notion of Section 4.1); arrival rate `λ` = expected arrivals `λ` per slot. Main result (`no_stable_local_protocol`): if `(1 - λ)^K < λ`, then for every family of stable short-link executions there are switch-on times `d` such that no long-link execution is stable. -/
