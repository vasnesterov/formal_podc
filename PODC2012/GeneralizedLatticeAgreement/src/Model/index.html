import Mathlib /-! # Generalized Lattice Agreement: the model (Algorithms 1 and 2) Faleiro, Rajamani, Rajan, Ramalingam, Vaswani. *Generalized Lattice Agreement.* PODC 2012. An interleaving model of Algorithm 2 (generalized lattice agreement: proposers, acceptors, learners) of [paper], written as guarded actions exactly as in the paper. * Values form a join-semilattice with a bottom element (`SemilatticeSup L`, `OrderBot L`). * Proposers `P`, acceptors `A`, learners `Ln` are arbitrary finite types (the paper allows a process to play several roles; this is the instance `P = A = Ln`). * Messages are kept in the set `sent` of all messages ever sent (never removed). Every message carries its sender (acknowledgements and rejections carry the acceptor), so a message is unique. Each receiver records which messages it has consumed, so a message is processed at most once by each receiver; a message that is never consumed is delayed forever or lost. Asynchrony, message loss and crashes are expressed by the scheduler: any enabled action may be taken at any time; a crashed process simply takes no more steps. * Proposers keep, for every proposal number, the set of acceptors whose `ACK`/`NACK` they have processed (`acks n`, `nacks n`). The paper's counters are `ackCount = (acks apn).card` and `nackCount = (nacks apn).card`; the sets for older numbers are ghost history. Learners likewise keep `ackCount[id][n]` as the set of acceptors heard from. * Ghost state: `received` (all received input values), `initiated` (the proposals made by `Propose`), `decisions` (all `Decide` steps). Algorithm 1 (one-shot lattice agreement) is the same system started with `bufferedValues` equal to the initial values and without `Receive` steps (see `Algorithm1.lean`). -/ namespace
