import Papers.PODC2012.OptimismConcurrency.IRMReject import Papers.PODC2012.OptimismConcurrency.Serializability /-! # Corollary 4: `σ_bad` is not excluded by the class `SM` Corollary 4 claims that `I_RM` accepts every schedule accepted by an implementation in `P` or `SM`; its proof combines Theorem 3 (false, `IRMReject.lean`) with the unproved remark that "it is easy to see that implementations in SM and P can only accept observable schedules". `sigmaBad_sm`: the schedule `σ_bad` rejected by `I_RM` is exported by a history that is honest, LS-linearizable, *quiescent* (every operation completed) and safe-strict serializable (serialization: the three initial inserts, `contains(4)`, `remove(3)`). So nothing in the definition of `SM` prevents a TM-based implementation from accepting it; e.g. TL2 does (the read-only `contains(4)` reads `X₃`, `X₄`, whose versions `remove(3)` did not change, and commits without validation).
