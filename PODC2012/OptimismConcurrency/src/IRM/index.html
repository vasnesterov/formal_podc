import Papers.PODC2012.OptimismConcurrency.Observable /-! # The optimistic implementation `I_RM` (Algorithm 1) Every object `X_ℓ` (a location `ℓ`) has three base objects: `t-var[ℓ]` (the node), `r[ℓ]` (marked for deletion) and `L[ℓ]` (version number and locked flag, with `read`, `write`, `cas`). Process `p` keeps a rotating buffer `rbuf` of its last two successful reads (object, version). The model (`RStep`) executes every shared-memory access of Algorithm 1 as one atomic step, in any interleaving. To make the impossibility result below as strong as possible, the model *over-approximates* `I_RM`: * the client is arbitrary: any process without a pending read/write may invoke any high-level operation, any read, any write, or return anything (the real client runs `LL`); * the initial content of `t-var` is arbitrary; * when a `cas` of line 22/25/35 fails, the write may either return `⊥` (pseudocode) or retry the `cas` with the current version (the refinement described in the text of §6); * a write of an `insert` to an object that is not in `rbuf` (the new node, whose allocation Algorithm 1 does not show) is a plain store followed by `ok`; a write of a `remove` to an object not in `rbuf`, or with no other object in `rbuf`, returns `⊥`. Writes of `contains` (never issued by `LL`) are treated like writes of `insert`. Ghost data (not influencing the behaviour): the read stage stores the deletion flag `g` of the object at the invocation; the stages of a `remove` write store `ℓ'` (line 24). -/ namespace
