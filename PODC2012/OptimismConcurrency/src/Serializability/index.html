import Papers.PODC2012.OptimismConcurrency.ImplModel /-! # The class `SM`: (safe-)strict serializability, and Theorem 6 (σ₀ of Figure 1) Gramoli, Kuznetsov, Ravi, *Optimism for Boosting Concurrency* (arXiv 1203.4751v8), §3 (Figure 1), §4 ("The class SM") and Appendix C.1 (Theorem 6 = part 1 of Theorem 2). In a TM-based implementation every high-level operation runs as a transaction; we identify a transaction with a high-level operation `(p, x, k)` (the `k`-th operation of `p` on `x`), its events being `H|π` (`txEvents`). A transaction is *committed* if it returned a response, *aborted* if a read or write returned `⊥`, and *commit-pending* ("started committing") if all its reads and writes are done, the code `LL` has nothing left to do but `return`, and no response was given. * `cseq H C` — the members of `Cseq(H)`: the subsequence of `H` of the events of the committed transactions (exactly `complete H`) and of the commit-pending transactions selected by `C`. * `Legal S` — a sequential execution `S` (a concatenation of transactions) is legal: every read returns the latest value written before it, starting from the empty list `head → tail` (`mem0`). * `StrictSer H`, `SafeStrictSer H` — the paper's definitions (§4, Appendix C.1). * `sigma0` — the schedule `σ₀` of Figure 1; `sigma0_lsl`: it is `(LL, set)`-LSL. * `theorem_6_loophole` — an honest, LSL, safe-strict serializable history exporting `σ₀` (with a stalled commit-pending `remove(2)`): Theorem 6 is false for the paper's definitions as stated. * `theorem_6_appendix` — the repair: with the definition of Appendix C.1 (`cseq` = complete operations only), a strictly serializable history whose committed operations follow `LL` does not export `σ₀` (the paper's proof); `theorem_6_quiescent` — the same for the §4 definition when every transaction committed or aborted. -/ namespace Podc.OptimismConcurrency open Cslib.SharedMemory /-!
