import Papers.PODC2012.OptimismConcurrency.ImplModel /-! # Observable schedules (§6) and the schedule `σ_bad` A schedule `σ` is *observable* (§6) "if it has an extension `σ'` such that for all `v ∈ ℤ`, `σ'` extended with a complete execution of `contains(v)` that returns a matching response is LS-linearizable". * `Observable`: the literal reading (the `contains(v)` execution is any solo sequential run of `contains(v)` of `LL`, from any memory). * `ObservableStrong`: a much stronger reading, in the spirit of "no lost updates": there is an honest history `H` exporting an extension of `σ`, and for every `v` the history `H` followed by `contains(v)` run solo on the *actual* final memory of `H` is LS-linearizable. `ObservableStrong.observable`: the strong reading implies the literal one. `sigmaBad`: from `{1, 3, 4}`, `contains(4)` (process 1) reads `head` and `X₁`; then `remove(3)` (process 2) runs completely (unlinks `X₃` by writing `X₁`); then `contains(4)` reads `X₃`, `X₄` and returns `true`. `sigmaBad_observableStrong`: this schedule is observable even in the strong sense.
