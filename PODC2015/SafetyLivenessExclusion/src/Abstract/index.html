import Mathlib /-! # Safety–liveness exclusion: the set-theoretic layer (Sections 3–4) V. Bushkov, R. Guerraoui. *Safety-Liveness Exclusion in Distributed Computing.* PODC 2015. Sections 3–4 of the paper are pure set theory over histories once two facts about the implementation model are known: * `fair I`, the set of fair histories of an implementation `I`; * `ensS I`, "`I` is an admissible implementation and `I` ensures the safety property `S`". This file fixes such data abstractly (`Setting`) and proves: * the characterization "`L` excludes `S` iff there is an adversary set w.r.t. `L` and `S`" (`Setting.excludes_iff_exists_adversarySet`, stated after Definition 4.3); * **Theorem 4.4** (`Setting.theorem_4_4`): a weakest liveness property excluding `S` exists iff `Gmax`, the intersection of all adversary sets w.r.t. `Lmax`, is itself an adversary set; * the corollary scheme of **Corollaries 4.5–4.6** (`Setting.no_weakest_of_disjoint`); * **Lemma 4.8** (`Setting.lemma_4_8`); * the exact characterization of strongest non-excluding liveness properties (`Setting.isStrongestNonExcl_iff`): it exists iff some implementation ensuring `S` has all its fair histories outside `Lmax` in the *core* (histories fair for *every* implementation ensuring `S`); it is then `Lmax ∪ core`. Theorem 4.9 ("it must be `Lmax`") is thus equivalent to `core ⊆ Lmax` whenever a strongest one exists (`Setting.eq_Lmax_of_core_subset`); whether this holds depends on the concrete model, see `Theorem49.lean` and `Counterexample.lean`; * the corollary scheme of **Corollaries 4.10–4.11** (`Setting.no_strongest_of_excludes_Lmax`).
