import Papers.PODC2015.HelpFreeWaitFree.Defs /-! # Global view types (Definitions 4.6.16–4.6.18 of [CPT15]) A global view type has an operation `op`, an infinite sequence of operations `Modifiers` (`M`) and an infinite sequence of operations `Views` (`V`) such that the result of a view tells how many of `op` and the next modifier precede it. Sequential histories over these operations are lists of *tags* (`GVTag`): `op`, `mod k` (the `k`-th modifier, 0-based, i.e. the paper's `(k+1)`-st) and `view k`. A tag list `x` denotes the sequence of operations `x.map (GVTag.toOp op M V)`. Tags are needed because the operations themselves may coincide (for fetch&increment all of them are the same operation). * `gvSet i j o m` — **Definition 4.6.16**: the histories consisting of the first `i` modifiers (and also the `(i+1)`-st if `m`), in their relative order, the first `j` views in their relative order, `op` iff `o`, and nothing else, whose last operation is a view. The paper's sets are `Set0 = gvSet i j false false`, `Set1 = gvSet i j true false ∪ gvSet i j false true`, `Set2 = gvSet i j true true`. * `gvRes op M V i j o m` — the results of the last (view) operation of the histories in `gvSet i j o m`; **Definition 4.6.17**: `RS0`, `RS1`, `RS2`. * `GlobalView A` — **Definition 4.6.18**: for all `i ≥ 0`, `j ≥ 1`, the sets `RS0`, `RS1`, `RS2` are pairwise disjoint. * `StrongGlobalView A` — the four result sets `gvRes i j o m` (`o m : Bool`) are pairwise disjoint: a view also tells *which* of `op` and the next modifier precede it when exactly one does. This is what the paper's proof of Claim 4.6.8 actually uses (see `differencies.md`); it holds for snapshots (Theorem 4.7) but not for fetch&increment. Examples: fetch&increment is a global view type (`fetchInc_globalView`) but not a strong one (`fetchInc_not_strongGlobalView`); a snapshot object with two components is a strong global view type (`snapshot_strongGlobalView` in `GVSnapshot.lean`). -/ set_option linter.style.longLine false namespace Podc.HelpFreeWaitFree open Cslib.SharedMemory /-- Names of the operations in modifier–view
