import Papers.PODC2015.HelpFreeWaitFree.ExactOrder /-! # Examples of (non-)exact order types: queue and stack [CPT15] states, after Definition 4.5.1, that the FIFO queue and the LIFO stack are exact order types. We check both claims against `ExactOrder` / `ExactOrderStrong`: * `queue_exactOrderStrong` — the queue is an exact order type, even in the paper's literal (strong) form, with the paper's witnesses `op = enq 1`, `W = enq 2, enq 2, …`, `R = deq, deq, …`, `m = n + 1`, and the distinguishing operation the `(n+1)`-st dequeue. * `stack_exists_equal` — for the stack, for *every* choice of `op`, `W`, `R`, `n`, `m` there are executions in `W(n+1) ∘ (R(m) + op?)` and `W(n) ∘ op ∘ (R(m) + W_{n+1}?)` in which all operations of `R(m)` return the same results. Hence `stack_not_exactOrder`: the stack is **not** an exact order type, refuting the paper's claim (this is Theorem 1 of V. Aksenov, P. Kuznetsov, A. Shalyto, *On helping and stacks*, NETYS 2018). The key step for the stack (`stack_insert`): if a stack differs from another one only below a prefix `Z` by one operation `w` applied to the rest, then the operation `w` can be inserted into any sequence of operations run on the second stack, exactly when the prefix `Z` is exhausted, so that the two runs return the same results. -/ namespace Podc.HelpFreeWaitFree open Cslib.SharedMemory /-!
