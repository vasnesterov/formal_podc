import Papers.PODC2015.HelpFreeWaitFree.Defs /-! # Linearization points inside the operation imply help-freedom (Claim 4.8.1 of [CPT15]) [CPT15]: K. Censor-Hillel, E. Petrank, S. Timnat. *Help!* PODC 2015 (full version: Chapter 4 of S. Timnat's PhD thesis). Section 4.8 of [CPT15]: "For any type, an obstruction-free implementation in which the linearization point of every operation can be specified as a step in the execution of the same operation is help-free." The linearization function `f` is "derived from the linearization points": operations are ordered by the execution order of their linearization points. We formalize "the linearization function is derived from linearization points that are steps of the operation itself" by a function `lin` such that, for every execution `h ++ [γ]`, the step `γ` either leaves `lin` unchanged or appends exactly one entry, whose instance is the current operation of the process taking `γ` (`LinPointFun`). The progress assumption of the paper (obstruction-freedom) is used, as in the paper's proof, to let the owner of an operation run solo until that operation is linearized; we additionally assume that every process may invoke some operation (otherwise the owner cannot reach a future operation instance). * `LinPointFun I lin` — the shape of `lin` described above. * `claim_4_8_1` — **Claim 4.8.1**: if `γ` makes `a` decided before `b`, then `γ` is the linearization point of `a`: it is a step of `a` (`curOp h γ.proc = a`) and it appends `a` to the linearization. * `helpFreeWith_of_linPointFun`, `helpFree_of_linPointFun` — such an implementation is help-free. -/ set_option linter.unusedSectionVars false set_option linter.style.longLine false namespace Podc.HelpFreeWaitFree open Cslib.SharedMemory variable {P : Type} {A : ObjSpec} /-!
