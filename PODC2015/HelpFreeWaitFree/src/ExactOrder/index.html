import Papers.PODC2015.HelpFreeWaitFree.Defs /-! # Exact order types (Definition 4.5.1 of [CPT15]) For a sequence of operations `S`, `S(n)` is the list of its first `n` operations, and `(S + op?)` is the set of sequences consisting of `S` itself and of `S` with one copy of `op` inserted at some position (`OptIns`). A type `A` is an *exact order type* if there are an operation `op`, an infinite sequence `W` and a sequence `R` such that for every `n` there is `m ≥ 1` such that the results of `R(m)` differ between any execution in `W(n+1) ∘ (R(m) + op?)` and any execution in `W(n) ∘ op ∘ (R(m) + W_{n+1}?)`. We record which entries of a sequence belong to `R` by a Boolean tag (`true` = an `R` operation), and `taggedResps` collects the results of the tagged operations of a sequential execution. `R` is an infinite sequence (`ℕ → A.Op`): a finite `R` can be padded arbitrarily, since only finite prefixes `R(m)` are used. * `ExactOrderStrong A` — the paper's literal wording: *one* operation of `R(m)` has a different result in every pair of executions; * `ExactOrder A` — every pair of executions differs in the result of *some* operation of `R(m)` (the form used by Aksenov–Kuznetsov–Shalyto 2018). It is implied by the strong form (`ExactOrderStrong.exactOrder`) and suffices for Theorem 4.3, which we therefore prove for the larger class. Paper indices are 1-based (`W_{n+1}` is the `(n+1)`-st operation of `W`); here sequences are 0-indexed, so the paper's `W_{n+1}` is `W n`. -/ set_option linter.style.longLine false namespace
