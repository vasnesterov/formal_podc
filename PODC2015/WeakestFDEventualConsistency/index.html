Weakest Failure Detector for Eventual Consistency — PODC 2015

Swan Dubois, Rachid Guerraoui, Petr Kuznetsov, Franck Petit, Pierre Sens. The Weakest Failure Detector for Eventual Consistency. PODC 2015. DOI 10.1145/2767386.2767404. Formalized version: arXiv:1505.03469v1 (full version with the appendix; numbering follows it).

DOI · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The sufficiency half of the main result holds: Ω implements eventual consensus (Lemma 2), and EC and ETOB are equivalent (Theorem 1); both proofs needed the same small repair. Local changes save the rest: Lemma 3 is false because the paper's ETOB algorithm (Algorithm 5) is not stable over non-FIFO links, and sequence numbers on promotions fix it, while Theorem 3 (EC ⇔ EIC, appendix) is false if EIC-Agreement is read literally, and holds among correct processes. The necessity half of the main result (Lemma 1, a CHT-style extraction) is not formalized, so this verdict does not cover it.

Mistakes in the paper

🔧 Lemma 3 (Algorithm 5 does not implement ETOB)

Algorithm 5 is not stable over non-FIFO links: an older, shorter promotion from the leader can arrive after a newer one and shrink d_i, so with two processes, no crashes and a leader stable from time 0, ETOB-Stability fails for every τ (Alg5.lemma_3_false).

Impact. Breaks the paper's ETOB algorithm and the §5 claim that it gives TOB when Ω is stable from the start. The sufficiency half of the main result rests on Lemma 2 and Theorem 1, which hold. Adding sequence numbers to promotions repairs it (Alg5Fixed.lemma_3_fixed, Alg5Fixed.tob_of_const_leader).

Details

On receiving a promotion from its current leader, a process sets d_i := promote_j. Links are reliable but not FIFO. Counterexample: two processes, no crashes, Ω outputs process 0 everywhere from time 0, and the application broadcasts 0, 1, 2, …. The adversary delivers promotion b followed by the delayed promotion b − 1 infinitely often, with all delays bounded. ETOB-Stability then fails for every τ. The proof's step "d_i(t₁) = promote_j(t₃), d_i(t₂) = promote_j(t₄), hence prefix" silently assumes t₃ ≤ t₄, i.e. FIFO delivery. The same run refutes the §5 TOB claim.

Repair

The leader numbers its promotions, and a process adopts a promotion only if its number is larger than the last one it adopted from that leader. The repaired algorithm implements ETOB from Ω in every environment, and TOB under a leader that is stable from the start.

🔧 Lemma 3 (proof, the choice τ = τ_Ω + Δt + Δc)

The proof uses a "longest communication delay Δc" and a longest local timeout Δt, which need not exist in an asynchronous run, where delays are finite but unbounded.

Impact. The step that gives every process a promotion after τ is not justified; it is replaced in the repaired algorithm (Alg5Fixed.lemma_3_fixed).

Repair

Take instead the maximum, over the finitely many correct processes, of the first adoption of a promotion of the final leader after τ_Ω.

🔧 Theorem 3 and Lemma 4 (EC ⇔ EIC, literal EIC-Agreement)

Under the literal, uniform reading of EIC-Agreement, EIC cannot be implemented with Ω at all, already with 3 processes and at least one correct (EICImpossible.not_solvesEIC), and Algorithm 6 violates it concretely (Alg6Counterexample.not_EICAgreement).

Impact. Appendix result. With agreement among correct processes, Lemmas 4 and 5, and hence Theorem 3, hold, with the printed Algorithms 6 and 7 (Alg6.lemma4, Alg7.lemma5). Reading it among correct processes is a plausible intent, but the paper words it exactly like the uniform EC-Agreement, so as printed the statement is false.

Details

The paper requires that "no two processes return infinitely different values", and it defines a process's response as its last response, so a crashed process keeps its response forever. Two processes run solo, respond to instance 0 with their own, different proposals, and crash, and nothing can change their last responses afterwards. EC, by contrast, is implementable with Ω. In Algorithm 6 a faulty process decides true and crashes while the correct one decides false forever, even though the EC box satisfies EC.

Typos

  • Lemma 3's proof (ETOB-Total-order) says "p_i and p_j receive at least one message of type promote from p_j"; the leader there is p_k.

Proof gaps in true statements (2)Algorithm 2 · Lemma 2 and Theorem 1, ETOB → EC

🔧 Algorithm 2 (ETOB's usage assumption)

ETOB is specified only for distinct broadcast messages, but two processes that propose the same v to instance ℓ both broadcast (ℓ, v).

Impact. Local fix: broadcast (p_i, ℓ, v) (ETOBtoEC.tobHist_distinct, ETOBtoEC.ec_of_etob).

🔧 Lemma 2 and Theorem 1, ETOB → EC (uniform agreement)

Both proofs pick k as the first instance invoked after the stabilization time of Ω (resp. ETOB), but Ω and ETOB constrain only correct processes, while EC-Agreement covers all processes.

Impact. Statements true; repaired (Alg4.agreement, ETOBtoEC.ecAgreement).

Details

A faulty process that is still alive after that time can return a different value.

Repair

Also choose k after every faulty process has crashed, which is possible because P is finite.

The formalizationmodel, Lean names of the results, trust

Model.

  • Asynchronous message passing with crash failures and failure detectors, following CHT / Jayanti–Toueg (Podc/Computability/Distributed/MessagePassing/FailureDetectors/Model.lean). The set of processes P is finite. In each step a process receives one message in transit, a time-out (λ), or an input; it queries the failure detector and broadcasts at most one message.

  • Links are reliable and not FIFO. Failure patterns are monotone.

  • An admissible run delivers every message to every correct process, and each correct process takes infinitely many time-out steps.

  • Ω is the set of histories that eventually output the same correct process at all correct processes.

  • All positive results hold for every failure pattern, so they hold in every environment.

  • Transformations treat the black box adversarially. Its responses or outputs are input events chosen by the scheduler, and the box is constrained only by the hypothesis that its history meets the spec whenever it is used properly. This covers every implementation of the box.

  • For EC, this assume-guarantee form is circular: a box that answers an instance twice makes its own usage improper and becomes unconstrained (etob_of_ec_needs_integrity). We therefore also assume EC-Integrity of the box in EC → ETOB, and Algorithms 6/7 use "invoke j+1 at the first response to j".

  • Applications are folded in: process p proposes inp p j to instance j. The algorithms are deterministic, so this loses nothing.

  • Instances are numbered from 0.
