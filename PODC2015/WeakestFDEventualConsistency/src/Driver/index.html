import Papers.PODC2015.WeakestFDEventualConsistency.Specs /-! # Sequential black-box drivers (skeleton of Algorithms 6 and 7) Algorithms 6 and 7 of [DGKPS15] (Appendix A) transform one consensus-like abstraction into another. Both have the same control skeleton, which we model once: a process keeps a counter `n` (`n = 0`: not started; `n = c + 1`: the current black-box instance is `c`) and some data `d : D`. * At its first step the process starts: it invokes instance `0` of the black box with `prop p 0 d₀` (and produces some application outputs `startOut p`). * When the black box returns `x` to the current instance `c` (an input event `(c, x)`), the process updates its data to `upd p c x d`, produces the application outputs `respOut p c x d`, and invokes instance `c + 1` of the black box with `prop p (c + 1) (upd p c x d)`. * All other events are ignored. No messages are sent. Black-box invocations are outputs (`DOut.bb`), black-box responses are input events chosen by the adversary; the black box is constrained only by hypotheses on `bbHist`. The main generic facts: the invocations of the black box satisfy the (receptive) usage assumption `ECHist.ProperUseEIC` whatever the black box does (`bbHist_properUseEIC`), faulty processes reach only finitely many instances (`exists_bound_of_not_correct`) and correct ones reach every instance if the black box terminates (`exists_trans_of_correct`). -/ namespace Podc.WeakestFDEventualConsistency
