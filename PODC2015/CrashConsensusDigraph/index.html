Crash-Tolerant Consensus in Directed Graphs — PODC 2015

Lewis Tseng, Nitin H. Vaidya. Fault-Tolerant Consensus in Directed Graphs. PODC 2015. DOI 10.1145/2767386.2767399. Formalized version: arXiv 1412.8532 v2 (Crash-Tolerant Consensus in Directed Graphs, same authors); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🔧 Easy fix. The tight conditions hold. Synchronous crash consensus with at most f crashes is solvable on a digraph iff every reduced graph G_F (|F| ≤ f) has a node reaching all of it (Theorems 1–4, binary and multi-valued), and in the asynchronous case the necessity (Theorem 6) holds, while the sufficiency (Theorem 7, only sketched) fails for Algorithm WA if phase-p messages are handled as soon as they arrive, but holds for the evident fix, which we verify. The side result Theorem 5 (no fixed iterative algorithm) survives only with "eventual" outputs: with outputs at a fixed iteration, as Min-Max does, the paper's counterexample graph admits a fixed iterative algorithm.

Mistakes in the paper

⚠️ Theorem 5 (no fixed iterative algorithm), under fixed-iteration outputs

If an iterative algorithm outputs its value after a fixed iteration, as Algorithm Min-Max does, the paper's own counterexample graph admits a fixed iterative algorithm for f = 1: Z(R) = ¬max R with output after iteration 4 (notMax_solvesAt).

Impact. Section 3 never says when an iterative algorithm outputs. With "eventual" outputs the paper's argument is sound and we prove Theorem 5 for every f (theorem5). Under the fixed-iteration reading the theorem is unestablished: whether it holds for some other graph is open.

Details

The proof claims that a fixed transition function Z must map all-0 (all-1) collections to 0 (1) and that the source's value never changes. With fixed-iteration outputs this is false. For f = 1, Z(R) = ¬max R with output after iteration 4 solves binary crash consensus on the paper's graph (source, clique of f + 1 = 2 nodes, leaf), against every crash pattern with one crash, including mid-round crashes with partial delivery. The values alternate between "true" and "negated", so ¬max simulates alternating Max and Min rounds. Python search also confirms this for f = 2; for f = 3 the same Z fails at T = 4.

Repair

With "eventual" outputs (from some iteration on, the fault-free values agree and are inputs) we prove Theorem 5 for every f (theorem5).

🔧 Algorithm WA and Theorem 7 (early messages, deadlock)

If a phase-p message is handled on arrival, as the pseudocode's wording suggests, a node can lose it before entering phase p and then wait forever, already in a failure-free run on 5 nodes with f = 1 (found by simulation, not in Lean).

Impact. The pseudocode does not say what happens to early messages, and the evident fix (keep early messages, re-check WAIT on entering a phase) works: we prove Theorem 7 for the fixed algorithm (theorem7). The asynchronous characterization stands.

Details

"On entering phase p" resets Rᵢ[p] and heardᵢ[p], but phase-p messages can arrive and be marked as seen while i is still in phase p − 1. They are then lost: later copies are not "received for the first time". In a failure-free run on 5 nodes with f = 1 (edges 0→1,2,3; 1→0,2,4; 2→0,1,3,4; 3→4, which satisfies the condition of Theorem 6), node 4 gets the phase-2 messages of nodes 1 and 2 before finishing phase 1. In phase 2 it then waits forever: Condition WAIT would need reach₄(F) ⊆ {0, 3, 4} with |F| ≤ 1, but reach₄({1}) ∋ 2 and reach₄({2}) ∋ 1. The run was found by simulating the pseudocode. If early messages are instead buffered until i enters phase p (and nodes keep relaying), simulation finds no deadlock.

Repair

Keep early messages and re-check WAIT when entering a phase. The proof of Theorem 7 is only a sketch ("the rest of the proof is standard"). We prove the fixed algorithm correct, including the liveness and the 1 − 1/n contraction per phase that the sketch omits (theorem7).

✏️ Slips

  • Algorithm MVC and Theorem 4: "inputs in the range [0, K]" must mean integers. With all inputs equal to 1/2 and K = 1, everybody outputs 1, which is nobody's input. The OUTER-LOOP tests tᵢ = l for integers l, so integer inputs are evidently meant. We prove Theorem 4 for inputs in {0, …, K} (theorem4).

  • Claim 3's "iff" holds only in the "only if" direction, which is the one used (inv_iteration).

  • The induction step of Lemma 3 says "l ≥ r" for "l ≤ r".

  • The executions of Theorem 5 crash a clique node, which is impossible for f = 0; our proof also covers that case (theorem5).

Typos

  • Step 4 of MVC: |min{b | …}| > 0 should be "{b | …} is non-empty".

  • Claim 8 speaks of "sets of 2f + 1 values" of size f + 1; Claim 8 is not needed for the case analysis.

The formalizationmodel, Lean names of the results, trust

Model.

  • Synchronous (SyncModel.lean). Static digraph G on a finite node set. Deterministic algorithms know G and the node identities. In lock-step rounds a node sends an optional message to each out-neighbour and updates its state from the messages received. Crash faults: a node crashing in round c behaves correctly before, reaches an adversarial subset of its out-neighbours in round c, and is silent afterwards. At most f crashes, chosen adversarially (they may depend on the inputs). Consensus = termination, agreement and validity (output = some node's input) for fault-free nodes. Theorem 1 holds against every algorithm in this model and uses only crashes before the start.

  • Iterative algorithms (Iterative.lean). Binary values. A fixed transition function Z : Multiset Bool → Bool is applied to the own value plus the received values, in the same crash model. Two output conventions: eventual (SolvesEventually) and fixed iteration T (SolvesAt).

  • Asynchronous (Async.lean). The event-driven model on digraphs of the PODC 2020 formalization (Cslib/Computability/Distributed/ApproxConsensus/Async/Model.lean, shared with the PODC 2020 paper): reliable FIFO links with adversarial finite delays and fairness on links between correct nodes. For Theorem 6 the faulty nodes are initially dead, which makes the impossibility stronger. For Theorem 7 (AsyncCrash.lean) nodes crash at arbitrary times: a crashed node takes no more steps, and its messages still in transit may or may not be delivered, which models a crash in the middle of a broadcast. Initially dead nodes are a special case (crashSolvesOn_of_gen). Validity: output between two inputs of any nodes. The input range [lo, hi] is known, so that p_end can be chosen.

The agreement argument of Min-Max is proved once for any binary trajectory that follows the Min/Max rule (minmax_core) and reused for MVC's INNER-LOOP. The clean pair of phases is found by pigeonhole over the f + 1 disjoint (Max, Min) pairs.

Routine details the paper skips:

  • The validity step of Theorem 1 is made precise by indistinguishability with the all-0 execution (theorem1).

  • The proof of Theorem 3 does not say that agreement persists after the clean pair of phases (theorem3).

  • In Lemma 4, the case "nobody exits the OUTER-LOOP, output K" in fact never occurs for inputs in [0, K] (theorem4).

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. notMax_solvesAt is checked by kernel evaluation (decide +kernel) over all delivery patterns with at most one crash. Non-vacuity: the graph of Appendix B satisfies the condition, and Min-Max and MVC run on it; theorem7 exhibits an algorithm for the hypothesis of Theorem 6 (consensus_on_pGraph); two isolated nodes admit no consensus algorithm (no_consensus_disconnected). The reach sets and 2-reach ⇔ CCA (cca_iff_twoReach) come from the shared library Cslib/Computability/Distributed/ApproxConsensus/DigraphConditions.lean (bounded walks: CSLib's Relation.RelatesWithinSteps), the asynchronous model and the two-phase replay lemma exists_replay₂ from Cslib/Computability/Distributed/ApproxConsensus/Async/.
