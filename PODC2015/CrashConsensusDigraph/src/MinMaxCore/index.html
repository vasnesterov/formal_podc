import Papers.PODC2015.CrashConsensusDigraph.SyncModel /-! # The agreement argument of Algorithm Min-Max (proof of Theorem 3), abstractly We analyse an arbitrary binary trajectory `x : ℕ → V → Bool` (`x r u` = value of `u` after `r` rounds) that follows the Min/Max update rule in a window of `(2f + 2)·D` rounds, split into `2f + 2` phases of `D` rounds; even phases (`0, 2, …`, the paper's phases `p = 1, 3, …`) are Max phases, odd ones are Min phases. This is used both for Algorithm Min-Max (`MinMax.lean`) and for the INNER-LOOP of Algorithm MVC (`MVC.lean`, Claim 2), which carries extra data. For binary values, "set `v` to the maximum (minimum) of the received values, including one's own" is the *absorbing rule* `AbsStep … a` with absorbing value `a = true` (`a = false`): the new value is `a` iff the node or some node whose message it received had `a`. Main result (`minmax_core`): if `G` satisfies `f` CT node connectivity and `D` bounds the fault-tolerant diameter, then after the window all nodes that have not crashed hold the same value. Proof as in the paper: some pair of consecutive phases `2k, 2k + 1` contains no crash (`exists_clean_pair`, pigeonhole over the `f + 1` disjoint pairs — so the clean pair is always a Max phase followed by a Min phase, no "WLOG" needed); let `F` be the nodes crashed before it. Case I: some root of `G_F` holds `1` — it floods `1` in the Max phase (`spread`). Case II: all roots hold `0` — they keep `0` during the Max phase (`roots_keep`; the roots form the source component, which has no incoming edges in `G_F`) and flood `0` in the Min phase. Afterwards agreement is preserved (`unanimity`). -/ open Finset -- CSLib candidate (synchronous crash-prone message passing on digraphs) set_option linter.unusedSectionVars false namespace
