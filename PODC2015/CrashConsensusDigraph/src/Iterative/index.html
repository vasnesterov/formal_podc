import Papers.PODC2015.CrashConsensusDigraph.Necessity /-! # Fixed iterative algorithms in anonymous networks: Theorem 5 Section 3 and Appendix B. An *iterative algorithm* keeps one value per node; in iteration `t` every node sends its value on all outgoing edges and applies a transition function to the collection `Rᵢ[t]` of its own value and the values received. It is *fixed* (Definition 5) if every node uses the same transition function `Z*` in every iteration. In an anonymous network `Z*` can only depend on the *multiset* of values (the paper counts 0's and 1's). We study binary consensus, so `Z : Multiset Bool → Bool`. * `iterState G Z adv inp t u` — the value of `u` after `t` iterations under the crash pattern `adv` (same crash model as `SyncModel.lean`). * The paper never says when an iterative algorithm *outputs*. Its proof of Theorem 5 shows executions where two fault-free nodes disagree *forever*, and argues that `Z` must map all-0 / all-1 collections to 0 / 1 "otherwise either validity or agreement is violated". This is sound for the **eventual** reading (`SolvesEventually`: from some iteration on, the values of fault-free nodes agree and are inputs), for which we prove **Theorem 5** (`theorem5`) with the paper's graph (`pGraph f`: a source `s`, a clique of `f + 1` nodes, a leaf `l`), for every `f` (the paper's argument crashes a clique node, so it does not apply to `f = 0` as written; there the graph is the path `s → c → l` and the same case analysis works without crashes). * For the **fixed-iteration** reading (`SolvesAt … T`: the output is the value after iteration `T`, as for Algorithm Min-Max), the paper's counterexample is not one: see `IterativeCounterexample.lean`. -/ open Finset set_option linter.unusedSectionVars false namespace CrashConsensusDigraph open Cslib.ApproxConsensus
