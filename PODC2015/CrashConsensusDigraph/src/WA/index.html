import Papers.PODC2015.CrashConsensusDigraph.AsyncCrash /-! # Algorithm WA (Wait-and-Average), Section 4.2 Algorithm WA proceeds in phases `p = 1, …, pend`. In phase `p` node `i` floods `(vᵢ[p − 1], i, p)`; every message `(h, j, p)` received for the first time is recorded and forwarded to all out-neighbours. With `heardᵢ[p]` the origins and `Rᵢ[p]` the (set of) values of the recorded phase-`p` messages (including its own), `i` completes phase `p` as soon as **Condition WAIT** holds: there is `Fᵢ ⊆ V − {i}`, `|Fᵢ| ≤ f`, with `reachᵢ(Fᵢ) ⊆ heardᵢ[p]` (`Wait`). It then sets `vᵢ[p]` to the average of the set `Rᵢ[p]` and enters phase `p + 1`; after phase `pend` it outputs `vᵢ[pend]`. **Deviation from the literal pseudocode.** The paper's pseudocode resets `Rᵢ[p] := {vᵢ[p−1]}`, `heardᵢ[p] := {i}` *on entering* phase `p`, so phase-`p` messages that arrived (and were forwarded, hence will never be processed again) while `i` was still in phase `p − 1` are lost; this can block a node forever even without crashes. We formalize the evident fix: the recorded messages are kept per phase and never reset (`WS.heard`, `WS.R` are computed from the set `seen` of recorded messages), and Condition WAIT is re-checked after every receipt and on entering a phase (`advN`: the check-and-complete step `adv1` is iterated `pend + 1` times, enough to reach a fixpoint). The state is `WS`: current phase `ph` (`pend + 1` = finished), phase values `val` (`val 0` is the input; `val q` is meaningful for `q < ph`), and `seen`. This file also contains the *local* invariant `LI` of one node with respect to a global state, and its preservation by the steps of the algorithm (`adv1_spec`, `advN_spec`, `recv_spec`, `start_spec`).
