import Papers.PODC2015.CrashConsensusDigraph.SyncModel /-! # Theorem 1: crash consensus requires `f` CT node connectivity If some algorithm solves crash consensus on `G` with at most `f` crash faults (for an input domain containing two distinct values), then `G` satisfies `f` crash-tolerant node connectivity. Proof (the paper's argument made precise). Otherwise, by `ctConn_iff_oneReach`, there are `F` with `|F| ≤ f` and `i, j ∉ F` without a common ancestor in `G_F`. Let `Sᵢ`, `Sⱼ` be the sets of ancestors of `i`, `j` in `G_F` (disjoint). Crash `F` before the start (round `0`, reaching nobody) and give input `a` to `Sᵢ` and `b` to the other nodes. `Sᵢ` only hears from `Sᵢ`, so `i` cannot distinguish this execution from the one where all inputs are `a`, and decides `a` by validity there; likewise `j` decides `b`, contradicting agreement. The paper says "the only input value learned by `x` is `0`, so `0` should be the output of `x`"; the indistinguishability with the all-`a` execution is what makes this step rigorous (`state_eq_of_closed`). -/ open Finset set_option linter.unusedSectionVars false namespace CrashConsensusDigraph open Cslib.ApproxConsensus variable {V I M S : Type*} [DecidableEq V] {G : Digraph V} /-- The adversary crashing exactly the nodes of `F`, before they send anything. -/ def crashAtStart (F : Finset V) : Adversary V where crash u := if u ∈ F then some 0 else none part _ _ := False theorem crashAtStart_admissible {F : Finset V} {f : ℕ} (hF : F.card ≤ f) : (crashAtStart F).Admissible f := ⟨F, hF, fun u c h => by by_contra hu;
