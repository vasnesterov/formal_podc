import Papers.PODC2015.EventualConsistencyLimits.Late /-! # Definition 14 as written is unsatisfiable Definition 14 of [AEM15] calls a data store eventually consistent if, for every infinite execution `α`, **every** abstract execution that `α` complies with is eventually consistent. Compliance (Definition 9) only fixes the per-replica sequences of operations, not visibility. So the abstract execution whose visibility is just the per-replica order complies with `α` as well. If two replicas read the same MVR forever and nothing is written, this abstract execution is correct and causally consistent, but not eventually consistent. `literalEC_false`: no data store with two replicas, available invisible reads, op-driven messages and correct finite executions satisfies Definition 14 literally, even if "every abstract execution" is restricted to correct, causally consistent ones. We therefore use the evident intent ("some correct abstract execution that `α` complies with is eventually consistent", `Store.EventuallyConsistent`). -/ namespace Podc.EventualConsistencyLimits
