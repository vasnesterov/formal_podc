Here: at most `6 q` rounds, with one semiring element per word. Nodes are triples `v = (v₁, v₂, v₃) ∈ [q]³` (`Node q`). Node `v` computes the block `P^(v₂)[v₁∗∗, v₃∗∗] = S[v₁∗∗, v₂∗∗] T[v₂∗∗, v₃∗∗]`: * Step 1a: `v` sends `S[v, u₂∗∗]` to every `u ∈ v₁∗∗`; * Step 1b: `v` sends `T[v, u₃∗∗]` to every `u ∈ ∗v₁∗` (the paper says `u ∈ ∗v₂∗`, a typo, see `step1_as_written_wrong`), so that `u` receives `T[w, u₃∗∗]` from every `w ∈ u₂∗∗`; * Step 2 (local, done on receipt in Step 1b): `v` multiplies its blocks; * Step 3: `v` sends `P^(v₂)[u, v₃∗∗]` to every `u ∈ v₁∗∗`; * Step 4 (local, done on receipt in Step 3): `u` sums `P[u, ∗] = ∑_w P^(w)[u, ∗]`. Each communication step has a fixed pattern in which every node sends and receives `q⁴ = n · q` words, so by oblivious routing (`Cslib.CongestedClique.Prog.exists_oblivious`) it takes `2 q` rounds. (The paper merges Steps 1a and 1b, with `2 q⁴` words per node, which also gives `4 q` rounds.)
