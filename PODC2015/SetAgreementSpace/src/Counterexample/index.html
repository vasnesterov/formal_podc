import Papers.PODC2015.SetAgreementSpace.Algorithm /-! # Figure 3 is not obstruction-free The algorithm of Figure 3 (`fig3 false`) satisfies validity and `k`-agreement (`Safety.lean`), but **not** `m`-obstruction-freedom, for any parameters `1 ≤ m ≤ k < n`. The flaw: a process adopts (lines 11–13) the value `w` of a duplicated pair `(w, q)` written by another process `q`, but afterwards it writes `(w, id)`, a *different pair*. If the duplicated pair stays in memory, the next scan again satisfies line 11 and the process adopts `w` again, forever, without changing `i`; it never decides when more than `m` different pairs are in memory. The proof of Lemma 5 (Case 2) assumes that adopting changes the preferred value, which is false here. Smallest instance (`n = 2`, `k = m = 1`, `r = 3`): `p₁` runs solo and decides, leaving `A = [(v,p₁),(v,p₁),(v,p₁)]`; then `p₀` runs solo: it writes `(v₀,p₀)` into `A[0]`, sees two different pairs and the duplicate `(v,p₁)`, adopts `v`, writes `(v,p₀)` into `A[0]`, sees two different pairs and the duplicate `(v,p₁)` again, … forever. General instance: processes `1, …, m` write `(v, j)` into prefixes of `A` of decreasing length and stop (crash), so that `A[1..r-1]` holds the `m` pairs `(v,1), …, (v,m)` with `(v,1)` duplicated; then process `0` runs solo forever. ## Main results * `fig3_not_obstructionFree`: from a reachable one-shot configuration, process `0` running solo never returns. * `fig3_not_mObstructionFree`: Figure 3 is not `m`-obstruction-free (on one-shot executions), for all `1 ≤ m ≤ k < n` and `r = n + 2m - k` — the termination claim of Theorem 7 (Section 4.1) for this algorithm is false. -/ namespace
