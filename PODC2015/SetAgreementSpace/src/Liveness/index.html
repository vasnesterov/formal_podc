import Papers.PODC2015.SetAgreementSpace.Lemma3 import Cslib.Foundations.Data.Nat.Descent /-! # Liveness of the corrected Figure 3: `m`-obstruction-freedom (Section 4.1) The original algorithm of Figure 3 (`fig3 false`) is not obstruction-free (`Counterexample.lean`): the proof of Lemma 5 (Case 2) assumes that adopting a value (lines 11–13) changes `pref`. With the extra guard of `fig3 true` (adopt only if the value of the first duplicated pair differs from `pref`, otherwise advance `i`, line 14) the paper's argument goes through, and we prove * `fig3Fixed_mObstructionFree`: `fig3 true n m r` is `m`-obstruction-free on one-shot executions, for **all** `n`, `m` and `r ≥ 1` (the size `r = n + 2m - k` of the paper is only needed for safety). The proof follows Section 4.1. Let `e` be an infinite one-shot execution and `S` the set of processes taking infinitely many steps, `|S| ≤ m`, `S ≠ ∅`. From some time `T₀` on only processes of `S` step, each of them is pending forever (one-shot: after its response a process can never step again) and therefore never decides (`Liveness.Setting`, `Liveness.exists_setting`). * `Liveness.lemma5` (**Lemma 5**): some process of `S` advances (line 14) infinitely often. Otherwise, after a time `μ`, every `q ∈ S` keeps its position `i_q`; the components `NM` not of the form `i_q` are constant. A pair written after `μ` cannot also lie in `NM` (its writer would see it at another position at its next scan and advance — Case 1 of the paper); components of `M` hold pairwise different pairs. Hence the first duplicated pair lies in `NM` and its value `w` is constant (`Liveness.dupVal_congr`). Every scan adopts, so some process adopts `w`, and at its next scan the corrected guard (`dupVal ≠ pref`) fails: it advances. (The paper's Case 2 instead claims that adoption always changes `pref`, which is false for `fig3 false`.) * `Liveness.cor6` (**Corollary 6**): the advancing process updates every component again and again, so eventually every component holds a pair of a process of `S`. * By **Lemma 3** (`lemma3`, `Lemma3.lean`) such a memory contains at most `|S| ≤ m` distinct pairs and no `⊥`, so the next scan satisfies line 9 (`Liveness.decideCond_of_run`) and the scanner decides — a contradiction (`Liveness.false_of_infSteppers`). In fact the proof shows more: every infinite one-shot execution has more than `m` processes taking infinitely many steps (the hypothesis that a given process is pending forever is not used). -/
