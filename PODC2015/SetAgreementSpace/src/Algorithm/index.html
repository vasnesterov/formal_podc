import Papers.PODC2015.SetAgreementSpace.Defs /-! # The algorithm of Figure 3 (one-shot `m`-obstruction-free `k`-set agreement) `n` processes `Fin n` share one snapshot object `A` with `r` components holding `⊥` or a pair `(value, id)` (the paper takes `r = n + 2m - k`). Code for process `id` (Figure 3): ``` Propose(v): pref ← v; i ← 0 loop update A[i] with (pref, id) s ← scan of A if |{s[j]}| ≤ m and ∀ j, s[j] ≠ ⊥ then (line 9) j₁ ← min {j₁ : ∃ j₂ > j₁, s[j₁] = s[j₂]}; output value in s[j₁] and halt (line 10) if ∀ j ≠ i, s[j] ∉ {⊥, (pref, id)} and ∃ j₁ ≠ j₂, s[j₁] = s[j₂] then (line 11) j₁ ← min {j₁ : ∃ j₂ > j₁, s[j₁] = s[j₂]}; pref ← value in s[j₁] (lines 12–13) else i ← (i + 1) mod r (line 14) ``` `fig3 fix n m r` is this algorithm as a CSLib `Impl`. With `fix = false` it is exactly Figure 3; with `fix = true` the adoption branch (lines 11–13) is additionally guarded by "the value in `s[j₁]` differs from `pref`" — otherwise the process advances `i` (line 14). The original algorithm is not obstruction-free (`Counterexample.lean`); the guarded one is (`Liveness.lean`), and both are safe (`Safety.lean`).
