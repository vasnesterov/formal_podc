import Cslib.Computability.Distributed.SharedMemory.Covering import Mathlib.Logic.Relation import Mathlib.Data.Set.Basic -- CSLib candidate: Cslib/Computability/Distributed/SharedMemory/Transactional/Basic.lean /-! # Transactional memory on top of the asynchronous shared-memory model Peluso, Palmieri, Romano, Ravindran, Quaglia. *Disjoint-Access Parallelism: Impossibility, Possibility, and Cost of Transactional Memory Implementations.* PODC 2015 (technical report, Virginia Tech, May 2015), Section 2. A **TM implementation** is an implementation (`Cslib.SharedMemory.Impl`) of the transactional interface `tmSpec X V` from arbitrary base objects `B : ι → ObjSpec`: processes are deterministic programs, every step applies one primitive to one base object, the environment chooses the invocations, and the scheduler is arbitrary (finite executions model crashes: a crashed process simply takes no more steps). * **Interface.** Operations `read x`, `write x v`, `tryC` (`TOp`). A response is an `Option V`: `none` is the abort event, `some v` a successful response (the value read for a read; the value is ignored for writes and `tryC`). As in Guerraoui–Kapałka, a transaction begins implicitly with its first invocation (the paper's `begin` operation would only add a step that does nothing). * **Transactions** are computed per process from the history (`pstate`): an operation that is aborted, or a `tryC` that returns successfully, ends the current transaction; `(p, k)` is the `k`-th transaction of `p` (`TxId`). `txRec h T` is its record (completed operations with their responses, and the pending operation). * **Histories and the DSG** (Section 2): versions of `x` are the initial version (`none`, value `v₀ x`) and the versions of the committed transactions that wrote `x`, ordered by commit time; direct read-, write- and anti-dependence edges (`wr`, `ww`, `rw`); the real-time order `RTO` and the *witnessable* real-time order `WRTO` (RTO between transactions joined by a direct edge), and the paper's notions "`H` preserves RTO / WRTO". * **Properties of TM implementations** used in Section 3: weak disjoint-access parallelism (`WDAP`), obstruction-free write transactions (`ObstructionFreeWrites`), write transactions that commit when run in isolation (`IsolatedWritesCommit`, implied by weak progressiveness), wait-free read-only transactions (`WaitFreeReadOnly`), invisible read-only transactions (`InvisibleReads`) and the standing assumption that a read returns the initial value or a value some write has written (`LegalReads`). -/ namespace Podc.DAPInvisibleReads open Cslib.SharedMemory /-! ### The transactional interface -/ /-- Transactional operations. -/ inductive TOp (X V : Type) where | read (x : X) | write (x : X) (v : V) | tryC deriving DecidableEq namespace TOp variable {X V : Type} /-- The transactional object accessed by an operation. -/ def obj : TOp X V → Option X | read x => some x | write x _ => some x | tryC => none /-- Whether the operation is a write. -/ def IsWrite : TOp X V → Prop | write _ _ => True | _ => False end TOp /-- The transactional interface as an `ObjSpec`.
