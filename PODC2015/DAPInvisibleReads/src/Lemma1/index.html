import Papers.PODC2015.DAPInvisibleReads.Commute import Mathlib.Tactic.FinCases /-! # Lemma 1 is false Lemma 1 of the paper: *in a WDAP TM two concurrent disjoint-access transactions cannot contend on a common base object* (not even at different times). Its proof only considers executions in which the two transactions are the only ones taking steps: it postpones the first contending event of `Tⱼ` so that it becomes concurrent with that of `Tᵢ`. With a third process the claim fails: information can flow from `Tᵢ` to `Tⱼ` through two *different* transactions of a third process, the first one sharing an object with `Tᵢ` and the second one sharing an object with `Tⱼ`. Then `Tⱼ` can read a base object written by `Tᵢ` *after* `Tᵢ` wrote it for the last time, so the two never concurrently contend, and yet they are disjoint-access. `chainTM` (three processes, two objects `x₀, x₁`): * base objects `o(y,q)` (written once, by `q`'s first write to `y`) and `f(x)` (a "board" for `x`: a list of pairs `(y,q)` whose `o(y,q)` is known to be written); * `write x v` by `p`: write `o(x,p)` (if not yet done), then publish everything `p` knows on `f(x)`; * `read x`: read `f(x)`, then read `o(y,q)` for every published pair and `o(x,q)` for every `q`; record the written ones. `chainTM_strongWDAP`: in every reachable configuration, two processes poised to contend on a base object run transactions whose data sets intersect (so `chainTM` is WDAP in any reading of the definition based on data sets / the conflict graph of Attiya, Hillel and Milani). `lemma_1_false`: in the execution `Tᵢ = W(x₀)` (left live), `T_k1 = R(x₀) c`, `T_k2 = W(x₁) c`, `Tⱼ = R(x₁)…` (left live), `Tᵢ` and `Tⱼ` are concurrent and disjoint-access (`Tᵢ — T_k1` and `T_k2 — Tⱼ` are the only conflict edges), and `Tⱼ` reads the base object `o(x₀, i)` that `Tᵢ` wrote. -/ namespace
