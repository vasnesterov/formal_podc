import Mathlib /-! # Servers and the `ss-broadcast` abstraction Bonomi, Dolev, Potop-Butucaru, Raynal. *Stabilizing Server-Based Storage in Byzantine Asynchronous Message-Passing Systems.* PODC 2015 (full version arXiv:1503.00140v1). The server code (lines 19–23) is the same in Fig. 2 (regular register) and Fig. 3 (practically atomic register); only the payload type `D` differs (`D = V` in Fig. 2, `D = seqnum × V` in Fig. 3). ## Model of `ss-broadcast` Every server `s` has two FIFO links, one from the writer (`wq`) and one from the reader (`rq`). Their initial contents are arbitrary (transient failures), an `ss_broadcast` appends the message at the end of the link of every server, and a server step `ss_deliver`s the head of one of its links. Hence *no duplication*, *validity* (a delivered message was broadcast or was in the initial link) and *FIFO order* hold by construction. *Synchronized delivery* is a guard of the client step that ends a broadcast: at least `n - 2t` correct servers have delivered it (their link is empty, since the client broadcasts one message at a time). *Termination* and *eventual delivery* are fairness properties of infinite executions. The paper matches acknowledgments with broadcasts by FIFO order (Remark of Section 3.1). We model this matching *favourably to the paper*: a server's reply is recorded in a ghost slot (`wack`, `rack`) only when it answers the client's *current* broadcast (the delivered message is the last one in the link); the slot is cleared by every new broadcast of that client. Stale replies are thus never used. -/ namespace Podc.StabilizingByzStorage /-- Messages `ss-broadcast` by the writer: `WRITE(v)` and `NEW_HELP_VAL(v)`. -/ inductive WMsg (D : Type) where | write (d : D) | newHelp (d : D) deriving DecidableEq, Repr /-- Local state of a server: `last_val`, `helping_val` (`none` = `⊥`), the two incoming links and the ghost reply slots for the clients' current broadcasts. -/ structure Server (D : Type) where last : D help : Option D /-- Link from the writer (pending messages, oldest first). -/ wq : List (WMsg D) /-- Link from the reader: pending `READ(new_read)` messages. -/ rq : List Bool /-- `ACK_WRITE(helping_val)` sent in answer to the writer's current broadcast, if any. -/ wack : Option (Option D) /-- `ACK_READ(last_val, helping_val)` sent in answer to the reader's current broadcast, if any. -/ rack : Option (D × Option D) deriving DecidableEq, Repr namespace Server variable {D : Type} /-- Lines 19–21: deliver the oldest pending message of the writer. `WRITE(v)`: `last_val ← v` and answer `ACK_WRITE(helping_val)`;
