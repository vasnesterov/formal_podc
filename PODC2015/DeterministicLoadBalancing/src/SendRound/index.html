import Papers.PODC2015.DeterministicLoadBalancing.Model /-! # Observation 3.2: `SEND([x/d⁺])` is a good `s`-balancer exactly for `s ≤ ⌈d⁺/2⌉ − d` Berenbrink, Klasing, Kosowski, Mallmann-Trenn, Uznański, PODC 2015 (arXiv:1404.4344v4), Observations 2.2 and 3.2. `SEND([x/d⁺])`: a node with load `x` sends `[x/d⁺]` (`x/d⁺` rounded to the nearest integer, halves rounded up) over each original edge and keeps the rest on its `d◦ ≥ d` self-loops (`d⁺ = d + d◦`). Observation 3.2 claims that it is a good `(d⁺ − 2d)`-balancer for `d⁺ > 2d`. This is false as soon as `d◦ ≥ d + 2`: when `x/d⁺` is rounded *up*, the `d` original edges take `d` of the `e = x mod d⁺` extra tokens, and only `e − d` self-loops receive `⌈x/d⁺⌉`; for the smallest such `e = ⌈d⁺/2⌉` this is `⌈d⁺/2⌉ − d < min{d⁺ − 2d, e}`. Smallest counterexample: `d = 1`, `d◦ = 4`, `x = 3`: one token goes to the original edge, the four self-loops share two tokens, so only two of them receive `⌈3/5⌉ = 1`, but `min{s, e} = min{3, 3} = 3` are required. We prove the exact characterisation (`sendRound_isGood_iff`): for a `d`-regular graph with `d < d◦`, `SEND([x/d⁺])` is a good `s`-balancer iff `1 ≤ s ≤ ⌈d⁺/2⌉ − d`. Since `⌈d⁺/2⌉ − d ≥ (d◦ − d)/2`, the applications in Table 1 (`s = Ω(d)` when `d⁺ ≥ 3d`) survive.
