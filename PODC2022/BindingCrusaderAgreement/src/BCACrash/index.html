import Podc.Computability.Distributed.Byzantine.AsyncBroadcast import Papers.PODC2022.BindingCrusaderAgreement.Basic /-! # Algorithms 3 and 5: (Graded) Binding Crusader Agreement with crash faults Abraham, Ben-David, Yandamuri, PODC 2022, Section 4.1 (Algorithm 3, Theorem 4.1) and Section 5.1 (Algorithm 5, Theorem 5.1). The proofs are deferred to the full version in the paper; we give our own. Both algorithms tolerate `t < n/2` crash faults (adaptive: the adversary crashes parties at any time, possibly in the middle of a broadcast). They share the first two steps: * send `⟨val, x⟩`; * upon `val` from `n − t` parties (and no `echo` sent yet): if they all carry the same `v`, send `⟨echo, v⟩`, otherwise `⟨echo, ⊥⟩`. Algorithm 3 then decides upon `echo` from `n − t` parties: `v` if they all carry `v`, else `⊥`. Algorithm 5 sends `echo2` in the same way and decides upon `echo2` from `n − t` parties: `v` grade 2 if they all carry `v ≠ ⊥`, `v` grade 1 if one carries `v ≠ ⊥` and another one a different value, `⊥` grade 0 if they all carry `⊥`. "From `n − t` parties, all with `v`" is modelled as "`v` from `n − t` parties", "not all the same" as "from `n − t` parties, and two different values among the received ones" (liberal guards, see `Cslib.Byzantine.AsyncBroadcast`). The crash versions of the properties (paper: "the full definition of BCA-Crash appears in the full version"; "all parties that terminate satisfy agreement … binding applies to all parties") are proved for *all* parties, including those that crash after deciding, with weak validity: if all parties have input `v`, every decision is `v` (grade 2). ## Main results * `Alg3.theorem_4_1`: Algorithm 3 implements BCA-Crash with at most 2 broadcasts per party; * `Alg5.theorem_5_1`: Algorithm 5 implements GBCA-Crash with at most 3 broadcasts per party. -/ namespace Podc.BindingCrusaderAgreement open
