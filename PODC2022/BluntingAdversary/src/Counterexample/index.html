import Papers.PODC2022.BluntingAdversary.Model import Cslib.Computability.Distributed.SharedMemory.OneAccess /-! # Counterexample to Lemmas 4.3 and 4.4 of the paper Lemma 4.3 claims that for every adversary `𝒜` against `P(O^k)`, `Prob[(P(O^k) ‖ 𝒜 → B) | X] ≤ Prob[P(O^a) → B]`, and Lemma 4.4 that `Prob[(P(O^k) ‖ 𝒜 → B) | ¬X] ≤ Prob[P(O) → B]`. Both fail: the adversary can make the event `X` (every object random step selects a randomization-free preamble iteration) depend on an earlier program coin, so conditioning on `X` (or on `¬X`) biases that coin. ## The instance Two processes `p = 0`, `q = 1`, one object `A` combining a register `R` (values `Option Bool`, initially `none`) and a dummy `S` whose read returns `none`. The implementation `I` performs every operation with a single atomic access (CSLib's `OneAccess`); it is strongly linearizable, hence tail strongly linearizable for every preamble mapping. The preamble mapping `Pi` declares the `S`-read to be inside its preamble until its access (effect free: it is a read). * `p`: `c₁ := random{0,1}; R.write(c₁); c₂ := random{0,1}`; * `q`: `S.read; y := R.read`. `B` = "`q` read `y = some true`". With atomic objects or with `I`, `Prob[P → B] ≤ 1/2` (`B` forces `c₁ = 1`). In `P(O²)`, the adversary `σ false` flips `c₁` first; if `c₁ = 0` it lets `q` start its `S`-read and lets `p` flip `c₂` during the first preamble iteration (which is thus not randomization-free), otherwise it runs `p` to completion first. Then `Pr[B ∧ X] = 1/2` and `Pr[X] = 3/4`, so `Pr[B | X] = 2/3 > 1/2`. The adversary `σ true` spoils the iteration when `c₁ = 1`: `Pr[B ∧ ¬X] = Pr[¬X] = 1/4`, so `Pr[B | ¬X] = 1 > 1/2`. -/ set_option linter.unnecessarySeqFocus false namespace
