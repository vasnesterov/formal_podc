import Papers.PODC2022.BluntingAdversary.Moves /-! # Tail strong linearizability: simulation by the atomic object (Lemma 4.3, property (4)) For a deterministic implementation `I` of `A` that is tail strongly linearizable w.r.t. the preamble mapping `Π`, every strong adversary against `P(O)` (with `O = implSem I Π`) is matched by an adversary against `P(A)` (the atomic object), as far as executions are concerned all of whose program random steps happen at prefixes that are complete w.r.t. `Π`: `optSafe_le_prob_atom`. ## Proof Golab–Higham–Woelfel style simulation. The O-configuration `s` is abstracted to a CSLib configuration `K` (`TSLSim.Abs`); the execution of the object is recorded by its history `γ` (`I.run γ = some K`). The atomic system lags behind: it is only synchronised at complete prefixes (program random steps and termination). At such a prefix `α` with linearization `L = f α`, the correspondence `TSLSim.QInv α s d L` says that the atomic configuration `d` has executed exactly `L`: its memory is `linState L`, and every process is either *in sync* (same client state; its pending operation is not in `L`) or *ahead* (its pending operation is in `L` and the atomic client already continued with the response the specification gives it in `L`). The **segment lemma** `TSLSim.seg_main`: if `QInv β sβ d (f β)` at a complete prefix `β` and a coin-free run of the O-system leads to a complete prefix `γ`, then the atomic system can deterministically reach `d'` with `QInv γ s d' (f γ)`. Along the segment the atomic system executes `L = f γ` greedily (`TSLSim.catchUp`), maintaining `QInv` relative to a prefix of `L` and the maximality property `TSLSim.Max`; maximality and the real-time order of `L` show that every operation returned by `O` has already been executed atomically, with the same response.
