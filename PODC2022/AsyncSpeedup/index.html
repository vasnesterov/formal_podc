Asynchronous Speedup Theorem — PODC 2022

Pierre Fraigniaud, Ami Paz, Sergio Rajsbaum. A Speedup Theorem for Asynchronous Computation with Applications to Consensus and Approximate Agreement. PODC 2022. DOI 10.1145/3519270.3538422. Formalized version: arXiv 2206.05356 v2 (full version with the proofs of Claims 3, 4 and of Section 5.3); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: ⚠️ Weakened. All the paper's numbered results are proved, for any number of processes: the speedup theorem (Theorems 1 and 2), Lemma 1, Corollaries 1–3, Theorems 3 and 4, and Claims 1–6. But the claim that binary consensus does not help solve approximate agreement faster, half of the paper's main application, is supported only in a weaker form: inputs depending on id and round, and a bound one round below the IIS bound when 1/ε ≤ n ≤ 2^⌈log₂ 1/ε⌉. The test&set half of that application stands for n ≥ 3.

Mistakes in the paper

⚠️ Abstract, Section 1.2 and Conclusion (scope of the binary-consensus result)

The abstract says binary consensus objects "are not more powerful as far as helping solving approximate agreement faster is concerned", but Theorem 4, the only supporting result, gives a bound one round below the IIS bound whenever 1/ε ≤ n ≤ 2^⌈log₂ 1/ε⌉ (for n = 4, ε = 1/4: 1 round versus 2).

Impact. Only a weaker form of these informal claims is proved. No numbered statement is false, and Theorem 4 itself is correct as stated (theorem4_log); the test&set half stands for n ≥ 3 (theorem3_log).

Details

Read literally, the abstract's claim fails for n = 2, where consensus solves the task in one round; the body states the qualifiers it needs. The conclusion says binary consensus is not useful "at least when n ≥ 1/ε". Theorem 4 covers only algorithms whose consensus inputs depend on the process id and the round. Its bound min(⌈log₂ n⌉ − 1, ⌈log₂ 1/ε⌉) matches the IIS bound only for n > 2^⌈log₂ 1/ε⌉ (e.g. n ≥ 2/ε).

✏️ Slips

  • Theorems 1 and 2: the speedup proofs use two model properties that the paper never states: a round of some processes extends to a round of all of them with the same views for the early ones (P^(1)(τ') ⊆ P^(1)(τ)), and a box called solo returns a value determined by the caller's input ("b_i = B_t(a_i)"). Both hold in all the paper's models, so every application is correct. We make them explicit hypotheses (Model.Extendable, Model.SoloDet) and prove them for IIS, iterated snapshot, IIS + test&set and IIS + binary consensus.

  • Section 2.2: solvability keeps the complex-based definition after the carrier-map requirement on Δ is dropped; read literally with faces, the liberal task of Definition 4 would not be liberal. The proofs use exact participation throughout (Solves).

  • The claims are applied to 3^k ε and 2^k ε beyond Definition 3's range ε ≤ 1 (we prove them for every ε ≥ 0).

Typos

  • Claim 4's proof (and Corollary 2's) says P^(1)(σ) for the protocol complex P^(1)(τ) of the local task.

  • The proceedings version of Theorem 1's proof mixes ρ'/ϱ'.

Claim 6 assumes |S| ≥ 5, and the proof of Theorem 4 applies it to every S_k but only checks |S_{t−1}| ≥ 3.

Impact. The statement is true; the missing inequality holds (theorem4_aux).

The formalizationmodel, Lean names of the results, trust

Model.

  • n asynchronous wait-free processes P (any finite type, decidable equality), iterated full-information protocols (Algorithms 1 and 2): in round r every participant writes its view to a fresh memory, optionally calls a fresh black-box object, and reads. One round is a pattern (who sees whom, box answers) admissible in the model for the participating set and box inputs (Cslib/Computability/Distributed/IteratedModel/Basic.lean). Models: IIS (iis, the chromatic-subdivision condition of Section 2.2), iterated snapshot (isnap), IIS + test&set (iisTS: the winner is a process of the first concurrency class), IIS + binary consensus (iisBC: the proposal of such a process wins), all in Cslib/Computability/Distributed/IteratedModel/Patterns.lean.

  • Crash failures: a task is solved if, for every input simplex σ and every execution in which exactly id(σ) participates, the decisions form an element of Δ(σ). Crashes mid-execution are faces of such executions (Model.Extendable). Deterministic processes, adversarial scheduler, no randomness.

  • Tasks are relations Δ(σ) without carrier-map assumption; approximate agreement on the grid {0, 1/m, …, 1} is scaled to integers {0,…,m} with ε = e/m. The paper drops the carrier-map requirement on Δ but keeps the complex-based definition of solvability, under which the liberal task of Definition 4 would not be liberal. We use the standard reading: the processes of σ participate exactly.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. Non-vacuity: all four models satisfy the hypotheses of the speedup theorem, and concrete algorithms solve tasks in them (aa_solvable_two, aa_solvable_many, twoConsensus_iisTS). So the lower bounds are tight and the solvability notions are not empty. The framework (Cslib/Computability/Distributed/IteratedModel/, now in CSLib) is new and independent of CSLib's Impl-based shared-memory model.
