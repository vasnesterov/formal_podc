In phase 1 the Byzantine leader proposes `true`, gets the three votes, sends `QC_commit(true)` to everybody, collects the three `decide` messages and keeps `QC_finalized(true)`. In phases 2 and 3 the correct leaders relay the commit on `true`, but without the Byzantine `decide` they get only two of the three messages: nobody decides. Both correct processes broadcast `help_req`, receive `t + 1 = 2` of them, and broadcast the fallback certificate with `decision = undecided` (line 11) and set `fallback_start` (so they never echo, line 21). In round 3 the Byzantine process answers `p2`'s help request with `⟨help, true, QC_finalized(true)⟩`: **`p2` decides `true`** (line 14). `p2` never sends `true` with its proof to anybody, so `p0` adopts nothing and runs `A_fallback` with its input `false` (or with `undecided`, line 15) while `p2` runs it with `true`. The inputs differ, so a strong-BA fallback may output `false` (e.g. interactive consistency + majority, with the Byzantine input `false`): **`p0` decides `false`**. The proof of Lemma 19 claims that in the `2δ` window every correct process learns the decisions of the others ("Specifically, they receive `v` from `p`"), but a decision made at line 14 is never broadcast with its proof. **Lemma 22 / Unique validity (`lemma22_false`, the printed line 15).** Only `true` is valid and both correct inputs are `true`; the Byzantine process is silent. Nobody decides in the phases (two votes `< q`), the fallback runs, and line 15 sets `bu_decision ← decision = undecided` at both correct processes. By strong unanimity the fallback returns `undecided`, which is not valid, so both decide `⊥` (line 29) although only one valid value exists. The proof of Lemma 22 says the fallback runs "with valid inputs (either their initial valid values, or a valid value they adopt)": with that reading (`intendedBu = true`) the run decides `true`
