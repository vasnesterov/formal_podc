Spiegelman. *Make Every Word Count: Adaptive Byzantine Agreement with Fewer Words.* PODC 2022; full version arXiv:2202.09123v2, Section 5 and Appendix A. This file is an executable lock-step model of the first two parts of Algorithm 1 (round 1 and the `n` "vetting" phases of Algorithm 2). The third part (the weak BA, line 9) is a black box, see `BBCorrect.lean`. ## Model * Processes `Fin n` (process `p_k` of the paper is `k`, so the leader `p_{j mod n}` of phase `j` is `j % n`, `ldr`), a designated `sender`, a static set `F` of Byzantine processes. Synchronous lock-step rounds; a message sent in a round is received in the same round; a broadcast includes the broadcaster itself. * Adaptive corruption reduces to static corruption here: the protocol is deterministic, so an adaptive adversary can be simulated by corrupting its final faulty set from the start and letting these processes follow the protocol until the original corruption time. All theorems quantify over all Byzantine behaviours, so they cover this. * Global round `0` is round 1 of Algorithm 1; phase `j ∈ [1, n]` occupies the global rounds `3j - 2, 3j - 1, 3j` (its rounds 1, 2, 3). * Signatures and threshold signatures are ideal and *symbolic*: `Item.signed s v` is `⟨v⟩_s`, `Item.qc j` the idk certificate `QC_idk(j)` (a `(t+1, n)`-threshold signature on `⟨idk, j⟩`), `Msg.idk p j` the signature share `⟨idk, j⟩_p`. Every message is one word. * Unforgeability is a validity condition on the adversary (`AdvValid`): a Byzantine process may send `⟨v⟩_s` of a correct `s` only if `s` is the sender and `v` its input (correct non-senders never sign values), `⟨idk, j⟩_p` of a correct `p` only if `p` has sent it (in this or an earlier round: rushing, eavesdropping adversary), and `QC_idk(j)` only if `t + 1` distinct `⟨idk, j⟩` shares are available in that sense. * Correct processes run Algorithm 2 (`reqH`, `repH`, `relH`, `ret`); their states are computed from the Byzantine messages (`vPh j` = the vector of the values `v_i` after `j` phases). The paper's `BB_valid(v)` ("signed by the sender or by `t + 1` processes") is read as "a sender-signed value or an idk certificate" (`bbValid`). * The leader's relay rule (line 23) is a parameter `Rule`: `printed` relays only a sender-signed value `v' = ⟨v⟩_sender` (as in the paper), `fixed` relays any `BB_valid` value. * A correct leader executes round 3 (lines 22-27) only in a non-silent phase, i.e. if it has sent the help request (otherwise it would broadcast unsolicited values sent to it by Byzantine processes, contradicting "no messages will be sent by correct processes in this
