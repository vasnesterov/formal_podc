Spiegelman. *Make Every Word Count: Adaptive Byzantine Agreement with Fewer Words.* PODC 2022; full version arXiv:2202.09123v2 (Algorithms 3, 4 and Appendix B). **Processes and adversary.** Processes are `Fin n`; the phase-`j` leader is `p_{j mod n}` (`leader n j`, index `j % n`). The adversary corrupts a set `F` (static: the protocol is deterministic, so an adaptive adversary is simulated by corrupting the final faulty set from the start and letting these processes follow the protocol until their "corruption"). Byzantine processes send arbitrary messages, subject to unforgeability (`AdvValid`). **Phases (Algorithm 4).** A phase has 5 lock-step rounds; all of its messages are leader-to-all or all-to-leader, so the adversary's messages are given per phase and per correct counterpart: `prop`, `com`, `fin` (a Byzantine leader's messages of rounds 1, 3, 5 to a correct process) and `reply`, `dec` (a Byzantine process's messages of rounds 2 and 4 to a correct leader). A commit certificate `QC_commit(v)` of level `ℓ` is the pair `⟨v, ℓ⟩ : Cert V` (its level is the phase whose votes it batches, so "`level_commit` is valid according to `QC_commit(v)`" holds by construction); the finalize certificate of phase `j` on `v` is `⟨v, j⟩` as well. **Signatures** are ideal: a Byzantine process may send a certificate only if enough signatures on its content are *available*, i.e. signed by a Byzantine process or sent by a correct process (eavesdropping, rushing adversary): `q = ⌈(n+t+1)/2⌉` votes `⟨vote, v, ℓ⟩` for `QC_commit`, `q` messages `⟨decide, v, j⟩` for `QC_finalized`, `t + 1` `help_req` signatures for `QC_fallback`. **After the phases (Algorithm 3, lines 5–29)** we use one lock-step round per paper round: undecided correct processes broadcast `help_req` (H1); decided ones answer, and every process that receives `t + 1` help requests forms and broadcasts a fallback certificate (H2, lines 9–12; we call it a *former*); undecided processes accept a valid `help` answer (H3). The fallback window and the black box `A_fallback`: if a fallback certificate reaches a correct process, all correct processes run `A_fallback` (Lemma 17, by the echo of line 22) on their `bu_decision`; its common output `fbOut` is chosen by the adversary subject to the black-box specification *strong unanimity* (`Admissible`). During the window an undecided process adopts a value carried with a valid proof by a fallback message (`adoptOf`): from formers (line 11; `proof` is read as `decide_proof`) or from Byzantine processes (possibly relayed by correct echoers). Correct echoers that never adopted carry `bu_proof = ⊥`, so they add no proof. Among several adoptable values we take a fixed one (the adversary would control the order; fixing it only restricts the adversary). **Readings.** `Params.intendedBu`: `false` is the printed line 15 (`bu_decision ← decision`, i.e. `undecided` for undecided processes); `true` is the reading of the proof of Lemma 22 (`bu_decision` stays the input `v_i` unless decided). `Params.guard`: `true` = a correct leader acts in rounds 3 and 5 only if it proposed in round 1 (the text: "if the leader decides not to send the initial message then no messages will be sent by correct processes in this phase"); `false` = the printed pseudocode (lines 37 and 48 are unguarded). `Params.K` is the number of phases: `t + 1` in the printed line 1, `n` in the text. `Params.voteOnce`: line 33 says a process
