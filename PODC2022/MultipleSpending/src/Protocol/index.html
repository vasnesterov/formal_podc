import Papers.PODC2022.MultipleSpending.Trust import Papers.PODC2022.MultipleSpending.Transactions /-! # The `k`-spending asset-transfer protocol (Algorithms 1–2): model and invariants An interleaving model of Algorithms 1–2 in the asynchronous Byzantine model with a **static** faulty set `B` (the paper's `F` of the run). Correct processes (`p ∉ B`) follow the protocol; Byzantine processes can make anybody receive any message from them, except that they cannot forge the signature of an issuer that is not Byzantine (`MsgSigned`). Message types: `req tx` (`REQ`, signed by the issuer), `echo tx` (`ECHO` carrying the issuer's signed request), `acc w tx tx'` (`ACC` with the accusation `({w}, {tx, tx'})`). Channels are authenticated (a reception `(q, s, m)` records the true sender `s`) and fully asynchronous: a sent message can be received at any time, never, or several times. The local variables of Algorithm 1–2 are derived from the messages: `usedInp[s]` = inputs of the transactions from `s` that `p` echoed; `signedRequests` = transactions whose signed request `p` received (`HasReq`); `acHist` = accusations `p` sent (lines 31–32 and 35–36 add and send together). `trHist` is the explicit `hist p` (initially `{tx_init}`). The guards are *liberal*: `p` may echo whenever it has received the request and `usedInp` allows it (in the code it does so right upon reception; since `usedInp` only grows, this is a superset of the code's behaviours, so safety results transfer). Line 5 of Algorithm 1 verifies the `REQ` signature with the *sender's* key; we read it as the issuer's key (the text: "σ is a signature for tx from tx.s"), i.e. a `REQ` counts only when received from the issuer.
