import Papers.PODC2022.HybridApproxAgreement.RBC /-! # The Overlap All-to-All Broadcast protocol `Π_oBC` (Section 4.2) and `Π_AA` with one iteration `Π_oBC`, code for party `P` with input `v` (`τ_start = 0`): ``` 3: invoke Π_rBC with input v; join the Π_rBC instance of every party P' 4: repeat 5: upon obtaining v via Π_rBC with sender P': FIFO-send (report, v, P'); add (v, P') to O 8: upon FIFO-receiving (report, v, P') from P'': add (v, P') to R_P'' 10: until τ_now > 3Δ and |O| ≥ n - tₛ 11: repeat 12: upon obtaining v via Π_rBC with sender P': add (v, P') to O 14: upon FIFO-receiving (report, v, P') from P'': add (v, P') to R_P'' 16: W := {P' | R_P' ⊆ O and |R_P'| ≥ n - tₛ} 17: until τ_now > 4Δ and |W| ≥ n - tₛ 18: output O and terminate ``` Encoding (on top of `RBC.lean`): one `RBC.St` per sender; messages `inst s m` (message `m` of the instance with sender `s`) and `report k v s` (the `k`-th report of the sender, FIFO channels simulated with sequence numbers as suggested in the paper: `R_P''` is the longest gap-free prefix of the reports received from `P''`). `O` is a partial map sender ↦ value (as in `Iteration.lean`). Within one step, the instances are stepped first (in the order of the senders), then reports are filed, then the exit conditions of the two loops are checked.
