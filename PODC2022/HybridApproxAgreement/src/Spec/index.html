import Cslib.Computability.Distributed.Byzantine.PartialSync.Auth import Cslib.Computability.Distributed.Byzantine.PartialSync.RunClasses import Cslib.Computability.Distributed.Byzantine.Specs import Mathlib /-! # Approximate agreement with synchronous and asynchronous guarantees (Ghinea–Liu-Zhang–Wattenhofer, PODC 2022): the specification We work in CSLib's Byzantine message-passing model `Cslib.Byzantine.PartialSync` (discrete time, deterministic per-process state machines, the adversary chooses the Byzantine set, the Byzantine messages, the GST and all delivery times) together with its abstract signature layer (`Auth`, `Algorithm.Unforging`, `Run.AuthValid`). Inputs and outputs are real numbers. * `Outputs A R p v`: the *first* decision of `p` in run `R` is `v` (the paper's parties output once and terminate; later decisions are ignored). * `SecureAA Au A ε D C` (Definition 2.1 of the paper, for a fixed `ε`): on every run of the class `C` that respects unforgeability and has inputs in `D`, every honest party outputs (termination), every output lies in the range of the honest inputs (`t`-validity), and any two honest outputs are `ε`-close (`(t, ε)`-agreement). * Run classes (the library classes of `Cslib.Computability.Distributed.Byzantine.PartialSync.RunClasses`): `syncRuns t δ` = `Run.SyncValid t δ` (at most `t` faults, `gst = 0`: every message between honest parties is delivered within `δ`; clocks are synchronised because all parties step every tick), `psyncRuns t δ` = `Run.Valid t δ` (the same bound only after an arbitrary GST) and `asyncRuns t` = `Run.AsyncValid t` (at most `t` faults, every message between honest parties is eventually delivered, **no bound**). `psyncRuns t δ ⊆ asyncRuns t`, so security on `asyncRuns` implies security on `psyncRuns` (`SecureAA.mono`). -/ open
