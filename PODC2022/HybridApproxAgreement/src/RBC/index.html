import Papers.PODC2022.HybridApproxAgreement.Spec import Cslib.Computability.Distributed.Byzantine.PartialSync.Sync /-! # The Reliable Broadcast protocol `Π_rBC` (Section 4.1) and a counterexample to Theorem 4.1 `Π_rBC` (after Momose–Ren), code for party `P` with `τ_start = 0`: 1. the sender `S` sends `(propose, v, sig_S(v))` to all; 2. upon receiving the first valid `propose v` and when `τ_now ≥ Δ`: forward it to all; 4. when `τ_now ≥ 2Δ`: if no valid `propose v'` with `v' ≠ v` was received, send `(vote, v, sig_P(v))`; 6. upon holding `n - tₛ` valid votes for the same `v` and when `τ_now ≥ 3Δ`: send the certificate `C(v)`, output `v` and terminate. **Theorem 4.1** claims `(tₛ, tₐ, 3, 1)`-security for all `tₐ ≤ tₛ` with `2 tₛ + tₐ < n`; in particular `(tₛ, 1)`-Synchronized Consistency: in a synchronous network with `≤ tₛ` corruptions all honest parties output the same value. **This is false** whenever `n ≤ 3 tₛ` (the regime `tₛ ≥ n/3` that the paper is about). The checks of lines 2/4 only detect equivocation for proposals received by time `Δ` (whose forwards arrive by `2Δ`); a Byzantine sender can deliver *different* proposals to two honest parties *late* (at time `2Δ`). Both vote immediately, before the conflicting forwards arrive, and the Byzantine parties complete both vote sets to `n - tₛ`: with `n = 3`, `tₛ = 1`, `tₐ = 0` (so `2 tₛ + tₐ < n`), honest `P₀`, `P₁` and Byzantine sender `C`, `C` sends `propose 0` to `P₀` and `propose 1` to `P₁` so that they arrive at `2Δ`, and votes for both values; at `3Δ`, `P₀` holds the votes `{P₀, C}` for `0` and outputs `0`, `P₁` holds `{P₁, C}` for `1` and outputs `1` (`rbc_not_syncConsistent`). ## Model `CSLib`'s PSync model with lock-step synchrony (`δ = 0`; time unit = `Δ = 1` tick): a message produced in the step at time `τ` (after processing the messages delivered at `τ`) is sent at `τ + 1` and processed by its receivers in their step at time `τ + 1 + (delay)`. The run used is fully synchronous with zero delay, i.e. every message produced at `kΔ` is processed at `(k+1)Δ` — exactly the paper's synchronous model with delivery after exactly `Δ`. Signatures are the abstract tokens of `Cslib.Byzantine.PartialSync.Auth`: a `propose v` message carries the sender's token on `v`, a vote of `p` on `v` carries `p`'s token, a certificate carries the tokens of its votes. The adversary of the counterexample only uses the Byzantine sender's own tokens (`Run.AuthValid`). Parties are `Fin n` (the order of `Fin n` is used to process the messages received at the same time; irrelevant in the counterexample, where no party receives two proposals at once before voting). Valid messages are those carrying the required tokens; in the token model every message carries its tokens by construction, so all received messages are valid.
