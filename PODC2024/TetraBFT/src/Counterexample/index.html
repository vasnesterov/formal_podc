import Papers.PODC2024.TetraBFT.Refinement import Cslib.Computability.Distributed.Byzantine.PartialSync.Sim /-! # Termination fails: a view-synchronization deadlock (counterexample to Theorem 1, termination) The view-change rule of Section 3.2 is: on a timeout, broadcast a view-change message for the next view; on `f + 1` view-change messages for a view `v'`, send a view-change message for `v'` *if no view-change message for `v'` or any higher view was sent*; on `n − f` view-change messages for a view, move to that view. Nothing is ever retransmitted, and the timer fires once per view. With `n = 7`, `f = 2` (nodes `0, 1` Byzantine; leaders round-robin, so views `0, 1` have Byzantine leaders) there is a run of the partially synchronous model with **reliable** channels (every message between correct nodes is delivered by `max(send time, GST) + Δ`; CSLib's `Run.Valid`), `GST = 30`, `Δ = 1`, timeout `9Δ`, in which, from time 41 on: * nodes `2, 3, 4` are in view 1, have sent view-change messages for views 1 and 2, and see only 4 (< n − f = 5) view-change messages for view 2 and 2 (< f + 1 = 3) for view 3; * nodes `5, 6` are in view 2 and have sent view-change messages for view 3, which only 2 correct nodes ever send; node 6 entered view 2 without ever sending a view-change message for view 2, because it had echoed the view-3 message of node 5 (supported by the two Byzantine nodes) first, and the echo rule forbids echoing a *lower* view afterwards; * no timer will ever fire again and no message is in transit: the system is stuck forever and no correct node ever decides (`termination_fails`). The schedule: all correct nodes time out in view 0 at time 9; nodes 2–5 enter view 1 at once, node 6 receives their messages only at time 31. Nodes 2–5 time out in view 1 at time 19; node 5 enters view 2 thanks to one Byzantine view-2 message. Node 5 times out at time 29; its view-3 message, together with two Byzantine ones, reaches node 6, which echoes view 3; at time 30 node 6 receives the delayed view-2 messages of nodes 2–5 plus a Byzantine one and enters view 2. The same pattern works for every `f ≥ 2` with `n = 3f + 1` (informal; see the README). With message loss before GST, which the paper's model explicitly allows, already `n = 4`, `f = 1` deadlocks (`termination_fails_lossy`). -/ namespace TetraBFT open Finset Cslib.Byzantine.PartialSync
