The processes share a max register `curr` (base object `maxRegObj`, **initialized to `1`**) and an infinite array `TS[1], TS[2], …` of readable test&set objects (`rtasObj`, all initially `0` = `false`; `TS[0]` exists in the model but is never accessed). * `test&set()`: `c ← curr.readMax()`; return `TS[c].test&set()`. * `read()`: `c ← curr.readMax()`; return `TS[c].read()`. * `reset()`: `c ← curr.readMax()`; `b ← TS[c].read()`; if `b = 1` then `curr.writeMax(c + 1)`; return (the acknowledgement `false`, as in `mtasObj`). Linearization (paper): `curr` only grows by one, and the abstract state is `TS[curr]`. Let `e_v` be the `writeMax(v + 1)` that changes `curr` from `v` to `v + 1`. Before `e_v`, the operations that read `v` from `curr` are linearized at their access to `TS[v]` (a reset that reads `0` there is a no-op reset on state `0`). At `e_v` we linearize, in this order: all test&set/read operations that read `v` from `curr` and have not accessed `TS[v]` yet (they all obtain `1`), the resetting operation, and all other resets that read `v` from `curr` and are not yet linearized (they have not read `TS[v]`, or read `1` and have not executed `writeMax(v + 1)`). A reset whose `writeMax` does not change `curr` was linearized at an earlier `e_u`. We prove that this is a forward simulation (`linSim`), hence strong linearizability; wait-freedom is immediate (at most three accesses per operation).
