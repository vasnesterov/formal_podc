The R-LLSC object (`rllsc P V v₀`, state `(val, context) : V × Finset P`) is implemented from a single CAS object `X` (`casObject (V × Finset P) (v₀, ∅)`). The paper stores the bit vector `(v, c₁, …, cₙ) ∈ V × {0,1}ⁿ` in `X`; we store `(v, {pᵢ | cᵢ = 1}) : V × Finset P`, which is the same encoding (the paper's translation `state(x)` of Lemma 40 becomes the identity). Code for process `p` (`Loc` is the program counter together with the local variable `cur`): * `LL`: `cur ← Read(X)`; `while ¬CAS(X, cur, (cur.val, cur.ctx ∪ {p})) do cur ← Read(X)`; return `cur.val` (Lines 1–6); * `SC(v)`: `cur ← Read(X)`; `while p ∈ cur.ctx do (if CAS(X, cur, (v, ∅)) then return true; cur ← Read(X))`; return `false` (Lines 7–11); * `VL`: `cur ← Read(X)`; return `p ∈ cur.ctx` (Lines 12–13); * `RL`: `cur ← Read(X)`; `while p ∈ cur.ctx do (if CAS(X, cur, (cur.val, cur.ctx \ {p})) then return true; cur ← Read(X))`; return `true` (Lines 14–20); * `Load`: `cur ← Read(X)`; return `cur.val` (Lines 21–22); * `Store(v)`: `Write(X, (v, ∅))`; return `true` (Lines 23–24). A process may only invoke `LL`/`VL`/`SC`/`RL` with its own id (`Impl.allowed`). ## Main results * `RLLSCFromCAS.isLinFun` and `RLLSCFromCAS.mem_eq_linState`: Lemma 40 — the paper's linearization function `h_llsc` (`RLLSCFromCAS.lin`, defined by the paper's linearization points, `RLLSCFromCAS.IsLinStep`) is a linearization function, and the CAS value equals the abstract state of `h_llsc(α)`. * `RLLSCFromCAS.perfectHI`, `RLLSCFromCAS.lockFree`: Theorem 28 (lock-freedom assumes finitely many processes, `[Fintype P]`; it is proved by a potential function that strictly decreases at every non-response step, without using the invariant). * `RLLSCFromCAS.lemma29`: Lemma 29 (in our model, where responses are separate steps: infinitely many context-changing operations are *linearized*). * `RLLSCFromCAS.lemma30`: Lemma 30 (in the form: once `p ∉ X.ctx` while `p`'s `SC`/`RL` is pending, `p` takes at most two more steps before returning). * `RLLSCFromCAS.exLLSC_run`, `exLLSC_bad`,
