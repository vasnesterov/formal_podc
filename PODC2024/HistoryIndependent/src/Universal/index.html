import Cslib.Computability.Distributed.SharedMemory.Objects.LLSC import Cslib.Computability.Distributed.SharedMemory.Model import Mathlib /-! # Algorithm 5: a universal implementation from R-LLSC objects Section 6.1 of Attiya, Bender, Farach-Colton, Oshman, Schiller, *History-Independent Concurrent Objects*, PODC 2024. `n` processes `Fin n` implement an arbitrary abstract object `A` from atomic R-LLSC base objects `head` and `announce[0..n-1]` (`Obj.head`, `Obj.ann j`). * `head` holds a value in `A.State × Option (A.Resp × Fin n)`: `(q, none)` is the paper's `⟨q, ⊥⟩`, `(q, some (r, j))` is `⟨q, ⟨r, j⟩⟩`. * `announce[j]` holds a value in `Option (A.Op ⊕ A.Resp)`: `none` is `⊥`, `some (inl o)` an announced operation, `some (inr r)` a response. (The paper assumes `R ∩ O = ∅` and `⊥ ∉ R ∪ O`; the sum/option type makes this automatic.) Read-only operations are recognized with a decidable instance for `A.ReadOnly`. ## The program Every program counter (`PC`) performs exactly one access to a base object (or returns), and the local computation between accesses is folded into the continuation. Here the base objects are atomic, so each `LL` is a single step, and the paper's `∥` allows any finite number of steps on either side: executing the left side to completion (zero steps on the right) is one of the allowed schedules of the paper's program.
