import Papers.PODC2024.HistoryIndependent.UniversalWF import Cslib.Computability.Distributed.SharedMemory.Model /-! # Theorem 32: Algorithm 5 over Algorithm 6, flattened Section 6.4 of Attiya, Bender, Farach-Colton, Oshman, Schiller, *History-Independent Concurrent Objects*, PODC 2024. Theorem 32 is an existence claim: *there is* a linearizable, wait-free, state-quiescent HI universal implementation from atomic CAS objects. We prove it for the **flattened** implementation `flat A n`: Algorithm 5 in which every operation on an R-LLSC object is inlined as the code of Algorithm 6 on a CAS object holding the R-LLSC state `(val, context)` (one CAS object per R-LLSC object `head`, `announce[j]`). ## The `∥` construct Lines 6, 18 and 25 of Algorithm 5 run an `LL` (left) in parallel with a waiting loop (right), "with some unspecified but finite number of steps taken on each side before the process switches". We fix one admissible schedule: **strict alternation**, starting with the left side, one step of the left side (a `Read` or a `CAS` of Algorithm 6's `LL`), then one step of the right side (a `Load`), and so on, until one side finishes: * the left side finishes when its `CAS` succeeds (the `LL` returns); the right side is then abandoned (it only performed `Load`s); * the right side finishes when its waiting condition holds; then the left `LL` is abandoned, and the right side runs to completion (line 18R.2's `RL(announce[j])` is executed with the left side suspended forever). Under this schedule an abandoned `LL` never took effect (its only effect is the successful `CAS`, which ends it), so the "pending forever" operation on the R-LLSC object does not matter. The local state `FLoc` consists of the local state of Algorithm 5 (`l5`, whose program counter is the R-LLSC operation in progress), the stage `st` of the current Algorithm 6 operation (`true`: `cur` has been read, next step is the `CAS`), the turn `turn` of the `∥` (`true`: right side) and the local variable `cur` of Algorithm 6 (one copy per object type). ## Modelling details * The CAS objects (`casC`) decide equality classically, so that no decidable equality on the abstract object's states, operations and responses is needed. * In Algorithm 6's `SC` and `RL` the loop condition `cur.context[i] = 1` is evaluated after the `Read` (as in the paper) and re-evaluated before the `CAS` (it always holds there). * Line 18R.2 (`RL(announce[j])` after the right-hand side of line 18 ends) is the program counter `PC.rl18 j` of Algorithm 5 (unreachable in the atomic `alg5`). ## Main results * `flat_tau`: every step is a stutter, a step of `alg5` (at the linearization point of an Algorithm 6 operation, Lemma 40), or the end of a right-hand side of `∥` (`Jump`). * `flat_invL`: the invariant of Algorithm 5 (`InvL`, extended to the jumps by `InvC.jump`) holds for the abstract configuration `absC C` of every reachable configuration. * `flat_isLinFun`, `flat_stateQuiescentHI`: linearizability and state-quiescent HI (Theorem 32). * Wait-freedom:
