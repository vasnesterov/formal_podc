import Papers.PODC2024.MemSnap.Defs import Podc.Computability.Distributed.SharedMemory.MetaConfig /-! # Algorithm 2: the meta-configuration tracking augmentation of MemSnap The augmentation adds two ghost variables, which do not influence the algorithm: * `x̂_π` (`Ghost.xh`): the value of `X` when `π` invoked its current `observe`/`update`; * `P` (`Ghost.PP`): the meta-configuration, a set of possibilities (`Poss`: an abstract state `(val, snap)` and, for each process, `⊥` or the response of its linearized current operation). The update rules of `P` are those of Algorithm 2: * line 1 (`X ← X + 1`, here the write of `X`): every subset `S ⊆ UnLin(p)` of not yet linearized updaters may linearize, in any order `α`, just before the click: `P ← {p' | ∃ p ∈ P, ∃ S ⊆ UnLin(p), ∃ α ∈ Perm(S), TransitionsOK(p, α · σ, p')}`; * line 4: `P ← {p' | ∃ p ∈ P, p.σ = ⊥ ∧ TransitionsOK(p, σ, p')}`; * line 7: `P ← P ∪ {p' | ∃ p ∈ P, p.π = ⊥ ∧ TransitionsOK(p, π, p')}`; * lines 2, 5, 8 (returns): `P ← Filter(P, π, r)`. `arun α` runs the augmented algorithm along the execution `α`; its first component is the configuration of Algorithm 1 (`arun_fst`, `exists_arun`). **Soundness of the augmentation** (`tracked_of_mem_PP`): every possibility in `P` is realized by a linearization of the execution so far (`Poss.Tracked`). This is the content of the remark of Section 6.1 that "the augmentation in Algorithm 2 indeed satisfies the two rules laid out in the Jayanti et al. paper"; with the tracker theorem `Poss.linearizable_of_tracked` it reduces linearizability of Algorithm 1 to the invariant `P ≠ ∅`. -/ set_option linter.unusedSectionVars false namespace Podc.MemSnap open Cslib.SharedMemory variable
