Swiper — PODC 2024

Andrei Tonkikh, Luciano Freitas. Swiper: a new paradigm for efficient weighted distributed protocols. PODC 2024. DOI 10.1145/3662158.3662799. Formalized version: arXiv 2307.15561 v2 (contains the appendix proofs). Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. The weight restriction and qualification bounds (Theorem 2.1, Theorem 2.2, Corollary 2.3) that the protocols rely on hold, but the weight separation bound of Theorem 2.4 and Swiper's construction for it fail, and keeping that problem linear in n took a new rounding offset and a new analysis. The protocol transformations of Sections 4–6 were checked only in the combinatorial core of Theorem 4.2.

Mistakes in the paper

🛠️ Theorem 2.4; Appendix A.2; Section 3, "Robustness" for weight separation

The claimed bound T ≤ (α+β)(1−α)/(β−α)·n is false (ws_upper_bound_false), because case 2 of Appendix A.2 substitutes 1−γ for γ without changing the rounding offset, so Swiper's own construction violates it too (swiper_ws_counterexample, swiper_ws_family_exceeds_bound).

Impact. The weight-separation guarantee does not hold as stated, and the algorithm's guarantee fails even under a disjoint-sets reading of Problem 3; the authors' public solver returns invalid tickets when the bound binds. The weight restriction and qualification results (Theorems 2.1, 2.2, Corollary 2.3) are unaffected.

Details

The bound fails for α = 1/20, β = 1/10, 8 parties of weight 14 and 13 of weight 1 (n = 21): every solution needs T ≥ 63 > 59.85. Here W = 125. Each weight-14 party alone is heavy, all 13 unit parties together are heavy, and light sets contain at most 6 unit parties. If at most 6 unit parties hold tickets, those (light) and all unit parties (heavy) have equally many tickets, a violation. Otherwise any 6 ticketed unit parties hold ≥ 6 tickets, so each weight-14 party needs ≥ 7 and the unit parties together ≥ 7: T ≥ 63 > 59.85. (The optimum is exactly 63; for this family OPT/n → α/β², here 5 versus the claimed 2.85.) This instance compares a set of unit parties with a superset of it, which the paper's Problem 3 allows. Under a "disjoint S₁, S₂" reading it would not be a counterexample, but the three-party instance below refutes the proof and Swiper's guarantee under either reading.

The proof rounds t_i = ⌊w_i s + γ⌋ with γ = (α+β)/2. Case 1 (t(S₁) ≥ γT) is correct; case 2 is claimed "analogous by substituting 1−γ for γ and 1−β for α". That would also require changing the rounding offset from γ to 1−γ, which is not done, so the argument works only for γ = 1/2. Redone honestly, case 2 gives max(γ², (1−γ)²)·n instead of γ(1−γ)·n.

On three parties w = (1, 1, 15) with α = 1/20, β = 1/10, the paper's s yields t = (0, 0, 7), which is invalid, and every valid member of its rounding family has T ≥ 14, while the bound is 8.55. The two unit parties (weight 2 > βW = 1.7) are heavy yet ticketless, so they tie with S₁ = ∅ (disjoint sets). The authors' public solver (DCL-TelecomParis/swiper, commit f1d7a3d) hard-codes this bound and silently returns invalid tickets when it binds: weights (2, 14) with α = 1/20, β = 1/10 give tickets (0, 5), although party 1 alone is heavy (checked by running it).

Repair

T ≤ ⌈(1−d²)/(2d)·n⌉ with d = β − α, using rounding offset (1−d)/2 (ws_upper_bound). It keeps all α < β, linearity in n and the shape n/(β−α) with numerator below 1. It is symmetric under (α, β) ↦ (1−β, 1−α), as the problem is (the paper's bound is not). It beats the paper's bound when α+β is near 1 and is weaker when α+β is small.

✏️ Slips

  • Appendix A.2, case 1: the complement bound writes βWs for (1−α)Ws; as printed it fails for α+β > 1 and does not yield the next line, which matches (1−α).

  • The §4.1 random-beacon example writes (1−αn)T ≥ ⌈αn T⌉, which is false in general (αn = 1/2, T = 3). The inequality (1−αn)T ≥ αn T of the proof of Theorem 4.2 and integrality of ticket counts give the conclusion (isBlunt_of_isWR).

Typos

  • In Definition 4.1 the second conjunct has F unbound (we read it as ∀ F, ∃ A, A ∩ F = ∅).

Proof gaps in true statements (1)Theorem 2.1

🔧 Theorem 2.1 (Appendix A.1)

Three steps are unjustified: "since we already proved that viable s exist" (no such proof is in the paper), "it is easy to see that such s* exists" (needs a right-continuity/discreteness argument for the infimum), and the non-emptiness of the border set J (needs 0 < αw < 1).

Impact. The theorem stands; all three steps are proved (exists_viable, exists_locallyMinimal, LocallyMinimal.border_nonempty).

Full list of differences (including modelling choices and minor imprecisions): differencies.md.

The formalizationmodel, Lean names of the results, trust

Model. No distributed model is involved: Sections 2, 3.1 and Appendix A are static combinatorics. Parties form a finite type ι, with weights w : ι → ℝ, w ≥ 0, W ≠ 0, and tickets t : ι → ℕ. Problems 1–3 are the predicates IsWR, IsWQ, IsWS, which quantify over all subsets as in the paper. The removal process of A.1 ("remove tickets while the assignment stays viable") is modelled by an arbitrary stopping point, so every run is covered.
