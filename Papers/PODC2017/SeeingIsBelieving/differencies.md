# Differences between the formalization and the paper

Paper: Crooks, Pu, Alvisi, Clement, *Seeing is Believing*, PODC 2017 (10-page author copy). Verdict rules: see
`.claude/skills/formalize-paper/verdicts.md`.

## Statement-level

1. **Quantification of Adya's history (Theorems 1–4, 10).** The paper writes `∃e: ∀T ∈ 𝒯: CT_I(T,e) ≡ ¬G1 ∧ ¬G2`
   (etc.) without saying which history the phenomena refer to. Adya's phenomena depend on a version order and, for
   G-SI, on start/commit timestamps, none of which is determined by `𝒯` and the values read. We formalize
   `(∃ e, ∀ T, CT_I(T,e)) ↔ ∃ vo, ¬G…` (Theorem 2: `∃ vo ts`). For a *fixed* version order the statements are false
   (`fixed_versionOrder_counterexample`: blind writes, serializable, but G0/G1 for `x₀ ≪ x₁, y₁ ≪ y₀`; for SI, a
   transaction committing before a reader of `⊥` starts gives G-SIb for fixed timestamps although the transactions are
   SI in the other order). **Rule:** under-specified statement whose intended reading is recoverable from the paper
   (its ⇒ proofs construct the version order and timestamps from `e`; Section 4 stresses that the state-based
   definitions do not use timestamps; Theorem 4 only makes sense this way) → not counted as a statement error.
   *Borderline call:* a reader taking "≡" per history would get a false statement; we judged the existential reading
   to be the evident intent, so the verdict stays ✅ rather than ⚠️. Reviewer's check (rendered p. 4–5): the theorem
   statements mention no history `H` at all (only `𝒯` and `e`), so no fixed version order is part of the literal
   claim; the ⇐ sketch of Theorem 2 starts from "any history satisfying ¬G1 ∧ ¬G-SI" and the ⇒ sketch from "the
   SSG(H) corresponding to e", selecting the start/commit points — i.e. exactly `(∃ e, …) ↔ ∃ H, ¬G…`. This is
   also the standard shape of the multiversion serializability theorem (Bernstein–Hadzilacos–Goodman: a history is
   one-copy serializable iff *some* version order makes MVSG acyclic). So the statements are true as written under
   the only reading consistent with the paper (R1), not a typo to be excused under R3.
2. **Theorem 10 / Theorem 5:** only `CT_PSI ⇔ PL-2+` is formalized; the equivalence with Sovran et al.'s operational
   PSI is not (no formal definition in the paper).
3. **Theorem 2 timestamps.** The ⇐ direction (`theorem2_of_adya`) is proved for timestamps in an arbitrary linear
   order; `theorem2` states the equivalence with `ℕ`-valued timestamps (the ⇒ direction produces those).

## Modelling choices

4. **Values.** Values are uniquely identifiable (paper, Section 3): the value written by `T` to `k` is `some T`, `⊥`
   is `none`; writes carry no explicit value. This bakes in the paper's assumption that a transaction writes a key at
   most once (repeated `write k` operations of one transaction are harmless duplicates).
5. **Committed / aborted.** `𝒯` (`TxnSet.committed`) is the set of committed transactions; executions permute `𝒯`.
   Aborted transactions are the other identifiers; they matter only through reads of their values (G1a). The paper's
   phrase "values produced by writes from aborted or committed transactions" (Section 3) is not followed: applying
   aborted writes in `e` would break Theorem 1 ⇒.
6. **G1b** (intermediate reads) is not defined: it cannot occur when every transaction writes a key at most once.
   `G1 := G1a ∨ G1c`.
7. **Well-formedness** (`TxnSet.WellFormed`, hypothesis of Theorems 1, 2, 3, 10): a read value of another
   transaction was written by it; a transaction reads its own value of `k` only after its write of `k`. Both are part
   of Adya's notion of a history and implicit in the paper; without the second, a transaction "reading" its own future
   value satisfies ¬G1 ∧ ¬G2 but has no read state. Adya's third condition (after writing `k`, reads of `k` return the
   own value) is not needed and not assumed. Theorem 4 needs no hypothesis.
8. **States** are indexed by position `0..|𝒯|` in `e` (`Execution.state`); the parent state of `T` is
   `s_{idx T}`, the state generated by `T` is `s_{idx T + 1}`. With a read-only transaction two consecutive states are
   equal as maps but distinct as elements of the sequence `𝒮_e`; this is the reading under which `s →* s_p` and
   "first/last read state" make sense.
9. **Read states (Definition 2).** The clause `∃ w(k,v) ∈ Σ_T : w(k,v) →to r(k,v)` becomes `v = some T ∧ write k`
   occurs earlier in `T`'s operation list. Write operations have all states up to `s_p` as read states (paper's
   convention). Operations are addressed by their index in the list.
10. **`sl_o` in Definition 6.** `CT_PSI` requires `s_{T'} →* s` for every last read state `s` of `o`; under PREREAD the
    last read state exists (`Execution.exists_isLastReadState`), so this is the paper's condition. `T_{sf_o}`: "the
    first read state of `o` is the state generated by `T'`" (`Execution.IsFirstReadState`); when `sf_o = s_0` no
    transaction qualifies.
11. **Adya's edges** use the *next* version, as in Adya: `T →ww T'` if `T'` installs the version of some key right
    after `T`'s; `T →rw T'` if `T` reads a version (or `x_init`) and `T'` installs the next one; `T →wr T'` if `T'`
    reads a version installed by `T`. All edges join distinct committed transactions (a read-modify-write transaction
    has no self-loop). `T →sd T'` iff `commit T < start T'`.
12. **Timestamps** (`Timestamps`): distinct start and commit timestamps with `start < commit` (the paper's time oracle).
13. **G-SIb / G-single / G2** are stated as "an anti-dependency edge `X →rw Y` plus a path `Y →* X` of the allowed
    edges", i.e. a cycle with exactly one (G-SIb, G-single) or at least one (G2) anti-dependency edge.
14. **Hierarchy.** `satisfies_hierarchy` shows SER ⇒ SI ⇒ PSI ⇒ RC; the step SI ⇒ PSI holds on the same execution
    (`Execution.ctPSI_of_ctSI`), which is stronger than what Figure 4 needs. Strictness is shown only for SER ⊋ SI
    (write skew).

## Proofs

15. **Theorem 1 ⇐.** The sketch shows that no anti-dependency points backwards, but a version read by `T` could also
    be hidden by a transaction installed *before* the version read in the version order yet placed after it in `e`;
    this is excluded by write-dependency edges (`VersionOrder.transGen_ww_of_lt`). Aborted reads must be excluded by
    ¬G1a. Routine.
16. **Theorem 2 ⇒.** (a) For a write-dependency edge `T' →ww T` the sketch asserts that `T'` precedes `T_rs`; this
    needs NO-CONF (else `T'` lies between the snapshot and `s_p` and writes a key of `𝒲_T`). (b) The start point
    "directly after the commit point of `T_rs`" is shared by all transactions with the same snapshot, contradicting
    distinct timestamps; we encode start `= (2·snap + 1)·M + idx T` and commit `= (2·idx T + 2)·M`. (c) For a
    transaction with no operations COMPLETE holds for every state, including states after `s_p`, so the snapshot must
    be capped at `s_p` (degenerate, R2). Routine.
17. **Theorem 2 ⇐** follows the paper (commit order; snapshot = state generated by the last transaction committed
    before `T` starts); for a writer `T''` of a read key we also handle `T''` installed before the version read (via
    ww edges and G-SIa) and the case where the next version after the one read is installed by `T` itself.
18. **Theorem 10** is not proved in the paper (deferred to the TR); our proof: ⇒ every ww/wr edge is a `▶` edge, so a
    G-single cycle `A →rw B →* A` makes `B ▷ A`, and `s_B →* sl_o` contradicts that `o` reads a version older than
    `B`'s; ⇐ take a topological order of ww ∪ wr, show `▷ ⊆ (ww ∪ wr)⁺`, and use ¬G-single / ¬G1c.
19. **Theorems 3, 4** are not proved in the paper; ours are direct (Theorem 4: both sides always hold).
