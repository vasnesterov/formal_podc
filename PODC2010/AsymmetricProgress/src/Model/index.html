import Mathlib import Cslib.Computability.Distributed.SharedMemory.ObjClasses -- CSLib candidate: shared memory with caller-aware, possibly blocking base objects; valency -- toolkit (deciders, critical configurations, all processes poised on one object). /-! # The model: asynchronous shared memory with (possibly blocking) base objects Imbs, Raynal, Taubenfeld. *On Asymmetric Progress Conditions.* PODC 2010 (full version: IRISA research report PI-1952, May 2010, HAL inria-00486977). Section 2 and Section 3.3. **Processes.** `n` deterministic, asynchronous processes `Fin n`. Process `p` starts in the local state `A.init p x` determined by its (binary) input `x` — every process participates and proposes its input (binary consensus, as in the proofs of the paper, Section 3.3). A crash is a process that stops taking steps (crash-stop): executions are finite or infinite *schedules* (sequences of process identifiers), and a process is correct in an infinite schedule iff it occurs infinitely often. **Base objects.** Objects are indexed by `ι`; object `i` is a `BObj n`: a deterministic, *caller-aware* transition function `δ : State → Fin n → Op → State × Option Resp`. A response `none` means that the object has taken the step of the caller but has not responded yet: the caller stays poised on the same operation. Atomic objects (registers, wait-free consensus objects, any linearizable wait-free object) always respond (`BObj.ofSpec` embeds a CSLib sequential specification). Blocking responses are needed only to model the non-wait-free `(n, x)`-live consensus base objects of Theorem 2 (`liveCons`). **Algorithms.** A local state either outputs a value (`Act.out v`; steps in output states are no-ops) or is poised to apply an operation `o` to object `i`, continuing with `k r` on response `r` (`Act.access i o k`). Local computation is folded into the continuation. **Correctness of an implementation of consensus** (`Safe`, `OFree`, `WFree`, `FFree`): agreement and validity over all finite executions from initial configurations; *obstruction-freedom* of `p` (from every reachable configuration, `p` running solo eventually outputs); *wait-freedom* of `p` (in every infinite schedule in which `p` takes infinitely many steps, `p` outputs); *fault-freedom* of `p` (in every infinite schedule in which every process takes infinitely many steps, `p` outputs). An implementation is `(n, X)`-live (`Live A X`) if it is safe, obstruction-free for every process and wait-free for the processes of `X`; the paper's `(n, x)`-liveness is `Live A X` with `X.card = x`. -/ namespace Podc.AsymmetricProgress open Cslib.SharedMemory set_option linter.unusedSectionVars false /-- A base object of an `n`-process system: a deterministic transition function that may depend on the calling process and may withhold the response (`none`; the caller then stays poised on the same operation). -/ structure BObj (n : ℕ) where /-- States of the object. -/ State : Type /-- Operations. -/ Op : Type /-- Responses. -/ Resp : Type /-- The transition: new state and (possibly no) response. -/ δ : State → Fin n → Op → State × Option Resp namespace BObj variable {n : ℕ} /-- The atomic object with sequential specification `S`: it always responds and ignores the identity of the caller. -/ def ofSpec (S : ObjSpec) : BObj n where State := S.State Op := S.Op Resp := S.Resp δ s _ o := ((S.δ s o).1, some (S.δ s o).2) /-- *Read/write-like* objects: every operation is read-only (never changes the state) or a blind overwrite (new state and response independent of the old state).
