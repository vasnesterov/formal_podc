import Mathlib /-! # The arbiter object (Section 6.1, Figure 4, Appendix A, Theorem 5) Imbs, Raynal, Taubenfeld. *On Asymmetric Progress Conditions.* PODC 2010 (full version: IRISA research report PI-1952). **Model.** Asynchronous shared memory, crash-stop processes indexed by an arbitrary type `ι`. Each process `p` has a fixed role `role p ∈ {owner, guest}` and invokes `arbitrate(role p)` at most once: a process *invokes* (participates) iff it takes at least one step, its first step being line 01. Executions are given by an arbitrary schedule `σ : ℕ → ι` (the process taking step `t`); a process is *correct* in `σ` iff it takes infinitely many steps (`Correct`), crash-stop = finitely many steps. Each step performs exactly one access to a shared object; local computation is folded into the step. Shared objects (`ArbSh`): atomic registers `PART[owner]`, `PART[guest]` (initially `false`) and `WINNER` (initially `⊥`), and the consensus object `XCONS`. `XCONS` is accessed by the (at most `x`) owners only and is wait-free for them, hence it is modelled as an atomic consensus object: the first proposal is decided and every `propose` returns the decided value in one step. (The bound "at most `x` owners" of Theorem 5 is only needed to implement `XCONS` from `(x, x)`-live consensus; in this model it plays no role.) **Program counters** (`APc`), one per access of Figure 4: `idle` (line 01), `oRead` (read `PART[guest]`, line 02), `oProp b` (`XCONS.propose(b)`, line 02), `oWrite w` (write `WINNER`, line 03), `gRead` (read `PART[owner]`, line 04), `gWait` (one read of the busy-wait `wait(WINNER ≠ ⊥)`, line 04), `gWrite` (`WINNER ← guest`, line 04), `ret` (read `WINNER` and return it, line 06), `done a` (returned `a`). **Results** (Theorem 5 = Lemmas 12–16): `arbiter_agreement`, `arbiter_validity_owner`, `arbiter_validity_guest` (the returned role was *invoked before the return* — the real-time version needed in the proof of Lemma 10 of the paper), `arbiter_termination`.
