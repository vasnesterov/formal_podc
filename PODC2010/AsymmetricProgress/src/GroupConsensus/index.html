import Papers.PODC2010.AsymmetricProgress.Arbiter /-! # Consensus with group-based asymmetric progress (Section 6.2–6.4, Figure 5, Theorem 6) Imbs, Raynal, Taubenfeld. *On Asymmetric Progress Conditions.* PODC 2010 (full version: IRISA research report PI-1952). **Model.** `n` asynchronous crash-stop processes `Fin n` communicating through shared memory. The processes are partitioned into `m` ordered groups by `grp : Fin n → ℕ` (`grp q < m`; group `0` here is group `1` of the paper, the group with the strongest progress guarantee). Process `q` proposes `inp q` (an arbitrary value type `V`). Executions are given by an arbitrary schedule `σ : ℕ → Fin n`; a process *participates* (invokes `propose()`) iff it takes at least one step, is *correct* iff it takes infinitely many steps (`Correct`), and crash-stop = finitely many steps. Each step performs one access to one shared object, local computation being folded into it. Shared objects (`GSh`): atomic registers `VAL[g]`, `ARB_VAL[g] : Option V` (`none` = `⊥`), the `(x, x)`-live consensus objects `GXCONS[g]` (accessed only by the at most `x` processes of group `g`, hence wait-free: modelled as atomic consensus objects — the first proposal is decided, every `propose` returns the decided value in one step), and the arbiters `ARBITER[g]`, `g + 1 < m`, inlined: their registers and their `XCONS` object (accessed by the owners of `ARBITER[g]` = the processes of group `g` only) are those of `Arbiter.lean`. **The two tasks.** Each process runs task T1 (lines 01–18 of Figure 5) and task T2 (`wait(ARB_VAL[1] ≠ ⊥); return(ARB_VAL[1])`). The two tasks of a process are interleaved *alternately*: the steps of a process are T1, T2, T1, T2, … (a fair interleaving; since a T2 step is a read, this loses no reachable shared state). A T2 step reads `ARB_VAL[1]` and, if it is not `⊥`, decides that value (the busy-wait read and the read in `return(ARB_VAL[1])` are folded into one read). Deciding does *not* stop task T1 (this only adds executions, so the safety results are stronger; the paper does not say whether `return` kills T1). Program counters of T1 (`Pc`): `start` (line 02, `GXCONS[y].propose(v)`), `wVal d` (line 02, `VAL[y] ← d`), `arb g s` (inside `ARBITER[g].arbitrate()`, at arbiter program counter `s`; lines 04 and
