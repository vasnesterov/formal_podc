Without the shaded lines `captured` stays `false`. * Every step of a process performs at most one shared-memory access, followed by the local computation up to the next access. The program counter `PC` carries the local variables (`rem` = the indices a `foreach` still has to visit, `acc` = the maximum read so far at line 15, `pred` = `predecessor_set`, `cap` = `captured`). A `foreach` visits the indices in an **arbitrary** order (chosen by the adversary at every step). When a `foreach` has nothing left to visit, one local step moves on (this also merges the local lines 17–18). * Process `p` reads its own variable `Ticket[p]` at lines 14, 16, 21, 22, 23 in the same step as the accompanying write/read of another variable: `p` is the only writer of `Ticket[p]`, so this does not change the behaviour (it only removes `p`'s re-reads of its own ticket from the RMR count, which the thesis bounds by one RMR per passage). * An execution is a schedule: at every time some process takes a step (the adversary also chooses the `foreach` index). A process *crashes* if it takes finitely many steps and stops outside the NCS. A process in the NCS that is scheduled leaves the NCS; one that is never scheduled again stays there forever (this is not a crash). The CS is a single location; a process in the CS that is scheduled leaves it. * RMRs: in the DSM model `Ticket[p]`, `Want[i][p]`, `Capture[i][p]` live in `p`'s module; in the (write-through, write-invalidate) CC model, `cached` records the valid cached copies: a read is an RMR iff the reader has no valid copy (afterwards it has one), every write is an RMR and invalidates all other processes' copies. `cached` is part of the cost model only; the algorithm never reads it. -/ namespace Podc.KBakery open Finset /-- Program counters together with the private variables of a process.
