Sides are `Bool` (`false` = 0, `true` = 1, `d̄ = !d`). * Every numbered line is one atomic step (it performs one access to a shared object, plus local computation). Line 1.8 (`return d`) is merged with line 1.7, and the critical section is a single step `cs`. A process in the remainder section that takes a step starts a new attempt with a session chosen by the adversary (the event carries it). * `G`, `C[s,d]` and `Q` are atomic (linearizable) objects, as in Theorems 2–3 of the paper. The priority process-queue is modelled by one slot per process (the paper's restrictions (i)–(ii): only `p` dequeues its element, and `p` dequeues before enqueuing again); `Min(Q)` returns the `(s,d)` of the element with the least `(tm, p)`. * LL/SC (`S` and `Ex`): a per-process link bit, set by `LL`, cleared for everybody by every successful `SC`; `SC` by `p` succeeds iff `p`'s bit is set ("no successful SC since `p`'s latest LL"). Line 16.12 is a plain read of `S`. * `Ex = false` is `none`.
