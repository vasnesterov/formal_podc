import Papers.PODC2010.ModularConsensus.Basic import Mathlib.Probability.ProbabilityMassFunction.Constructions import Mathlib.Analysis.SpecialFunctions.Exp import Mathlib.Data.Nat.Log /-! # Procedure ImpatientFirstMoverConciliator (Section 5.2, Theorem 7 of Aspnes, PODC 2010) J. Aspnes, *A modular approach to shared-memory consensus, with applications to the probabilistic-write model*, PODC 2010. ``` shared data: register r, initially ⊥ procedure ImpatientFirstMoverConciliator(v) 1 k ← 0 2 while r = ⊥ do 3 write v to r with probability 2^k / (2n) 4 k ← k + 1 5 end 6 return (adopt, r) ``` ## Model * `n` processes `Fin n`, process `p` has input `inp p : V` (any type of values). * One multi-writer register `reg : Option V` (`none` = ⊥). Every scheduled step of a process is one register operation: either the loop test (a read of `r`) or the probabilistic write. * **Probabilistic writes** (the model of Section 2): the `k`-th write attempt (`k = 0, 1, …`) of a process takes effect with probability `attemptProb n k = min 1 (2^k / (2n))`; the coin is flipped atomically with the write step, *after* the adversary has scheduled it. * **Adversary**: adaptive and full-information about the past. An `Adversary` is an arbitrary function of the history (the list of scheduled processes with the outcomes of their coins) and of the current configuration; it returns the process to schedule next, or `none` (an idle step: this lets the adversary stop, i.e. crash, any set of processes). It cannot see coins that have not been flipped yet, because those do not exist yet: the execution is the probability distribution `run inp adv N h c : PMF _` obtained by iterating "the adversary chooses `p`, then `p`'s coin is flipped (if `p` is about to write), then `p` takes its step" for `N` steps. This adversary is at least as strong as the paper's (location-oblivious adversary, which can see memory and pending operations but cannot base the scheduling of a probabilistic write on the outcome of its coin). * Probabilities are those of `PMF` (Mathlib), as `ℝ≥0∞`-valued outer measures. ## Main results * `agreement_prob` — **Theorem 7, probabilistic agreement**: for every adversary and every number of steps `N`, the processes that have returned agree with probability at least `(1 - e^{-1/4}) / 4`. * `individual_work` — **Theorem 7, individual work**: in every execution each process performs at most `2⌈lg n⌉ + 5` register operations (and returns if it performed that many); `attempts_le` — at most `⌈lg n⌉ + 2` loop iterations. * `expected_total_work` — **Theorem 7, expected total work `O(n)`**: at most `7n` (expected number of register operations of all processes, for every adversary and every `N`). * `validity`, `coherence` — **Theorem 7**, validity and coherence (with the predicates of `Papers.PODC2010.ModularConsensus.Basic`). * `attempts_tight` — the bound `⌈lg n⌉ + 2` on the number of loop iterations is attained (`n = 1`), so the sentence "the loop is never executed for more than `⌈lg n⌉ + 1` iterations" of the paper is off by one (its final bound `2⌈lg 2n⌉ + 3 = 2⌈lg n⌉ + 5` is correct and also attained). * `disagreement_possible` — non-vacuity: for `n = 2` some adversary produces disagreement with positive probability. ## Proof method Instead of the paper's argument on the "all-failures path", we use a potential function (a submartingale) `Φ` on configurations: as long as `r = ⊥`, `Φ = g(S)` with `S = ∑ (probabilities of all failed attempts)` and `g(S) = (1 - e^{min(S, 1/4) - 1/4}) / 4`; once `r ≠ ⊥`, `Φ = ∏_{p about to write} (1 - P[p's pending write succeeds])` as long as every returned value equals the content of `r` (and `0` otherwise). `Φ ≤ 1[agreement]`, `Φ(initial) = (1 - e^{-1/4})/4`, and every step does not decrease `Φ` in expectation (`Φ_step`), so `P[agreement after N steps] ≥ E[Φ] ≥ Φ(initial)` (`Φ_le_run`). This avoids the paper's case distinctions (the index `t` may not exist, the execution may stop early). The paper's estimates appear in the step where the first write succeeds: `attemptProb_le_sum` (`2^k/(2n) = 1/(2n) + ∑_{j<k} 2^j/(2n)`, valid also with the `min 1` cap) and `one_sub_sum_le_prod` (union bound). Expected total work uses the potential `Ψ = (operations so far) + (credits 3/2/1/0 per process) + 4n·[r = ⊥]` (`Ψ_step`), using that every write attempt succeeds with probability `≥ 1/(2n)`
