import Papers.PODC2010.MultiVersionSTM.SnapshotProofs /-! # The eager snapshot STM with self-erasing read-only transactions A variant `snapSmall` of the eager snapshot STM (`snapSTM false`, `Snapshot.lean`): its shared memory holds the history *without the events of committed read-only transactions* (`erase h`). A read-only transaction erases its own events when it commits. Under well-formedness the responses are the same as those of `snapSTM false` (`snapResp_erase`), so the two STMs have the same histories (`snapSmall_hist`), and `snapSmall` is valid with the kept versions `keptSmall C = snapKept false (C.mem ())` (`snapSmall_valid`). The point of the construction (used in `Theorem3False.lean`): a solo read-only transaction of `snapSmall` leaves the shared memory unchanged (`erase_append_ro`). Main lemmas: * `latest_filter`: removing events of read-only transactions does not change the latest versions; * `take_findIdx_filter`: the snapshot prefix of a filtered history is the filtered snapshot prefix; * `validates_filter`: the read-set validation of an update transaction only depends on its own events and on the latest versions; * `snapResp_erase`, `snapKept_erase`, `erase_snoc`: the snapshot strategy and the kept versions are the same on `erase h` and on `h`, and `erase` is maintained step by step. -/ namespace Podc.MultiVersionSTM open scoped Classical variable {Tx O P :
