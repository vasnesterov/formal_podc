import Mathlib -- CSLib candidate: synchronous dual-graph radio networks (reliable/unreliable links), collision -- rule CR1, synchronous start, ID-level executions and the broadcast problem. /-! # The dual graph radio network model (Sections 2.1 and 3 of the paper) Kuhn, Lynch, Newport, Oshman, Richa. *Broadcasting in Unreliable Radio Networks.* PODC 2010 (full version: MIT-CSAIL-TR-2010-029). **Networks.** A dual graph network (`DualGraph V`) has nodes `V`, reliable links `E`, all links `E' ⊇ E` (both directed relations), and a source `src` from which every node is reachable in `E`. It is undirected if both relations are symmetric. **Algorithms.** A deterministic algorithm (`Algorithm I S M`) is a family of automata indexed by the process identifiers `I`: an initial state `init i b` (`b` says whether the process holds the broadcast message, i.e. is the source process), a sending function `send : S → Option M` and a transition `trans : S → Rx M → S` on the value received in a round. The broadcast message itself is not part of the state: processes treat it as a black box (Section 3). **Executions.** Processes are placed on nodes by a bijection `π : V ≃ I` (chosen by the adversary). Rounds are synchronous and all processes start in round 1 (synchronous start). In round `t` every process `p` with `send (state p) = some m` sends `m`; the message of the process at node `v` reaches `v` itself, every `E`-out-neighbour of `v`, and an arbitrary further subset of the `E'`-out-neighbours chosen by the adversary (`Adversary`, `Adversary.Admissible`). The adversary may base this choice on the round number and on the set of senders; for deterministic algorithms this is no restriction (an execution is determined by the round, so any history-dependent adversary coincides with one of this form along its execution). **Collision rule CR1.** A process reached by no message receives `⊥` (`Rx.silence`), by exactly one message receives it (`Rx.msg`), and by two or more messages (its own included) receives `⊤` (`Rx.collision`). **ID-level executions.** Since an execution only depends on which *processes* a message reaches, we run algorithms on a `Delivery I` (`D t B j` = processes reached by `j`'s message in round `t` when the set of sending processes is `B`); a node-level adversary is transported along `π` (`toDelivery`), and conversely an ID-level delivery is realised by `fromDelivery`. **Broadcast.** The broadcast message is held initially by the source process. A process becomes *informed* when it receives (as `Rx.msg`) a message sent by an informed process.
