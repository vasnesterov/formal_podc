import Papers.PODC2010.HindsightLinearizability.Invariants import Cslib.Computability.Distributed.SharedMemory.Potential /-! # Theorem 6.4: wait-freedom of `contains` **Theorem 6.4** of the paper: the `contains` operation of the optimistic set algorithm is wait-free, i.e. every invocation of `contains` returns after finitely many steps of its own thread, whatever the other threads do. We state it over infinite executions (`Cslib.SharedMemory.Impl.InfExec`): a thread whose `contains k` stays pending forever takes only finitely many steps (`theorem_6_4`). As in the paper, the proof uses only `ϕ<` (keys strictly increase along links, here via the local invariant `LocInv`: at `test p c`, `p.k < c.k`), `δk` (keys of allocated nodes are immutable, `MemEffect.key_eq`) and the code of `locate`: the key of the node `p` held by the traversal strictly increases and stays below `k`. Formally, we use the lexicographic potential `containsPot` (a phase counter for the steps through the head node `H = 1`, whose key is `-∞`, followed by the distance `k - p.k`), which never increases
