import Papers.PODC2010.HindsightLinearizability.Trace /-! # Lemma 5.4 (Backbone Lemma) as stated is false The paper states: for a temporal backbone `ζ` going through `τ(i₀), …, τ(i_k)` of a shape-legal trace, *there exists a sequence `i₀ = j₀ < j₁ < … < j_k = i_k`* such that `ζ(m)` is a backbone link in `τ(j_m)` and `i₀ ≤ j_m ≤ i_m`. Both the strict inequalities and `j_k = i_k` are wrong: the last link of a temporal backbone need not be a backbone link when it is crossed (this is the whole point of hindsight), and consecutive links may be backbone links only at the same past state. The Hindsight Lemma only gives `j_{m-1} ≤ j_m ≤ i_m`, which is what the paper's own proof ("follows directly from Lemma 5.2") yields and all that is used later (`backbone_lemma` in `Heap.lean`). Counterexample, in an actual execution of the set algorithm (`cexExec`): thread 0 runs `add(5)` (heap `H → a → T` with `a = 2`), then thread 1 runs `remove(5)`. Let `i₀ = 10` be the state just before the atomic section of `remove` and `i₁ = 11` the state right after it. Then `ζ = ⟨H, a⟩, ⟨a, T⟩` is a temporal backbone through `τ(10), τ(11)`: `H.n ↦ a` is a backbone link at `10` and `a.n ↦ T` is a link at `11` (the removed node keeps its successor). But `a.n ↦ T` is a backbone link at `10` only: either requirement `j₁ = i₁` or `j₀ < j₁ ≤ i₁` forces `j₁ = 11`, where `a` is marked and unreachable.
