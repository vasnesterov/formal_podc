Taken literally, a vertex adjacent to several `u ∈ U` only keeps the reduction of the *last* `u` processed, instead of the sum `w₂(v) = ∑_{u ∈ U ∩ N(v)} w(u)` defined in the text of Section 2.1 (and used in the proof of Lemma 2.2). The intended line is `w₁(v) = w₁(v) - w(u)`. We show that with the literal line the induction step of Lemma 2.2 fails, and so does the `Δ`-approximation of Algorithm 1. Graph (`Δ = 2`): edges `a₁v`, `a₂v`, `a₁b`, weights `w(a₁) = 3, w(a₂) = 1, w(v) = 2, w(b) = 3` (vertices `0, 1, 2, 3`). Take `U = {a₁, a₂}`, processed in the order `a₁, a₂`. Literal line 11 gives `w₁ = (0, 0, 1, 0)` (with the closed neighbourhood): `v` keeps weight `2 - w(a₂) = 1`. The recursive call can only pick `U = {v}` and returns `{v}`, which is optimal for `w₁`; line 13 then adds nothing (`a₁, a₂ ∈ N(v)`), so Algorithm 1 returns `{v}` of weight `2`, while `{v, b}` is independent of weight `5 > Δ · 2`.
