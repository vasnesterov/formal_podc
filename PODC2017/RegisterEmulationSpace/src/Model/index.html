import Mathlib import Cslib.Foundations.Data.Nat.Descent /-! # Fault-prone shared memory with servers (Section 2 and Appendix A) Chockler, Spiegelman. *Space Complexity of Fault-Tolerant Register Emulations.* PODC 2017 (arXiv 1705.07212v1). **System.** Clients `C` access base read/write registers `B` (values `W`, initially `A.winit`); each register lives on a server, `δ : B → S`. A client *triggers* a low-level read or write on a register; the operation stays *pending* until a `resp` event applies it to the register (atomically) and delivers its response (the value for a read, an acknowledgement for a write) to the client. A client may have several pending operations (also on the same register). Clients are deterministic state machines (`Alg`): when scheduled (`step c`) a client triggers an operation, returns from its current high-level operation, or does nothing, depending only on its local state. High-level invocations `inv c op` are inputs from the environment and are ignored when the client is busy. Linearizing each base operation at its response is a restriction of the paper's model (where a pending write may take effect earlier); it only removes runs, so hypotheses quantified over all runs become weaker and the lower bounds stronger. The paper itself adopts it in the proof (Assumption 1). **Failures and fairness.** Failures are not events. A failure pattern `(Fc, Fs)` (crashed clients, crashed servers) only enters fairness (`Alg.Fair`): crashed clients take finitely many steps, registers on crashed servers respond finitely often, correct clients are scheduled infinitely often, and every pending operation of a correct client on a register of a correct server eventually responds. Pending operations of crashed clients may still take effect (as in the paper). **Correctness conditions.** `Alg.ObstructionFree δ f Wr`: in every fair run with at most `f` crashed servers in which only the clients in `Wr` (the writers of the emulated `k`-register) invoke writes, a high-level operation of a correct client that is not concurrent with operations of other correct clients returns. `Alg.SeqSafe v₀ Wr`: in a *sequential* run (high-level operations never overlap) a read returns the value of the last write (`v₀` if none). This is implied by the paper's WS-Safety (in a sequential history every read is a read not concurrent with any write of a write-sequential history), so the lower bounds assuming only `SeqSafe` are stronger than the paper's.
