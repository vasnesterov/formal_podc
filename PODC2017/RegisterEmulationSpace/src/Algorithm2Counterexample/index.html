With 1-based `i` the set `R_0` gets `z - 1` writers and the last set gets one writer more than it is sized for (and if `z ∣ k`, client `c_k` is mapped to the non-existent set `R_m`). Smallest instance: `n = 4`, `f = 1`, `k = 3`, so `z = 2`, `m = 2`, `|R_0| = 4`, `|R_1| = (k - ⌊k/z⌋ z) f + f + 1 = 3`; clients `c_2, c_3` both use `R_1 = {a, b, c}` (registers 4, 5, 6 on servers 0, 1, 2), which only accommodates one writer. Sequential run: 1. `c_2` writes `1`: `(1,1)` lands on `a, b`; its write on `c` stays pending; `c_2` returns. 2. `c_3` writes `2` (it reads timestamp 1): `(2,2)` lands on `c` and `a`, its write on `b` stays pending; `c_3` returns. 3. `c_2`'s old write `(1,1)` lands on `c`.
