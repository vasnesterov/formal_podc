Values are *uniquely identifiable* (Section 3): the value that transaction `j` writes to key `k` is represented by `some j`, the initial value `⊥` by `none`. A transaction writes each key at most once, so `Op.write k` carries no value. * `TxnSet`: the transactions with their operations in program order (what the clients observe: the value returned by every read) and the committed ones (`𝒯`). * `Execution`: a permutation `e` of `𝒯`; its states `s_0, …, s_n` are indexed by positions (`Execution.state i`), the parent state of `T` is `s_{idx T}`, the state it generates `s_{idx T + 1}`. * Read states (Definition 2), `PREREAD` (Definition 3), `COMPLETE` (Definition 4), the commit tests of Table 1 for serializability, snapshot isolation, read committed, read uncommitted and parallel snapshot isolation (Definition 6), and `TxnSet.Satisfies` (Definition 5). -- CSLib candidate (together with `Adya.lean`): a transactional key-value history model. -/ set_option linter.unusedSectionVars false namespace Podc.SeeingIsBelieving open Relation /-- Operations of a transaction.
