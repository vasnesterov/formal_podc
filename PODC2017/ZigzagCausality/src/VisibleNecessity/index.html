The necessity direction of Theorem 4 is false in general (`Counterexample.lean`). We prove it in the two cases needed for timed coordination (Theorem 5), for flooding full-information protocols: * `visible_zigzag_necessity_early` — `θ₁ = σ₁` is a basic node of `past(r, σ)` and `θ₂` is any σ-recognized node (this covers `Early⟨b --x--> a⟩`, with `θ₁ = σ`, `θ₂ = σ_C · A`); * `visible_zigzag_necessity_late` — `θ₂ = σ₂` is a basic node of `past(r, σ)` and `θ₁` is any σ-recognized node (this covers `Late⟨a --x--> b⟩`, with `θ₁ = σ_C · A`, `θ₂ = σ`); * `visible_zigzag_necessity_basic` — both nodes are basic nodes of the past. **Proof.** Instead of longest paths in the extended bounds graph `G_E(r, σ)` (Definition 16) we use directly the *zigzag potential* `Dz v = max {wt(Z) | Z σ-visible zigzag from θ₁ ending at v}` of the past nodes `v` (it is bounded by Theorem 1 in `r`; this replaces Lemmas 10–16, the conversion of `G_E`-paths into zigzags). The fast timing (Definition 23) is `T v = C + Dz v` for the nodes reachable from `θ₁` by such zigzags and `T v = timer_r(v)` for the others, for a large constant `C`. Every constraint of `G_E(r, σ)` from a reachable node leads to a reachable node (appending one fork to a zigzag: `zreach_recv`, `zreach_recv_back`, `zreach_local`, `zreach_esc`), so `T` satisfies the constraints (`zT_good`), and the fast run `FData.run` (Definition 24, Lemma 18) realizes it. In the fast run the arrival time of the chain of the other node is computed explicitly (`FData.chain_first`, `FData.chain_slow`); each of its possible values is the weight of a σ-visible zigzag (this
