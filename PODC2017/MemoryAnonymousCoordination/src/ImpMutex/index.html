import Papers.PODC2017.MemoryAnonymousCoordination.ImpCommon import Cslib.Computability.Distributed.SharedMemory.Mutex /-! # Theorem 6.2: no deadlock-free mutual exclusion with unnamed registers for unknown `n` Taubenfeld, *Coordination Without Prior Agreement*, PODC 2017, Section 6.2. There is no deadlock-free mutual exclusion algorithm using unnamed read/write registers when the number of processes is not a priori known (`theorem_6_2`). The same covering argument shows that `n ≥ 2` processes need at least `n` unnamed registers (`mutex_card_lt`; for named registers this is the classical Burns–Lynch bound). Mutual exclusion and deadlock-freedom are CSLib's `Impl.MutualExclusion` and `Impl.DeadlockFree` (fair, client-well-formed infinite executions; processes may stay in the remainder section forever). For a finite but unknown number of processes, deadlock-freedom is only required of executions with finitely many participants (`DeadlockFreeFin`, used in `theorem_6_2`); `theorem_6_2_unbounded` is the corollary for `Impl.DeadlockFree`. ## Deadlock-freedom used as a progress guarantee `df_progress`: if, after a client-well-formed execution in which nobody is in the critical section, exactly the processes of `ps` are pending (all trying), then running them in round-robin order some process of `ps` eventually returns from `lock()`. Otherwise the round-robin execution is fair and client-well-formed and contradicts deadlock-freedom. -/ open Cslib.SharedMemory Impl namespace Podc.MemoryAnonymousCoordination section Regions variable
