import Papers.PODC2011.SymmetryBreakingTasks.Basic /-! # From the `(n-1)`-slot task to `(n+1)`-renaming (Section 6, Figure 2, Theorem 12) The algorithm of Figure 2 (code for `p_i`): 1. `my_slot ← KS.slot_request()` (an object solving the `(n-1)`-slot task `⟨n, n-1, 1, n⟩`); 2. `STATE[i] ← ⟨my_slot, id_i⟩`; `snapshot` of `STATE`; 3. if no other process with the same slot is in the snapshot, return `my_slot`; 4. otherwise, with `p_j` such a process, return `n` if `id_i < id_j` and `n + 1` otherwise. **Execution model.** Since the snapshot object is atomic and `STATE[i]` is written once, an execution is determined, as far as the decisions are concerned, by * the slots `s : Fin n → Fin (n - 1)` returned by the `KS` object (in an execution where every process decides, `s` is an output vector of the `(n-1)`-slot task); * the linearization times `w i` of the write of `p_i` and `r i` of its snapshot, with `w i < r i` and all write/snapshot times distinct; the snapshot of `p_i` contains `STATE[j]` iff `w j < r i`. Names are `0, …, n` (the paper's `1, …, n+1`): slots are `0, …, n-2`, and the paper's names `n` and `n + 1` are `n - 1` and `n`. Validity (Definition 1) only constrains executions in which every process decides, and decisions are write-once, so it suffices to check those executions; wait-freedom is obvious (straight-line code). -/ namespace Podc.SymmetryBreakingTasks.SlotRenaming open Finset variable {n : ℕ} /-- The name returned by `p_i` in Figure 2 (`0`-indexed). -/ noncomputable def newName (id : Fin n → ℕ) (s : Fin n → Fin (n - 1)) (w r : Fin n → ℕ) (i : Fin n) : Fin (n + 1) := open Classical in if h : ∃ j, j ≠ i ∧ w j < r i ∧ s j = s i then if id i < id h.choose then ⟨n - 1, by omega⟩ else ⟨n, by omega⟩ else ⟨s i, by have := (s i).isLt;
