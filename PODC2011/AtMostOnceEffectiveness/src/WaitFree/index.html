import Papers.PODC2011.AtMostOnceEffectiveness.Progress /-! # Lemma 4.3: `KK_β` is wait-free (for `β ≥ m`) We show that every run of `KK_β` takes only finitely many steps (`lemma_4_3`): there is no infinite execution at all, fair or not (an infinite execution is fair for the set of processes that take finitely many steps, so this is the paper's "no infinite fair execution"). Proof outline (following the paper, with one repair, see below). Suppose a run takes infinitely many steps; let `S` be the set of processes stepping infinitely often (`S ≠ ∅`). 1. The lines of `done` only grow and are bounded, so after some time `K0` they are constant, and the processes outside `S` take no more steps (`After`). Then no process of `S` is ever in status `do`/`done`/`end` after `K0` (`After.status_ok`): its next step would perform or record a job, or it could not step. 2. Every process of `S` keeps cycling `compNext → setNext → gatherTry* → gatherDone* → check → compNext` (a measure `mu` increases at every step except `check → compNext`). 3. Stable predicates (once true after `K0`, true forever): `DONE_p = recorded` (all recorded jobs); `TRY_p` contains the (frozen) `next` values of all processes outside `S` (`TryFull`); `NEXT_p` and `next_p` have rank `≥ k_p` in `POOL` (`GoodNext`), where `POOL = (J \ recorded) \ {next_q | q ∉ S}` and `k_p = kIdx m p |J \ recorded|`. 4. For the smallest `p₀ ∈ S`, the element `x₀` of rank `k_{p₀}` of `POOL` is never in `TRY_{p₀}` (other processes of `S` hold jobs of higher rank since `kIdx` is strictly increasing in `p`; processes outside `S` hold jobs outside `POOL`), so `p₀` eventually picks `x₀` and passes `check` — contradiction with 1. **Repair.** The paper defines `POOL_α = J \ (J_α ∪ STUCK_α)` with `STUCK_α` the jobs held by *crashed* processes only and claims that no process other than `p₀` ever holds `x₀`. A process that *terminated* (status `end`) keeps its last value in `next`, which may be an unperformed job of `POOL_α`, possibly `x₀`. We exclude the values held by all processes outside `S` (crashed or terminated) from `POOL`; with this change the argument goes through. -/ set_option linter.unusedSectionVars false namespace
