import Papers.PODC2011.AtMostOnceEffectiveness.Progress /-! # The adversary of Theorem 4.4: `KK_β` may perform only `n − (β + m − 2)` jobs For `m ≥ 1` processes, `β ≥ m` and `n ≥ β + m − 1`, we construct a fair run of `KK_β` with `m − 1` crashes in which at most `n − (β + m − 2)` jobs are performed (the upper-bound half of Theorem 4.4 of the paper). We write the number of processes as `m + 1`; the survivor is the last process `s = m` (`Fin.last m`), the others `0, …, m − 1` crash. 1. **Phase 1** (times `0, …, 2m − 1`): each process `i < m` takes two steps, `compNext` and `setNext`. Since `FREE_i = {1, …, n}` and `TRY_i = ∅`, it announces the job `k_i = kIdx (m + 1) i n` (`kj`), the element of rank `k_i` of `{1, …, n}`. It is then never scheduled again (it crashes in status `gatherTry`). 2. **Phase 2** (times `≥ 2m`): the survivor is scheduled whenever it has not terminated. Because `n ≥ 2m + 1`, `i ↦ k_i` is strictly increasing on `0, …, m`, so `STUCK = {k_i | i < m}` has `m` elements and does not contain the survivor's first choice `k_m`. In every iteration of the survivor, `TRY_s = STUCK` is gathered, the `done` lines of the crashed processes are empty, and the survivor's job lies outside `STUCK`. A job is chosen only while `|FREE_s \ TRY_s| ≥ β` (or as the first job), so the survivor's jobs never exceed `n − m − (β − 1)` (invariant `Solo`). The run is fair with crash set `{0, …, m − 1}`, since at every time of phase 2 the survivor either steps or has terminated. Wait-freedom (termination) is not needed for the upper bound; with it, the run performs exactly `n − (β + m − 2)` jobs (`exists_fair_run_do_eq`, by Lemma 4.2). -/ set_option linter.unusedSectionVars
