import Mathlib /-! # The at-most-once problem: model Sotirios Kentros, Aggelos Kiayias. *Solving the At-Most-Once Problem with Nearly Optimal Effectiveness.* PODC 2011 (full version: arXiv 1107.2990v2, TCS 2013), Section 2. `m` asynchronous crash-prone processes (`Fin m`) communicate through atomic read/write registers (`R`, values in `V`) and perform jobs `1, …, n` (action `do_{p,j}`). Every process runs a *deterministic* program: in local state `l` it either reads a register, writes a register, performs a job, takes an internal step, or has terminated (`Step.halt`: no locally controlled action is enabled). This covers the I/O-automaton formalisation of the paper for deterministic algorithms (each process has exactly one enabled locally controlled action in every state). * A configuration records the local states, the memory and a ghost `log` of all `do` actions. * Finite executions are lists of process identifiers (`runFrom`); `Reachable` is the inductive version. * Infinite executions (`Run`) may *stutter* (`ev k = none`), so finite executions followed by stuttering are runs too; a run is `Fair F` (the processes of `F` crash) if every process outside `F` takes a step at infinitely many times or terminates. Crashes are therefore fairness exemptions rather than events: a crashed process simply stops being scheduled (the paper's `stop_p`). * `Run.Do n` is the number of jobs in `{1, …, n}` performed in the run (Definition 2.1), `Alg.AtMostOnce n` is Definition 2.2, `Alg.effectiveness n f` is Definition 2.4 (the infimum of `Do` over the fair runs with at most `f` crashes). -/ set_option
