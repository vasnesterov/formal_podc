Distributed k-Core Decomposition — PODC 2011

Alberto Montresor, Francesco De Pellegrini, Daniele Miorandi. Distributed k-core decomposition. PODC 2011 (brief announcement). DOI 10.1145/1993806.1993836. Formalized version: arXiv 1103.5320 v2 (full version); numbering follows it. Copy of the paper: paper.pdf.

DOI · arXiv · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. The algorithm is correct: estimates never increase, never drop below the coreness and converge to it, in the one-node-per-host version (synchronous and asynchronous) and in the many-nodes-per-host version, and the bounds of Theorem 4 (1 + Σ(d − k)), Theorem 5 (N) and Corollary 1 (N − K + 1) hold. The liveness proof of Theorem 3 fails in its induction step and needed a new fixpoint argument. The bound N − K + 1 is not met exactly as claimed: the "worst-case" family of Fig. 3 needs N − 2 rounds, within 2 of the bound for this family, and no other result depends on this.

Mistakes in the paper

⚠️ Introduction and §6 (the upper bound "is met exactly")

The Introduction says §4 "describes a worst-case graph that requires exactly" N − K + 1 rounds, and §6 calls the upper bounds "strict for specific worst-case examples", but for the Fig. 3 family K = 1, so the bound is N, while the family needs N − 2 (worstGraph_execTime); even the paper's own count N − 1 misses it.

Impact. Exact tightness is not saved. What is proved is tightness up to an additive 2 for this family, which still shows that time grows linearly in N; the theorems are unaffected.

Details

An exhaustive search over all graphs with N ≤ 8 nodes (computational, not formalized) finds a maximum execution time of N − 2 for 4 ≤ N ≤ 8. So the family is optimal there, and the bound N is never reached.

🔧 §4.2, Fig. 3 (the "worst-case" family)

The paper claims the family of Fig. 3 needs exactly N − 1 rounds for every N ≥ 5, but in the paper's own synchronous model it needs N − 2 (worstGraph_execTime).

Impact. Off by one, not a typo; changing the constant keeps "close to the bound" and linear time, and the theorems are unaffected.

Details

The family: hub N joined to all nodes but N − 3, a path 1 – 2 – … – N − 1, and the chord (N − 3, N − 1). We use the paper's own definition of execution time; that accounting gives the 3 rounds of the Fig. 2 example. Round 1 broadcasts the degrees; already in that round node 2 drops to 2 and the hub to 3. Nodes 3, …, N − 4 then drop one per round, and two more rounds settle N − 3, N and then N − 2, N − 1. The paper counts the initial round twice. (worstGraph_execTime)

🔧 Corollary 2 (message complexity)

The bound Σ_v d(v)² − 2M counts only update messages and ignores the initial broadcast of the degrees, so for a single edge it gives 0 while 2 messages are sent (corollary_2_false).

Impact. The bound holds for update messages, which is what the proof counts, and O(∆ · M) stands.

Details

Algorithm 1 sends every degree to every neighbour at initialization, which is 2M messages.

Repair

We prove the bound for update messages, and Σ_v d(v)² for all messages. (corollary_2_updates, total_messages_le)

✏️ Slips

  • In Theorem 1's proof (⇐), "d_{G(U)}(v) ≥ k + 1" should be ≥ k.

  • Algorithm 2 returns 1, not 0, when no neighbour has estimate ≥ 1; this is harmless, because it never happens in a run.

  • Algorithm 5 (§3.2.1) builds S from all boundary estimates every round without testing changed[u], so as printed it never becomes silent; the test is in Algorithm 3.

  • The Fig. 3 family has diameter 2 (not 3) for N = 5, 6.

Typos

  • In Theorem 2's proof, "|V₁| = k(u)" should be k(u₁), and "⟨u₂, core(u₃)⟩" should be ⟨u₃, core(u₃)⟩.

  • In Theorem 4's proof, "at most one message is broadcast per round" is loose wording for "at least one estimate decreases in every round but the first".

Proof gaps in true statements (2)Theorem 3 · Theorem 5

🛠️ Theorem 3 (liveness, induction step)

The proof builds a cycle of stuck nodes of coreness k and assumes each of them has k neighbours of coreness > k, which nothing guarantees.

Impact. Statement true; proved by a fixpoint argument (le_coreness_of_le_hIndex, theorem_3).

Details

The proof says "the remaining f − 1 ≥ k neighbors of u₁ have coreness k + 1 or more". Such a node may have many neighbours of coreness exactly k.

Repair

A stable estimate vector c with c(u) ≤ h-index of the neighbours' c lies below the coreness, since {v : c(v) ≥ c(u)} induces minimum degree ≥ c(u). (le_coreness_of_le_hIndex, theorem_3)

🔧 Theorem 5 (execution time ≤ N)

The proof says "the execution time equals T + 1", which is off by one in the model of §4.2, and its compensating argument for T ≤ N − 1 skips the case where the last two wrong nodes become correct in consecutive rounds.

Impact. Statement true; proved via the progress claim (progress, corollary_1, theorem_5).

Details

T is the first round in which all estimates are correct. In the model of §4.2 the execution time equals T: in Fig. 2, T = 3 and the time is 3. (With the indexing of the Fig. 2 narrative, T + 1 is right, and the lost round is instead that the nodes of minimal degree are correct already before round 1.) To compensate, the proof adds an argument for T ≤ N − 1 about the last two wrong nodes, which is incomplete.

Repair

The real content is the progress claim: in each round some wrong node of minimal coreness becomes correct. With the correct accounting this gives execTime ≤ N − K + 1 ≤ N at once. The paper argues the progress claim only informally; we prove it. (progress, corollary_1, theorem_5)

The formalizationmodel, Lean names of the results, trust

Model.

  • A finite simple graph G : SimpleGraph V. Definitions 1–2 are formalized literally: IsKCore is the maximum induced subgraph of minimum degree ≥ k, kCore is its unique witness, and coreness is the largest k with u ∈ kCore k. Estimates live in ℕ∞, with ⊤ = +∞.

  • Synchronous rounds (§4.2), Algorithm 1 at message level (Run.lean). Round 1 broadcasts the degrees. In each later round a node processes the previous round's messages with Algorithm 1's handler, which calls Algorithm 2's computeIndex after every lowering of est. The messages are processed in an arbitrary order, and the node broadcasts iff changed. All results hold for every order. Execution time is the number of rounds in which some node broadcasts, as in the paper.

  • Asynchronous Algorithm 1 (Async.lean), used for Theorems 2–3 in the paper's general setting. Reliable channels with arbitrary delays and reordering, no crashes, and arbitrary scheduling of the periodic repeat every δ block. Liveness assumes fairness: every node ticks infinitely often and every message is eventually delivered.

  • One host, many nodes (MultiHost.lean): Algorithms 3–4 in synchronous rounds with an arbitrary node-to-host assignment. Each host runs improveEstimate to a local fixpoint. The result is the greatest quiescent vector below the input, so it does not depend on the pass order, and processing messages one at a time gives the same state as processing them together. Hosts then broadcast the changed estimates of their own nodes. Messages are delivered to all other hosts, following the text of §3.2. Besides safety and liveness, we prove that after round s + 1 the estimates are at most those of the one-to-one algorithm. So the one-to-many version needs at most as many rounds.
