import Papers.PODC2011.KCoreDecomposition.Algorithm import Cslib.Foundations.Data.Nat.Descent /-! # Asynchronous execution of Algorithm 1: Theorems 2 (Safety) and 3 (Liveness) Montresor, De Pellegrini, Miorandi, *Distributed k-Core Decomposition*, PODC 2011 (arXiv 1103.5320v2), §3.1 and §4.1. ## Model (one host = one node) * **Global state** `GState`: the local states `st : V → NodeState V` of Algorithm 1 and the multiset `net` of messages in transit, each a triple `(sender, receiver, value)`. Channels are reliable but have arbitrary delays and may reorder messages (no FIFO assumption); no crashes. * **Initial state** `initGState`: every node is in `initState` (`core = d(u)`, `est = +∞`, `changed = false`) and the initialization broadcast `⟨u, d(u)⟩` to all neighbours is in transit. * **Actions** (`Action`, semantics `perform`): - `deliver m`: if `m ∈ net`, one copy of `m` is removed and the receiver runs the handler `on receive ⟨sender, value⟩` (`receive` from `Algorithm.lean`). A `deliver m` with `m ∉ net` is a **no-op** (so schedules need not be state-dependent). - `tick u`: the periodic block `repeat every δ`: if `changed`, send `⟨u, core⟩` to all neighbours and reset `changed`; otherwise a no-op. The round duration `δ` plays no role in the proofs: a tick is an arbitrary point at which the node's periodic block runs. * **Executions** `Async.run G act`: the sequence of global states produced by an arbitrary schedule `act : ℕ → Action V` (the interleaving of all events, chosen by an adversary). * **Fairness** `Fair G act`: every node ticks infinitely often, and every message in transit at time `t` is delivered at some time `t' ≥ t` (i.e. `deliver m` is performed while `m` is in transit; identical copies are indistinguishable). ## Results * `Async.theorem_2` (**Safety**): in *every* execution, `core(u) ≥ k(u)` at all times. Also `coreness_le_est`, `coreness_le_of_mem_net` (all estimates and in-transit values are safe) and `core_anti` (`core` never increases). * `Async.theorem_3` (**Liveness**): in every *fair* execution there is a time after which `core(u) = k(u)` for all `u`. * `Async.exists_fair`: fair schedules exist (any schedule in which every action occurs infinitely often is fair, `fair_of_frequently`), so Theorem 3 is not vacuous. ## Proof Both theorems follow from one inductive invariant `Inv` of all reachable states: `core ≤ d`, `core ≥ k` (safety), `core_v ≤ est_u[v]` and `core_v ≤ value` of every message from `v`, `computeIndex(est_u, u, core_u) = core_u` (every node's `core` is a fixpoint of its own estimates), and, for every edge `(v, u)`: `est_u[v] = core_v`, or a message `⟨v, core_v⟩` to `u` is in transit, or `changed_v`. Liveness then avoids the paper's induction on the coreness: cores are non-increasing, hence eventually constant (`c∞`); after one more tick of every node all `changed` flags stay `false`; by fairness every edge then gets `est_u[v] = c∞(v)` forever; the fixpoint invariant gives `step G c∞ = c∞`, and `eq_coreness_of_step_eq` (with safety) gives `c∞ = k`. ## Remarks on the paper's proofs * The paper never states the fairness assumptions Theorem 3 needs (reliable eventual delivery, every node runs its periodic block infinitely often); without them liveness fails trivially. No FIFO assumption is needed (est only ever takes minima). * The liveness proof (induction on `k(u)` with cycle arguments) silently relies on the fact that a node's `core` is always a fixpoint of `computeIndex` on its current estimates (the `fix` invariant), i.e. that once the final estimates have arrived, `u` has already lowered its `core` accordingly. This holds because `computeIndex` is rerun after every decrease of an estimate. -/ open Finset Filter set_option linter.unusedSectionVars false namespace KCoreDecomposition variable {V : Type*} [Fintype V] [DecidableEq V] (G : SimpleGraph V) [DecidableRel G.Adj] /-!
