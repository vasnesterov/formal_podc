import Papers.PODC2011.KCoreDecomposition.Trajectory /-! # One host, multiple nodes (§3.2, Algorithms 3 and 4) in synchronous rounds Montresor, De Pellegrini, Miorandi, *Distributed k-Core Decomposition*, PODC 2011 (arXiv 1103.5320v2), §3.2. The paper proves safety and liveness only for the one-to-one version and says (§4) that "the results can be easily extended to the one-to-many case". Here we do this extension for the synchronous round model of §4.2, and prove in addition that the one-to-many version is never slower (in rounds) than the one-to-one version. ## Model * A finite set of hosts `H` and an assignment `h : V → H`; host `x` is responsible for `own h x = {u | h u = x}` (the paper's `V(x)`). * Host state `HostState` (Algorithm 3): `est : V → ℕ∞` (`⊤` = `+∞`; one entry per node, entries of nodes that are neither own nodes nor neighbours of own nodes are never read) and `changed : V → Bool`. * `improveEstimate G L s` is Algorithm 4: passes over the list `L` of own nodes (an **arbitrary order**, duplicates allowed) doing `k ← computeIndex(est, u, est[u]); if k < est[u] then est[u] ← k, changed[u] ← true`, repeated until a pass changes nothing. It is defined by well-founded recursion (the measure `pot` decreases at each pass that changes something); `improvePass_improveEstimate`: the last pass changes nothing (termination of the `while` loop). * `improveEstimate_isGreatest`: the result is the **greatest** vector below the input that is quiescent on `L` (`Quiescent`: no own node can improve its estimate). Hence it does not depend on the order of `L` (`improveEstimate_congr`) and processing messages one at a time with an `improveEstimate` after each one (as in Algorithm 3) gives the same state as processing them all and calling `improveEstimate` once (`receiveSeq_improveEstimate`). * Messages are sets `S` of pairs `(v, k)`; receiving `S` performs `foreach (v, k) ∈ S: if k < est[v] then est[v] ← k`, i.e. `est[v] ← min(est[v], min_{(v,k)∈S} k)` (`receive`). * Synchronous rounds (`run G h ord r` is the global state at the end of round `r + 1`): - round 1: `est[v] = d(v)` for own `v`, `+∞` otherwise; `improveEstimate`; send all own estimates (`allMsg`); reset `changed`; - round `r + 2`: receive all sets sent in round `r + 1` by the **other** hosts (broadcast policy of Algorithm 3; only the senders' own nodes appear in them), `improveEstimate`, send `S = {(u, est[u]) : u own, changed[u]}` (`changedMsg`; `S = ∅` means nothing is sent), reset `changed`. All messages of a round are processed and then `improveEstimate` is called once; `run_succ_host_eq_receiveSeq` shows this is the same as Algorithm 3's per-message handler, for every order of the messages. - The pass order of host `x` is `ord x`, any list whose members are exactly the own nodes (`hord`); `run_congr_ord`: the run does not depend on it. No failures, reliable channels. Algorithm 5 (point-to-point policy) is not modelled; as printed it sends all boundary estimates to every neighbour host in every round, without testing `changed[u]` and without resetting it, so it never becomes silent. The run is a total deterministic function of `(G, h, ord)`, so the theorems below are about actual executions and are not vacuous. ## Results * `safety` (Theorem 2): every entry of `est` at every host in every round is `≥ k(v)`; `safety_sent`: so is every value in every message; `ownEst_ne_top`: own estimates are finite. * `ownEst_le_traj` (speed comparison): the estimate of `u` at its host at the end of round `s + 1` is `≤ traj G s u`, the estimate of the one-to-one algorithm at the end of round `s + 1` (`Run.run_spec`). Hence `liveness`: from round `stab G + 1` on (the round at which the one-to-one version is correct), every host knows the exact coreness of its own nodes. * `est_eq_coreness`, `sent_eq_empty`, `theorem_3_multiHost` (Theorem 3): from round `stab G + 2` on every entry of every host is the coreness and no host sends anything. -/ open Finset set_option linter.unusedSectionVars false namespace KCoreDecomposition namespace MultiHost variable {V : Type*} [Fintype V] [DecidableEq V] (G : SimpleGraph V) [DecidableRel G.Adj] /-! ### Host state and Algorithm 4 -/ /-- The variables of a host in Algorithm 3. -/ @[ext] structure HostState (V : Type*) where /-- `est[v]`: the most up-to-date estimate of the coreness of `v` (`⊤` = `+∞`) -/ est : V → ℕ∞ /-- `changed[v]`: the estimate of the own node `v` changed since the last broadcast -/ changed : V → Bool /-- `computeIndex(est, u, est[u])`, the value computed in the loop body of Algorithm 4. -/ noncomputable def newEst (e : V → ℕ∞) (u : V) : ℕ := computeIndex G e u (e u).toNat /-- The body of the `foreach` loop of Algorithm 4, for node `u`: `k ← computeIndex(est, u, est[u]);
