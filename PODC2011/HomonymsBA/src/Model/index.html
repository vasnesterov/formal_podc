Decisions are read off the state (`decide s`). A process also receives its own message. * *Numerate* processes see the multiset; *innumerate* processes only see the underlying set: `Algorithm.Innumerate` (the transition depends only on the set of received pairs). * A `Run` is the adversary's choice: the identifier assignment, the (static) Byzantine set, the inputs, the global stabilization round `gst`, which messages between correct processes are lost (`drop`, only before `gst`), and the multiset of pairs that the Byzantine processes deliver to each process in each round (`adv`; every pair must carry the identifier of some Byzantine process: identifiers cannot be forged). States are computed (`Run.st`). * *Restricted* Byzantine processes send at most one message per recipient per round: at most `#{b ∈ byz | id b = j}` pairs tagged `j` per recipient and round (`Run.Restricted`). * *Synchronous* runs have `gst = 0` (no loss); *partially synchronous* runs (the basic model of Dwork, Lynch and Stockmeyer) lose finitely many messages, i.e. none from round `gst` on. Byzantine agreement (`Run.BA`): termination, agreement (also for `p = q`: a correct process never changes its decision) and validity (if all correct processes have input `v`, only `v` is decided). An algorithm *solves* BA for `(n, ℓ, t)` if this holds in every admissible run of every `n`-process system with `ℓ` identifiers and at most `t` Byzantine processes, whatever the identifier assignment
