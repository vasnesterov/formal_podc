import Papers.PODC2011.CoordinatedConsensusDynamic.UpperBounds /-! # The dynamic-diameter-based protocol (Section 6, after Lemma 6.3) * `DiamLit`: Definition 3 read literally ("for all `t' ≤ t` and `u, v`: `(u, max{0, t' - D}) ↝ (v, t')`"). At `t' = 0` this demands `(u, 0) ↝ (v, 0)`, i.e. `u = v`, so **no execution with `n ≥ 2` has any finite dynamic diameter** (`not_diamLit`). * `DiamUpTo`: the corrected definition (only `t'` with `D ≤ t' ≤ t`). * `diamProtocol`: at time `n - kΔ - 1` a node decides `f(x̄)` if it knows the input assignment `x̄` and knows that, for some `D` with `(k-1)D ≤ n - kΔ - 1`, the graph had dynamic diameter `≤ D` up to time `(k-1)D`. It is an instance of the approximate `Δ`-ladder (`diamProtocol_solves`). * Running time: `diamProtocol_decides` — in an execution of dynamic diameter `D` (up to time `kD`) every node has decided by `n - kΔ - 1` whenever `k(D + Δ) < n` (and `k ≤ kmax`); `diamProtocol_time` — hence by time `t < nD/(D+Δ) + Δ`.
