Coordinated Consensus in Dynamic Networks — PODC 2011

Fabian Kuhn, Yoram Moses, Rotem Oshman. Coordinated Consensus in Dynamic Networks. PODC 2011. DOI 10.1145/1993806.1993808. Formalized version: the 10-page proceedings version (no full version exists); numbering follows it. Copy of the paper: paper.pdf.

DOI · PDF · All differences · Lean source · GitHub

Verdict: 🛠️ Hard fix. All the bounds survive, and most hold as printed or after a local change: Lemma 3.1 (the knowledge test for "I have heard from everybody"), Theorem 5.1 (nothing non-trivial is common knowledge before time n − 1 with known n, or n with unknown n, so simultaneous consensus needs exactly n − 1, resp. n, rounds), Theorem 6.1, Lemmas 6.2–6.4 and Theorem 6.7 (the static-line lower bound n − O(Δ^{0.28} n^{0.72})). The lower bound Ω(nD/Δ) of Theorem 6.8, one of the results the abstract closes on, is only a sketch that never specifies its graph H; we had to supply a new construction of H and the walk. Theorem 4.1, the running-time claim of the dynamic-diameter protocol (its final bound nD/(D+Δ) + Δ holds) and Lemma 6.5 are false as printed, each with a local fix.

Mistakes in the paper

🔧 Theorem 4.1 (quantifier order)

Theorem 4.1 claims one bit i such that, in every execution with all inputs i and the upper bound 2n, no node decides before hearing from everybody, but the bound 2n reveals n, so a correct algorithm may favour 0 for some sizes and 1 for others (theorem_4_1_literal_false).

Impact. No single bit works for all network sizes.

Details

Counterexample: decide b = [⌊N/2⌋ odd] as soon as an input b is heard, else decide ¬b at time N − 1. This is a correct comparison-based consensus algorithm for every valid bound N ≥ n. It decides at time 0 in the all-0 execution with n = 2 and in the all-1 execution with n = 3. The stitching proof tacitly assumes that both bad executions have the same size.

Repair

The per-n version ("for every n there is an i") and its proof are correct (theorem_4_1).

🔧 Running time of the dynamic-diameter protocol (§6)

The paper says nodes can stop at n − kmax·Δ − 1 once kmax ≥ ⌊n/(D+Δ)⌋, but level k fires only when k(D+Δ) ≤ n − 1; a counterexample is the static graph on 6 nodes with D = 2, Δ = 1 (diamProtocol_counterexample_strict).

Impact. Only the intermediate claim fails; the final bound t < nD/(D+Δ) + Δ is still true (diamProtocol_decides, diamProtocol_time).

Details

The paper's side condition (k−1)D < n − kΔ − 1 is necessary but not sufficient. To know that the diameter was ≤ D up to time (k−1)D, a node must hear every node's state at that time, which takes until kD. The paper is inconsistent about the side condition: the rule says (k−1)D ≤ n − kΔ − 1, and the later remark says <.

  • With ≤, the 4-clique with D = Δ = 1, kmax = 2 is a counterexample: nobody decides at time 1, because a node cannot exclude that round 1 was a star centred at itself (diamProtocol_counterexample).

  • With the strict < and D = 1, the paper's condition coincides with the correct one, so a counterexample needs D ≥ 2. One exists: n = 6, D = 2, Δ = 1, kmax = 2, and the static graph with edges 01, 02, 03, 14, 24, 35, 45 (diameter 2). Node 3 cannot decide at time 3: it cannot exclude an execution in which node 2 has not heard from node 5 by time 3 (diamProtocol_counterexample_strict).

Repair

Use the condition k(D+Δ) ≤ n − 1 and kmax ≥ ⌊(n−1)/(D+Δ)⌋.

🔧 Lemma 6.5 (wrong node)

The node that cannot distinguish the cycle-prefix from the path-prefix execution is u_{k+s+1} (the start of P_{k+s}), not u_{k+s−1} (lemma_6_5_paper_node_false).

Impact. The wrong index is repeated in the statement, the proof and Figure 2, but later uses need only some node.

Details

In the instance n = 6, k = 0, s = 2, a = 1, b = 2, t = 3, u_1 does distinguish.

Repair

Corrected index: lemma_6_5.

✏️ Slips

  • Lemma 6.5, case s < 0: the hypothesis must be a + b < n − |s| (lemma_6_5_neg_false). This case is never used: only s ≥ 0 is used later.

  • Definition 3 (dynamic diameter) is vacuous as written: "(u, max{0, t'−D}) ↝ (v, t') for all t' ≤ t" fails at t' = 0, so no graph with two or more nodes has a dynamic diameter (not_diamLit). Read literally, the dynamic-diameter protocol never decides early. The evident fix quantifies only over t' ≥ D (DiamUpTo).

  • The abstract's min{O(nD/Δ), …} drops the additive Δ of the bound nD/(D+Δ) + Δ printed in §6, which matters when Δ is large: for Δ ≥ n the protocol never decides before n − 1 (diamProtocol_eq_none_of_le).

  • Lemma 6.3 never states the level-0 rule.

  • Lemma 3.1 holds only for unknown n (implicit in the text).

  • Theorem 6.7's proof writes log₂ e for log₂ 3.

Typos

  • Lemma 6.2's proof drops a factor Δ, and its two conditions on Δ differ.

Proof gaps in true statements (1)Theorem 6.8

🛠️ Theorem 6.8 (graph H and walk unspecified)

The proof is only a sketch that never specifies its graph H or the O(t/D)-step walk.

Impact. We supply H and the walk, and the bound Ω(nD/Δ) then holds (Diameter68.theorem_6_8).

Details

We reconstructed them: the path 0 — ⋯ — (n−1) plus a star at a covering everything left of a, and a star at b = n/2 − 1 covering everything right of b, with b − a = D − 2. The walk deletes the left and right stars alternately in staggered blocks of D − 1 rounds, observed by the far ends of the path. It needs D ≥ 2, and D = O(Δ) is unnecessary.

Full list of differences (including modelling choices and minor imprecisions): differencies.md.

The formalizationmodel, Lean names of the results, trust

Model.

  • Rounds and adversary. Synchronous rounds. In round r ≥ 1 an adversary picks an arbitrary undirected, loopless, connected graph on the node set V, and nodes broadcast to their neighbours. There are no failures and the protocols are deterministic.

  • Nodes and a-priori knowledge. Nodes are their UIDs (V : Finset ℕ, which may differ between executions). There are three systems:

    • KnownN n: every node is given N = n.

    • UnknownN: no information.

    • BoundN: a valid upper bound N ≥ n.

  • Views. Indist G H u t is the full-information view relation, defined recursively: the shared Cslib.HeardOf.FIIndist (Cslib/Computability/Distributed/DynamicNetworks/FullInfo.lean) with time-0 views (UID, input, N); the causal order Reach is the shared journey relation Cslib.DynNet.Journey (Cslib/Computability/Distributed/DynamicNetworks/Journey.lean). Protocol.state_eq_of_indist shows that every protocol's state is a function of it. Lower bounds therefore quantify over all local decision rules, which covers all protocols. Indistinguishability is always obtained from one locality lemma, indist_of_agree.

  • Knowledge. Knowledge, the similarity graph and common knowledge are defined semantically, as in §2.1 (Knows, Sim, CK). They are the modalities K and C (common knowledge among the nodes present) of the indistinguishability system indistSystem of Cslib/Computability/Distributed/Knowledge/Basic.lean (knows_iff_K, simStep_iff_reach, CK_iff_C).

  • Problems.

    • Consensus is binary, with irrevocable decisions.

    • Δ-coordination: every node has decided within Δ rounds of the first decision. Simultaneous consensus is the case Δ = 0.

    • "Comparison-based" means invariant under order-preserving renaming of UIDs.

The two forms of Theorem 6.7:

  • Explicit: if n ≤ 2^m β, no node of the static line decides by any time t with t + ⌈n/β⌉·3^{m+1}·Δ ≤ n − 1 − β, for every input.

  • Asymptotic: no node decides by t whenever t + 57·Δ^{1/(2+log₂3)}·n^{1−1/(2+log₂3)} ≤ n.

Theorem 5.1 is proved in a stronger form:

  • Known n: all size-n executions are similar at every t ≤ n−2, even with different UID sets.

  • Unknown n: all executions with at least t+1 nodes are similar at time t.

Theorem 6.8 (theorem_6_8'): for 2 ≤ D ≤ n/2 + 1 there is a graph H on {0, …, n−1} of diameter ≤ D such that no Δ-coordinated consensus protocol decides by any time t with t(D−1+Δ) + 4Δ(D−1) ≤ (D−1)(n/2−1), in any execution that follows H up to time t. This is Ω(nD/Δ) for D ≤ Δ + 1.

Lemma 6.6: the proof omits its base case and needs n ≥ 3, which is the paper's model, since it assumes |V| > 2 (lemma_6_6).

Not formalized. The extension of Section 5 to facts about arbitrary times, and the exact (non-approximate) Δ-ladder with nested E^{@t} operators. Theorem 6.8 outside what the Lean theorem covers: D = 1 (the clique) is not reached by our H, D > n/2 + 1 needs a monotonicity step, and the bound says nothing once 3Δ > n/2 − 1.

Trust. No sorry; the listed theorems use only the axioms propext, Classical.choice, Quot.sound. Non-vacuity:

  • The hypotheses of the lower bounds are satisfiable. The rules simKnown, simUnknown, clearMajority, ladder, diamProtocol and majRule are proved to solve the respective problems.

  • The lower bounds are tight where the paper says so (simKnown_spec, simUnknown_spec).

  • The model (Model.lean) is built on the shared journeys, full-information views (with the locality lemma FIIndist.of_agree) and knowledge of Cslib/Computability/Distributed/DynamicNetworks/ and Cslib/Computability/Distributed/Knowledge/. CSLib candidates: the hiding lemma (Hiding.lean) and the generic first-firing/ladder combinator (UpperBounds.lean).
