import Cslib.Computability.Distributed.SyncCrash.Model import Mathlib /-! # Model of Herlihy–Moses–Tuttle, *Transforming worst-case optimal solutions for simultaneous tasks into all-case optimal solutions* (PODC 2011), §2 * Synchronous message passing with crash failures (§2.1): CSLib's `Cslib.SyncCrash` model. A run (`Cslib.SyncCrash.Run P I`) is an input vector plus a crash pattern (crash round `c ≥ 1`, the set `reach p` of processes still reached in the crashing round); `Run.Admissible t` = at most `t` crashes. Protocols are CSLib's deterministic history-based lock-step protocols (`Cslib.Byzantine.LockStep.Protocol P I M O`): the local state of `p` at time `m` is its input and the list of inboxes of rounds `1, …, m` (`Cslib.SyncCrash.state`). The run of a protocol is determined by the protocol, the input vector and the failure pattern (`r = A[ı, F]`). * Decisions (§2.2): `A.decide p x h` is the content of `p`'s output register; `p` *decides `d` at time `m`* (`Decides`) iff `p` is alive at time `m`, the register holds `d` at time `m` and was empty before (the first write). * Decision tasks (`Task`), solving a task (`Solves`), the simultaneous version (`SolvesSim`), and solving within `k` rounds (`SolvesWithin`). * Truncated failure patterns (`Run.trunc`) and the key consequence for simultaneous protocols: if some process decides at time `k`, every process alive at time `k` decides at time `k` (`SolvesSim.decides_of_alive`). This fact is used silently in the paper's proofs of Lemma 1, Theorem 3 and Lemma 4. * Exposed failures and the waste `W(F)` (§4). -/ namespace Podc.SimultaneousAllCaseOptimal open Cslib.SyncCrash
