import Papers.PODC2011.UnboundedConcurrency.Lemma14 /-! # Lemma 15: the two critical operations are not writes to the same iterator stack Afek–Morrison–Wertheim, PODC 2011, Section 5.3. Suppose that after `α a b` only `u` and after `α b a` only `¬u` can be decided, and that `a` and `b` are both poised to write (values `v_a`, `v_b`) to the same iterator stack `O`. The two executions differ only in `O`'s value sequence: `[v_b, v_a, …]` versus `[v_a, v_b, …]` (and in the local states of `a`, `b`). We build two infinite executions, extending `α a b` and `α b a` by the *same* schedule, in which a fresh victim process `R` takes infinitely many steps but can never tell them apart, hence never decides — contradicting wait-freedom. Throughout, the memories differ only in two adjacent entries of `O`'s value sequence (the *window*, positions `w + 1, w + 2`), swapped; a read is *distinguishing* if the iterator it reads points into the window. **Repaired construction.** Whenever `R` is about to perform a distinguishing read, we unblock it with fresh processes, each run solo until it is about to perform a distinguishing read or a write to `O`: * a distinguishing read is executed and its process is never scheduled again (the read changes the memory in the same way in both executions); * a process about to write is kept pending; once there are two pending writers, both writes are executed, shifting the window two positions down, past `R`'s iterator. After each distinguishing read we check whether `R`'s read is still distinguishing (other processes may read `R`'s iterator). Distinguishing reads strictly decrease the potential `Φ = Σ_iterators (w + 3 - pos)` while no write is executed, so `R` is unblocked after finitely many fresh processes. The paper's construction differs in two points that make it fail as written: it freezes a new process at *any* read with an old iterator (so new processes may be frozen forever without any progress, e.g. if each first reads an exhausted iterator), and it lets `R` read only after two writes, although the frozen readers may have advanced `R`'s iterator so that after the two writes it points into
